## ปัญหาของคิวแบบตรง ๆ

คิวเข้าทางหลังและออกทางหน้า ถ้าเก็บไว้ในอาเรย์แบบ vector แล้วให้ตัวหน้าอยู่ที่ `mData[0]` เสมอ ทุกครั้งที่ pop จะต้องเลื่อนทุกตัวมาทางซ้าย ซึ่งเป็น $O(n)$ ต่อครั้ง ถ้ามีการ pop เป็นล้านครั้ง TLE แน่นอน

ทางแก้คือ **อย่าเลื่อนข้อมูล ให้เลื่อนจุดเริ่มต้นแทน**

## ring buffer

`CP::queue<T>` มีฟิลด์เพิ่มมาหนึ่งตัวคือ `mFront` ซึ่งบอกว่าตัวหน้าสุดอยู่ช่องไหน แล้วมองอาเรย์ให้เป็นวงกลม คือช่องถัดจาก `mCap - 1` วนกลับไปที่ `0`

```text
mCap = 6, mFront = 4, mSize = 4

ดัชนี:  0    1    2    3    4    5
mData: [ C ][ D ][ . ][ . ][ A ][ B ]
                            หน้า
ลำดับในคิว: A B C D
```

สมาชิกตัวที่ $i$ ของคิว (นับจากหน้า เริ่มที่ $0$) จึงอยู่ที่

$$(\text{mFront} + i) \bmod \text{mCap}$$

ลองเช็กกับรูป: $i = 2$ ได้ $(4 + 2) \bmod 6 = 0$ ซึ่งคือ `C` ถูกต้อง

:::problem hp_que01_at

## สูตรที่ใช้บ่อย

| อยากได้ | ดัชนีในอาเรย์ |
|---|---|
| ตัวหน้า | `mFront` |
| ตัวที่ `i` | `(mFront + i) % mCap` |
| ตัวท้าย | `(mFront + mSize - 1) % mCap` |
| ช่องว่างถัดจากตัวท้าย (ที่ push จะเขียน) | `(mFront + mSize) % mCap` |

ส่วน `pop()` ก็แค่ขยับ `mFront = (mFront + 1) % mCap` แล้วลด `mSize` ไม่ต้องย้ายอะไรเลย ได้ $O(1)$ อย่างที่ต้องการ

:::problem hp_que02_back

## ถอยหลังแบบวงกลม: กับดัก size_t

ถ้าจะ push เข้าทางหน้า (`push_front`) ต้องถอย `mFront` ไปทางซ้ายหนึ่งช่อง และถ้า `mFront` เป็น `0` ต้องวนไปที่ `mCap - 1`

หลายคนเขียน `(mFront - 1) % mCap` ซึ่ง **ผิด** เพราะ `mFront` เป็น `size_t` พอเท่ากับ `0` แล้วลบ 1 จะไม่ได้ $-1$ แต่ได้ $2^{64} - 1$ ซึ่งพอเอาไป mod กับ `mCap` ก็ได้เลขมั่ว ๆ (ยกเว้น `mCap` บังเอิญเป็นกำลังของสอง ซึ่งทำให้ test เล็ก ๆ บางชุดผ่านไปได้ น่ากลัวกว่าเดิมอีก)

ทางที่ถูกคือ **บวก `mCap` ก่อนค่อยลบ**

```cpp
mFront = (mFront + mCap - 1) % mCap;
```

และอย่าลืม `ensureCapacity(mSize + 1)` **ก่อน** ขยับ `mFront` เพราะ `expand` ของคิวจะจัดข้อมูลใหม่ให้เริ่มที่ดัชนี `0` และตั้ง `mFront = 0` ถ้าขยับก่อนแล้วค่อยขยาย ค่าที่ขยับไว้จะหายไป

:::problem hp_que03_push_front

:::note expand ของคิวไม่เหมือนของ vector
`expand` ใน `queue.h` คัดลอกตามลำดับของคิว (`mData[(mFront + i) % mCap]`) ไปไว้ที่ `arr[i]` แล้วตั้ง `mFront = 0` ดังนั้นหลังขยายเสร็จ คิวจะเรียงตรง ๆ ในอาเรย์ใหม่ทุกครั้ง
:::

## pop ทางหลัง

ใน ring buffer การเอาตัวท้ายออกง่ายกว่าที่คิด เพราะตัวท้ายถูกกำหนดจาก `mFront + mSize - 1` อยู่แล้ว การลด `mSize` ลงหนึ่งจึงทำให้มันหายไปเองโดยไม่ต้องแตะ `mFront` ลองคิดต่อด้วยว่าถ้า pop จนว่างแล้ว push ใหม่ ทุกอย่างยังถูกต้องอยู่ไหม

:::problem hp_que04_pop_back

## กลับด้านใน $O(1)$ ด้วยธง

ถ้าต้อง reverse คิวเป็นล้านครั้ง การย้ายข้อมูลจริงทุกครั้งเป็นไปไม่ได้ ไอเดียคือ **ไม่ต้องย้ายเลย** แค่จำไว้ในฟิลด์ `aux` ว่าตอนนี้ "กลับด้านอยู่หรือเปล่า" แล้วให้ทุกฟังก์ชันตีความคำว่า "หน้า" กับ "หลัง" ตามธงนั้น

* ไม่กลับด้าน: หน้าคือ `mFront` และ push ไปต่อที่ท้าย
* กลับด้านอยู่: หน้าในมุมมองของผู้ใช้คือตัวท้ายจริงในอาเรย์ และ push ของผู้ใช้ต้องไปเติมที่หน้าจริงแทน

:::hint ใบ้ Queue Reverse
`reverse()` แค่สลับค่า `aux` ระหว่าง 0 กับ 1 งานจริงอยู่ที่ `front`, `back`, `push` และ `pop` ซึ่งแต่ละตัวต้องมีสองแบบตามธง ลองเขียนแบบปกติให้ถูกก่อน แล้วสังเกตว่าแบบกลับด้านคือการสลับบทบาทของ "ปลายหน้า" กับ "ปลายหลัง" ซึ่งก็คือ push_front กับ pop_back ที่เพิ่งทำไปนั่นเอง
:::

## สรุปสั้น ๆ

* ไม่เลื่อนข้อมูล แต่เลื่อน `mFront` และมองอาเรย์เป็นวงกลม
* ตัวที่ $i$ อยู่ที่ `(mFront + i) % mCap`
* ถอยหลังให้ใช้ `(mFront + mCap - 1) % mCap` ห้ามลบก่อน
* ขอที่ด้วย `ensureCapacity` ก่อนขยับ `mFront` เสมอ
* งานที่ต้องทำซ้ำเยอะ ๆ บางทีแค่เก็บธงไว้ แล้วเปลี่ยนวิธีตีความ ก็พอแล้ว
