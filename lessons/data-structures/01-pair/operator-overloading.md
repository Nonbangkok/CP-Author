## เริ่มจากคลาสที่เล็กที่สุด

`CP::pair<T1, T2>` มีแค่สองช่อง คือ `first` กับ `second` ไม่มีอาเรย์ ไม่มี pointer ให้ปวดหัว เลยเหมาะมากสำหรับฝึก "ท่า" ที่ header problem ทุกข้อใช้ นั่นคือการเขียน **member function นอกคลาส** ลงในไฟล์ `student.h`

คลาสในไฟล์ `pair.h` จะ *ประกาศ* ฟังก์ชันไว้แล้ว เช่น

```cpp
bool operator==(const pair<T1, T2> &other) const;
```

งานของเราคือ *นิยาม* มันใน `student.h` ซึ่งหน้าตาจะยาวกว่าปกตินิดหน่อย เพราะคลาสเป็น template

## หน้าตาของ member function นอกคลาส

สมมติว่าเราอยากเพิ่มฟังก์ชัน (ที่ไม่ได้อยู่ในโจทย์ข้อไหนนะ) ชื่อ `is_diagonal()` ที่ตอบว่า `first` เท่ากับ `second` หรือเปล่า จะเขียนแบบนี้

```cpp
template <typename T1, typename T2>
bool CP::pair<T1, T2>::is_diagonal() const
{
  return first == second;
}
```

แยกทีละท่อนจะเห็นว่ามีแค่ 4 อย่างที่ต้องจำ

1. `template <typename T1, typename T2>` ต้องมีทุกครั้ง เพราะคลาสเป็น template
2. ชนิดที่คืน (`bool`) อยู่หน้าสุด
3. ชื่อเต็มคือ `CP::pair<T1, T2>::` ตามด้วยชื่อฟังก์ชัน
4. ถ้าในคลาสประกาศว่า `const` ตรงนี้ก็ต้องมี `const` ด้วย ไม่งั้นคอมไพล์ไม่ผ่าน

ข้างในฟังก์ชันเราเรียก `first`, `second` ได้ตรง ๆ เพราะมันเป็นสมาชิกของ `*this` และเรียก `other.first` ของอีกตัวได้ด้วย

:::note const แปลว่าอะไร
ฟังก์ชันที่มี `const` ท้ายชื่อสัญญาว่า "จะไม่แก้ `*this`" เลยเรียกได้แม้กับ pair ที่เป็น `const` ถ้าเผลอไปแก้ `first` ข้างใน คอมไพเลอร์จะฟ้องทันที ซึ่งดีมาก เพราะ error ตอนคอมไพล์หาง่ายกว่าตอนรันเยอะ
:::

## เรียงแบบพจนานุกรม (lexicographic)

การเทียบ pair ปกติเทียบ `first` ก่อน ถ้า `first` เท่ากันค่อยไปดู `second` เหมือนเรียงคำในพจนานุกรมที่ดูตัวอักษรตัวแรกก่อน

$$(a_1, b_1) < (a_2, b_2) \iff a_1 < a_2 \;\lor\; (a_1 = a_2 \land b_1 < b_2)$$

อ่านว่า "`first` น้อยกว่า **หรือ** `first` เท่ากัน **และ** `second` น้อยกว่า"

จุดที่คนพลาดบ่อยที่สุดคือกรณี `first` เท่ากัน ลองเช็กกับตัวอย่างนี้ในหัวดู: $(3, 1) < (3, 2)$ ต้องเป็นจริง แต่ $(3, 2) < (3, 2)$ ต้องเป็นเท็จ เพราะ `<` คือ "น้อยกว่าแท้ ๆ"

:::problem hp_pair02_less

## เขียนทุกอย่างจาก `<` ตัวเดียว

ถ้าโจทย์ให้เขียนหลาย operator พร้อมกัน วิธีที่ปลอดภัยที่สุดคือเขียน `<` ให้ถูกก่อนตัวเดียว แล้วสร้างตัวอื่นจากมัน เพราะแบบนี้มันจะไม่มีวันขัดกันเอง

| อยากได้ | เขียนจาก `<` |
|---|---|
| `a > b` | `b < a` |
| `a <= b` | `!(b < a)` |
| `a >= b` | `!(a < b)` |
| `a == b` | `!(a < b) && !(b < a)` |
| `a != b` | `(a < b) \|\| (b < a)` |

ไฟล์ `pair.h` ของบางข้อก็ใช้ท่านี้อยู่แล้ว เช่น `!=` ถูกเขียนจาก `==` ไว้ให้ ถ้า `==` ของเราผิด `!=` ก็จะผิดตามไปด้วย ระวังนะ

:::hint ข้อ Pair Ordering ทำยังไงดี
ข้อ `hp_pair10_ordering` ตรวจว่า operator ทั้งหกตัว "ตกลงกันได้" ทุกคู่ ลองเขียน `<` ให้ถูกก่อน แล้วให้อีกห้าตัวเรียก `<` ตามตารางด้านบน แทนที่จะเขียนเงื่อนไขซ้ำหกรอบ จะได้ไม่มีตัวไหนแอบคิดต่างจากตัวอื่น
:::

## คืนค่าเป็นอะไรดี: copy หรือ reference

ลองเทียบสอง operator นี้

* `a + b` สร้าง pair **ใหม่** แล้วคืนค่านั้นออกไป จึงคืนเป็น `pair<T1, T2>` (copy) ส่วน `a` กับ `b` ต้องไม่เปลี่ยน ฟังก์ชันเลยเป็น `const`
* `a += b` แก้ `a` **ตัวเดิม** แล้วคืน `*this` เป็น reference (`pair<T1, T2> &`) ฟังก์ชันนี้จึงเป็น `const` ไม่ได้

ที่ต้องคืน `*this` ก็เพื่อให้ต่อกันได้แบบ `a += b += c` ซึ่ง C++ อ่านจากขวาไปซ้าย คือ `a += (b += c)` และถ้าคืนเป็น copy แทน reference จะเกิดเรื่องแปลก ๆ ตอน `(a += b) += c` เพราะ `+= c` ไปแก้สำเนา ไม่ได้แก้ `a`

:::warning อย่าคืน reference ไปที่ตัวแปรในฟังก์ชัน
ถ้าฟังก์ชันคืน `const pair &` ต้องคืนสิ่งที่ยังมีชีวิตอยู่หลังฟังก์ชันจบ เช่น `*this` หรือ `other` ห้ามคืนตัวแปร local เด็ดขาด เพราะมันถูกทำลายทันทีที่ return โปรแกรมอาจดูเหมือนรันได้บนเครื่องเรา แต่ไปพังบน grader
:::

## สรุปสั้น ๆ

* member function นอกคลาส = `template` + ชนิดคืน + `CP::pair<T1, T2>::ชื่อ` + `const` ถ้าในคลาสมี
* `<` แบบพจนานุกรม: ดู `first` ก่อน เท่ากันค่อยดู `second`
* อยากได้หลาย operator ให้สร้างจาก `<` ตัวเดียว
* operator ที่สร้างค่าใหม่คืน copy ส่วน operator ที่แก้ตัวเองคืน `*this` เป็น reference
