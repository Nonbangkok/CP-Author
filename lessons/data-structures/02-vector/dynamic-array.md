## อาเรย์ที่โตเองได้

อาเรย์ธรรมดาใน C++ ต้องบอกขนาดตอนสร้าง แล้วเปลี่ยนไม่ได้อีก `CP::vector<T>` แก้ปัญหานี้ด้วยการเก็บข้อมูลไว้ในอาเรย์บน heap แล้วจดตัวเลขไว้สองตัว

| ฟิลด์ | ความหมาย |
|---|---|
| `T *mData` | ชี้ไปที่อาเรย์จริงที่จองไว้ |
| `size_t mCap` | อาเรย์นั้นจุได้กี่ช่อง (capacity) |
| `size_t mSize` | ตอนนี้ใช้จริงอยู่กี่ช่อง |

สมาชิกที่มีความหมายอยู่ที่ดัชนี `0` ถึง `mSize - 1` เท่านั้น ช่องที่เหลือจนถึง `mCap - 1` เป็นที่ว่างสำรองไว้ และเงื่อนไขที่ต้องจริงเสมอคือ $0 \le \text{mSize} \le \text{mCap}$

:::note clear() ไม่ได้คืนหน่วยความจำ
`clear()` ใน `vector.h` แค่ตั้ง `mSize = 0` อาเรย์เดิมยังอยู่ครบ `capacity()` เลยเท่าเดิม แบบนี้ถ้าจะเติมข้อมูลกลับเข้าไปใหม่ก็ไม่ต้องจองหน่วยความจำอีกรอบ
:::

## พื้นที่เต็มแล้วทำยังไง

ใน `vector.h` มีฟังก์ชันช่วยสองตัวที่ทุกข้อใช้ได้

```cpp
void expand(size_t capacity)
{
  T *arr = new T[capacity]();
  for (size_t i = 0; i < mSize; i++)
    arr[i] = mData[i];
  delete[] mData;
  mData = arr;
  mCap = capacity;
}

void ensureCapacity(size_t capacity)
{
  if (capacity > mCap)
  {
    size_t s = (capacity > 2 * mCap) ? capacity : 2 * mCap;
    expand(s);
  }
}
```

`expand` จองอาเรย์ใหม่ ย้ายข้อมูลทั้งหมดไป แล้วทิ้งอันเก่า ซึ่งแพงถึง $O(n)$ ส่วน `ensureCapacity` เรียก `expand` เฉพาะตอนที่ที่ไม่พอจริง ๆ และที่สำคัญคือ **ขยายเป็นสองเท่า** ไม่ใช่ทีละช่อง

## ทำไมต้องสองเท่า

สมมติเรา push ไปเรื่อย ๆ จนมี $n$ ตัว

* ถ้าขยายทีละ 1 ช่อง ทุกครั้งที่ push ต้องย้ายของเดิมทั้งหมด รวมแล้ว $1 + 2 + \cdots + n = O(n^2)$ ช้ามาก
* ถ้าขยายเป็นสองเท่า การย้ายจะเกิดตอนขนาด $1, 2, 4, 8, \ldots$ เท่านั้น รวมแล้วไม่เกิน $2n$ ครั้ง

แปลว่าถ้าเฉลี่ยต่อการ push หนึ่งครั้ง ใช้เวลาแค่ $O(1)$ เราเรียกแบบนี้ว่า **amortized** $O(1)$ บาง push อาจช้า แต่โดยรวมเร็วเสมอ

:::warning เรียก ensureCapacity ก่อนเขียนเสมอ
ทุกฟังก์ชันที่ทำให้ `mSize` เพิ่ม ต้องเรียก `ensureCapacity(ขนาดใหม่)` **ก่อน** เขียนลงอาเรย์ ถ้าเขียนก่อนจะเลยขอบอาเรย์ไป บนเครื่องเราอาจดูเหมือนรันได้ แต่บน grader มักจบที่ Runtime Error
:::

## `[]` กับ `at()` ต่างกันยังไง

`operator[]` คืน `mData[index]` ตรง ๆ ไม่เช็กอะไรเลย เร็วสุด แต่ถ้าดัชนีเกินก็ไปอ่านขยะในหน่วยความจำ ส่วน `at()` ของ `std::vector` จะเช็กก่อนแล้ว `throw std::out_of_range` ถ้าเกิน

ใน `vector.h` มี `rangeCheck(index)` ที่ทำแบบนั้นไว้ให้แล้ว ใช้ได้เลยไม่ต้องเขียนใหม่

:::problem hp_vec01_fill

## ลองนึกก่อนข้อถัดไป

ถ้าอยากลบตัวแรก (`pop_front`) ต้องทำอะไรบ้าง ลองนึกดูก่อนจะไปอ่านบทถัดไปนะ คำใบ้คือ `mData[0]` ต้องว่างไม่ได้ เพราะสมาชิกต้องเริ่มที่ดัชนี `0` เสมอ

:::hint ใบ้ pop_front
ทุกตัวต้องขยับมาทางซ้ายหนึ่งช่อง แล้วค่อยลด `mSize` เลยใช้เวลา $O(n)$ ต่อครั้ง ซึ่งโจทย์ก็ยอมรับเวลานี้ และถ้า vector ว่างอยู่ก็แค่ไม่ต้องทำอะไร
:::

## สรุปสั้น ๆ

* ข้อมูลจริงอยู่ที่ `mData[0 .. mSize-1]` ส่วน `mCap` คือที่จองไว้ทั้งหมด
* ขยายเป็นสองเท่า ทำให้ push เป็น amortized $O(1)$
* เพิ่มข้อมูลเมื่อไหร่ ให้ `ensureCapacity` ก่อนทุกครั้ง
* `at()` = `rangeCheck` + คืนค่า
