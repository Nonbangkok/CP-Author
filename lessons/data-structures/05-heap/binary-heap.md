## ต้นไม้ที่ซ่อนอยู่ในอาเรย์

`CP::priority_queue<T, Comp>` เก็บข้อมูลใน `mData` เหมือน vector ทุกอย่าง แต่เรามองอาเรย์นั้นเป็น **ต้นไม้ทวิภาคที่เต็มทุกชั้น** (complete binary tree) โดยไม่ต้องมี pointer สักตัว

ปุ่มที่ดัชนี $i$ มี

* ลูกซ้ายที่ $2i + 1$
* ลูกขวาที่ $2i + 2$
* พ่อที่ $\lfloor (i - 1) / 2 \rfloor$ (เมื่อ $i > 0$)

```text
mData: [ 50 ][ 30 ][ 40 ][ 10 ][ 20 ][ 35 ]
ดัชนี:    0     1     2     3     4     5

            50            <- 0
         /      \
       30        40       <- 1, 2
      /  \      /
    10    20  35          <- 3, 4, 5
```

ลองเช็กกับรูป: ลูกของดัชนี `1` (ค่า 30) อยู่ที่ $2 \cdot 1 + 1 = 3$ และ $2 \cdot 1 + 2 = 4$ ส่วนพ่อของดัชนี `5` อยู่ที่ $\lfloor 4 / 2 \rfloor = 2$ ถูกต้องทั้งคู่

## เงื่อนไขของฮีป และ mLess

ฮีปมีกติกาข้อเดียวคือ **ทุกปุ่มต้องสำคัญไม่น้อยกว่าลูกของมัน** ผลคือตัวที่สำคัญที่สุดอยู่ที่ราก `mData[0]` เสมอ `top()` เลยตอบได้ใน $O(1)$

คำว่า "สำคัญ" ไม่ได้วัดด้วย `<` ตรง ๆ แต่วัดด้วย `Comp mLess` ที่คลาสเก็บไว้ โดย `mLess(a, b)` เป็นจริงเมื่อ `a` **สำคัญน้อยกว่า** `b`

* `Comp = std::less<T>` (ค่าเริ่มต้น) ตัวใหญ่สุดอยู่บนสุด เรียกว่า max-heap
* `Comp = std::greater<T>` ตัวเล็กสุดอยู่บนสุด เรียกว่า min-heap

:::warning เทียบผ่าน mLess เท่านั้น
grader ใช้ฮีปของ struct ที่ **ไม่มี** `operator<` ด้วย ถ้าในโค้ดเราเผลอเขียน `a < b` จะคอมไพล์ไม่ผ่าน และถึงคอมไพล์ผ่าน ฮีปแบบ `std::greater` ก็จะได้คำตอบกลับด้าน ให้ใช้ `mLess(a, b)` ทุกครั้งที่เทียบ
:::

## push: ต่อท้าย แล้วลอยขึ้น (fixUp)

`push` ใส่ค่าใหม่ไว้ท้ายอาเรย์ ซึ่งยังเป็นต้นไม้ที่เต็มทุกชั้นอยู่ แต่ค่านั้นอาจสำคัญกว่าพ่อ ก็เลยต้อง **ลอยขึ้น** ไปเรื่อย ๆ จนพ่อสำคัญไม่น้อยกว่ามัน หรือจนถึงราก

```cpp
void fixUp(size_t idx)
{
  T tmp = mData[idx];
  while (idx > 0)
  {
    size_t p = (idx - 1) / 2;
    if (mLess(tmp, mData[p]))
      break;               // พ่อสำคัญกว่าแล้ว หยุด
    mData[idx] = mData[p]; // ดึงพ่อลงมา
    idx = p;
  }
  mData[idx] = tmp;
}
```

## pop: ย้ายตัวท้ายมาที่ราก แล้วจมลง (fixDown)

`pop` เอาตัวท้ายสุดมาวางแทนราก แล้วลด `mSize` จากนั้นรากใหม่มักจะไม่ใช่ตัวที่สำคัญที่สุด เลยต้อง **จมลง** โดยแลกกับลูกที่สำคัญกว่าในสองตัว จนกว่าจะสำคัญไม่น้อยกว่าลูกทั้งสอง

ความสูงของต้นไม้ที่มี $n$ ปุ่มคือ $\lfloor \log_2 n \rfloor$ การลอยขึ้นหรือจมลงจึงเดินไม่เกินความสูงนี้ `push` กับ `pop` เลยเป็น $O(\log n)$

:::note ทำไมต้องเลือกลูกที่สำคัญกว่า
ถ้าเราสลับกับลูกที่สำคัญน้อยกว่า ลูกอีกตัวที่สำคัญกว่าจะกลายเป็นลูกของปุ่มที่สำคัญน้อยกว่าตัวมันเอง ซึ่งผิดกติกาทันที
:::

## ใบมีครึ่งหนึ่งของอาเรย์

ปุ่มที่ดัชนี $i$ มีลูกก็ต่อเมื่อ $2i + 1 < n$ ดังนั้น **ใบ** (ปุ่มที่ไม่มีลูก) คือดัชนีตั้งแต่ $\lfloor n / 2 \rfloor$ ถึง $n - 1$ ซึ่งเป็นประมาณครึ่งหนึ่งของอาเรย์

ข้อเท็จจริงนี้ช่วยได้มาก เพราะตัวที่สำคัญน้อยที่สุดเป็นพ่อของใครไม่ได้ (ถ้าเป็นพ่อ ลูกจะต้องสำคัญน้อยกว่ามันอีก) มันจึงต้องเป็นใบเสมอ

:::problem hp_pq01_min

## ตรวจว่ายังเป็นฮีปอยู่ไหม

การตรวจเงื่อนไขของฮีปไม่ต้องไล่ทั้งต้นไม้แบบ recursive ให้ดูทีละลูก: สำหรับทุก $c$ ตั้งแต่ $1$ ถึง $n - 1$ พ่อของ $c$ ต้องไม่สำคัญน้อยกว่า $c$ ถ้ามีคู่ไหนผิดก็ตอบเท็จได้เลย ใช้เวลา $O(n)$

:::problem hp_pq02_is_heap

## ตัวที่สำคัญเป็นอันดับสอง

ตัวที่สำคัญเป็นอันดับสองต้องเป็น **ลูกของราก** เท่านั้น ลองคิดดูว่าทำไม: ถ้ามันอยู่ลึกกว่านั้น พ่อของมันซึ่งไม่ใช่รากจะต้องสำคัญไม่น้อยกว่ามัน ซึ่งขัดกับที่ว่ามันเป็นอันดับสอง ดังนั้นแค่เทียบ `mData[1]` กับ `mData[2]` (ถ้ามีอยู่) ก็ตอบได้ใน $O(1)$

:::hint ใบ้ Priority Queue Third
อันดับสามก็ใช้เหตุผลแบบเดียวกัน พ่อของมันต้องเป็นอันดับหนึ่งหรือสองเท่านั้น ผู้สมัครจึงมีแค่ลูกของรากที่เหลืออยู่ กับลูกของตัวอันดับสอง ไม่เกินไม่กี่ตัว และอย่าลืมกรณีที่ฮีปมีสมาชิกน้อยกว่าที่ต้องการ
:::

## สรุปสั้น ๆ

* ลูกอยู่ที่ $2i + 1$ และ $2i + 2$ ส่วนพ่ออยู่ที่ $\lfloor (i - 1)/2 \rfloor$
* รากคือตัวที่สำคัญที่สุด และเทียบทุกครั้งผ่าน `mLess`
* push = ต่อท้ายแล้ว fixUp ส่วน pop = ย้ายตัวท้ายมาที่รากแล้ว fixDown ทั้งคู่เป็น $O(\log n)$
* ใบอยู่ที่ดัชนี $\lfloor n/2 \rfloor$ ขึ้นไป และอันดับสองต้องเป็นลูกของราก
