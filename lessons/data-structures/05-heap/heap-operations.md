## สองเครื่องมือที่ใช้ซ่อมฮีปได้ทุกงาน

บทที่แล้วเราใช้ `fixUp` หลัง push และใช้ `fixDown` หลัง pop บทนี้จะใช้สองฟังก์ชันเดิม (ซึ่งอยู่ใน `priority_queue.h` แล้ว) ทำงานที่ยากขึ้น หลักคิดมีข้อเดียว

> ถ้าแก้ปุ่มเดียวแล้วฮีปเสีย มันเสียได้แค่สองแบบ คือปุ่มนั้นสำคัญเกินพ่อ (ต้องลอยขึ้น) หรือสำคัญน้อยกว่าลูก (ต้องจมลง) ไม่มีทางเป็นทั้งสองแบบพร้อมกัน

## เปลี่ยนค่ากลางฮีป

สมมติเปลี่ยน `mData[i]` เป็นค่าใหม่

* ถ้าค่าใหม่สำคัญ **มากขึ้น** มันอาจสำคัญเกินพ่อ ให้ `fixUp(i)`
* ถ้าค่าใหม่สำคัญ **น้อยลง** มันอาจสำคัญน้อยกว่าลูก ให้ `fixDown(i)`

จะเทียบค่าเก่ากับค่าใหม่ด้วย `mLess` ก็ได้ หรือจะเรียก `fixUp(i)` แล้วตามด้วย `fixDown(i)` เลยก็ได้เหมือนกัน เพราะตามหลักข้างบน จะมีแค่ตัวเดียวที่ขยับจริง แต่ต้องระวังว่าหลัง `fixUp` ค่านั้นอาจย้ายไปอยู่ดัชนีอื่นแล้ว `fixDown(i)` ที่ตามมาจะไปทำงานที่ปุ่มที่ถูกดึงลงมาแทน ซึ่งก็ยังถูกต้องอยู่ดี เพราะปุ่มนั้นมาจากพ่อที่สำคัญกว่าลูกเดิมอยู่แล้ว ลองไล่ในหัวดูสักครั้งให้มั่นใจ

ทั้งหมดนี้ใช้เวลา $O(\log n)$

## ลบตามค่า

ถ้าต้องลบค่า `x` หนึ่งตัวออกจากฮีป ทำได้สามขั้น

1. หาดัชนีของ `x` ก่อน ฮีปไม่ได้เรียงลำดับไว้ให้ค้นหา จึงต้องไล่ดู ใช้เวลา $O(n)$ และถ้าหาไม่เจอก็ไม่ต้องทำอะไร
2. ย้ายตัวท้ายสุดมาแทนที่ดัชนีนั้น แล้วลด `mSize`
3. ซ่อมที่ดัชนีนั้น

:::warning จุดที่พลาดบ่อยที่สุด
ตัวท้ายที่ย้ายมาอาจ **สำคัญกว่า** พ่อของตำแหน่งใหม่ก็ได้ (เพราะมันมาจากคนละกิ่ง) ถ้าเรียกแค่ `fixDown` อย่างที่ pop ทำ ฮีปจะเสียแบบเงียบ ๆ ต้องซ่อมทั้งขึ้นและลงตามหลักของหัวข้อที่แล้ว และอย่าลืมกรณีที่ตัวที่ลบเป็นตัวท้ายสุดพอดี ซึ่งไม่ต้องย้ายอะไรเลย
:::

:::problem hp_pq08_erase

## รวมสองฮีปใน $O(n + m)$

วิธีที่ใครก็คิดออกคือ push สมาชิกของอีกฮีปเข้ามาทีละตัว ซึ่งใช้เวลา $O(m \log(n + m))$ และช้าเกินไปเมื่อมีเป็นล้านตัว

วิธีที่เร็วกว่าคือ **ต่ออาเรย์เข้าด้วยกันก่อน แล้วสร้างฮีปใหม่จากล่างขึ้นบน**

```cpp
// สร้างฮีปจากอาเรย์ใด ๆ ที่มี mSize ตัว (ใช้ fixDown ที่มีอยู่แล้ว)
for (size_t i = mSize / 2; i-- > 0; )
  fixDown(i);
```

ลูปนี้เริ่มจากปุ่มสุดท้ายที่มีลูก (ใบไม่ต้องทำอะไร เพราะใบเป็นฮีปขนาดหนึ่งอยู่แล้ว) แล้วไล่ขึ้นไปถึงราก เมื่อถึงปุ่มไหน ลูกทั้งสองของมันเป็นฮีปที่ถูกต้องแล้ว การ `fixDown` ครั้งเดียวจึงพอ

ที่น่าทึ่งคือรวมแล้วใช้แค่ $O(n)$ ไม่ใช่ $O(n \log n)$ เพราะปุ่มส่วนใหญ่อยู่ชั้นล่างที่จมได้แค่ไม่กี่ขั้น: ครึ่งหนึ่งเป็นใบที่จมได้ 0 ขั้น หนึ่งในสี่จมได้ไม่เกิน 1 ขั้น และไล่ไปเรื่อย ๆ ผลรวมคือ

$$\sum_{h \ge 0} \frac{n}{2^{h+1}} \cdot h = O(n)$$

:::note สังเกตลูปถอยหลัง
`for (size_t i = mSize / 2; i-- > 0; )` เป็นท่านับถอยหลังด้วย `size_t` ที่ปลอดภัย เพราะเช็ก `i > 0` ก่อนจะลด ลูปเลยหยุดหลังจากทำ `i = 0` เสร็จ โดยไม่วนไปถึง $2^{64} - 1$
:::

:::problem hp_pq09_merge

:::hint ใบ้ Priority Queue Merge
ขอที่ด้วย `ensureCapacity` ครั้งเดียวสำหรับขนาดรวม copy ข้อมูลของอีกฮีปมาต่อท้าย แล้วสร้างฮีปใหม่ด้วยลูปข้างบน อย่าลืมว่าโจทย์ให้อีกฮีป **ว่างลง** หลังรวมเสร็จด้วย
:::

## หาตัวที่สำคัญเป็นอันดับ $k$ โดยไม่แตะฮีป

ถ้า copy ทั้งฮีปแล้วเรียงลำดับ จะใช้เวลา $O(n \log n)$ ซึ่งเยอะเกินไปเมื่อ $n$ เป็นล้านแต่ $k$ แค่หลักแสน

สังเกตว่าตัวที่สำคัญเป็นอันดับ $j$ ต้องเป็นลูกของตัวใดตัวหนึ่งในอันดับ $1$ ถึง $j - 1$ (หรือเป็นราก) เราจึงไม่ต้องดูทั้งฮีป ดูแค่ "ขอบ" ของส่วนที่หยิบออกมาแล้วก็พอ

:::hint ใบ้ Priority Queue K-th
ใช้ฮีปเล็ก ๆ อีกตัวเก็บ **ดัชนี** ของผู้สมัคร เริ่มจากราก แล้วทำ $k - 1$ รอบ: หยิบผู้สมัครที่สำคัญที่สุดออก แล้วใส่ลูกของมันในฮีปหลักเข้าไปเป็นผู้สมัครแทน ตัวที่อยู่บนสุดของฮีปเล็กหลังจบลูปคือคำตอบ ฮีปเล็กมีไม่เกิน $O(k)$ ตัว จึงใช้เวลารวม $O(k \log k)$ และฮีปหลักไม่ถูกแก้เลย จะใช้ `std::priority_queue` กับตัวเปรียบเทียบที่เรียก `mLess` ผ่านดัชนีก็ได้
:::

:::problem hp_pq10_kth

## สรุปสั้น ๆ

* แก้ปุ่มเดียวแล้วต้องซ่อมได้ทั้งขึ้นและลง: ใช้ `fixUp` หรือ `fixDown` ให้ถูกตัว หรือเรียกทั้งสอง
* ลบตามค่า = หาให้เจอ แล้วย้ายตัวท้ายมาแทน แล้วซ่อม **ทั้งสองทาง**
* สร้างฮีปจากอาเรย์ด้วย `fixDown` จากล่างขึ้นบนได้ใน $O(n)$ ใช้รวมฮีปได้
* อันดับ $k$ หาได้โดยไล่เฉพาะขอบของส่วนที่หยิบไปแล้ว ด้วยฮีปผู้สมัครขนาด $O(k)$
