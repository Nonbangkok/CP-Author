## ลูปซ้อนที่เราอยากเลิกเขียน

ลองดูโจทย์นี้ก่อนนะ: มีอาเรย์ $a$ ขนาด $N$ ที่ **เรียงจากน้อยไปมากแล้ว** อยากรู้ว่ามีคู่ $i < j$ ที่ $a_i + a_j = X$ หรือเปล่า

ท่าแรกที่ทุกคนคิดออกคือลองทุกคู่

```cpp
for (int i = 0; i < n; i++)
  for (int j = i + 1; j < n; j++)
    if (a[i] + a[j] == x) { /* เจอแล้ว */ }
```

ถูกแน่นอน แต่มีประมาณ $\frac{N^2}{2}$ คู่ ถ้า $N = 10^5$ ก็คือ $5 \cdot 10^9$ รอบ ไม่ทันเวลาแน่ ๆ ที่น่าเสียดายคือโค้ดนี้ **ไม่ได้ใช้เลยว่าอาเรย์เรียงแล้ว** บทนี้จะเอาข้อมูลข้อนั้นมาใช้ให้คุ้ม

**Two pointers** คือการใช้ดัชนีสองตัว (เรียกว่า "พอยน์เตอร์" แต่ส่วนใหญ่เป็นแค่ `int`) ที่ **ขยับไปทางเดียวเสมอ ไม่เคยถอยหลัง** แล้วอาศัยความเรียง (หรือเงื่อนไขที่ "เป็นทางเดียว") ตัดตัวเลือกทิ้งทีละเยอะ ๆ จนเหลือ $O(N)$ มีอยู่สองหน้าตาหลัก ๆ ที่จะเจอบ่อยมาก

1. **สองฝั่งเดินเข้าหากัน** ตัวหนึ่งเริ่มซ้ายสุด อีกตัวเริ่มขวาสุด
2. **เดินไปทางเดียวกัน (slow/fast)** ทั้งคู่เริ่มทางซ้าย ตัวหน้าวิ่งนำ ตัวหลังเดินตาม

## หน้าตาที่ 1: สองฝั่งเดินเข้าหากัน

ตั้ง `l = 0` กับ `r = n - 1` แล้วดูผลรวม `a[l] + a[r]`

* ถ้า **น้อยกว่า** $X$: ลองนึกดูว่า `a[l]` จะจับคู่กับใครได้บ้าง ทุกตัวที่เหลือ (ตั้งแต่ `l + 1` ถึง `r`) มีค่า **ไม่เกิน** `a[r]` ผลรวมจึงยิ่งน้อยลงหรือเท่าเดิม ไม่มีทางถึง $X$ เลย แปลว่า `a[l]` หมดหวังแล้ว ทิ้งมันได้ `l++`
* ถ้า **มากกว่า** $X$: กลับกัน `a[r]` จับกับใครก็มีแต่ใหญ่เท่าเดิมหรือใหญ่ขึ้น ทิ้งได้ `r--`
* ถ้า **เท่ากับ** $X$: เจอแล้ว

หัวใจของท่านี้คือ **ทุกครั้งที่ขยับ เราพิสูจน์ได้ว่าตัวที่ถูกทิ้งไม่มีคู่ที่ใช้ได้เหลืออยู่แล้ว** จึงไม่พลาดคำตอบไหนเลย ทั้งที่ไม่ได้ลองทุกคู่

### Template: หาคู่ที่รวมได้ $X$ ในอาเรย์ที่เรียงแล้ว

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
  ios::sync_with_stdio(false);
  cin.tie(nullptr);
  int n;
  long long x;
  cin >> n >> x;
  vector<long long> a(n);
  for (auto &v : a) cin >> v;
  // ถ้าโจทย์ไม่รับประกันว่าเรียงแล้ว ต้อง sort(a.begin(), a.end()) ก่อน

  int l = 0, r = n - 1;
  bool found = false;
  while (l < r) {              // l < r เพราะต้องเป็นสองตัวคนละตำแหน่ง
    long long sum = a[l] + a[r];
    if (sum == x) {
      found = true;
      break;
    }
    if (sum < x) l++;          // a[l] เล็กเกินไปสำหรับทุกคู่ที่เหลือ
    else r--;                  // a[r] ใหญ่เกินไปสำหรับทุกคู่ที่เหลือ
  }

  if (found) cout << "YES " << l + 1 << ' ' << r + 1 << '\n';
  else cout << "NO\n";
}
```

### ลองไล่ด้วยมือ

ให้ `a = [1, 3, 4, 6, 8, 11]` และ $X = 10$

| รอบ | `l` | `r` | `a[l] + a[r]` | ทำอะไร |
|---|---|---|---|---|
| 1 | 0 | 5 | $1 + 11 = 12$ | มากไป `r--` |
| 2 | 0 | 4 | $1 + 8 = 9$ | น้อยไป `l++` |
| 3 | 1 | 4 | $3 + 8 = 11$ | มากไป `r--` |
| 4 | 1 | 3 | $3 + 6 = 9$ | น้อยไป `l++` |
| 5 | 2 | 3 | $4 + 6 = 10$ | เจอแล้ว |

ห้ารอบเท่านั้น ทั้งที่มีคู่ทั้งหมด $15$ คู่

### ทำไมถึงเป็น $O(N)$

ดูที่ระยะ `r - l` ตอนเริ่มมันเท่ากับ $N - 1$ และทุกรอบจะลดลง **หนึ่งเสมอ** (ไม่ `l` ก็ `r` ขยับเข้าหากัน) พอเหลือ $0$ ลูปก็จบ ดังนั้นมีไม่เกิน $N - 1$ รอบ งานต่อรอบเป็น $O(1)$ รวมเป็น $O(N)$

ถ้าอาเรย์ยังไม่เรียง ก็ `sort` ก่อน รวมเป็น $O(N \log N)$ ซึ่งก็ยังเร็วกว่า $O(N^2)$ มาก

### เพื่อนบ้านของท่านี้: นับคู่ทีละก้อน

ถ้าเปลี่ยนคำถามเป็น "มีกี่คู่ที่ $a_i + a_j \leq X$" ก็ยังใช้การขยับแบบเดิมได้ ตอนที่ `a[l] + a[r] <= X` ให้สังเกตว่า `a[l]` จับกับ **ทุกตัว** ในช่วง `(l, r]` ได้หมด (เพราะพวกนั้นไม่เกิน `a[r]`) จึงบวก `r - l` ทีเดียวแล้วค่อย `l++` ส่วนถ้าเกินก็ `r--` เหมือนเดิม นี่คือหลักที่ใช้บ่อยมาก: **ถ้ารู้ว่าทั้งก้อนใช้ได้ ให้นับทั้งก้อน**

:::hint ใบ้ Swan Boats

:::

:::problem lp_tp02_closest_sum

:::hint ใบ้ Closest Sum
ใช้การขยับแบบเดียวกับ template เป๊ะ ๆ แค่เปลี่ยนจาก "เจอหรือยัง" เป็น "จดค่า $|a_l + a_r - T|$ ที่ดีที่สุดไว้ทุกรอบ" ทำไมการขยับแบบนี้ไม่ทำให้พลาดคู่ที่ดีที่สุด? เหตุผลเดียวกับข้างบนเลย อย่าลืมว่าข้อนี้ **ยังไม่ได้เรียง** และ $a_l + a_r - T$ อาจไกลถึง $4 \cdot 10^9$
:::

## หน้าตาที่ 2: เดินไปทางเดียวกัน (slow/fast)

คราวนี้ทั้งสองตัวเริ่มจากซ้าย ตัว **fast** เดินไปข้างหน้าทีละช่องเสมอ ส่วนตัว **slow** เดินตามเฉพาะตอนที่จำเป็น ทั้งคู่ไม่เคยถอยหลัง

### ตัวอย่างอุ่นเครื่อง: ลบตัวซ้ำในอาเรย์ที่เรียงแล้ว

อยากเก็บค่าที่ไม่ซ้ำไว้ข้างหน้าอาเรย์โดยไม่ใช้อาเรย์ช่วย ให้ `fast` อ่านทุกตัว ส่วน `slow` ชี้ช่องถัดไปที่จะเขียน ตัวไหนต่างจากตัวที่เขียนล่าสุดก็เขียนลงไป

```cpp
int slow = 0;
for (int fast = 0; fast < n; fast++) {
  if (fast == 0 || a[fast] != a[slow - 1])
    a[slow++] = a[fast];
}
// ตอนนี้ a[0 .. slow-1] คือค่าที่ไม่ซ้ำ เรียงเหมือนเดิม
```

### ตัวอย่างหลัก: นับคู่ที่ห่างกันไม่เกิน $D$

โจทย์: อาเรย์เรียงแล้ว นับคู่ $i < j$ ที่ $a_j - a_i \leq D$

ลองตรึง $j$ ไว้ก่อน ตัว $i$ ที่ใช้ได้คือตัวที่ $a_i \geq a_j - D$ และเพราะอาเรย์เรียง พวกมันอยู่ติดกันเป็นช่วง $[i_0, j - 1]$ พอดี ทีนี้สังเกตสิ่งสำคัญ: **เมื่อ $j$ ขยับไปขวา $a_j$ ใหญ่ขึ้น ขอบซ้าย $i_0$ ก็มีแต่ขยับไปขวา ไม่มีทางถอย** เราจึงเก็บ $i_0$ ไว้ในตัวแปร `i` แล้วค่อย ๆ ดันมันตาม

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
  ios::sync_with_stdio(false);
  cin.tie(nullptr);
  int n;
  long long d;
  cin >> n >> d;
  vector<long long> a(n);
  for (auto &v : a) cin >> v;   // เรียงจากน้อยไปมากแล้ว

  long long pairs = 0;
  int i = 0;                     // slow: ตัวแรกที่ยังห่างจาก a[j] ไม่เกิน d
  for (int j = 0; j < n; j++) {  // fast
    while (a[j] - a[i] > d) i++;
    pairs += j - i;              // คู่ (i, j), (i+1, j), ..., (j-1, j)
  }
  cout << pairs << '\n';
}
```

ลองกับ `a = [1, 2, 4, 7, 8]`, $D = 3$

| `j` | `a[j]` | `i` หลัง while | คู่ที่ได้ `j - i` |
|---|---|---|---|
| 0 | 1 | 0 | 0 |
| 1 | 2 | 0 | 1 |
| 2 | 4 | 0 | 2 |
| 3 | 7 | 2 | 1 |
| 4 | 8 | 3 | 1 |

รวม $5$ คู่: $(1,2), (1,4), (2,4), (4,7), (7,8)$

**ทำไมยังเป็น $O(N)$ ทั้งที่มี `while` ซ้อนใน `for`?** เพราะ `i` ไม่เคยลดลงเลย มันเพิ่มได้ไม่เกิน $N$ ครั้ง **ตลอดทั้งโปรแกรม** ไม่ใช่ต่อรอบของ `j` ดังนั้นงานรวมของ `while` ทุกรอบรวมกันคือ $O(N)$ บวกกับ `for` อีก $O(N)$ รวมเป็น $O(N)$ การนับแบบ "ดูการเคลื่อนที่รวมทั้งหมด" แบบนี้เรียกว่า amortized analysis ซึ่งจะเจออีกบ่อยมาก

:::note เมื่อไหร่ท่านี้ใช้ได้
คำถามที่ต้องถามตัวเองทุกครั้งคือ **"ถ้า fast ขยับไปข้างหน้า ขอบเขตของ slow ขยับไปทางเดียวเสมอไหม?"** ถ้าใช่ (เพราะอาเรย์เรียง หรือเพราะค่าไม่ติดลบ ผลรวมเลยมีแต่เพิ่ม) ก็ใช้สองพอยน์เตอร์ได้ ถ้าบางทีต้องถอย เช่น ผลรวมของช่วงที่มีค่าติดลบ ท่านี้จะพังทันที
:::

:::problem lp_tp03_budget_streaks

:::hint ใบ้ Budget Streaks
ลองตรึง "วันสุดท้าย" $r$ ของช่วงไว้ แล้วถามว่าวันเริ่ม $l$ ที่ใช้ได้หน้าตาเป็นยังไง เป็นช่วงติดกันไหม? แล้วถ้า $r$ ขยับไปขวาหนึ่งวัน ขอบเขตนั้นขยับไปทางไหน (ข้อนี้รับประกันว่าไม่มีค่าติดลบ ซึ่งสำคัญมาก) คิดออกแล้วจะหน้าตาคล้ายตัวอย่างนับคู่ข้างบนมาก และคำตอบอาจเกิน int
:::

## รวมสองอาเรย์ที่เรียงแล้ว (merge)

สองพอยน์เตอร์ไม่จำเป็นต้องอยู่ในอาเรย์เดียวกัน งานคลาสสิกคือรวมอาเรย์ที่เรียงแล้วสองอัน `A` (ขนาด $N$) กับ `B` (ขนาด $M$) ให้เป็นอาเรย์ที่เรียงอันเดียว ให้ `i` ชี้ใน `A` และ `j` ชี้ใน `B` แล้วหยิบตัวที่น้อยกว่าออกมาทีละตัว

```cpp
#include <bits/stdc++.h>
using namespace std;

vector<int> merge_sorted(const vector<int> &A, const vector<int> &B) {
  vector<int> out;
  out.reserve(A.size() + B.size());
  size_t i = 0, j = 0;
  while (i < A.size() && j < B.size()) {
    if (A[i] <= B[j]) out.push_back(A[i++]);   // <= ทำให้ตัวที่เท่ากันจาก A มาก่อน
    else out.push_back(B[j++]);
  }
  while (i < A.size()) out.push_back(A[i++]);  // เทของที่เหลือ (มีอย่างมากฝั่งเดียว)
  while (j < B.size()) out.push_back(B[j++]);
  return out;
}

int main() {
  int n, m;
  cin >> n >> m;
  vector<int> A(n), B(m);
  for (int &x : A) cin >> x;
  for (int &x : B) cin >> x;
  for (int x : merge_sorted(A, B)) cout << x << ' ';
  cout << '\n';
}
```

ทุกรอบหยิบออกมาหนึ่งตัว และมีของทั้งหมด $N + M$ ตัว จึงเป็น $O(N + M)$ ใน STL มี `std::merge` ให้ใช้ตรง ๆ ด้วย แต่ควรเขียนเองเป็น เพราะโจทย์จริงมักไม่ได้อยากได้อาเรย์ที่รวมแล้ว แต่อยากได้อะไรระหว่างทาง เช่น นับว่ามีกี่ค่าที่อยู่ในทั้งสองอาเรย์ (ถ้า `A[i] == B[j]` ก็นับแล้วขยับทั้งคู่) หรือหาคู่ข้ามอาเรย์ที่ต่างกันน้อยที่สุด และขั้นตอนนี้ก็คือหัวใจของ merge sort ที่จะเจอในบท Divide and Conquer

## จุดที่พลาดบ่อย

:::warning ลืมว่าอาเรย์ต้องเรียง
ท่าสองฝั่งเดินเข้าหากันทั้งหมดพึ่งความเรียง ถ้าโจทย์บอกว่า "ยังไม่ได้เรียง" แล้วลืม `sort` โค้ดจะรันผ่านตัวอย่างบางตัวแบบงง ๆ แล้วตอบผิดเงียบ ๆ อ่านโจทย์ให้ดีทุกครั้ง
:::

:::warning l < r กับ l <= r
ถ้าโจทย์ต้องการสองตัว **คนละตำแหน่ง** ต้องใช้ `while (l < r)` ถ้าใช้ `l <= r` จะได้คู่ที่เอาตัวเดียวกันมาบวกกับตัวเอง แต่บางโจทย์ตอนที่ `l == r` ยังมีงานค้างอยู่ (ตัวสุดท้ายที่ยังต้องนับ) ก็ต้องให้ลูปทำรอบนั้นด้วย ถามตัวเองทุกครั้งว่า "ตอน `l == r` ต้องทำอะไรไหม" แล้วลองนึกถึงกรณี $N = 1$ ก่อนส่ง
:::

:::warning นับทีละคู่แทนที่จะนับทั้งก้อน
ในโจทย์นับ ถ้าตำแหน่งปัจจุบันทำให้ "ทุกตัวในช่วงหนึ่ง" ใช้ได้ ต้องบวกขนาดของช่วงนั้นทีเดียว (เช่น `j - i`) ถ้าไปไล่นับทีละตัวก็กลับไปเป็น $O(N^2)$ เหมือนเดิม
:::

:::warning int ล้น
$10^9 + 10^9 = 2 \cdot 10^9$ ยังพอดีใน `int` (สูงสุดประมาณ $2.147 \cdot 10^9$) แต่เฉียดมาก ส่วนผลต่างกับเป้าหมาย ผลรวมของช่วงยาว ๆ และจำนวนคู่ (ซึ่งได้ถึง $\frac{N^2}{2}$) เกินแน่นอน ใช้ `long long` ไว้ก่อนเป็นนิสัยที่ดี
:::

## สรุปสั้น ๆ

* Two pointers = ดัชนีสองตัวที่ **ไม่เคยถอยหลัง** เลยขยับรวมกันได้ไม่เกิน $O(N)$ ครั้ง
* สองฝั่งเดินเข้าหากัน: ผลรวมน้อยไปขยับ `l` มากไปขยับ `r` เพราะตัวที่ทิ้งไม่มีคู่ที่ใช้ได้เหลือแล้ว ต้องเรียงก่อน
* slow/fast: fast เดินทีละช่อง slow ตามเมื่อจำเป็น ใช้ได้เมื่อขอบเขตของ slow ขยับทางเดียวเสมอ (ความเรียง หรือค่าไม่ติดลบ)
* `while` ข้างใน `for` ไม่ได้แปลว่า $O(N^2)$ เสมอไป ให้นับการเคลื่อนที่รวมของพอยน์เตอร์
* merge สองอาเรย์ที่เรียงแล้วด้วยสองพอยน์เตอร์ใน $O(N + M)$
* นับทั้งก้อน และใช้ `long long`
