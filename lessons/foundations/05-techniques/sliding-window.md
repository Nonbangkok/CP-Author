## ช่วงติดกันที่ค่อย ๆ เลื่อนไป

โจทย์จำนวนมากถามเกี่ยวกับ **ช่วงที่ติดกัน** (subarray) ของอาเรย์ เช่น "$K$ วันติดกันที่ขายดีที่สุด" หรือ "ช่วงที่สั้นที่สุดที่ผลรวมถึงเป้า" ท่าตรง ๆ คือไล่ทุกช่วงแล้วคำนวณใหม่ตั้งแต่ต้นทุกครั้ง ซึ่งเป็น $O(NK)$ หรือ $O(N^2)$

**Sliding window** มองช่วงเป็น "หน้าต่าง" `[l, r]` ที่เลื่อนไปทางขวาเรื่อย ๆ แล้ว **เก็บข้อมูลของหน้าต่างไว้** (ผลรวม, จำนวนแต่ละค่า, ...) พอหน้าต่างเลื่อนก็แค่อัปเดตข้อมูลจากตัวที่เข้ากับตัวที่ออก ไม่ต้องคิดใหม่ทั้งหมด ถ้าเพิ่งอ่านบท Two Pointers มา จะเห็นว่ามันคือ slow/fast นั่นเอง: `r` คือ fast, `l` คือ slow และทั้งคู่ไม่เคยถอยหลัง

มีสองแบบหลัก ๆ

1. **หน้าต่างขนาดคงที่** ยาว $K$ ตลอด
2. **หน้าต่างยืดหดได้** ขยายขวาไปเรื่อย ๆ แล้วหดซ้ายเมื่อหน้าต่าง "ผิดเงื่อนไข"

## หน้าต่างขนาดคงที่

ตอนเลื่อนจากหน้าต่าง `[i - K, i - 1]` ไปเป็น `[i - K + 1, i]` มีแค่สองตัวที่เปลี่ยน คือ `a[i]` **เข้า** และ `a[i - K]` **ออก** ผลรวมใหม่จึงเท่ากับผลรวมเก่า `+ a[i] - a[i - K]` เป็น $O(1)$ ต่อการเลื่อนหนึ่งครั้ง

### Template: นับว่ามีกี่หน้าต่างยาว $K$ ที่ผลรวมอย่างน้อย $X$

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
  ios::sync_with_stdio(false);
  cin.tie(nullptr);
  int n, k;
  long long x;
  cin >> n >> k >> x;
  vector<long long> a(n);
  for (auto &v : a) cin >> v;

  long long sum = 0;
  for (int i = 0; i < k; i++) sum += a[i];   // หน้าต่างแรก [0, k-1]
  int good = (sum >= x);

  for (int i = k; i < n; i++) {
    sum += a[i];        // ตัวใหม่เข้าทางขวา
    sum -= a[i - k];    // ตัวเก่าออกทางซ้าย
    if (sum >= x) good++;
  }
  cout << good << '\n';
}
```

### ลองไล่ด้วยมือ

`a = [2, 1, 5, 1, 3, 2]`, $K = 3$, $X = 7$

| หน้าต่าง | เข้า | ออก | ผลรวม | ผ่านไหม |
|---|---|---|---|---|
| `[2, 1, 5]` | | | $8$ | ผ่าน |
| `[1, 5, 1]` | $1$ | $2$ | $8 + 1 - 2 = 7$ | ผ่าน |
| `[5, 1, 3]` | $3$ | $1$ | $7 + 3 - 1 = 9$ | ผ่าน |
| `[1, 3, 2]` | $2$ | $5$ | $9 + 2 - 5 = 6$ | ไม่ผ่าน |

ได้ $3$ หน้าต่าง ทุกหน้าต่างใช้งานแค่ $O(1)$ รวมเป็น $O(N)$ ไม่ว่า $K$ จะใหญ่แค่ไหน

:::problem lp_sw01_best_window

:::hint ใบ้ Best Window
ใช้ template ข้างบนได้เลย แค่เปลี่ยนจากนับเป็นจดค่าที่ดีที่สุด ระวังค่าเริ่มต้น: กำไรติดลบได้ทุกวัน ถ้าเริ่ม `best = 0` จะตอบ $0$ ทั้งที่ไม่มีหน้าต่างไหนได้ $0$ เลย ให้เริ่มจากผลรวมของหน้าต่างแรก และผลรวมได้ถึง $10^{14}$ ต้องเป็น `long long`
:::

## หน้าต่างยืดหดได้

ทีนี้ความยาวไม่ได้ถูกกำหนดมา แต่โจทย์ให้ **เงื่อนไข** ของหน้าต่างที่ "ใช้ได้" แล้วถามหาหน้าต่างที่ยาวที่สุดหรือสั้นที่สุด ตัวอย่างที่ใช้อธิบาย: อาเรย์ **ไม่มีค่าติดลบ** หา **ช่วงที่ยาวที่สุดที่ผลรวมไม่เกิน $S$**

ท่ามาตรฐานคือ

1. ขยาย `r` ไปทางขวาทีละช่อง เติม `a[r]` เข้าหน้าต่าง
2. **ตราบใดที่** หน้าต่างผิดเงื่อนไข ให้เอา `a[l]` ออกแล้ว `l++`
3. ตอนนี้ `[l, r]` คือหน้าต่างที่ใช้ได้ที่ยาวที่สุดที่จบที่ `r` จดคำตอบ

ทำไมขั้นที่ 3 ถึงจริง? เพราะค่าไม่ติดลบ ถ้า `[l, r]` ผลรวมเกิน $S$ แล้ว หน้าต่างที่เริ่มก่อน `l` ยิ่งยาวยิ่งเกิน และถ้า `[l, r]` เกิน `[l, r + 1]` ก็เกินด้วย จุดเริ่มที่ใช้ได้จึง **ขยับไปขวาอย่างเดียว** `l` เลยไม่ต้องถอยกลับเลย

### Template: ช่วงที่ยาวที่สุดที่ผลรวมไม่เกิน $S$ (ค่าไม่ติดลบ)

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
  ios::sync_with_stdio(false);
  cin.tie(nullptr);
  int n;
  long long s;
  cin >> n >> s;
  vector<long long> a(n);
  for (auto &v : a) cin >> v;   // ทุกตัว >= 0

  long long sum = 0;
  int best = 0, l = 0;
  for (int r = 0; r < n; r++) {
    sum += a[r];                 // 1. ขยายขวา
    while (sum > s) {            // 2. หดซ้ายจนกว่าจะใช้ได้ (ใช้ while ไม่ใช่ if)
      sum -= a[l];
      l++;
    }
    best = max(best, r - l + 1); // 3. [l, r] ใช้ได้ (ถ้า l > r คือหน้าต่างว่าง ยาว 0)
  }
  cout << best << '\n';
}
```

### ลองไล่ด้วยมือ

`a = [3, 1, 2, 1, 4, 1]`, $S = 5$

| `r` | เติม | `sum` ก่อนหด | เอาออก | `l` | หน้าต่าง | ยาว |
|---|---|---|---|---|---|---|
| 0 | 3 | 3 | | 0 | `[3]` | 1 |
| 1 | 1 | 4 | | 0 | `[3, 1]` | 2 |
| 2 | 2 | 6 | 3 | 1 | `[1, 2]` | 2 |
| 3 | 1 | 4 | | 1 | `[1, 2, 1]` | 3 |
| 4 | 4 | 8 | 1, 2 | 3 | `[1, 4]` | 2 |
| 5 | 1 | 6 | 1 | 4 | `[4, 1]` | 2 |

คำตอบคือ $3$ จากช่วง `[1, 2, 1]` สังเกตแถว `r = 4` ที่ต้องเอาออกสองตัวติดกัน นี่คือเหตุผลที่ต้องเป็น `while`

### ความซับซ้อน

`r` ขยับ $N$ ครั้ง และ `l` ก็ขยับรวมกันได้ไม่เกิน $N$ ครั้ง **ตลอดทั้งโปรแกรม** (มันไม่เคยถอย) งานรวมจึงเป็น $O(N)$ ทั้งที่หน้าตาเป็นลูปซ้อน เหตุผลเดียวกับบท Two Pointers เป๊ะ

### กลับด้าน: อยากได้หน้าต่างที่สั้นที่สุด

บางโจทย์กลับด้าน: หน้าต่าง "ดี" คือหน้าต่างที่ผลรวม **ถึง** เป้า และอยากได้อันที่ **สั้น** ที่สุด โครงยังเหมือนเดิม คือขยายขวาทีละช่อง แล้วหดซ้ายใน `while` สิ่งที่ต้องคิดใหม่มีแค่ว่า เงื่อนไขของ `while` คืออะไร และควรจดคำตอบตรงไหน

:::problem lp_sw02_shortest_segment

:::hint ใบ้ Shortest Segment
หน้าต่างที่ผลรวม $\geq S$ อยู่แล้ว ถ้าลองตัดตัวซ้ายทิ้งอาจจะยังพออยู่และสั้นลงด้วย แล้วจะจดความยาวก่อนหรือหลังตัด? ลองไล่กับตัวอย่างที่ 1 บนกระดาษดู และอย่าลืมกรณีที่ทั้งอาเรย์รวมกันยังไม่ถึง $S$ ซึ่งต้องตอบ $-1$
:::

## นับค่าที่ไม่ซ้ำในหน้าต่าง

ข้อมูลที่เก็บไม่จำเป็นต้องเป็นผลรวม อีกอันที่ใช้บ่อยมากคือ "ในหน้าต่างมีกี่ค่าที่ไม่ซ้ำกัน" ให้เก็บ `cnt[v]` = จำนวนครั้งที่ค่า `v` อยู่ในหน้าต่าง และ `distinct` = จำนวนค่าที่ `cnt[v] > 0`

* เติม `v`: ถ้า `cnt[v]` เป็น $0$ ก่อนเติม แปลว่าเป็นค่าใหม่ `distinct++`
* เอา `v` ออก: ถ้า `cnt[v]` กลายเป็น $0$ หลังเอาออก แปลว่าค่านี้หายไปจากหน้าต่างแล้ว `distinct--`

ถ้าค่าใหญ่ถึง $10^9$ จะสร้าง `cnt` ขนาดนั้นไม่ได้ ให้ **ย่อค่า (coordinate compression)** ก่อน: เรียงค่าที่ไม่ซ้ำ แล้วแทนแต่ละค่าด้วยลำดับของมัน ($0$ ถึง $M - 1$) หรือจะใช้ `map` / `unordered_map` แทนอาเรย์ก็ได้ แลกกับความช้าลงนิดหน่อย

### Template: จำนวนค่าที่ไม่ซ้ำในทุกหน้าต่างยาว $K$

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
  ios::sync_with_stdio(false);
  cin.tie(nullptr);
  int n, k;
  cin >> n >> k;
  vector<int> a(n);
  for (int &v : a) cin >> v;

  // ย่อค่า: ค่าใด ๆ -> 0 .. M-1 โดยยังเท่ากัน/ต่างกันเหมือนเดิม
  vector<int> vals(a);
  sort(vals.begin(), vals.end());
  vals.erase(unique(vals.begin(), vals.end()), vals.end());
  for (int &v : a) v = lower_bound(vals.begin(), vals.end(), v) - vals.begin();

  vector<int> cnt(vals.size(), 0);
  int distinct = 0;
  auto add = [&](int v) { if (cnt[v]++ == 0) distinct++; };
  auto remove = [&](int v) { if (--cnt[v] == 0) distinct--; };

  for (int i = 0; i < n; i++) {
    add(a[i]);
    if (i >= k) remove(a[i - k]);        // ให้หน้าต่างยาว k พอดี
    if (i >= k - 1) cout << distinct << ' ';
  }
  cout << '\n';
}
```

ลองกับ `a = [1, 2, 1, 3, 4, 2, 3]`, $K = 4$: หน้าต่างคือ `[1, 2, 1, 3]` ได้ $3$ ค่า, `[2, 1, 3, 4]` ได้ $4$, `[1, 3, 4, 2]` ได้ $4$ และ `[3, 4, 2, 3]` ได้ $3$ โปรแกรมพิมพ์ `3 4 4 3`

`add` กับ `remove` เป็น $O(1)$ ส่วนการย่อค่าใช้ $O(N \log N)$ จากการ `sort` และ `lower_bound` รวมเป็น $O(N \log N)$

ท่า `add` / `remove` นี้เอาไปต่อกับหน้าต่างยืดหดได้ก็ได้ด้วย: แค่ให้ "หน้าต่างผิดเงื่อนไข" กลายเป็นเรื่องของ `distinct` แทนเรื่องของผลรวม

:::problem lp_sw03_k_flavors

:::hint ใบ้ At Most K Flavors
หน้าต่างแบบไหนที่ "ผิดเงื่อนไข"? ถ้าหน้าต่างหนึ่งมีรสไม่เกิน $K$ แล้ว หน้าต่างที่อยู่ข้างในมันมีรสไม่เกิน $K$ ด้วยไหม? ถ้าใช่ แปลว่า `l` ไม่ต้องถอยหลังเลย ใช้โครงของหน้าต่างยืดหดได้ แล้วเปลี่ยนของในหน้าต่างเป็น `cnt` กับ `distinct` ส่วนหมายเลขรสที่ใหญ่ถึง $10^9$ ก็ย่อค่าก่อน
:::

## จุดที่พลาดบ่อย

:::warning if แทน while
ตอนหดซ้ายต้องเป็น `while` เสมอ ตัวที่เพิ่งเข้ามาอาจใหญ่จนต้องเอาออกหลายตัว ถ้าใช้ `if` หน้าต่างจะยังผิดเงื่อนไขอยู่แต่โค้ดไปจดคำตอบแล้ว
:::

:::warning หน้าต่างยืดหดได้ต้องมีเงื่อนไขทางเดียว
ท่านี้ใช้ได้เมื่อ "หดหน้าต่างที่ใช้ได้แล้ว ก็ยังใช้ได้" (หรือกลับกันตามโจทย์) ผลรวมของค่าที่ **ติดลบได้** ไม่เป็นแบบนั้น: ตัดตัวซ้ายที่ติดลบทิ้ง ผลรวมกลับเพิ่มขึ้น ถ้าโจทย์ไม่รับประกันว่าค่าเป็นบวกหรือไม่ติดลบ อย่าเพิ่งรีบใช้ท่านี้
:::

:::warning ค่าเริ่มต้นของคำตอบ
หาค่ามากสุดของผลรวมที่ติดลบได้ ห้ามเริ่มที่ $0$ ให้เริ่มจากหน้าต่างแรก ส่วนหาค่าน้อยสุดก็เริ่มด้วยค่าที่ใหญ่พอ (เช่น `INT_MAX`) แล้วอย่าลืมเช็กว่ามีคำตอบจริงก่อนพิมพ์
:::

:::warning ดัชนีของตัวที่ออก
หน้าต่างยาว $K$ ที่จบที่ `i` คือ `[i - K + 1, i]` ตัวที่ต้องเอาออกตอนเติม `a[i]` คือ `a[i - K]` ไม่ใช่ `a[i - K + 1]` ลองไล่กับ $K = 1$ ดู ถ้าถูกต้องหน้าต่างจะมีตัวเดียวตลอด
:::

:::note แล้วถ้าอยากได้ค่ามากสุดในหน้าต่างล่ะ
ผลรวมกับการนับเอาออกง่าย แต่ "ค่ามากสุด" เอาออกไม่ง่าย เพราะถ้าตัวที่ออกเป็นตัวมากสุดพอดี เราไม่รู้ว่าตัวที่มากรองลงมาคือใคร งานแบบนั้นมีเครื่องมือเฉพาะ (monotonic queue) ซึ่งอยู่ในแทร็ก Intermediate
:::

## สรุปสั้น ๆ

* Sliding window เก็บข้อมูลของช่วง `[l, r]` ไว้ แล้วอัปเดตจากตัวที่เข้ากับตัวที่ออก แทนการคิดใหม่ทุกช่วง
* ขนาดคงที่ $K$: เติม `a[i]` เอา `a[i - K]` ออก รวม $O(N)$
* ยืดหดได้: ขยาย `r` ทีละช่อง หดด้วย `while` จนหน้าต่างใช้ได้ แล้วจดคำตอบ `l` ไม่เคยถอยจึงเป็น $O(N)$
* ใช้ได้เมื่อเงื่อนไขเป็นทางเดียว เช่น ค่าไม่ติดลบ หรือจำนวนค่าที่ไม่ซ้ำ
* นับค่าที่ไม่ซ้ำด้วย `cnt` กับ `distinct` และย่อค่าก่อนเมื่อค่าใหญ่
* ระวัง `long long`, ค่าเริ่มต้นของคำตอบ และดัชนีของตัวที่ออก
