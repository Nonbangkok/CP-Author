## ทำไมต้องใช้ STL

ลองนึกถึงโจทย์ "เรียงนักเรียน $50{,}000$ คนตามคะแนน" ถ้าเขียน bubble sort เองก็ต้องเทียบราว $N^2 / 2 \approx 1.25 \times 10^9$ ครั้ง ซึ่งไม่ทันแน่ ๆ ส่วนถ้าเขียน merge sort เองก็ทันเวลา แต่เสียเวลาเขียนและเสี่ยงบั๊กอีกสิบนาที

STL (Standard Template Library) คือกล่องเครื่องมือที่มากับ C++ อยู่แล้ว มีทั้งโครงสร้างข้อมูล (container) และอัลกอริทึมที่ทดสอบมาอย่างดี บทนี้จะเก็บสี่อย่างที่ใช้แทบทุกข้อ

* `vector` อาเรย์ที่โตเองได้
* `pair` / `tuple` มัดหลายค่าเป็นก้อนเดียว และเทียบกันได้ทันที
* `sort` เรียงใน $O(N \log N)$ พร้อมกำหนดเกณฑ์การเรียงเองได้
* `unique` + `erase` และ `lower_bound` สำหรับจัดการค่าซ้ำและค้นหาในข้อมูลที่เรียงแล้ว

## vector: อาเรย์ที่โตเองได้

```cpp
vector<int> a;            // ว่าง
vector<int> b(n);         // n ตัว ค่าเริ่มต้นเป็น 0
vector<int> c(n, -1);     // n ตัว ค่าเริ่มต้นเป็น -1
vector<vector<int>> g(n, vector<int>(m, 0));  // ตาราง n x m

a.push_back(5);           // ต่อท้าย O(1) โดยเฉลี่ย
a.pop_back();             // ลบตัวท้าย O(1)
a.size();                 // จำนวนสมาชิก (เป็น size_t ไม่มีค่าติดลบ)
a.back();                 // ตัวท้ายสุด
a.clear();                // ล้างทิ้งทั้งหมด
```

`push_back` ต่อท้ายได้เร็วเพราะ vector จองที่เผื่อไว้เป็นเท่าตัวทุกครั้งที่เต็ม (ใครอยากรู้ไส้ในดูได้ในบท *Dynamic Array* ของแทร็ก Data Structures) แต่การแทรกหรือลบ **ตรงกลาง** ด้วย `insert` / `erase` ยังเป็น $O(N)$ เพราะต้องเลื่อนทุกตัวที่อยู่ข้างหลัง

:::warning ส่ง vector เข้าฟังก์ชันให้ส่งแบบ reference
`void solve(vector<int> a)` จะ **copy ทั้ง vector** ทุกครั้งที่เรียก ถ้าเรียกในลูปหรือใน recursion ก็ $O(N)$ ต่อครั้งแบบไม่รู้ตัว ให้เขียน `const vector<int> &a` ถ้าแค่อ่าน หรือ `vector<int> &a` ถ้าต้องแก้
:::

## pair และ tuple: มัดหลายค่าเป็นก้อนเดียว

`pair<A, B>` เก็บสองค่า เข้าถึงด้วย `.first` และ `.second` ส่วน `tuple` เก็บกี่ค่าก็ได้ จุดเด่นที่สุดคือ **เทียบกันได้ทันทีแบบพจนานุกรม** (lexicographic) คือเทียบตัวแรกก่อน ถ้าเท่ากันค่อยเทียบตัวถัดไป

```cpp
pair<int, string> p = {90, "bank"};
auto [score, name] = p;                    // structured binding (C++17)

tuple<int, int, int> t = {3, 1, 2};
auto [x, y, z] = t;                        // หรือ get<0>(t), get<1>(t), ...

// (1, 5) < (2, 0) เพราะ 1 < 2
// (2, 0) < (2, 3) เพราะตัวแรกเท่ากัน แล้ว 0 < 3
```

เพราะเทียบกันได้ `sort` ของ `vector<pair<...>>` จึงเรียงตาม `.first` ก่อน แล้วค่อยตัดสินด้วย `.second` โดยไม่ต้องเขียนอะไรเพิ่มเลย

## iterator เบื้องต้น

ฟังก์ชันใน `<algorithm>` ไม่ได้รับ vector ตรง ๆ แต่รับ **ช่วง** `[first, last)` เป็น iterator สองตัว ซึ่งคิดง่าย ๆ ว่าเป็น "ตัวชี้ตำแหน่ง" ก็พอ

* `a.begin()` ชี้ตัวแรก ส่วน `a.end()` ชี้ **ถัดจาก** ตัวสุดท้าย (ช่วงครึ่งเปิด) ห้าม `*a.end()`
* `a.begin() + k` ชี้ดัชนี `k` ดังนั้น `sort(a.begin(), a.begin() + k)` เรียงแค่ `k` ตัวแรก
* ลบ iterator สองตัวได้ระยะห่าง เช่น `it - a.begin()` คือดัชนีที่ `it` ชี้อยู่

## sort และการกำหนดเกณฑ์เอง

```cpp
sort(a.begin(), a.end());                    // น้อยไปมาก
sort(a.begin(), a.end(), greater<int>());    // มากไปน้อย
sort(a.rbegin(), a.rend());                  // มากไปน้อยเหมือนกัน (เรียงแบบถอยหลัง)
```

ถ้าเกณฑ์ซับซ้อนกว่านั้น ให้ส่ง **comparator** เป็นตัวที่สาม คือฟังก์ชัน `comp(x, y)` ที่คืน `true` **เมื่อ `x` ต้องมาก่อน `y` เท่านั้น** นิยมเขียนเป็น lambda ไว้ตรงที่เรียกเลย

### ตัวอย่างเต็ม: เรียงจุดตามระยะห่าง

โจทย์: มีจุด $N$ จุดบนระนาบ ให้เรียงตาม **ระยะจากจุดกำเนิดน้อยไปมาก** ถ้าระยะเท่ากันให้ $x$ น้อยกว่ามาก่อน ถ้ายังเท่ากันอีกให้ $y$ น้อยกว่ามาก่อน

ไม่ต้องถอดรากที่สอง เทียบ $x^2 + y^2$ ก็พอ (เลี่ยงทศนิยมด้วย) เกณฑ์มีหลายชั้น เราเลยเทียบทีละชั้น ชั้นไหนต่างกันก็ตัดสินจบที่ชั้นนั้น

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
  ios::sync_with_stdio(false);
  cin.tie(nullptr);
  int n;
  cin >> n;
  vector<pair<long long, long long>> pts(n);
  for (auto &[x, y] : pts) cin >> x >> y;

  sort(pts.begin(), pts.end(), [](const auto &p, const auto &q) {
    long long dp = p.first * p.first + p.second * p.second;
    long long dq = q.first * q.first + q.second * q.second;
    if (dp != dq) return dp < dq;                     // ชั้นที่ 1: ระยะ น้อยไปมาก
    if (p.first != q.first) return p.first < q.first; // ชั้นที่ 2: x น้อยไปมาก
    return p.second < q.second;                       // ชั้นที่ 3: y น้อยไปมาก
  });

  for (auto [x, y] : pts) cout << x << ' ' << y << '\n';
}
```

ถ้ารับ `3` จุดคือ `(3, 4)`, `(0, 5)`, `(1, 1)` จะได้ `(1, 1)` ก่อน (ระยะกำลังสอง $2$) แล้วตามด้วย `(0, 5)` และ `(3, 4)` ซึ่งระยะกำลังสองเท่ากันคือ $25$ จึงตัดสินด้วย $x$

อีกท่าที่สั้นกว่าคือ **แปลงเป็น tuple แล้วเทียบ** เช่น `return make_tuple(dp, p.first, p.second) < make_tuple(dq, q.first, q.second);` และถ้าชั้นไหนต้องเรียง **มากไปน้อย** ก็ใส่เครื่องหมายลบให้ชั้นนั้น เช่น `make_tuple(-score, name)`

:::problem lp_stl01_leaderboard

:::hint ใบ้ Leaderboard
comparator มีสองชั้น: ถ้าคะแนนต่างกัน คนที่คะแนน **มากกว่า** มาก่อน ถ้าคะแนนเท่ากัน ค่อยเทียบชื่อด้วย `<` ของ `string` ซึ่งเป็นลำดับพจนานุกรมอยู่แล้ว (`"ab" < "abc" < "b"`) หรือจะเก็บเป็น `pair<int, string>` ของ `(-คะแนน, ชื่อ)` แล้ว `sort` เฉย ๆ ก็ได้เหมือนกัน
:::

:::warning ห้ามใช้ `<=` ใน comparator
comparator ต้องเป็น **strict weak ordering** สรุปสั้น ๆ คือ `comp(x, x)` ต้องเป็น `false` เสมอ และถ้า `comp(x, y)` จริงแล้ว `comp(y, x)` ต้องเป็นเท็จ ถ้าเขียน `return a.score >= b.score;` กฎนี้พังทันทีเมื่อมีสองค่าเท่ากัน ผลคือ **undefined behaviour** ไม่ใช่แค่เรียงผิด: `std::sort` อาจอ่านเลยขอบอาเรย์จนโปรแกรมพัง (Runtime Error) และมักเกิดเฉพาะตอนข้อมูลใหญ่และมีค่าซ้ำเยอะ ซึ่งเทสต์ตัวอย่างเล็ก ๆ จับไม่ได้ ให้ใช้ `<` หรือ `>` เสมอ
:::

## ค่าซ้ำ: sort + unique + erase

`unique(first, last)` ยุบสมาชิกที่ **ติดกันและเท่ากัน** ให้เหลือตัวเดียว ย้ายตัวที่ไม่ซ้ำมาไว้ด้านหน้า แล้วคืน iterator ชี้จุดสิ้นสุดของส่วนนั้น มันไม่ได้ลบอะไรจริง ส่วนท้ายที่เหลือเป็นขยะ เราจึงต้อง `erase` ทิ้งเอง และเพราะมันดูแค่ตัวที่ติดกัน ต้อง `sort` ก่อนเสมอ

```cpp
vector<int> v = {5, 1, 5, 3, 1, 5};
sort(v.begin(), v.end());                    // 1 1 3 5 5 5
v.erase(unique(v.begin(), v.end()), v.end()); // 1 3 5
// v.size() คือจำนวนค่าที่ต่างกัน
```

### lower_bound: ค้นในข้อมูลที่เรียงแล้ว

เมื่อ vector เรียงแล้ว `lower_bound(v.begin(), v.end(), x)` คืน iterator ไปยัง **ตัวแรกที่ `>= x`** ใน $O(\log N)$ (ถ้าไม่มีจะได้ `v.end()`) ลบด้วย `v.begin()` ก็ได้ดัชนีของมัน ส่วน `upper_bound` คืนตัวแรกที่ `> x` วิธีที่มันค้นได้เร็วขนาดนี้ (binary search) จะได้เรียนเต็ม ๆ ในโมดูล Binary Search ตอนนี้ใช้เป็นก่อนก็พอ

ตัวอย่างเต็มข้างล่างตอบคำถาม "ค่า $x$ อยู่ในรายการไหม และมีค่าที่ต่างกันกี่ค่าที่น้อยกว่า $x$" ซึ่งเป็นท่าเดียวกับที่ใช้บีบค่าใหญ่ ๆ ให้กลายเป็นเลขเล็ก ๆ ติดกัน (coordinate compression)

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
  ios::sync_with_stdio(false);
  cin.tie(nullptr);
  int n, q;
  cin >> n >> q;
  vector<long long> v(n);
  for (auto &x : v) cin >> x;
  sort(v.begin(), v.end());
  v.erase(unique(v.begin(), v.end()), v.end());   // v = ค่าที่ต่างกัน เรียงแล้ว

  while (q--) {
    long long x;
    cin >> x;
    auto it = lower_bound(v.begin(), v.end(), x);  // ตัวแรกที่ >= x
    int smaller = it - v.begin();                  // จำนวนค่าที่ต่างกันที่ < x
    bool found = (it != v.end() && *it == x);      // เช็ก end() ก่อนเสมอ
    cout << (found ? "YES" : "NO") << ' ' << smaller << '\n';
  }
}
```

:::hint ใบ้ Coordinate Compression
สร้าง vector ของค่าที่ต่างกันที่เรียงแล้วก่อน ขนาดของมันคือ $D$ จากนั้นถามตัวเองว่า "ค่าที่น้อยกว่า $a_i$ มีกี่ค่า" แล้วเลขกำกับของ $a_i$ คือเท่าไร อย่าลืมว่าต้องเก็บ $a$ ตัวเดิมไว้ด้วย เพราะต้องตอบตามลำดับเดิม
:::

## เรียงก่อน แล้วโจทย์จะง่ายลง

หลายโจทย์ที่ดูเหมือนต้องเทียบทุกคู่ ($O(N^2)$) กลายเป็นเดินรอบเดียวหลังจากเรียง เพราะของที่ "เกี่ยวข้องกัน" จะมาอยู่ติดกัน

ตัวอย่างเพื่อนบ้าน: มีนัดประชุม $N$ นัด นัดที่ $i$ ใช้ห้องช่วงเวลา $[s_i, e_i)$ ถามว่ามีสองนัดไหนชนกันไหม ถ้าเรียงตามเวลาเริ่ม นัดที่ชนกันต้องมีคู่ที่ **อยู่ติดกัน** ชนกันด้วยเสมอ จึงเช็กแค่ $N - 1$ คู่ที่ติดกัน

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
  int n;
  cin >> n;
  vector<pair<int, int>> m(n);              // (s, e)
  for (auto &[s, e] : m) cin >> s >> e;
  sort(m.begin(), m.end());                 // pair เรียงตาม s ก่อน
  bool clash = false;
  for (int i = 0; i + 1 < n; i++)
    if (m[i + 1].first < m[i].second) clash = true;  // นัดถัดไปเริ่มก่อนนัดนี้จบ
  cout << (clash ? "CLASH" : "OK") << '\n';
}
```

เวลารวมคือ $O(N \log N)$ จากการเรียง บวก $O(N)$ จากการเดิน

:::problem lp_stl03_merge_intervals

:::hint ใบ้ Painted Road
เรียงช่วงตามจุดเริ่ม แล้วเดินจากซ้ายไปขวาโดยจำ "แถบปัจจุบัน" ไว้แค่สองค่า คือจุดเริ่มกับจุดไกลสุดที่ทาถึง ช่วงถัดไปจะต่อกับแถบนี้ได้ก็ต่อเมื่อเริ่มก่อนหรือ **ตรงกับ** จุดไกลสุดพอดี (แตะกันนับว่าต่อ) และระวังช่วงที่อยู่ข้างในช่วงอื่นทั้งช่วง จุดไกลสุดต้องใช้ `max` ไม่ใช่แทนที่ด้วยปลายของช่วงใหม่
:::

## เวลาที่ใช้

| งาน | เวลา |
|---|---|
| `push_back`, `pop_back`, `a[i]` | $O(1)$ |
| `insert` / `erase` ตรงกลาง vector | $O(N)$ |
| `sort` | $O(N \log N)$ |
| `unique`, `reverse`, `count`, `find` | $O(N)$ |
| `lower_bound`, `upper_bound` (บนข้อมูลที่เรียงแล้ว) | $O(\log N)$ |

judge นี้คอมไพล์ **ไม่มี** `-O2` STL จึงช้ากว่าบนเครื่องที่เปิด optimization ราวสามถึงสี่เท่า `sort` หนึ่งล้านตัวยังสบาย แต่อย่าไปเรียก `sort` ซ้ำในลูป

## จุดที่พลาดบ่อย

:::warning size() เป็น unsigned
`a.size()` เป็น `size_t` ถ้า vector ว่าง `a.size() - 1` จะไม่ใช่ $-1$ แต่วนกลับเป็นเลขมหาศาล ลูป `for (int i = 0; i < a.size() - 1; i++)` จึงพังตอน `a` ว่าง ให้เขียน `i + 1 < a.size()` แทน หรือแปลงเป็น `(int)a.size()` ก่อน
:::

* `unique` โดยไม่ `sort` ก่อน จะลบแค่ตัวซ้ำที่ติดกัน และลืม `erase` แล้ว `size()` จะไม่เปลี่ยน
* `lower_bound` บน vector ที่ **ไม่ได้เรียง** ไม่ error แต่ได้คำตอบมั่ว
* `*lower_bound(...)` โดยไม่เช็กว่าเป็น `end()` คืออ่านหน่วยความจำนอกอาเรย์
* comparator ที่มี `<=` หรือ `>=` คือ undefined behaviour ไม่ว่าจะ "ดูเหมือนผ่าน" บนเครื่องเราหรือไม่

## สรุปสั้น ๆ

* `vector` แทนอาเรย์ได้ทุกที่ ส่งเข้าฟังก์ชันด้วย reference
* `pair` / `tuple` เทียบแบบพจนานุกรมให้อัตโนมัติ เรียงหลายเกณฑ์ได้โดยไม่ต้องเขียน comparator
* comparator คืน `true` เมื่อ `x` ต้องมาก่อน `y` ใช้ `<` / `>` เท่านั้น ห้าม `<=`
* ค่าที่ต่างกัน = `sort` แล้ว `erase(unique(...), end())` ตำแหน่งของ `x` = `lower_bound(...) - begin()`
* เจอโจทย์ที่ดูต้องเทียบทุกคู่ ลองเรียงก่อน แล้วดูว่าเหลือแค่เทียบตัวที่ติดกันหรือเปล่า
