## ยกกำลังเลขใหญ่ ๆ ยังไงให้ทัน

โจทย์สาย math ชอบถามอะไรแบบ "จงหา $a^b \bmod m$" โดยที่ $b$ ใหญ่ได้ถึง $10^{18}$ ท่าที่ทุกคนคิดออกก่อนคือคูณ $a$ ไปเรื่อย ๆ $b$ ครั้ง

```cpp
long long result = 1;
for (long long i = 0; i < b; i++) result = result * a % m;
```

ถูกต้องแน่นอน แต่ใช้เวลา $O(b)$ ถ้า $b = 10^{18}$ ต่อให้คอมคูณได้วินาทีละ $10^9$ ครั้งก็ยังต้องรอราว $30$ ปี บทนี้จะทำให้มันเหลือแค่ประมาณ $60$ รอบ ด้วยท่าที่เรียกว่า **binary exponentiation** (หรือ fast power)

## ไอเดีย: ยกกำลังสองซ้ำ ๆ

ลองนึกดูก่อนนะ ถ้ารู้ค่า $a^{6}$ แล้ว จะหา $a^{12}$ ต้องคูณกี่ครั้ง? คำตอบคือครั้งเดียว เพราะ $a^{12} = a^6 \cdot a^6$ นี่แหละหัวใจของเรื่องนี้ทั้งหมด

$$a^b = \begin{cases} 1 & b = 0 \\ \left(a^{b/2}\right)^2 & b \text{ even} \\ a \cdot \left(a^{(b-1)/2}\right)^2 & b \text{ odd} \end{cases}$$

แต่ละชั้น $b$ ลดลงครึ่งหนึ่ง จึงลึกแค่ประมาณ $\log_2 b$ ชั้น สำหรับ $b = 10^{18}$ ก็แค่ราว $60$ ชั้น

มองอีกมุมหนึ่งผ่านเลขฐานสองของ $b$ ก็ได้ เช่น $13 = 1101_2 = 8 + 4 + 1$ ดังนั้น

$$a^{13} = a^{8} \cdot a^{4} \cdot a^{1}$$

ค่า $a^1, a^2, a^4, a^8, \ldots$ ได้มาจากการยกกำลังสองตัวก่อนหน้าไปเรื่อย ๆ เราจึงเดินดูบิตของ $b$ จากขวาไปซ้าย บิตไหนเป็น $1$ ก็คูณ $a^{2^i}$ ตัวนั้นเข้าไปในคำตอบ นี่คือแบบ iterative ที่ใช้กันบ่อยที่สุด

## กฎของ mod ที่ต้องรู้

ก่อนจะเขียนโค้ด ต้องรู้ก่อนว่าเราเอา $\bmod$ แทรกตรงไหนได้บ้าง เพราะเลขจริงอย่าง $a^{b}$ ใหญ่เกินกว่าจะเก็บในตัวแปรไหนได้เลย

* บวก: $(x + y) \bmod m = \big((x \bmod m) + (y \bmod m)\big) \bmod m$
* ลบ: $(x - y) \bmod m = \big((x \bmod m) - (y \bmod m) + m\big) \bmod m$
* คูณ: $(x \cdot y) \bmod m = \big((x \bmod m) \cdot (y \bmod m)\big) \bmod m$

แปลว่าเรา mod ทุกครั้งหลังบวก ลบ หรือคูณ ได้เลยโดยคำตอบไม่เพี้ยน ตัวเลขระหว่างทางจึงเล็กอยู่เสมอ ส่วน **การหารไม่มีกฎแบบนี้** ($\frac{x}{y} \bmod m$ ไม่เท่ากับ $\frac{x \bmod m}{y \bmod m}$) ต้องใช้ตัวผกผัน ซึ่งเดี๋ยวจะพูดถึงท้ายบท

สองเรื่องที่ C++ ชอบเล่นงานเรา

1. **ผลคูณล้น** ถ้า $x, y < m$ แล้ว $x \cdot y < m^2$ เมื่อ $m \leq 10^9$ ผลคูณไม่เกิน $10^{18}$ ใส่ `long long` ได้สบาย (ขีดจำกัดราว $9.2 \times 10^{18}$) แต่ใส่ `int` ไม่ได้แน่นอน และถ้า $m$ ใหญ่ถึงราว $10^{18}$ ผลคูณจะใหญ่ถึง $10^{36}$ แม้แต่ `long long` ก็ไม่พอ ต้องคูณผ่าน `__int128` แทน
2. **เศษติดลบ** ใน C++ `-7 % 3` ได้ `-1` ไม่ใช่ `2` นั่นคือเหตุผลที่กฎการลบต้องบวก $m$ กลับเข้าไปก่อน mod

## Template

โค้ดนี้คอมไพล์ได้ทั้งไฟล์ มีทั้งแบบ iterative (ใช้ตัวนี้เป็นหลัก) แบบ recursive (เขียนตามสูตรตรง ๆ) และ `mulmod` สำหรับตอนที่ $m$ ใหญ่จนผลคูณล้น `long long`

```cpp
#include <bits/stdc++.h>
using namespace std;

// a^b mod m แบบ iterative: เดินบิตของ b จากขวาไปซ้าย, O(log b)
long long power(long long a, long long b, long long m) {
  long long result = 1 % m;  // 1 % m เพราะถ้า m = 1 คำตอบต้องเป็น 0
  a %= m;                     // ลด a ก่อน ไม่งั้น a * a อาจล้น
  while (b > 0) {
    if (b & 1) result = result * a % m;  // บิตนี้เป็น 1: คูณ a^(2^i) เข้าไป
    a = a * a % m;                       // เตรียม a^(2^(i+1))
    b >>= 1;
  }
  return result;
}

// แบบ recursive: ตามสูตร a^b = (a^(b/2))^2 และคูณ a เพิ่มถ้า b เป็นเลขคี่
long long powerRec(long long a, long long b, long long m) {
  if (b == 0) return 1 % m;
  long long half = powerRec(a, b / 2, m);
  long long result = half * half % m;
  if (b & 1) result = result * (a % m) % m;
  return result;
}

// (x * y) mod m เมื่อ m ใหญ่ถึงราว 10^18: คูณใน __int128 ก่อนค่อย mod
long long mulmod(long long x, long long y, long long m) {
  return (long long)((__int128)x * y % m);
}

// a^b mod m สำหรับ m ใหญ่: โครงเดิม แค่เปลี่ยนการคูณเป็น mulmod
long long powerBig(long long a, long long b, long long m) {
  long long result = 1 % m;
  a %= m;
  while (b > 0) {
    if (b & 1) result = mulmod(result, a, m);
    a = mulmod(a, a, m);
    b >>= 1;
  }
  return result;
}

int main() {
  long long a, b, m;
  cin >> a >> b >> m;
  cout << power(a, b, m) << '\n';
}
```

:::note ทำไมต้อง `1 % m`
ถ้า $m = 1$ ทุกจำนวน mod $1$ ได้ $0$ หมด แต่ถ้าเริ่ม `result = 1` แล้ว $b = 0$ ลูปจะไม่ทำงานเลย และคืนค่า $1$ ออกไปซึ่งผิด การเขียน `1 % m` แก้ปัญหานี้ในบรรทัดเดียว
:::

## ลองไล่มือ: $3^{13} \bmod 7$

$13 = 1101_2$ เริ่มจาก `result = 1`, `a = 3`

| รอบ | `b` (ฐานสอง) | บิตขวาสุด | `result` หลังรอบ | `a` หลังรอบ |
|---|---|---|---|---|
| 1 | `1101` | 1 | $1 \cdot 3 = 3$ | $3^2 \bmod 7 = 2$ |
| 2 | `110` | 0 | $3$ (ไม่คูณ) | $2^2 \bmod 7 = 4$ |
| 3 | `11` | 1 | $3 \cdot 4 \bmod 7 = 5$ | $4^2 \bmod 7 = 2$ |
| 4 | `1` | 1 | $5 \cdot 2 \bmod 7 = 3$ | $2^2 \bmod 7 = 4$ |

ได้ $3^{13} \bmod 7 = 3$ ใช้แค่ $4$ รอบแทนที่จะคูณ $13$ ครั้ง ลองเช็กด้วยวิธีอื่นดู: $3^6 = 729 = 7 \cdot 104 + 1$ ดังนั้น $3^{12} \equiv 1$ และ $3^{13} \equiv 3$ ตรงกัน

## ความซับซ้อน

ลูปทำงานเท่ากับจำนวนบิตของ $b$ คือ $\lfloor \log_2 b \rfloor + 1$ รอบ แต่ละรอบคูณไม่เกินสองครั้ง จึงเป็น $O(\log b)$ ต่อการยกกำลังหนึ่งครั้ง ถ้ามี $Q$ คำถามก็เป็น $O(Q \log b)$ ซึ่งสำหรับ $Q = 10^5$ และ $b = 10^{18}$ ก็แค่ราว $6 \times 10^6$ รอบ ส่วนแบบ recursive ใช้ stack ลึก $O(\log b)$ ชั้น ไม่มีปัญหาอะไร

## ท่าเดียวกัน ใช้ได้มากกว่าการยกกำลัง

สิ่งที่เราทำจริง ๆ คือ "ถ้ารู้คำตอบของ $k$ ก็หาคำตอบของ $2k$ และ $k + 1$ ได้เร็ว" อะไรที่มีโครงแบบนี้ก็ใช้ท่า halving ได้หมด

ตัวอย่างใกล้ตัวคือ **การคูณแบบ binary** หา $x \cdot y \bmod m$ โดยไม่ใช้ `__int128` แค่เปลี่ยน "คูณ" เป็น "บวก" และ "ยกกำลังสอง" เป็น "คูณสอง"

```cpp
// (x * y) mod m โดยใช้แค่การบวก: x * 13 = x * 8 + x * 4 + x * 1
// ใช้ได้เมื่อ 2m ยังไม่ล้น long long (m < 4.6 * 10^18)
long long mulAdd(long long x, long long y, long long m) {
  long long result = 0;
  x %= m;
  while (y > 0) {
    if (y & 1) result = (result + x) % m;
    x = (x + x) % m;
    y >>= 1;
  }
  return result;
}
```

โครงเหมือน `power` ทุกบรรทัด ช้ากว่า `__int128` นิดหน่อย ($O(\log y)$ ต่อการคูณ) แต่ใช้ได้กับคอมไพเลอร์ที่ไม่มี `__int128`

:::problem lp_bexp02_geometric_sum

:::hint ใบ้ Geometric Sum
สูตร $\frac{a^{n+1} - 1}{a - 1}$ ใช้ตรง ๆ ไม่ได้ เพราะ $m$ ไม่ใช่จำนวนเฉพาะ และ $a - 1$ อาจหารด้วย $m$ ลงตัว ให้ลองแบ่งครึ่งแทน ถ้าผลรวมมีจำนวนพจน์เป็นเลขคู่ $2k$ จะได้

$$1 + a + \cdots + a^{2k-1} = \left(1 + a + \cdots + a^{k-1}\right)\left(1 + a^{k}\right)$$

ถ้าจำนวนพจน์เป็นเลขคี่ ลองแยกพจน์สุดท้ายออกมาก่อน และถ้าให้ฟังก์ชันคืนค่า $a^k$ ออกมาคู่กับผลรวมด้วย จะไม่ต้องเรียก `power` ใหม่ในทุกชั้น
:::

## แถมท้าย: หารแบบ mod ด้วย Fermat

เมื่อ $p$ เป็น **จำนวนเฉพาะ** และ $a$ หารด้วย $p$ ไม่ลงตัว Fermat's little theorem บอกว่า $a^{p-1} \equiv 1 \pmod p$ แปลว่า

$$a^{-1} \equiv a^{p-2} \pmod p$$

ตัวผกผัน $a^{-1}$ คือเลขที่คูณกับ $a$ แล้วได้ $1$ (mod $p$) พอมีมันแล้ว "หารด้วย $a$" ก็กลายเป็น "คูณด้วย $a^{-1}$" ซึ่งหาได้ด้วย `power(a, p - 2, p)` ใน $O(\log p)$ เช่น $3^{-1} \bmod 7 = 3^{5} \bmod 7 = 243 \bmod 7 = 5$ และเช็กได้ว่า $3 \cdot 5 = 15 \equiv 1 \pmod 7$ จริง

ถ้าโจทย์ให้ mod เป็นจำนวนเฉพาะอย่าง $998244353$ หรือ $10^9 + 7$ มักเป็นสัญญาณว่าเขาตั้งใจให้หารได้ด้วยท่านี้ เรื่องนี้จะได้ใช้จริงจังตอนเรียน combinatorics

:::warning จุดที่พลาดบ่อย
* ลืม `a %= m` ก่อนเข้าลูป ทำให้ `a * a` ล้นตั้งแต่รอบแรก
* ใช้ `int` เก็บ `result` หรือ `a` ผลคูณของเลขหลัก $10^9$ สองตัวล้น `int` แน่นอน
* $m$ ใหญ่ราว $10^{18}$ แต่ยังคูณด้วย `long long` ธรรมดา ต้องใช้ `mulmod` ผ่าน `__int128`
* เริ่ม `result = 1` แทน `1 % m` แล้วตอบผิดเมื่อ $m = 1$
* ลบแล้วไม่บวก $m$ กลับ ได้เศษติดลบออกไป
* ใช้ Fermat กับ mod ที่ไม่ใช่จำนวนเฉพาะ หรือกับ $a$ ที่หารด้วย $p$ ลงตัว ซึ่งให้คำตอบผิดแบบเงียบ ๆ
:::

## สรุปสั้น ๆ

* $a^b$ หาได้ใน $O(\log b)$ ด้วยการยกกำลังสองซ้ำ ๆ แล้วคูณเฉพาะบิตที่เป็น $1$ ของ $b$
* mod ได้ทุกครั้งหลังบวก ลบ คูณ แต่หารตรง ๆ ไม่ได้ และหลังลบต้องบวก $m$ กลับ
* $m \leq 10^9$ ใช้ `long long` พอ $m$ ราว $10^{18}$ ต้องคูณผ่าน `__int128`
* ท่า halving ใช้ได้กับทุกอย่างที่ "รู้ $k$ แล้วได้ $2k$ กับ $k + 1$ เร็ว" เช่นการคูณแบบ binary หรือผลรวมอนุกรมเรขาคณิต
* mod เป็นจำนวนเฉพาะ $p$: $a^{-1} = a^{p-2} \bmod p$
