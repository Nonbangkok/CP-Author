## เก็บทั้งเซตไว้ในจำนวนเต็มตัวเดียว

สมมติมีของ $N$ ชิ้น แล้วอยากเก็บว่า "เลือกชิ้นไหนไปบ้าง" ทางที่ตรงที่สุดคือ `vector<bool>` ยาว $N$ แต่ถ้า $N$ ไม่เกิน $60$ มีท่าที่เร็วกว่าและสั้นกว่ามาก คือใช้ **จำนวนเต็มหนึ่งตัว** แทนทั้งเซต ให้บิตที่ $i$ เป็น $1$ แปลว่าเลือกชิ้นที่ $i$ จำนวนเต็มตัวนี้เราเรียกว่า **bitmask** (หรือ mask)

เช่นมีของ $4$ ชิ้น ชิ้นที่ $0$ ถึง $3$ แล้วเลือกชิ้นที่ $0$, $2$ และ $3$ ก็เขียนเป็น $1101_2 = 13$ (บิตที่ $0$ คือบิตขวาสุด) ข้อดีคือ CPU ทำงานกับบิตทั้ง $64$ ตัวได้ในคำสั่งเดียว การเช็ก การรวมเซต หรือการหาส่วนร่วม จึงเร็วมาก

## ตัวดำเนินการบิต

ลองดูกับ $x = 12 = 1100_2$ และ $y = 10 = 1010_2$

```text
x      = 1100   (12)
y      = 1010   (10)

x & y  = 1000   (8)    AND  บิตที่เป็น 1 ทั้งคู่ = ส่วนร่วมของสองเซต
x | y  = 1110   (14)   OR   บิตที่เป็น 1 อย่างน้อยตัวเดียว = ยูเนียน
x ^ y  = 0110   (6)    XOR  บิตที่ต่างกัน
~x     = ...11110011   NOT  กลับทุกบิต รวมบิตสูง ๆ ด้วย (~12 ได้ -13 ใน int)
x << 1 = 11000  (24)   เลื่อนซ้าย k บิต = คูณ 2^k
x >> 2 = 11     (3)    เลื่อนขวา k บิต = หาร 2^k ปัดลง
```

## จัดการบิตที่ $i$

สี่ท่านี้ใช้บ่อยจนควรจำได้โดยไม่ต้องคิด

```cpp
bool on  = (x >> i) & 1;   // ทดสอบ: บิตที่ i เป็น 1 หรือไม่
x |=  (1LL << i);          // ตั้งบิตที่ i ให้เป็น 1
x &= ~(1LL << i);          // ล้างบิตที่ i ให้เป็น 0
x ^=  (1LL << i);          // สลับบิตที่ i
```

สังเกตว่าเราใช้ `1LL` ไม่ใช่ `1` เพราะเลข `1` เฉย ๆ เป็น `int` ซึ่งมีแค่ $32$ บิต ถ้า `i` เป็น $31$ ขึ้นไป `1 << i` จะพังทันที

นอกจากนี้ GCC มีฟังก์ชันสำเร็จรูปให้ใช้

* `__builtin_popcount(x)` นับจำนวนบิตที่เป็น $1$ ของ `int`/`unsigned` และ `__builtin_popcountll(x)` สำหรับ `long long`
* `__builtin_ctz(x)` นับเลข $0$ ท้ายสุด ก็คือดัชนีของบิต $1$ ที่ต่ำที่สุด (ห้ามเรียกกับ $x = 0$) มีรุ่น `ll` เหมือนกัน
* `x & (x - 1)` ลบบิต $1$ ที่ต่ำที่สุดทิ้ง และ `x & -x` เหลือไว้เฉพาะบิต $1$ ที่ต่ำที่สุด

:::problem lp_bit01_bit_ops

:::hint ใบ้ Bit Operations
ทุกคำสั่งคือหนึ่งในสี่ท่าข้างบน ส่วนคำสั่งนับใช้ `__builtin_popcountll` ระวังให้ดีว่า $k$ ไปได้ถึง $59$ ทั้ง `a[i]` และ `1LL << k` ต้องเป็น `long long` ทั้งหมด
:::

## ไล่ทุกเซตย่อย

ของ $N$ ชิ้นมีเซตย่อยทั้งหมด $2^N$ แบบ และ mask ของเซตย่อยเหล่านั้นก็คือจำนวนเต็ม $0, 1, 2, \ldots, 2^N - 1$ พอดี ไม่ขาดไม่เกิน จะไล่ทุกเซตย่อยจึงเหลือแค่ลูปธรรมดาลูปเดียว

ลองดูของ $3$ ชิ้น A (บิต $0$), B (บิต $1$) และ C (บิต $2$)

| `mask` | ฐานสอง | เซตย่อย |
|---|---|---|
| $0$ | `000` | (ว่าง) |
| $1$ | `001` | A |
| $2$ | `010` | B |
| $3$ | `011` | A, B |
| $4$ | `100` | C |
| $5$ | `101` | A, C |
| $6$ | `110` | B, C |
| $7$ | `111` | A, B, C |

ตัวอย่างข้างล่างนับว่ามีกี่เซตย่อยที่ผลรวมน้ำหนักเท่ากับ $S$ พอดี (โจทย์คนละข้อกับในแบบฝึก แต่ใช้ท่าเดียวกัน) มีสองเวอร์ชันให้เทียบ: แบบตรง ๆ ที่ไล่บิตทุกตัวของทุก mask กับแบบที่ต่อยอดจาก mask ที่เล็กกว่า

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
  int n;
  long long target;
  cin >> n >> target;
  vector<long long> w(n);
  for (auto &x : w) cin >> x;

  // แบบตรง ๆ: O(2^n * n)
  long long count = 0;
  for (int mask = 0; mask < (1 << n); mask++) {
    long long sum = 0;
    for (int i = 0; i < n; i++)
      if ((mask >> i) & 1) sum += w[i];
    if (sum == target) count++;
  }

  // แบบต่อยอด: ผลรวมของ mask = ผลรวมของ mask ที่ตัดบิตต่ำสุดออก + ชิ้นนั้น, O(2^n)
  vector<long long> sumOf(1 << n, 0);
  long long count2 = (target == 0);  // mask = 0 คือเซตว่าง ผลรวม 0
  for (int mask = 1; mask < (1 << n); mask++) {
    int low = __builtin_ctz(mask);
    sumOf[mask] = sumOf[mask & (mask - 1)] + w[low];
    if (sumOf[mask] == target) count2++;
  }

  cout << count << ' ' << count2 << '\n';  // สองค่านี้ต้องเท่ากัน
}
```

แบบต่อยอดใช้ได้เพราะ `mask & (mask - 1)` เล็กกว่า `mask` เสมอ ตอนที่ลูปมาถึง `mask` ค่า `sumOf` ของมันจึงถูกคำนวณไว้แล้ว ท่านี้ใช้ได้กับทุกอย่างที่ "บวกเพิ่มทีละชิ้น" ได้ เช่น ผลรวม XOR หรือการเช็กว่าเซตยังถูกเงื่อนไขอยู่หรือไม่

### เมื่อไหร่ถึงใช้ได้

$2^{20} \approx 10^6$ ถ้าคูณ $n$ อีกก็ประมาณ $2 \times 10^7$ ซึ่งทันสบาย แต่ $2^{30} \approx 10^9$ ไม่ทันแล้ว ไม่ต้องพูดถึงการคูณ $n$ ดังนั้นเวลาเห็นโจทย์ที่ $N \leq 20$ (หรือราว ๆ นั้น) ให้สงสัยไว้ก่อนเลยว่าเขาอยากให้ไล่ทุกเซตย่อย และถ้าเก็บตารางขนาด $2^N$ ก็ต้องคิดหน่วยความจำด้วย `long long` $2^{20}$ ตัวใช้ $8$ MB ยังสบายอยู่

:::problem lp_bit02_party_planning

:::hint ใบ้ Party Planning
เก็บข้อมูลคู่ที่ทะเลาะกันเป็น mask ต่อคน: `conflict[i]` มีบิต $j$ เป็น $1$ ถ้าคนที่ $i$ ทะเลาะกับคนที่ $j$ เซตที่เลือก `mask` ใช้ได้ก็ต่อเมื่อทุกคน $i$ ในเซต มี `(mask & conflict[i]) == 0` และอย่าลืมว่างบรวมเกิน `int` ได้
:::

## ไล่ submask ของ mask

บางทีเราไม่ได้อยากไล่ทุกเซตย่อยของทั้ง $N$ ชิ้น แต่อยากไล่เฉพาะเซตย่อยของ mask ตัวหนึ่ง (เรียกว่า **submask**) ท่ามาตรฐานคือ

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
  int mask = 0b1011;  // 11
  for (int s = mask; ; s = (s - 1) & mask) {
    cout << bitset<4>(s) << '\n';  // ทำงานกับ submask s ตรงนี้
    if (s == 0) break;              // s = 0 ก็เป็น submask ทำงานก่อนแล้วค่อยหยุด
  }
}
```

โปรแกรมนี้พิมพ์ `1011`, `1010`, `1001`, `1000`, `0011`, `0010`, `0001`, `0000` คือ submask ทั้ง $8$ ตัวเรียงจากมากไปน้อย ทำไมถึงได้? `s - 1` ทำให้บิต $1$ ที่ต่ำที่สุดของ `s` กลายเป็น $0$ และบิตที่ต่ำกว่ามันกลายเป็น $1$ หมด แล้ว `& mask` ตัดบิตที่ไม่อยู่ใน `mask` ทิ้ง ผลคือได้ submask ตัวถัดไปที่เล็กกว่าพอดี

ถ้าไล่ submask ของ **ทุก** mask รวมกันจะเป็น $3^N$ ไม่ใช่ $4^N$ เพราะของแต่ละชิ้นมีได้แค่สามสถานะ: ไม่อยู่ใน mask, อยู่ใน mask แต่ไม่อยู่ใน submask, หรืออยู่ทั้งคู่ $3^{15} \approx 1.4 \times 10^7$ ทันสบาย แต่ $3^{20} \approx 3.5 \times 10^9$ ไม่ทัน

## เทคนิค XOR

XOR มีสมบัติที่ใช้ได้บ่อยมาก

* $a \oplus a = 0$ และ $a \oplus 0 = a$
* สลับที่และจัดกลุ่มได้ ($a \oplus b = b \oplus a$) ลำดับจึงไม่สำคัญ
* XOR กับอะไรสองครั้งก็กลับมาเท่าเดิม: $a \oplus b \oplus b = a$

ตัวอย่างคลาสสิก: มีเลข $N$ ตัว ทุกค่าปรากฏเป็นจำนวนครั้งคู่ ยกเว้นค่าเดียวที่ปรากฏเป็นจำนวนครั้งคี่ จงหาค่านั้น ถ้า XOR ทุกตัวเข้าด้วยกัน คู่ที่ซ้ำกันจะหักล้างกันเป็น $0$ หมด เหลือแค่ค่าที่เราตามหา ใช้เวลา $O(N)$ และหน่วยความจำ $O(1)$ ไม่ต้องเรียงหรือนับเลย

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
  int n;
  cin >> n;
  long long acc = 0;
  for (int i = 0; i < n; i++) {
    long long x;
    cin >> x;
    acc ^= x;  // ค่าที่ซ้ำเป็นจำนวนครั้งคู่หักล้างกันเอง
  }
  cout << acc << '\n';
}
```

อีกมุมหนึ่งของ XOR คือ "การสลับ" (toggle) ถ้ามองบิตเป็นสวิตช์เปิดปิด XOR กับ mask ก็คือสลับทุกบิตใน mask พร้อมกัน และสลับสองครั้งก็เหมือนไม่ได้ทำอะไรเลย ข้อนี้สำคัญมากกับข้อท้าทายของบทนี้

:::problem lp_bit03_light_switches

:::hint ใบ้ Light Switches
ถามตัวเองสองข้อ: กดสวิตช์ตัวเดิมสองครั้งได้ผลเหมือนอะไร และลำดับการกดสำคัญไหม? พอตอบได้ ข้อนี้จะกลายเป็นการเลือก **เซต** ของสวิตช์ ซึ่งมีแค่ $2^M$ แบบ แปลงแต่ละสตริงเป็น `long long` mask ก่อน (หลอดมีได้ถึง $60$ ดวง) แล้วผลของการกดทั้งเซตคือ XOR ของ mask ในเซตนั้น ถ้าไล่สลับทีละหลอดในทุกเซตจะช้าเกินไป
:::

:::warning จุดที่พลาดบ่อย
* `1 << i` เมื่อ $i \geq 31$ ล้น `int` ต้องเขียน `1LL << i`
* ลำดับความสำคัญของตัวดำเนินการ: `x & 1 << i == 0` ถูกอ่านเป็น `x & ((1 << i) == 0)` เพราะ `==` ทำก่อน `&` ใส่วงเล็บทุกครั้ง เช่น `((x >> i) & 1) == 0`
* เรียก `__builtin_popcount` กับ `long long` บิตบน ๆ จะหายไปเงียบ ๆ ต้องใช้ `__builtin_popcountll`
* `__builtin_ctz(0)` ไม่มีความหมาย ต้องเช็กก่อนว่า mask ไม่เป็น $0$
* ลืมว่าเซตว่าง (`mask = 0`) ก็เป็นเซตย่อยหนึ่งตัว บางโจทย์นับมัน บางโจทย์ไม่นับ
* ใช้ bitmask กับ $N$ ที่ใหญ่เกินไป: $2^N$ โตเร็วมาก เกินราว $25$ ก็เริ่มไม่ทันแล้ว
:::

## สรุปสั้น ๆ

* mask คือจำนวนเต็มที่บิตที่ $i$ บอกว่าชิ้นที่ $i$ อยู่ในเซตหรือไม่
* ทดสอบ `(x >> i) & 1` ตั้ง `x | (1LL << i)` ล้าง `x & ~(1LL << i)` สลับ `x ^ (1LL << i)` นับบิต `__builtin_popcountll`
* ไล่ทุกเซตย่อยด้วย `for (mask = 0; mask < (1 << n); mask++)` ใช้ได้เมื่อ $N \leq 20$ ราว ๆ และต่อยอดค่าจาก `mask & (mask - 1)` ได้ใน $O(2^N)$
* ไล่ submask ด้วย `s = (s - 1) & mask` รวมทุก mask เป็น $3^N$
* XOR หักล้างตัวเอง ($a \oplus a = 0$) ลำดับไม่สำคัญ และทำหน้าที่เป็น "สลับ" ได้
