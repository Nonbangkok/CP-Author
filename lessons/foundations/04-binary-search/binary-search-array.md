## ถามซ้ำ ๆ บนข้อมูลชุดเดิม

สมมติมีตัวเลข $N$ ตัว แล้วมีคำถาม $Q$ ข้อ แต่ละข้อถามว่า "มีเลข $x$ อยู่ไหม" หรือ "มีกี่ตัวที่ไม่เกิน $x$" ถ้าไล่ดูทุกตัวทุกคำถามก็ใช้เวลา $O(NQ)$ พอ $N$ กับ $Q$ เป็นหลักแสนทั้งคู่ก็คือ $10^{10}$ ครั้ง TLE แน่นอน

ทางออกคือ **เรียงข้อมูลครั้งเดียว** แล้วตอบแต่ละคำถามด้วย binary search ใน $O(\log N)$ รวมแล้วเหลือ $O((N + Q) \log N)$ ซึ่งสบายมาก

## ไอเดีย: ตัดครึ่งทุกรอบ

ลองนึกถึงเกมทายเลข 1 ถึง 100 ที่คนคิดเลขบอกแค่ว่า "มากไป" หรือ "น้อยไป" วิธีที่ดีที่สุดคือทายตรงกลางเสมอ เพราะไม่ว่าคำตอบจะเป็นอะไร ช่วงที่เหลือก็หายไปครึ่งหนึ่ง จาก 100 เหลือ 50, 25, 13, … ไม่เกิน 7 ครั้งก็เจอ

อาเรย์ที่เรียงแล้วก็เหมือนกัน ถ้าดูตัวตรงกลางแล้วมันน้อยกว่า $x$ ก็รู้ทันทีว่าทุกตัวทางซ้ายของมันน้อยกว่า $x$ ด้วย ทิ้งครึ่งซ้ายไปได้เลย ทำแบบนี้ไปเรื่อย ๆ จำนวนรอบคือ $\lceil \log_2 N \rceil$ สำหรับ $N = 10^6$ ก็แค่ประมาณ $20$ รอบ

## เขียนเองให้ถูก: คิดเป็น invariant

binary search ขึ้นชื่อเรื่องเขียนผิดง่ายที่สุดเรื่องหนึ่ง (บวกหนึ่งหรือไม่บวก? `<` หรือ `<=`?) วิธีที่ทำให้ไม่ต้องเดาคือ **กำหนดความหมายของ `lo` กับ `hi` ให้ชัดก่อน** แล้วเขียนโค้ดให้ความหมายนั้นจริงตลอดเวลา (เรียกว่า invariant)

โจทย์: หา **ดัชนีแรก** ที่ `a[i] >= x` (ถ้าไม่มีให้ได้ `n`)

ลองมองอาเรย์ที่เรียงแล้วเป็นแถบสองสี ตัวที่ `a[i] < x` เป็นสีแดง ตัวที่ `a[i] >= x` เป็นสีเขียว เพราะเรียงแล้ว สีแดงต้องอยู่ซ้ายทั้งหมด และสีเขียวอยู่ขวาทั้งหมด เราต้องการหาจุดเปลี่ยนสี

```text
a     =  1   3   3   5   8   13        x = 5
สี     =  R   R   R   G   G   G
ดัชนี  =  0   1   2   3   4   5        คำตอบ = 3
```

ใช้ช่วงแบบ **half-open** `[lo, hi)` โดยให้

* ทุกดัชนี **น้อยกว่า** `lo` เป็นสีแดงแน่นอน
* ทุกดัชนี **ตั้งแต่** `hi` ขึ้นไปเป็นสีเขียวแน่นอน
* ช่วง `[lo, hi)` คือส่วนที่ยังไม่รู้

เริ่มที่ `lo = 0, hi = n` (ยังไม่รู้อะไรเลย) แล้วดูตัวกลาง `mid`

* ถ้า `a[mid] < x` แปลว่า `mid` เป็นสีแดง ทุกตัวถึง `mid` จึงแดงด้วย ให้ `lo = mid + 1`
* ไม่อย่างนั้น `mid` เป็นสีเขียว ให้ `hi = mid`

ทั้งสองกรณี invariant ยังจริงอยู่ และช่วงแคบลงเสมอ พอ `lo == hi` ช่วงที่ไม่รู้ก็ว่างแล้ว `lo` คือดัชนีสีเขียวตัวแรกพอดี

## Template

โค้ดข้างล่างเป็นโปรแกรมเต็ม copy ไปใช้ได้เลย มีทั้งแบบเขียนเองและแบบ STL ให้เทียบกัน

```cpp
#include <bits/stdc++.h>
using namespace std;

// ดัชนีแรกที่ a[i] >= x  (ถ้าไม่มีได้ n)   -- เหมือน std::lower_bound
int firstAtLeast(const vector<int> &a, int x) {
  int lo = 0, hi = (int)a.size();      // [0, lo) < x,  [hi, n) >= x
  while (lo < hi) {
    int mid = lo + (hi - lo) / 2;      // lo <= mid < hi เสมอ
    if (a[mid] < x) lo = mid + 1;
    else hi = mid;
  }
  return lo;
}

// ดัชนีแรกที่ a[i] > x   (ถ้าไม่มีได้ n)   -- เหมือน std::upper_bound
int firstGreater(const vector<int> &a, int x) {
  int lo = 0, hi = (int)a.size();      // [0, lo) <= x,  [hi, n) > x
  while (lo < hi) {
    int mid = lo + (hi - lo) / 2;
    if (a[mid] <= x) lo = mid + 1;
    else hi = mid;
  }
  return lo;
}

// ดัชนีสุดท้ายที่ a[i] <= x  (ถ้าไม่มีได้ -1)
int lastAtMost(const vector<int> &a, int x) {
  return firstGreater(a, x) - 1;
}

int main() {
  ios::sync_with_stdio(false);
  cin.tie(nullptr);
  int n, q;
  cin >> n >> q;
  vector<int> a(n);
  for (int &v : a) cin >> v;
  sort(a.begin(), a.end());            // binary search ใช้ได้กับข้อมูลที่เรียงแล้วเท่านั้น

  while (q--) {
    int x;
    cin >> x;
    int lb = firstAtLeast(a, x);
    int ub = firstGreater(a, x);

    // แบบ STL ได้ผลเท่ากันทุกครั้ง
    int lb2 = lower_bound(a.begin(), a.end(), x) - a.begin();
    int ub2 = upper_bound(a.begin(), a.end(), x) - a.begin();
    assert(lb == lb2 && ub == ub2);

    cout << "first >= x at " << lb
         << ", last <= x at " << lastAtMost(a, x)
         << ", x appears " << ub - lb << " time(s)\n";
  }
}
```

สังเกตว่า `firstAtLeast` กับ `firstGreater` ต่างกันแค่ `<` กับ `<=` บรรทัดเดียว เพราะต่างกันแค่ "สีแดง" หมายถึงอะไร ถ้าจำ invariant ได้ ก็ไม่ต้องจำโค้ด

## ใช้ STL: `lower_bound` และ `upper_bound`

ในการแข่งจริงเราใช้ของ STL แทบทุกครั้ง

* `lower_bound(first, last, x)` คืน iterator ไปยังตัวแรกที่ `>= x`
* `upper_bound(first, last, x)` คืน iterator ไปยังตัวแรกที่ `> x`
* ถ้าไม่มีตัวแบบนั้น ทั้งคู่คืน `last` (เช่น `a.end()`)
* อยากได้ดัชนีก็เอา `a.begin()` ไปลบ เช่น `lower_bound(a.begin(), a.end(), x) - a.begin()`

จากสองตัวนี้ได้ของที่ใช้บ่อยมาก

| อยากได้ | เขียนว่า | ระวัง |
|---|---|---|
| ตัวเล็กสุดที่ `>= x` | `*lower_bound(...)` | ได้ `end()` เมื่อทุกตัว `< x` |
| ตัวเล็กสุดที่ `> x` | `*upper_bound(...)` | ได้ `end()` เมื่อทุกตัว `<= x` |
| ตัวใหญ่สุดที่ `<= x` | `*prev(upper_bound(...))` | ถ้าได้ `begin()` แปลว่าไม่มี |
| ตัวใหญ่สุดที่ `< x` | `*prev(lower_bound(...))` | ถ้าได้ `begin()` แปลว่าไม่มี |
| จำนวนตัวที่เท่ากับ `x` | `upper_bound(...) - lower_bound(...)` | |

## ตัวอย่าง: ไล่มือหนึ่งรอบ

อาเรย์ `1 3 3 5 8 13` (n = 6) หา `firstAtLeast(a, 4)`

```text
lo=0 hi=6  mid=3  a[3]=5  >= 4  -> hi=3
lo=0 hi=3  mid=1  a[1]=3  <  4  -> lo=2
lo=2 hi=3  mid=2  a[2]=3  <  4  -> lo=3
lo=3 hi=3  จบ  คำตอบ 3  (a[3] = 5 คือตัวแรกที่ >= 4)
```

ถ้าหา `x = 3` จะได้ `lower_bound = 1` และ `upper_bound = 3` ผลต่างคือ $2$ ซึ่งก็คือจำนวน `3` ในอาเรย์พอดี และถ้าหา `x = 20` จะได้ `6` คือ "ไม่มี" (เท่ากับ `n`) ห้ามเอาไปอ่าน `a[6]` เด็ดขาด

## นับจำนวนในช่วง

การนับตัวที่เท่ากับ `x` คือ `upper_bound(x) - lower_bound(x)` แบบเดียวกันนี้ใช้นับตัวที่อยู่ในช่วงค่าใด ๆ ได้ด้วย เพราะ "จำนวนตัวที่ `< x`" ก็คือ `lower_bound(x)` และ "จำนวนตัวที่ `<= x`" ก็คือ `upper_bound(x)` เอามาลบกันก็ได้ส่วนตรงกลาง

:::problem lp_bsa01_count_range

:::hint ใบ้ Count in Range
อยากได้จำนวนตัวที่ $l \leq a_i \leq r$ ให้คิดเป็น "จำนวนตัวที่ `<= r`" ลบ "จำนวนตัวที่ `< l`" แต่ละอันคือ `upper_bound` หรือ `lower_bound` ตัวไหน ลองเทียบกับตารางข้างบนดู และอย่าลืมเรียงก่อน
:::

## หาเพื่อนบ้านที่ใกล้ที่สุด

หลายโจทย์ไม่ได้ถามว่า "มีไหม" แต่ถามว่า "ตัวที่ใกล้ $x$ ที่สุดคือตัวไหน" ในอาเรย์ที่เรียงแล้ว ตัวที่ใกล้ที่สุดต้องเป็นหนึ่งในสองตัวนี้เท่านั้น: ตัวแรกที่ `>= x` กับตัวก่อนหน้ามัน เพราะทุกตัวที่อยู่ไกลออกไปกว่านั้นก็ห่างจาก $x$ มากกว่าแน่ ๆ

ดังนั้นงานจริงมีแค่ `lower_bound` หนึ่งครั้ง แล้วระวังขอบสองข้าง คือตอนที่ได้ `begin()` (ไม่มีตัวก่อนหน้า) และตอนที่ได้ `end()` (ไม่มีตัวที่ `>= x`)

:::problem lp_bsa02_nearest_value

:::hint ใบ้ Nearest Value
เช็กกรณี `it == a.end()` และ `it == a.begin()` ก่อน แล้วค่อยเทียบ `x - *prev(it)` กับ `*it - x` ถ้าเท่ากันโจทย์ให้ตอบตัวที่น้อยกว่า ซึ่งก็คือ `*prev(it)` ราคาอยู่ระหว่าง $-10^9$ ถึง $10^9$ ผลต่างจึงไปได้ถึง $2 \cdot 10^9$ ซึ่งเกิน `int` แล้ว ใช้ `long long`
:::

## binary search ทีละตัว

อีกท่าที่เจอบ่อยคือโจทย์นับ **คู่** ถ้าไล่ทุกคู่ก็ $O(N^2)$ แต่ถ้าเรียงแล้ว พอเรายึดตัวหนึ่งไว้ เงื่อนไขของอีกตัวมักกลายเป็น "ค่าไม่เกินอะไรสักอย่าง" ซึ่ง binary search ตอบได้ทันที

ตัวอย่างโจทย์ข้างเคียง: นับคู่ $i < j$ ที่ $|a_i - a_j| \leq D$ หลังจากเรียงแล้ว ถ้ายึด $j$ ไว้ ตัว $i < j$ ทุกตัวมี $a_i \leq a_j$ อยู่แล้ว เงื่อนไขจึงเหลือแค่ $a_i \geq a_j - D$ ซึ่งก็คือ "ตั้งแต่ `lower_bound(a_j - D)` ไปจนถึง $j - 1$"

```cpp
sort(a.begin(), a.end());
long long pairs = 0;
for (int j = 0; j < n; j++) {
  int from = lower_bound(a.begin(), a.begin() + j, a[j] - d) - a.begin();
  pairs += j - from;                   // ดัชนี from .. j-1 ใช้ได้ทั้งหมด
}
```

ค้นแค่ในช่วง `[a.begin(), a.begin() + j)` เพื่อนับแต่ละคู่ครั้งเดียว ทั้งหมดเป็น $O(N \log N)$ และสังเกตว่า `pairs` เป็น `long long` เพราะจำนวนคู่ไปได้ถึง $\frac{N(N-1)}{2}$ ซึ่งเกิน `int` ตั้งแต่ $N$ ประมาณ $65{,}000$

:::problem lp_bsa03_pair_budget

:::hint ใบ้ Pair Budget
ยึด $j$ ไว้ แล้วถามว่า $i < j$ ตัวไหนบ้างที่ $a_i \leq K - a_j$ ในอาเรย์ที่เรียงแล้วพวกนั้นเป็นช่วงต่อกันตั้งแต่ต้น `upper_bound` ตัวเดียวจบ ระวัง $K - a_j$ ไปได้ถึง $3 \cdot 10^9$ เก็บใน `int` ไม่ได้
:::

## ความซับซ้อน

* เรียงครั้งเดียว $O(N \log N)$
* แต่ละคำถาม $O(\log N)$ รวม $Q$ คำถามเป็น $O(Q \log N)$
* เทียบกับไล่ทุกตัว $O(NQ)$: ที่ $N = Q = 10^5$ คือประมาณ $3.4 \cdot 10^6$ เทียบกับ $10^{10}$

:::warning จุดที่พลาดบ่อย
* **ลืมเรียง** binary search บนอาเรย์ที่ไม่เรียงไม่ error แต่ได้คำตอบมั่ว
* **ลูปไม่จบ** ถ้าเขียน `lo = mid` ในลูป `while (lo < hi)` พอ `hi = lo + 1` จะได้ `mid = lo` ช่วงไม่แคบลง วนไปตลอดกาล ในแบบ half-open ฝั่ง `lo` ต้องเป็น `mid + 1` เสมอ
* **`mid` ล้น** `(lo + hi) / 2` ล้นได้ถ้า `lo + hi` เกินขอบของชนิดข้อมูล ให้ชินกับ `lo + (hi - lo) / 2` ไว้ จะได้ไม่ต้องคิดอีก (สำคัญมากในบทถัดไปที่ช่วงใหญ่ถึง $10^{18}$)
* **อ่าน `*end()`** ก่อนใช้ค่าที่ `lower_bound` คืนมา ต้องเช็กก่อนว่าไม่ใช่ `end()` และก่อน `prev(it)` ต้องเช็กว่าไม่ใช่ `begin()`
* **`std::lower_bound` กับ `set`** เขียน `lower_bound(s.begin(), s.end(), x)` ได้ แต่ช้าเป็น $O(N)$ เพราะ iterator ของ `set` กระโดดไปตรงกลางไม่ได้ ใช้ `s.lower_bound(x)` ซึ่งเป็น $O(\log N)$ แทน
:::

## สรุปสั้น ๆ

* เรียงครั้งเดียว แล้วตอบแต่ละคำถามด้วย binary search ใน $O(\log N)$
* คิดเป็น invariant แบบ half-open: `[0, lo)` ไม่ผ่าน, `[hi, n)` ผ่าน วน `while (lo < hi)` แล้ว `lo = mid + 1` หรือ `hi = mid`
* `lower_bound` = ตัวแรกที่ `>= x`, `upper_bound` = ตัวแรกที่ `> x` นับในช่วงได้ด้วยการลบกัน
* ตัวที่ใกล้ $x$ ที่สุดคือ `lower_bound` หรือตัวก่อนหน้า ระวัง `begin()` กับ `end()`
* โจทย์นับคู่: เรียง แล้วยึดทีละตัวแล้ว binary search หาอีกตัว และใช้ `long long` กับผลรวมกับจำนวนคู่
