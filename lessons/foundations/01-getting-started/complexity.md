## คิดก่อนเขียน: จะทันเวลาไหม

ก่อนจะลงมือเขียนโค้ดสักบรรทัด คนที่แข่งเก่ง ๆ จะถามตัวเองก่อนเสมอว่า "วิธีนี้ทำงานกี่ครั้ง แล้วจะทันเวลาไหม" ถ้าคำตอบคือไม่ทัน ก็ไม่ต้องเสียเวลาเขียน ให้หาวิธีใหม่เลย บทนี้จะสอนเครื่องมือสำหรับตอบคำถามนั้นภายในไม่กี่วินาที คือ **Big O**, **การนับจำนวนการทำงาน** และ **การอ่าน constraints**

## Big O คืออะไร

Big O บอกว่าเมื่อข้อมูลใหญ่ขึ้น จำนวนงานโตเร็วแค่ไหน เราสนใจแค่ **พจน์ที่โตเร็วที่สุด** และ **ไม่สนค่าคงที่**

* $3N + 5$ คือ $O(N)$
* $\frac{N(N-1)}{2}$ คือ $O(N^2)$
* $N^2 + 100N \log N$ คือ $O(N^2)$ เพราะเมื่อ $N$ ใหญ่พอ $N^2$ ชนะขาด

ที่ทิ้งค่าคงที่ได้ เพราะเมื่อ $N = 10^5$ ความต่างระหว่าง $O(N)$ กับ $O(N^2)$ คือหนึ่งแสนเท่า ในขณะที่ค่าคงที่ปกติต่างกันแค่ไม่กี่เท่า

### รูปแบบที่เจอบ่อย

| โค้ดหน้าตาแบบนี้ | ความซับซ้อน |
|---|---|
| คำนวณจากสูตรตรง ๆ | $O(1)$ |
| ลดขนาดลงครึ่งหนึ่งทุกรอบ (binary search) | $O(\log N)$ |
| ลูปเดียววิ่งครบ $N$ ตัว | $O(N)$ |
| `sort` | $O(N \log N)$ |
| ลูปซ้อนสองชั้น ชั้นละ $N$ | $O(N^2)$ |
| ไล่ทุกเซตย่อย | $O(2^N)$ |
| ไล่ทุกการเรียงสับเปลี่ยน | $O(N!)$ |

## นับจำนวนการทำงาน

ลองนับลูปนี้ดู

```cpp
for (int i = 0; i < n; i++)
  for (int j = 0; j < i; j++)
    work(i, j);
```

รอบ $i = 0$ ทำ $0$ ครั้ง รอบ $i = 1$ ทำ $1$ ครั้ง ไปจนถึงรอบ $i = n - 1$ ทำ $n - 1$ ครั้ง รวมเป็น

$$0 + 1 + \cdots + (n - 1) = \frac{n(n-1)}{2}$$

ก็คือ $O(n^2)$ แม้จะทำแค่ครึ่งหนึ่งของ $n^2$ ก็ตาม ถ้า $n = 10^5$ จะได้ราว $5 \times 10^9$ ครั้ง ซึ่งไม่ทันแน่นอน

เวลามีหลายส่วนต่อกัน ให้บวกกัน แล้วเก็บพจน์ที่ใหญ่สุด เช่น อ่านข้อมูล $O(N)$ + เรียง $O(N \log N)$ + ตอบ $Q$ คำถามคำถามละ $O(\log N)$ รวมเป็น $O((N + Q) \log N)$

## กฎ $10^8$ ต่อวินาที

กฎหัวแม่มือที่ใช้กันทั่วไปคือ **คอมพิวเตอร์ทำงานง่าย ๆ (บวก เทียบ เข้าถึงอาเรย์) ได้ราว $10^8$ ครั้งต่อวินาที** เอาจำนวนการทำงานที่นับได้มาเทียบกับ time limit

* ไม่เกิน $10^7$: สบาย
* ราว $10^8$: เสี่ยง ขึ้นกับค่าคงที่
* $10^9$ ขึ้นไป: ไม่ทันแน่นอน หาวิธีใหม่

:::note judge นี้ไม่มี -O2
หลาย judge compile ด้วย `-O2` ซึ่งให้ compiler ปรับโค้ดให้เร็วขึ้น แต่ judge นี้ **ไม่มี** ลองวัดบนเครื่องที่ compile แบบเดียวกับ judge: ลูปซ้อนที่ทำ $10^8$ ครั้งใช้ราว 260 ms ถ้าเปิด `-O2` จะเหลือราว 60 ms และ `sort` $10^6$ ตัวใช้ราว 280 ms เทียบกับราว 60 ms ช้าลงประมาณสี่เท่า โดยเฉพาะโค้ดที่เรียก STL ถี่ ๆ ในลูป เพราะไม่มีการ inline ให้ ดังนั้นให้ยึด $10^8$ เป็นเพดานจริงจัง อย่าหวังว่าจะเบียดไปถึง $10^9$ ได้
:::

## อ่าน constraints แล้วเดาอัลกอริทึม

constraints ของโจทย์เป็นใบ้ที่ดีที่สุด คนตั้งโจทย์เลือกขนาดข้อมูลให้วิธีที่ตั้งใจผ่านพอดี และวิธีที่ช้ากว่าไม่ผ่าน เมื่อเห็น $N$ ก็ย้อนกลับได้เลยว่าควรใช้ความซับซ้อนประมาณไหน

| ถ้า $N$ ไม่เกิน | ความซับซ้อนที่ยังทัน | ตัวอย่างวิธี |
|---|---|---|
| $10$ | $O(N!)$ | ไล่ทุกการเรียงสับเปลี่ยน |
| $20$ | $O(2^N \cdot N)$ | ไล่ทุกเซตย่อย, bitmask |
| $500$ | $O(N^3)$ | ลูปซ้อนสามชั้น |
| $5{,}000$ | $O(N^2)$ | ลูปซ้อนสองชั้น |
| $10^5$ ถึง $10^6$ | $O(N \log N)$ | sort, binary search, `set`/`map` |
| $10^7$ | $O(N)$ | ลูปเดียว, prefix sum, two pointers |
| ใหญ่กว่านั้น | $O(\log N)$ หรือ $O(1)$ | สูตร, fast power |

ลองแทนค่าดู: $N = 5{,}000$ กับ $O(N^2)$ ได้ $2.5 \times 10^7$ ทันสบาย แต่ $N = 10^5$ กับ $O(N^2)$ ได้ $10^{10}$ ช้าไปร้อยเท่า ในขณะที่ $O(N \log N)$ ได้แค่ราว $1.7 \times 10^6$

ถ้ามีหลายตัวแปรก็คิดแบบเดียวกัน เช่น $N, Q \le 10^5$ แล้วตอบแต่ละคำถามแบบไล่ทั้งอาเรย์ ได้ $N \times Q = 10^{10}$ ไม่ทัน แปลว่าต้องเตรียมข้อมูลไว้ก่อน แล้วตอบแต่ละคำถามให้เร็วกว่า $O(N)$

## ตัวอย่างเต็ม: จาก $O(N^2)$ เหลือ $O(N)$

โจทย์ข้างเคียง: รู้ราคาหุ้น $N$ วัน คือ $p_1, \ldots, p_N$ ซื้อหนึ่งวันแล้วขายในวันหลังจากนั้น (หรือวันเดียวกัน กำไร $0$) อยากได้กำไร $p_j - p_i$ ที่มากที่สุด โดย $i \le j$ และ $N \le 10^6$

วิธีตรง ๆ คือลองทุกคู่

```cpp
long long best = 0;
for (int i = 0; i < n; i++)
  for (int j = i; j < n; j++)
    best = max(best, p[j] - p[i]);
```

นับได้ราว $\frac{N^2}{2} = 5 \times 10^{11}$ ครั้ง ไม่มีทางทัน

ลองคิดใหม่: ถ้าตัดสินใจว่าจะขายวันที่ $j$ วันซื้อที่ดีที่สุดก็คือ **วันที่ราคาต่ำที่สุดในช่วง $1..j$** ซึ่งเราจำไว้ระหว่างเดินได้เลย ไม่ต้องย้อนกลับไปหาใหม่ทุกรอบ

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
  ios::sync_with_stdio(false);
  cin.tie(nullptr);
  int n;
  cin >> n;
  long long lowest = LLONG_MAX, best = 0;
  for (int j = 0; j < n; j++) {
    long long p;
    cin >> p;
    lowest = min(lowest, p);         // ราคาต่ำสุดตั้งแต่วันแรกถึงวันนี้
    best = max(best, p - lowest);    // ขายวันนี้ได้กำไรเท่าไร
  }
  cout << best << '\n';
}
```

ลูปเดียว $O(N)$ ทำงานราว $10^6$ ครั้ง เร็วกว่าเดิมห้าแสนเท่า ใช้หน่วยความจำ $O(1)$ ด้วยเพราะไม่ต้องเก็บอาเรย์เลย นี่คือรูปแบบที่จะเจอซ้ำตลอดทาง: **วิธีช้ามักทำงานเดิมซ้ำ ๆ ให้หาว่าอะไรที่คำนวณซ้ำ แล้วจำมันไว้** หรือ **จัดข้อมูลให้เป็นระเบียบก่อน (เช่น sort) แล้วงานที่เหลือจะง่ายลง**

:::problem lp_cx01_distinct_values

:::hint ใบ้ Distinct Values
วิธีเทียบทุกคู่คือ $O(N^2)$ และ $N$ ถึง $10^5$ ลองคิดดูว่าถ้าเรียงลำดับก่อน ค่าที่ซ้ำกันจะไปอยู่ตรงไหน แล้วการนับจะเหลือกี่รอบ ($O(N \log N)$ รวมการเรียง) ค่าอยู่ถึง $10^9$ จึงทำอาเรย์นับตามค่าไม่ได้
:::

:::problem lp_cx02_range_sums

:::hint ใบ้ Range Sums
งานที่ถูกทำซ้ำคือการบวกช่วงเดิม ๆ ใหม่ทุกคำถาม ลองเตรียม $S_i = a_1 + \cdots + a_i$ ไว้ก่อนทุก $i$ ในรอบเดียว แล้วดูว่าผลรวมช่วง $[l, r]$ เขียนด้วย $S$ สองตัวได้อย่างไร อย่าลืมว่าผลรวมอาจถึง $4 \times 10^{10}$
:::

## หน่วยความจำ

memory limit ส่วนใหญ่คือ 256 MB ประเมินได้จาก **จำนวนช่อง × ขนาดของหนึ่งช่อง**

| ชนิด | ขนาด |
|---|---|
| `char`, `bool` | 1 byte |
| `int`, `float` | 4 bytes |
| `long long`, `double` | 8 bytes |

* อาเรย์ `int` $10^7$ ช่อง = $4 \times 10^7$ bytes = **40 MB** สบาย
* อาเรย์ `long long` $10^7$ ช่อง = 80 MB ยังได้
* ตาราง `int` ขนาด $5{,}000 \times 5{,}000$ = 100 MB เริ่มหนัก
* ตาราง `int` ขนาด $10^4 \times 10^4$ = 400 MB เกินแน่นอน ต้องหาวิธีที่ไม่เก็บทั้งตาราง

`vector<vector<int>>` มีค่าใช้จ่ายเพิ่มอย่างน้อยราว 24 bytes ต่อแถว ถ้ามีแถวเป็นล้านแถวก็ต้องนับด้วย ส่วน `set`/`map` ใช้หน่วยความจำต่อสมาชิกหลายสิบ bytes มากกว่าอาเรย์หลายเท่า

:::warning อาเรย์ใหญ่ห้ามประกาศใน main
ตัวแปรที่ประกาศในฟังก์ชันอยู่บน stack ซึ่งปกติมีแค่ราว 8 MB การเขียน `int a[10000000];` ไว้ใน `main` จึงทำให้โปรแกรมพังเป็น Runtime Error ทั้งที่ memory limit ยังเหลือเยอะ ให้ประกาศเป็นตัวแปร global (นอกฟังก์ชัน) หรือใช้ `vector<int> a(n);` ซึ่งเก็บข้อมูลไว้บน heap
:::

## งาน $O(N)$ ที่ซ่อนอยู่ในบรรทัดเดียว

บางบรรทัดดูสั้น แต่ทำงาน $O(N)$ ถ้าอยู่ในลูปก็กลายเป็น $O(N^2)$ ทันที

:::warning จุดที่พลาดบ่อย
* `v.erase(v.begin())` หรือ `v.insert(v.begin(), x)` ต้องเลื่อนทุกตัว เป็น $O(N)$
* `s = s + c` สร้างสตริงใหม่ทั้งก้อนทุกครั้ง ใช้ `s += c` หรือ `s.push_back(c)` แทน
* `count(v.begin(), v.end(), x)` หรือ `find` บน `vector` ไล่ทั้งอาเรย์
* ส่ง `vector` เข้าฟังก์ชันแบบ by value (`void f(vector<int> v)`) copy ทั้งก้อนทุกครั้งที่เรียก ใช้ `const vector<int> &v`
* `memset` หรือสร้างอาเรย์ขนาดเต็มใหม่ในทุก test case ทั้งที่แต่ละเคสเล็ก
* นับจำนวนการทำงานแล้วลืมว่า $N \times Q$ เองก็ล้น `int` ได้ ตอนคิดในหัวไม่เป็นไร แต่ถ้าเขียนในโค้ดให้ใช้ `long long`
:::

## สรุปสั้น ๆ

* Big O ดูแค่พจน์ที่โตเร็วที่สุด ไม่สนค่าคงที่
* นับจำนวนการทำงานคร่าว ๆ แล้วเทียบกับราว $10^8$ ต่อวินาที และจำไว้ว่า judge นี้ไม่มี `-O2`
* อ่าน constraints ก่อน: $N \le 20$ คิดถึง $2^N$, $N \le 5{,}000$ คิดถึง $N^2$, $N \le 10^5$ ถึง $10^6$ คิดถึง $N \log N$ หรือ $N$
* วิธีช้ามักทำงานซ้ำ: จำผลที่คำนวณแล้ว หรือเรียงข้อมูลก่อน
* หน่วยความจำ = จำนวนช่อง × ขนาด อาเรย์ `int` $10^7$ ช่อง = 40 MB และอาเรย์ใหญ่ให้เป็น global หรือ `vector`
