## โค้ดถูก แต่ทำไมไม่ผ่าน

หลายคนเจอแบบนี้ตั้งแต่ข้อแรก ๆ: อัลกอริทึมถูกแล้วแน่ ๆ ทดสอบกับตัวอย่างก็ผ่าน แต่ส่งไปแล้วได้ Time Limit Exceeded, Runtime Error หรือ Wrong Answer สาเหตุส่วนใหญ่ไม่ได้อยู่ที่ตัวอัลกอริทึมเลย แต่อยู่ที่เรื่องพื้นฐานสามเรื่อง

1. **อ่านข้อมูลช้า** ข้อมูลเป็นแสนเป็นล้านตัว แต่ใช้ `cin` แบบค่าเริ่มต้น
2. **ชนิดข้อมูลเล็กไป** ผลรวมหรือผลคูณเกินที่ `int` เก็บได้
3. **พิมพ์ผิดรูปแบบ** โจทย์ขอทศนิยมสองตำแหน่ง แต่เราพิมพ์ `73.6667` หรือ `73`

บทนี้จะเก็บทั้งสามเรื่องให้เรียบร้อย แล้วจบด้วยไฟล์ template ที่ใช้ได้กับแทบทุกข้อ

## Template ที่ใช้ทุกข้อ

เริ่มจากโครงนี้ทุกครั้ง แล้วค่อยเติมโค้ดของโจทย์ลงใน `main`

```cpp
#include <bits/stdc++.h>
using namespace std;

using ll = long long;
const ll MOD = 1000000007LL;

int main() {
  ios::sync_with_stdio(false);
  cin.tie(nullptr);

  int n;
  cin >> n;
  vector<ll> a(n);
  for (ll &x : a) cin >> x;

  // เขียนคำตอบตรงนี้
  ll sum = 0;
  for (ll x : a) sum += x;
  cout << sum << '\n';
}
```

ทีละบรรทัด:

* `#include <bits/stdc++.h>` ดึง standard library ของ GCC มาทั้งหมดในบรรทัดเดียว (`vector`, `sort`, `iomanip`, ...) ไม่ต้องจำว่าอะไรอยู่ header ไหน
* `using ll = long long;` ตั้งชื่อสั้นให้ชนิดที่ใช้บ่อยที่สุด
* สองบรรทัดแรกใน `main` คือ **fast I/O** ซึ่งเดี๋ยวจะอธิบายในหัวข้อถัดไป
* จบบรรทัดด้วย `'\n'` ไม่ใช่ `endl` (เหตุผลอยู่ในหัวข้อการพิมพ์ผล)

## อ่านข้อมูลให้ไว

`cin` แบบค่าเริ่มต้นต้อง sync กับ `scanf`/`printf` ของภาษา C ตลอดเวลา และทุกครั้งที่อ่านมันจะ flush `cout` ให้ก่อน ซึ่งเสียเวลาเปล่าในงานแข่งขัน สองบรรทัดนี้ปิดทั้งสองอย่าง

```cpp
ios::sync_with_stdio(false);  // เลิก sync กับ stdio ของภาษา C
cin.tie(nullptr);             // ไม่ต้อง flush cout ก่อนอ่าน cin ทุกครั้ง
```

ลองวัดในเครื่องที่ compile แบบเดียวกับ judge ดู: อ่านจำนวนเต็ม $10^6$ ตัว แบบค่าเริ่มต้นใช้ราว 250–450 ms แต่พอเปิดสองบรรทัดนี้เหลือราว 90–150 ms เร็วขึ้นประมาณสามเท่า โดยไม่ต้องเปลี่ยนโค้ดส่วนอื่นเลย

:::warning ห้ามใช้ cin ปนกับ scanf
พอสั่ง `sync_with_stdio(false)` แล้ว `cin`/`cout` กับ `scanf`/`printf` จะมี buffer แยกกัน ถ้าใช้ปนกันในโปรแกรมเดียว ลำดับของข้อมูลจะสลับกันมั่ว เลือกใช้ชุดเดียวไปทั้งโปรแกรม
:::

### อ่านจนจบไฟล์

บางโจทย์ไม่บอกว่ามีข้อมูลกี่ตัว ให้อ่านไปจนหมด ท่ามาตรฐานคือใช้ `cin >> x` เป็นเงื่อนไขของ `while` เพราะมันจะเป็นเท็จเมื่ออ่านไม่สำเร็จ (ซึ่งก็คือตอนจบไฟล์)

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
  ios::sync_with_stdio(false);
  cin.tie(nullptr);
  long long x, best = LLONG_MIN;
  int count = 0;
  while (cin >> x) {      // หยุดเองเมื่ออ่านไม่ได้แล้ว
    count++;
    best = max(best, x);
  }
  cout << count << ' ' << best << '\n';
}
```

ตัวอย่างนี้นับว่ามีกี่ตัวและหาค่ามากที่สุด `cin >>` ข้ามช่องว่างและการขึ้นบรรทัดใหม่ให้เอง ข้อมูลจะกระจายอยู่กี่บรรทัดก็ไม่เป็นไร

:::problem lp_gs01_piggy_bank

:::hint ใบ้ Piggy Bank
ท่าอ่านจนจบไฟล์ข้างบนใช้ได้ตรง ๆ เลย เหลือแค่คิดว่า "เงินรวม" ควรเก็บในชนิดอะไร ลองดูตัวอย่างที่ 2 ของโจทย์ แล้วอ่านหัวข้อถัดไปก่อนส่ง
:::

ถ้าต้องอ่านทั้งบรรทัด (เช่น ข้อความที่มีช่องว่าง) ใช้ `getline(cin, s)` แต่ระวัง: ถ้าก่อนหน้านั้นอ่านด้วย `cin >> n` จะมี `'\n'` ค้างอยู่ `getline` ครั้งแรกจะได้สตริงว่าง ให้เรียก `cin.ignore()` หนึ่งครั้งก่อน

## เลือกชนิดข้อมูล: int หรือ long long

| ชนิด | ขนาด | ช่วงค่าโดยประมาณ |
|---|---|---|
| `int` | 4 bytes | $\pm 2.1 \times 10^9$ |
| `long long` | 8 bytes | $\pm 9.2 \times 10^{18}$ |
| `unsigned long long` | 8 bytes | $0$ ถึง $1.8 \times 10^{19}$ |
| `double` | 8 bytes | ทศนิยม แม่นราว 15–16 หลัก |

กฎง่าย ๆ: **ค่าที่รับมาอยู่ใน `int` ได้ ไม่ได้แปลว่าผลลัพธ์จะอยู่ได้** ถ้า $a_i \le 10^9$ และมี $10^5$ ตัว ผลรวมอาจถึง $10^{14}$ ซึ่งต้องใช้ `long long` ถ้าไม่แน่ใจ ให้ประมาณค่าที่ใหญ่ที่สุดที่เป็นไปได้ก่อนเสมอ

### ทำไม overflow บน judge ถึงเป็น Runtime Error

judge นี้ compile C++ ด้วย

```text
g++ -std=c++20 -fsanitize=signed-integer-overflow -fno-sanitize-recover=signed-integer-overflow
```

แปลว่าทันทีที่จำนวนเต็มแบบมีเครื่องหมาย (`int`, `long long`) ล้น โปรแกรมจะถูกหยุดและได้ **Runtime Error** ทันที **แม้คำตอบสุดท้ายจะดูเหมือนถูก** เช่น ผลรวมระหว่างทางล้นไปแล้วล้นกลับมาเป็นค่าที่ถูกพอดี เครื่องอื่นอาจให้ผ่าน แต่ judge นี้ไม่ให้ ข้อดีคือเราจะรู้ทันทีว่าโค้ดมีจุดล้น แทนที่จะได้ Wrong Answer แบบงง ๆ

ส่วน `unsigned` ล้นได้ตามปกติ (วนกลับไปที่ $0$) ไม่ถือเป็นข้อผิดพลาด

### กับดักของการคูณ

```cpp
int a = 100000, b = 100000;
long long c = a * b;          // ผิด: a * b คำนวณเป็น int ก่อน แล้วล้น
long long d = 1LL * a * b;    // ถูก: แปลงเป็น long long ก่อนคูณ
```

การเก็บผลลัพธ์ใน `long long` ไม่ช่วยอะไร ถ้าตัวการคูณเองยังเป็น `int` ต้องให้ตัวตั้งตัวใดตัวหนึ่งเป็น `long long` ตั้งแต่แรก

### ตอบเป็นเศษจากการหาร

เมื่อคำตอบใหญ่เกินจะเก็บได้ โจทย์มักขอ "เศษจากการหารด้วย $10^9 + 7$" หลักคือ **mod ทุกขั้น** เพราะ

$$(a + b) \bmod P = \big((a \bmod P) + (b \bmod P)\big) \bmod P$$

$$(a \times b) \bmod P = \big((a \bmod P) \times (b \bmod P)\big) \bmod P$$

ถ้าทั้งสองตัวน้อยกว่า $P \approx 10^9$ ผลคูณจะน้อยกว่า $10^{18}$ ซึ่ง `long long` เก็บได้สบาย ตัวอย่างนี้หา $N! \bmod (10^9 + 7)$

```cpp
#include <bits/stdc++.h>
using namespace std;

const long long MOD = 1000000007LL;

int main() {
  int n;
  cin >> n;
  long long f = 1;
  for (int i = 1; i <= n; i++)
    f = f * i % MOD;      // f < MOD และ i <= n ผลคูณจึงไม่ล้น
  cout << f << '\n';
}
```

:::problem lp_gs03_mod_product

:::hint ใบ้ Sum and Product Modulo
ข้อนี้ $a_i$ ใหญ่ได้ถึง $10^{18}$ ซึ่งมากกว่า $P$ มาก ถ้าเอา $a_i$ ไปคูณตรง ๆ ก็ล้นแน่นอน ต้อง mod ตัว $a_i$ ก่อนใช้ และผลบวกก็เหมือนกัน แค่บวก $10^{18}$ สิบตัวก็เกิน `long long` แล้ว อย่าลืมกรณีที่มี $a_i$ หารด้วย $P$ ลงตัวด้วย
:::

## พิมพ์ผลให้ตรงรูปแบบ

judge เทียบผลลัพธ์ทีละบรรทัด (ช่องว่างท้ายบรรทัดไม่นับ) ดังนั้น `73.67` กับ `73.6667` คือคำตอบคนละตัว

### ทศนิยมกี่ตำแหน่ง

```cpp
cout << fixed << setprecision(2);   // ตั้งครั้งเดียว มีผลกับทุก double ที่พิมพ์ต่อจากนี้
cout << 2.0 / 3 << '\n';            // 0.67
cout << 90.0 << '\n';               // 90.00
```

`fixed` บังคับให้พิมพ์แบบทศนิยมจุดตายตัว (ไม่ใช่ `1e+06`) และ `setprecision(2)` คือจำนวนหลักหลังจุด ถ้าใช้ `printf` ก็เขียน `printf("%.2f\n", x);` ได้ผลเหมือนกัน ส่วน Python ใช้ `f"{x:.2f}"`

### หารจำนวนเต็มได้จำนวนเต็ม

```cpp
int sum = 221, m = 3;
cout << sum / m << '\n';           // 73 ปัดทิ้งไปแล้วตั้งแต่ตอนหาร
cout << (double)sum / m << '\n';   // 73.67 (หลังตั้ง fixed << setprecision(2))
```

ถ้าทั้งสองตัวเป็นจำนวนเต็ม การหารจะตัดเศษทิ้งก่อนจะไปถึง `double` เสมอ ต้องแปลงตัวใดตัวหนึ่งเป็น `double` ก่อนหาร และควรเก็บผลรวมเป็นจำนวนเต็มไว้จนถึงตอนหารครั้งสุดท้าย จะได้ไม่มีความคลาดเคลื่อนสะสม

### '\n' หรือ endl

`endl` = ขึ้นบรรทัดใหม่ **แล้ว flush** คือสั่งให้เขียนข้อมูลออกไปจริงทันที ถ้าพิมพ์เป็นแสนบรรทัด การ flush ทุกบรรทัดจะช้ามาก ลองวัดพิมพ์ $10^6$ บรรทัด: `endl` ใช้ราว 450–600 ms ส่วน `'\n'` ใช้ราว 55 ms ช้ากว่ากันเกือบสิบเท่า ในงานแข่งขันใช้ `'\n'` เสมอ โปรแกรมจะ flush ให้เองตอนจบ

## ตัวอย่างเต็ม: สรุปอุณหภูมิ

โจทย์ข้างเคียง: รับ $N$ แล้วรับอุณหภูมิ $N$ ค่า (จำนวนเต็ม $|t_i| \le 10^9$) ให้พิมพ์ค่าต่ำสุด ค่าสูงสุด และค่าเฉลี่ยแบบทศนิยมหนึ่งตำแหน่ง

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
  ios::sync_with_stdio(false);
  cin.tie(nullptr);
  int n;
  cin >> n;
  long long lo = LLONG_MAX, hi = LLONG_MIN, sum = 0;  // sum ถึง 1e9 * n ได้
  for (int i = 0; i < n; i++) {
    long long t;
    cin >> t;
    lo = min(lo, t);
    hi = max(hi, t);
    sum += t;
  }
  cout << lo << ' ' << hi << '\n';
  cout << fixed << setprecision(1) << (double)sum / n << '\n';
}
```

สังเกตสามจุด: fast I/O, ผลรวมเป็น `long long`, และหารเป็น `double` ครั้งเดียวตอนพิมพ์ ข้อ Report Card ใช้ท่าเดียวกัน แค่มีหลายแถวและต้องการสองตำแหน่ง

:::problem lp_gs02_report_card

:::hint ใบ้ Report Card
ค่าเฉลี่ยของทั้งห้องไม่ใช่ค่าเฉลี่ยของค่าเฉลี่ยรายคนที่ปัดแล้ว ให้เก็บผลรวมคะแนนทั้งหมดเป็นจำนวนเต็มไว้ แล้วหารด้วย $N \times M$ ทีเดียวตอนท้าย
:::

## ถ้าเขียน Python

judge รับ Python ด้วย และให้เวลาเป็นสี่เท่าของ C++ จำนวนเต็มใน Python ไม่มีวันล้น เรื่อง `long long` จึงไม่ต้องห่วง แต่การอ่านทีละบรรทัดด้วย `input()` ช้า ท่าที่ไวกว่าคืออ่านทั้งไฟล์ทีเดียวแล้วแยกเป็นคำ

```python
import sys

data = sys.stdin.buffer.read().split()
n = int(data[0])
a = list(map(int, data[1:1 + n]))
print(sum(a))
```

ท่านี้ใช้กับ "อ่านจนจบไฟล์" ได้ด้วย เพราะ `data` คือทุกคำในไฟล์อยู่แล้ว

## ความเร็วของ I/O

การอ่านและพิมพ์ $K$ ค่าใช้เวลา $O(K)$ เสมอ แต่ค่าคงที่ต่างกันได้มาก จากตัวเลขที่วัดข้างบน fast I/O กับ `'\n'` ทำให้งาน I/O ล้วน ๆ เร็วขึ้นหลายเท่า เมื่อข้อมูลมีเป็นล้านตัว นั่นคือความต่างระหว่างผ่านกับ TLE ได้ บทถัดไปจะนับเวลาของตัวอัลกอริทึมเองอย่างเป็นระบบ

:::warning จุดที่พลาดบ่อย
* `a * b` ที่ทั้งคู่เป็น `int` ล้นก่อนจะถูกเก็บใน `long long` ใช้ `1LL * a * b`
* `sum / m` ที่เป็นจำนวนเต็มทั้งคู่ ตัดเศษทิ้งเงียบ ๆ แปลงเป็น `double` ก่อนหาร
* ลืม `fixed` ทำให้ `setprecision(2)` กลายเป็น "สองหลักสำคัญ" และพิมพ์ `74` แทน `73.67`
* ใช้ `scanf` ปนกับ `cin` หลังปิด sync
* `endl` ในลูปที่พิมพ์เป็นแสนบรรทัด
* `pow(a, b)` คืนค่าเป็น `double` ถ้าจะยกกำลังจำนวนเต็มให้คูณเอง ไม่งั้นอาจได้ค่าคลาดไปหนึ่ง
:::

## สรุปสั้น ๆ

* เปิดทุกไฟล์ด้วย template: `bits/stdc++.h`, `ios::sync_with_stdio(false); cin.tie(nullptr);`
* อ่านจนจบไฟล์ด้วย `while (cin >> x)`
* ประเมินค่าที่ใหญ่ที่สุดก่อนเลือกชนิด ผลรวมหรือผลคูณที่อาจเกิน $2 \times 10^9$ ใช้ `long long` และบน judge นี้ overflow = Runtime Error
* โจทย์ mod: mod ทุกขั้น และ mod ค่าที่รับมาก่อนคูณ
* ทศนิยม: `fixed << setprecision(k)` และหารเป็น `double` ครั้งเดียวตอนท้าย
* จบบรรทัดด้วย `'\n'` ไม่ใช่ `endl`
