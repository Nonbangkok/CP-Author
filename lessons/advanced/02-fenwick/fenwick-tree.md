## ผลรวมช่วงที่ข้อมูลเปลี่ยนได้

จำ prefix sum จากบท Time & Space Complexity ได้ไหม เก็บ `pre[i]` = $a_1 + \cdots + a_i$ แล้วผลรวมช่วง $[l, r]$ คือ `pre[r] - pre[l - 1]` ตอบได้ใน $O(1)$ สวยมาก **ตราบใดที่อาเรย์ไม่เปลี่ยน**

ทีนี้ถ้าโจทย์สลับกันระหว่าง "แก้ $a_i$" กับ "ถามผลรวม $[l, r]$" เป็นแสนครั้งล่ะ

| วิธี | แก้ $a_i$ | ถามผลรวม $[l, r]$ |
|---|---|---|
| อาเรย์ธรรมดา | $O(1)$ | $O(N)$ ไล่บวกทีละตัว |
| prefix sum | $O(N)$ ต้องแก้ `pre[i..N]` ทั้งหมด | $O(1)$ |
| **Fenwick tree** | $O(\log N)$ | $O(\log N)$ |

สองวิธีแรกเร็วด้านหนึ่งแต่ช้าอีกด้าน ถ้ามี $Q$ คำสั่งปนกันก็ได้ $O(NQ)$ อยู่ดี **Fenwick tree** (หรือ **Binary Indexed Tree, BIT**) ยอมช้าลงนิดหน่อยทั้งสองด้าน เหลือ $O(\log N)$ ทั้งคู่ โค้ดสั้นแค่สิบกว่าบรรทัด และเป็นโครงสร้างข้อมูลที่ใช้คุ้มที่สุดตัวหนึ่งในการแข่ง

## หัวใจ: lowbit

ทุกอย่างเริ่มจากฟังก์ชันเดียว: **lowbit** ของ $i$ คือค่าของบิต $1$ ที่อยู่ขวาสุดของ $i$

| $i$ | ฐานสอง | lowbit |
|---|---|---|
| $6$ | `0110` | `0010` = $2$ |
| $8$ | `1000` | `1000` = $8$ |
| $12$ | `1100` | `0100` = $4$ |
| $7$ | `0111` | `0001` = $1$ |

ในภาษา C++ (และ Python) หาได้ด้วย `i & -i` เพราะจำนวนลบเก็บแบบ two's complement: `-i` คือ `~i + 1` ซึ่งกลับทุกบิตแล้วบวกหนึ่ง บิตทางขวาของ lowbit ที่เป็น $0$ จะกลายเป็น $1$ แล้วการบวกหนึ่งทดกลับเป็น $0$ หมด จนไปหยุดที่ตำแหน่ง lowbit พอดี ส่วนบิตทางซ้ายถูกกลับหมด เลยเหลือบิตเดียวที่ตรงกันทั้งสองฝั่ง

```text
 i  =  12  =  0000 1100
-i  = -12  =  1111 0100
 i & -i    =  0000 0100  =  4
```

(ถ้ายังไม่คล่องเรื่องบิต ย้อนไปดูบท Bitmasks ได้ ใช้ `&` ตัวเดียวกันเลย)

## แต่ละช่องเก็บผลรวมของช่วงหนึ่ง

Fenwick tree คืออาเรย์ `t[1..N]` ขนาดเท่าเดิม โดย **`t[i]` เก็บผลรวมของช่วง $(i - \text{lowbit}(i),\ i]$** คือช่วงยาว lowbit$(i)$ ที่ **จบที่ $i$ พอดี**

```text
index :  1   2   3   4   5   6   7   8
t[8]  : [=============================]   ครอบ (0, 8]  lowbit = 8
t[4]  : [=============]                   ครอบ (0, 4]  lowbit = 4
t[2]  : [=====]                           ครอบ (0, 2]  lowbit = 2
t[6]  :                 [=====]           ครอบ (4, 6]  lowbit = 2
t[1]  : [=]                               ครอบ (0, 1]  lowbit = 1
t[3]  :         [=]                       ครอบ (2, 3]  lowbit = 1
t[5]  :                 [=]               ครอบ (4, 5]  lowbit = 1
t[7]  :                         [=]       ครอบ (6, 7]  lowbit = 1
```

เลขคี่ครอบตัวเองตัวเดียว เลขคู่ครอบยาวขึ้นตามจำนวน $0$ ท้ายเลข ช่วงพวกนี้ซ้อนกันเป็นชั้น ๆ คล้ายต้นไม้ (เลยได้ชื่อว่า tree ทั้งที่เก็บเป็นอาเรย์ธรรมดา)

### ถาม prefix: กระโดดลงด้วย `i -= i & -i`

อยากได้ $a_1 + \cdots + a_i$ ให้เริ่มที่ `t[i]` ซึ่งครอบ $(i - \text{lowbit}(i), i]$ ส่วนที่ยังขาดคือ $(0, i - \text{lowbit}(i)]$ ก็กระโดดไปที่ $i - \text{lowbit}(i)$ แล้วทำซ้ำจนถึง $0$

ทุกครั้งที่กระโดด บิต $1$ ขวาสุดหายไปหนึ่งบิต ตัวเลขไม่เกิน $N$ มีบิต $1$ ไม่เกิน $\lfloor \log_2 N \rfloor + 1$ บิต จึงกระโดดไม่เกิน $O(\log N)$ ครั้ง

```text
prefix(7):  7 = 0111  ->  t[7] ครอบ (6, 7]
            6 = 0110  ->  t[6] ครอบ (4, 6]
            4 = 0100  ->  t[4] ครอบ (0, 4]
            0          หยุด      รวมได้ (0, 7] พอดี
```

### แก้ค่า: กระโดดขึ้นด้วย `i += i & -i`

ถ้า $a_p$ เพิ่มขึ้น $\delta$ ทุก `t[i]` ที่ช่วงของมันครอบ $p$ ต้องเพิ่ม $\delta$ ด้วย ช่องพวกนั้นคือ $p$, แล้ว $p + \text{lowbit}(p)$, แล้วบวก lowbit ต่อไปเรื่อย ๆ จนเกิน $N$ (ดูจากรูป: ช่องที่ครอบตำแหน่ง $3$ คือ `t[3]`, `t[4]`, `t[8]` และ $3 \to 4 \to 8$ ก็คือการบวก lowbit พอดี) การบวก lowbit ทำให้บิต $1$ ขวาสุดขยับไปทางซ้ายอย่างน้อยหนึ่งตำแหน่งทุกครั้ง จึงเป็น $O(\log N)$ ครั้งเหมือนกัน

ไม่ต้องพิสูจน์เองตอนแข่งก็ได้ จำแค่ว่า **ถามลง (`-=`) แก้ขึ้น (`+=`)**

## Template: point update + range sum

:::tabs
```cpp
#include <bits/stdc++.h>
using namespace std;

// Fenwick tree (Binary Indexed Tree), ตำแหน่ง 1..n
struct Fenwick {
  int n;
  vector<long long> t;
  Fenwick(int n) : n(n), t(n + 1, 0) {}

  void add(int i, long long delta) {      // a[i] += delta
    for (; i <= n; i += i & -i) t[i] += delta;
  }
  long long prefix(int i) const {         // a[1] + ... + a[i]
    long long s = 0;
    for (; i > 0; i -= i & -i) s += t[i];
    return s;
  }
  long long rangeSum(int l, int r) const { // a[l] + ... + a[r]
    return prefix(r) - prefix(l - 1);
  }
};

int main() {
  ios::sync_with_stdio(false);
  cin.tie(nullptr);
  int n, q;
  cin >> n >> q;
  Fenwick fw(n);
  for (int i = 1; i <= n; i++) {
    long long x;
    cin >> x;
    fw.add(i, x);                         // สร้างด้วยการ add ทีละตัว O(N log N)
  }
  while (q--) {
    int type;
    cin >> type;
    if (type == 1) {                      // 1 i d : a[i] += d
      int i;
      long long d;
      cin >> i >> d;
      fw.add(i, d);
    } else {                              // 2 l r : ถามผลรวม a[l..r]
      int l, r;
      cin >> l >> r;
      cout << fw.rangeSum(l, r) << '\n';
    }
  }
}
```
```python
import sys


def main() -> None:
    data = sys.stdin.buffer.read().split()
    n, q = int(data[0]), int(data[1])
    t = [0] * (n + 1)
    for i in range(1, n + 1):           # สร้างแบบ O(N): ส่งค่าขึ้นไปให้ "พ่อ" i + lowbit(i)
        t[i] += int(data[1 + i])
        j = i + (i & -i)
        if j <= n:
            t[j] += t[i]
    out = []
    pos = 2 + n
    for _ in range(q):
        typ, u, v = data[pos], int(data[pos + 1]), int(data[pos + 2])
        pos += 3
        if typ == b"1":                 # a[u] += v
            while u <= n:
                t[u] += v
                u += u & -u
        else:                           # ผลรวม a[u..v] = prefix(v) - prefix(u - 1)
            s = 0
            while v > 0:
                s += t[v]
                v -= v & -v
            u -= 1
            while u > 0:
                s -= t[u]
                u -= u & -u
            out.append(s)
    sys.stdout.write("\n".join(map(str, out)) + "\n")


main()
```

ฝั่ง Python เขียนแบบแบน ๆ: list ธรรมดา วน `while` ตรง ๆ ในลูปหลัก ไม่เรียกเมธอดของคลาสทุกครั้ง และอ่าน input ทีเดียวด้วย `sys.stdin.buffer.read().split()` Fenwick ใน Python ช้ากว่า C++ หลายสิบเท่า ทุกบรรทัดในลูปที่ตัดได้คือเวลาที่ได้คืน

ส่วนการสร้างแบบ $O(N)$ ในโค้ด Python ใช้ได้กับ C++ เหมือนกัน: ใส่ $a_i$ ลง `t[i]` แล้วส่ง `t[i]` ต่อให้ `t[i + lowbit(i)]` ซึ่งเป็นช่องที่เล็กที่สุดที่ครอบช่วงของ `t[i]` ไว้ ทำจาก $i = 1$ ขึ้นไป แต่ปกติ $N$ ครั้งของ `add` ก็เร็วพอแล้ว

### ลองไล่ด้วยมือ

`a = [5, 2, 9, 1, 4, 7, 3, 6]` ตามรูปข้างบน

| ช่อง | ครอบ | ค่า |
|---|---|---|
| `t[1]` | $a_1$ | $5$ |
| `t[2]` | $a_1 + a_2$ | $7$ |
| `t[3]` | $a_3$ | $9$ |
| `t[4]` | $a_1 + \cdots + a_4$ | $17$ |
| `t[5]` | $a_5$ | $4$ |
| `t[6]` | $a_5 + a_6$ | $11$ |
| `t[7]` | $a_7$ | $3$ |
| `t[8]` | $a_1 + \cdots + a_8$ | $37$ |

1. `2 1 7` ถามผลรวม $[1, 7]$ = `prefix(7) - prefix(0)` เดิน $7 \to 6 \to 4 \to 0$ ได้ $3 + 11 + 17 = 31$ ตรงกับ $5 + 2 + 9 + 1 + 4 + 7 + 3 = 31$
2. `1 3 5` ให้ $a_3$ เพิ่ม $5$ เดิน $3 \to 4 \to 8 \to 16$ (เกิน $8$ หยุด) ได้ `t[3] = 14`, `t[4] = 22`, `t[8] = 42`
3. `2 2 7` = `prefix(7) - prefix(1)` = $(3 + 11 + 22) - 5 = 31$ ตรงกับ $2 + 14 + 1 + 4 + 7 + 3 = 31$
4. `2 3 3` = `prefix(3) - prefix(2)` = $(14 + 7) - 7 = 14$ ถามช่วงยาวหนึ่งก็คือถามค่า $a_3$ นั่นเอง

input `8 4 / 5 2 9 1 4 7 3 6 / 2 1 7 / 1 3 5 / 2 2 7 / 2 3 3` โปรแกรมพิมพ์ `31`, `31`, `14`

:::problem lp_fw01_shelf_stock

:::hint ใบ้ Shelf Stock
คำสั่ง `1 i x` ไม่ได้บอกว่า "เพิ่ม $x$" แต่บอกว่า "ตอนนี้เป็น $x$" ส่วน Fenwick รู้จักแค่ `add` จะแปลงจาก "ตั้งค่าใหม่" เป็น "บวกเพิ่มเท่าไร" ได้ยังไง? ต้องรู้ค่าเดิมของชั้นนั้น เลยต้องเก็บอาเรย์ธรรมดาไว้ข้าง ๆ ด้วย ดูตัวอย่างที่ 2 ที่ตั้งค่าเดิมซ้ำสองครั้ง แล้วอย่าลืมว่าผลรวมเกิน $2^{31}$ ได้
:::

## Range update, point query: เล่นกับอาเรย์ผลต่าง

กลับด้านกันบ้าง: คราวนี้โจทย์สั่ง "บวก $x$ ให้ **ทุกตัว** ใน $[l, r]$" และถาม "ตอนนี้ $a_i$ เป็นเท่าไร" ไล่บวกทีละตัวก็ $O(N)$ ต่อคำสั่งอีกแล้ว

ทริกคือ **อาเรย์ผลต่าง (difference array)** $d_i = a_i - a_{i-1}$ (ให้ $a_0 = 0$) ซึ่งมีสมบัติสองข้อ

* $a_i = d_1 + d_2 + \cdots + d_i$ คือ $a_i$ เป็น **prefix sum ของ $d$**
* บวก $x$ ให้ $a_l, \ldots, a_r$ ทำให้ผลต่างเปลี่ยนแค่สองที่: $d_l$ เพิ่ม $x$ (ตัวที่ $l$ สูงกว่าเพื่อนทางซ้ายมากขึ้น) และ $d_{r+1}$ ลด $x$ (ตัวที่ $r + 1$ สูงกว่าเพื่อนทางซ้ายน้อยลง) ตรงกลางขยับขึ้นพร้อมกันทั้งแถบ ผลต่างจึงเท่าเดิม

```text
a      :  0   0   0   0   0   0
บวก 3 ให้ [2, 5]
a      :  0   3   3   3   3   0
d      :  0  +3   0   0   0  -3      (เปลี่ยนแค่ d[2] กับ d[6])
```

ถ้าทุกคำถามมาหลังคำสั่งบวกทั้งหมด ใช้อาเรย์ $d$ ธรรมดาแล้วทำ prefix sum รอบเดียวตอนจบก็พอ แต่ถ้าคำถามแทรกอยู่ระหว่างคำสั่ง ให้เก็บ $d$ ไว้ใน Fenwick: บวกช่วงคือ `add` สองครั้ง ถามค่าคือ `prefix` หนึ่งครั้ง ทั้งคู่ $O(\log N)$

### Template: range add + point query

```cpp
#include <bits/stdc++.h>
using namespace std;

// range add / point query: Fenwick เก็บอาเรย์ผลต่าง d
struct RangeAddFenwick {
  int n;
  vector<long long> t;
  RangeAddFenwick(int n) : n(n), t(n + 2, 0) {}   // n + 2 เพราะจะแตะตำแหน่ง r + 1 = n + 1

  void addAt(int i, long long delta) {
    for (; i <= n + 1; i += i & -i) t[i] += delta;
  }
  void rangeAdd(int l, int r, long long x) {      // a[l..r] += x
    addAt(l, x);
    addAt(r + 1, -x);
  }
  long long pointQuery(int i) const {             // a[i] = d[1] + ... + d[i]
    long long s = 0;
    for (; i > 0; i -= i & -i) s += t[i];
    return s;
  }
};

int main() {
  RangeAddFenwick fw(6);          // a = [0, 0, 0, 0, 0, 0]
  fw.rangeAdd(2, 5, 3);           // a = [0, 3, 3, 3, 3, 0]
  fw.rangeAdd(4, 6, 10);          // a = [0, 3, 3, 13, 13, 10]
  for (int i = 1; i <= 6; i++) cout << fw.pointQuery(i) << (i < 6 ? ' ' : '\n');
}
```

โปรแกรมพิมพ์ `0 3 3 13 13 10` ลองไล่ `pointQuery(4)` ดู: ในต้นไม้ของ $d$ มี $d_2 = 3$, $d_4 = 10$, $d_6 = -3$ และ $d_7 = -10$ ส่วน prefix ถึง $4$ เดิน $4 \to 0$ ได้แค่ `t[4]` ซึ่งครอบ $d_1 + d_2 + d_3 + d_4 = 0 + 3 + 0 + 10 = 13$ ถูกต้อง (ตำแหน่ง $7$ คือ $r + 1$ ของคำสั่งที่สอง เลยต้องจองไว้ถึง $n + 1$)

:::problem lp_fw02_bonus_points

:::hint ใบ้ Bonus Points
ตอนเริ่มทุกคนมีคะแนน $a_i$ ไม่ใช่ $0$ มีสองทาง: เก็บ $a_i$ ไว้ในอาเรย์ธรรมดาแล้วให้ Fenwick เก็บแค่ "ส่วนที่บวกเพิ่ม" (คำตอบคือ $a_i$ บวก prefix) หรือใส่ $a_i - a_{i-1}$ ลง Fenwick ตั้งแต่ต้น แบบแรกง่ายกว่า ระวังคะแนนที่บวกหรือหักสะสมได้เกิน $2^{31}$ ทั้งสองทิศ
:::

:::note ถ้าอยากได้ทั้ง range add และ range sum
ใช้ Fenwick สองต้นก็ได้ จาก $a_j = \sum_{k \leq j} d_k$ จะได้ $\sum_{j=1}^{i} a_j = (i + 1) \sum_{k \leq i} d_k - \sum_{k \leq i} k \cdot d_k$ ต้นหนึ่งเก็บ $d_k$ อีกต้นเก็บ $k \cdot d_k$ แต่ถ้าการอัปเดตซับซ้อนกว่านี้ (เช่น ตั้งค่าทั้งช่วง หรือถามค่ามากสุด) ไปใช้ segment tree แบบ lazy ในบทถัดไปจะสบายกว่า
:::

## Fenwick บนค่า: นับว่ามีกี่ตัวที่น้อยกว่า

ตำแหน่งใน Fenwick ไม่จำเป็นต้องเป็นตำแหน่งในอาเรย์ ให้มันเป็น **ค่า** แทนก็ได้: `t` นับว่า "ค่า $v$ ถูกใส่เข้ามากี่ครั้ง" ใส่ค่า $v$ คือ `add(v, 1)` และ `prefix(v - 1)` คือจำนวนค่าที่ **น้อยกว่า $v$** ที่ใส่ไปแล้ว เช่น นับว่าก่อนหน้าตำแหน่ง $i$ มีกี่ตัวที่น้อยกว่า $a_i$:

```cpp
// a[] ย่อค่าเป็น 1..m แล้ว, Fenwick มีขนาด m
for (int i = 0; i < n; i++) {
  smaller[i] = prefix(a[i] - 1);   // ค่าที่ใส่ไปแล้วและน้อยกว่า a[i]
  add(a[i], 1);                    // แล้วค่อยใส่ a[i]
}
```

ค่ามักใหญ่ถึง $10^9$ ทำ Fenwick ขนาดนั้นไม่ได้ ก็ **ย่อค่า (coordinate compression)** ก่อนเหมือนในบท Containers & Sorting: เรียงค่าที่ไม่ซ้ำ แล้วแทนแต่ละค่าด้วยลำดับของมัน $1$ ถึง $m$ (ถ้าค่ามาทีหลังระหว่างคำสั่ง ให้อ่าน input ทั้งหมดก่อนแล้วย่อทุกค่าพร้อมกัน) ใครยังจำโจทย์ Taller in Front ในบท Divide and Conquer ได้ ลองกลับไปแก้ด้วยท่านี้แทน merge sort เป็นแบบฝึกหัดดู ได้ $O(N \log N)$ เท่ากัน

### หาตัวที่ $k$ ด้วยการไต่ลงต้นไม้

เมื่อ `t` นับจำนวนค่า คำถาม "ค่าที่น้อยเป็นอันดับ $k$ คืออะไร" ก็คือหาตำแหน่ง $p$ ที่เล็กที่สุดที่ `prefix(p)` $\geq k$ จะ binary search บน `prefix` ก็ได้แต่เป็น $O(\log^2 N)$ มีวิธีที่เร็วกว่าคือไต่ลงทีละบิต (คล้าย binary lifting ในบท LCA)

เริ่ม `pos = 0` แล้วลอง `step` เป็นกำลังสองจากใหญ่ไปเล็ก ตอนที่ `pos` มีแต่บิตที่ใหญ่กว่า `step` ช่อง `t[pos + step]` ครอบ $(pos, pos + step]$ พอดี ถ้าผลรวมในช่วงนั้นยัง **น้อยกว่า $k$** แปลว่าคำตอบอยู่ทางขวา ก็ข้ามไปทั้งช่วงแล้วหักจำนวนออกจาก $k$ จบแล้วคำตอบคือ `pos + 1` ใช้แค่ $O(\log N)$ (ใช้ได้เมื่อทุกช่องไม่ติดลบ ซึ่งการนับจำนวนเป็นแบบนั้นอยู่แล้ว)

### Template: median ตัวล่างหลังใส่ค่าแต่ละตัว

```cpp
#include <bits/stdc++.h>
using namespace std;

int m, LOG;           // m = จำนวนค่าหลังย่อ, LOG = 2 ยกกำลังที่มากที่สุดที่ไม่เกิน m
vector<int> t;        // t นับจำนวน "ครั้งที่เจอค่า" ไม่ใช่ผลรวมของค่า

void add(int i, int delta) {
  for (; i <= m; i += i & -i) t[i] += delta;
}

// ตำแหน่ง p ที่เล็กที่สุดที่ prefix(p) >= k (ต้องมี 1 <= k <= จำนวนทั้งหมด)
int kth(int k) {
  int pos = 0;
  for (int step = LOG; step > 0; step >>= 1) {
    if (pos + step <= m && t[pos + step] < k) {
      pos += step;
      k -= t[pos];
    }
  }
  return pos + 1;
}

int main() {
  ios::sync_with_stdio(false);
  cin.tie(nullptr);
  int n;
  cin >> n;
  vector<int> a(n);
  for (int &x : a) cin >> x;

  // ย่อค่า: vals[0..m-1] เรียงจากน้อยไปมาก ค่า vals[p - 1] อยู่ที่ตำแหน่ง p ของ Fenwick
  vector<int> vals(a);
  sort(vals.begin(), vals.end());
  vals.erase(unique(vals.begin(), vals.end()), vals.end());
  m = vals.size();
  LOG = 1;
  while (LOG * 2 <= m) LOG *= 2;
  t.assign(m + 1, 0);

  for (int i = 0; i < n; i++) {
    int p = lower_bound(vals.begin(), vals.end(), a[i]) - vals.begin() + 1;
    add(p, 1);                                   // ใส่ a[i] ลงใน multiset
    int k = (i + 2) / 2;                         // มี i + 1 ตัว: median ตัวล่างคือตัวที่ (i + 2) / 2
    cout << vals[kth(k) - 1] << (i + 1 < n ? ' ' : '\n');
  }
}
```

input `5 / 5 1 9 1 7` ได้ `5 1 5 1 5`: หลังใส่ครบห้าตัว multiset คือ $\{1, 1, 5, 7, 9\}$ ตัวที่ $3$ คือ $5$ ลองไล่ `kth(3)` ตอนนั้น: ค่าที่ย่อแล้วคือ $1 \to 1$, $5 \to 2$, $7 \to 3$, $9 \to 4$ จำนวนคือ `[2, 1, 1, 1]` ได้ `t[1] = 2`, `t[2] = 3`, `t[3] = 1`, `t[4] = 5` และ `LOG = 4`

| `step` | ลองช่อง | ค่าในช่อง | `< k`? | `pos` | `k` |
|---|---|---|---|---|---|
| $4$ | `t[4]` | $5$ | ไม่ | $0$ | $3$ |
| $2$ | `t[2]` | $3$ | ไม่ | $0$ | $3$ |
| $1$ | `t[1]` | $2$ | ใช่ | $1$ | $1$ |

คำตอบคือ `pos + 1 = 2` คือค่า $5$ ถ้าจะลบค่าออกจาก multiset ก็แค่ `add(p, -1)`

## ตอบคำถามแบบ offline

บางโจทย์ให้คำถามทั้งหมดมาตั้งแต่แรก ไม่มีการแก้ข้อมูลเลย แต่คำถามแต่ละข้อยากเกินจะตอบตรง ๆ ทริกที่ใช้บ่อยคู่กับ Fenwick คือ **เรียงคำถามใหม่** (เช่น ตามปลายขวา $r$) แล้วกวาดไปทางขวาทีละตำแหน่ง ระหว่างกวาดก็ `add` ข้อมูลของตำแหน่งที่ผ่านมา พอถึงปลายขวาของคำถามข้อไหนก็ตอบข้อนั้นด้วย `prefix` แล้วเก็บคำตอบตามหมายเลขเดิม ค่อยพิมพ์ตามลำดับเดิมตอนจบ เหมือนคำถามแบบ offline ในบท Sweep Line นั่นเอง ต่างกันแค่ตอนนี้ของที่เก็บระหว่างกวาดคือ Fenwick

ความยากอยู่ที่ต้องคิดว่า "ตอนกวาดมาถึง $r$ ควรมีเลขอะไรวางอยู่ที่ตำแหน่งไหน ถึงจะให้ผลรวม $[l, r]$ เป็นคำตอบพอดี"

:::problem lp_fw03_bird_species

:::hint ใบ้ Bird Species (1)
ลองคิดแค่คำถามที่ $r$ เท่ากันหมดก่อน นกชนิดหนึ่งอยู่ใน $[l, r]$ ก็ต่อเมื่อ **จุดสุดท้ายที่เจอมันไม่เกิน $r$** อยู่ที่ $l$ หรือหลังจากนั้น ถ้าวางเลข $1$ ไว้เฉพาะที่จุดสุดท้ายของแต่ละชนิด (นับถึง $r$) แล้วผลรวมของ $[l, r]$ คืออะไร?
:::

:::hint ใบ้ Bird Species (2)
เรียงคำถามตาม $r$ แล้วกวาด $r$ ไปทางขวา เมื่อเจอนกชนิดที่เคยเจอแล้ว เลข $1$ ของชนิดนั้นต้อง **ย้าย** จากจุดเก่ามาที่จุดใหม่ (ลบหนึ่งที่เก่า บวกหนึ่งที่ใหม่) ต้องจำจุดล่าสุดของแต่ละชนิด รหัสใหญ่ถึง $10^9$ ก็ย่อค่าก่อน หรือใช้ `map` / dict
:::

## ความซับซ้อน

| งาน | เวลา |
|---|---|
| สร้างจาก $N$ ค่า | $O(N \log N)$ ด้วย `add` ทีละตัว หรือ $O(N)$ ด้วยการส่งค่าให้พ่อ |
| `add`, `prefix`, `rangeSum` | $O(\log N)$ |
| range add / point query | $O(\log N)$ (อัปเดต `add` สองครั้ง) |
| หาตัวที่ $k$ ด้วยการไต่ลง | $O(\log N)$ |

หน่วยความจำคืออาเรย์เดียวขนาด $N + 1$ เท่านั้น เล็กกว่า segment tree ที่ใช้ราว $2N$ ถึง $4N$ ช่อง และค่าคงที่ก็เล็กมาก

## จุดที่พลาดบ่อย

:::warning Fenwick เริ่มที่ 1 ไม่ใช่ 0
`0 & -0 = 0` ถ้าเรียก `add(0, x)` ลูป `i += i & -i` จะติดอยู่ที่ $0$ ตลอดกาล (โปรแกรมค้างจน TLE) ถ้าข้อมูลเป็น 0-indexed ให้ $+1$ ก่อนส่งเข้า Fenwick ทุกครั้ง และ `prefix(l - 1)` เมื่อ $l = 1$ ก็คือ `prefix(0) = 0` ซึ่งถูกต้องอยู่แล้ว
:::

:::warning ขนาดอาเรย์และตำแหน่ง r + 1
range add แตะตำแหน่ง $r + 1$ ซึ่งอาจเป็น $N + 1$ จะจองถึง $N + 1$ (แบบ template) หรือข้ามการ `add` เมื่อ $r + 1 > N$ ก็ได้ แค่อย่าเขียนเลยขอบอาเรย์ ส่วน Fenwick บนค่าต้องมีขนาดเท่าจำนวนค่า **หลังย่อ** ไม่ใช่ $N$
:::

:::warning long long
ผลรวมของ $10^5$ ค่าที่ใหญ่ถึง $10^9$ เกิน `int` แน่นอน ให้ `t` เป็น `long long` ตั้งแต่แรก (ยกเว้นตอนนับจำนวน ซึ่ง `int` พอ)
:::

:::warning Fenwick รู้จักแค่ "บวกเพิ่ม"
ถ้าโจทย์สั่ง "ตั้ง $a_i$ เป็น $x$" ต้องแปลงเป็นการบวก $x - a_i$ เอง และต้องเก็บ $a_i$ ปัจจุบันไว้ข้างนอก Fenwick ส่วน "ค่ามากสุด / น้อยสุดในช่วง" ทำแบบนี้ไม่ได้เพราะลบออกไม่ได้ (ค่ามากสุดของ $[l, r]$ ไม่ใช่ผลต่างของ prefix สองตัว) งานแบบนั้นเป็นของ segment tree
:::

:::warning Python ช้า
ทุกรอบของ `while` ใน Python ช้ากว่า C++ หลายสิบเท่า พอคูณ $\log N$ คูณจำนวนคำสั่งแล้วเยอะกว่าที่คิด เขียนลูปตรง ๆ บน list อ่าน input ทีเดียว และรวบคำตอบไว้พิมพ์ด้วย `"\n".join(...)` ครั้งเดียว
:::

## สรุปสั้น ๆ

* Fenwick tree ตอบ point update + prefix sum ใน $O(\log N)$ ด้วยอาเรย์ขนาด $N + 1$
* `t[i]` เก็บผลรวมของ $(i - \text{lowbit}(i), i]$ โดย lowbit คือ `i & -i`
* ถามลง `i -= i & -i` แก้ขึ้น `i += i & -i` และผลรวมช่วงคือ `prefix(r) - prefix(l - 1)`
* range add / point query: เก็บอาเรย์ผลต่างไว้ใน Fenwick, `add(l, x)` กับ `add(r + 1, -x)`
* Fenwick บนค่า (หลังย่อค่า) นับว่ามีกี่ตัวที่น้อยกว่า และไต่ลงทีละบิตเพื่อหาตัวที่ $k$ ได้ใน $O(\log N)$
* คำถามที่รู้ล่วงหน้าทั้งหมด ลองเรียงตาม $r$ แล้วกวาดไปพร้อม Fenwick
* เริ่มที่ 1 เสมอ ใช้ `long long` และจำไว้ว่า Fenwick ทำได้แค่ "บวกเพิ่ม" กับ "ลบออก"
