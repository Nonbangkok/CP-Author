## ต่อทุกเมืองให้ถึงกันด้วยราคาถูกที่สุด

สมมติมีเมือง $N$ เมือง และมีถนนที่ "สร้างได้" $M$ เส้น แต่ละเส้นมีราคา $w$ ของตัวเอง เราอยากเลือกสร้างบางเส้นให้ **ทุกเมืองไปถึงกันได้** (ตรง ๆ หรืออ้อมผ่านเมืองอื่นก็ได้) โดย **ราคารวมน้อยที่สุด** โจทย์หน้าตานี้โผล่บ่อยมาก จะเป็นเดินสายไฟ วางท่อ หรือต่อเครือข่ายก็คือเรื่องเดียวกัน

ลองนึกดูก่อนนะว่าคำตอบหน้าตาเป็นยังไง ถ้าชุดถนนที่เลือกมี **วง** อยู่ เราทุบเส้นไหนในวงทิ้งก็ได้ ทุกเมืองยังไปถึงกันเหมือนเดิม (อ้อมไปอีกทางของวง) แถมราคาลดลงด้วย (ราคาเป็นบวก) ดังนั้นคำตอบที่ดีที่สุด **ไม่มีวง** และต้องเชื่อมกันหมด ก็คือ **ต้นไม้** ที่ครอบทุกจุดนั่นเอง (จำจากบท Trees ได้ว่าต้นไม้ $N$ จุดมี $N - 1$ เส้นพอดี)

* **spanning tree** = ชุดเส้น $N - 1$ เส้นที่เชื่อมทุกจุดเข้าด้วยกันโดยไม่มีวง
* **minimum spanning tree (MST)** = spanning tree ที่ผลรวมน้ำหนักน้อยที่สุด

กราฟตัวอย่างที่จะใช้ทั้งบท ($N = 5$, $M = 7$)

```text
          4
    1 ---------- 2
     \          / \
    1 \      2 /   \ 5
       \      /     \
          3 -------- 4
           \   8    /
          6 \      / 3
             \    /
               5
```

MST ของกราฟนี้คือ `1-3`, `2-3`, `4-5`, `2-4` ราคารวม $1 + 2 + 3 + 5 = 11$ เดี๋ยวเราจะหามันด้วยสองวิธี คือ **Kruskal** และ **Prim** แต่ก่อนอื่นต้องรู้ก่อนว่าทำไมการเลือกแบบโลภ (greedy) ถึงไม่พลาด

## Cut property: หัวใจของทุกอัลกอริทึม MST

**แบ่งจุดทั้งหมดออกเป็นสองฝั่งยังไงก็ได้** (ขอแค่ไม่มีฝั่งไหนว่าง) แล้วดูเส้นที่ **ข้ามฝั่ง** เส้นที่ถูกที่สุดในบรรดาเส้นข้ามฝั่ง **อยู่ใน MST สักต้นเสมอ** และถ้ามันถูกที่สุดแบบไม่มีเส้นไหนราคาเท่า มันจะอยู่ใน **ทุก** MST

```text
     ฝั่ง A          |          ฝั่ง B
                     |
   1 ------ 2 ---(5)-|--- 4
     \     /         |    |
      \   /  ---(8)--|--- |
        3 -----(6)---|--- 5
                     |
 เส้นข้ามฝั่ง: 2-4 (5), 3-4 (8), 3-5 (6)  ->  ถูกสุดคือ 2-4 ต้องอยู่ใน MST
```

ทำไมถึงจริง? สมมติมี MST ต้นหนึ่ง $T$ ที่ไม่มีเส้นถูกสุด $e$ นี้ ลองเติม $e$ เข้าไปใน $T$ จะเกิดวงหนึ่งวงพอดี วงนี้เดินข้ามจากฝั่ง A ไป B ด้วย $e$ แล้วต้องเดินข้ามกลับมาอีกอย่างน้อยหนึ่งครั้ง ด้วยเส้น $f$ อีกเส้นที่ข้ามฝั่งเหมือนกัน เพราะ $e$ ถูกที่สุด $f$ จึงแพงกว่าหรือเท่ากับ $e$ ทุบ $f$ ทิ้ง ได้ spanning tree ใหม่ที่ราคาไม่แพงกว่าเดิม และมี $e$ อยู่ด้วย จบ

อีกด้านของเหรียญเดียวกันคือ **cycle property**: ในวงใดก็ตาม ถ้ามีเส้นหนึ่งที่ **แพงกว่าทุกเส้นที่เหลือในวงจริง ๆ** (ไม่มีใครเท่า) เส้นนั้นไม่อยู่ใน MST ใดเลย เพราะทุบมันทิ้งแล้วทุกจุดยังถึงกันผ่านส่วนที่เหลือของวง เก็บสองข้อนี้ไว้ในหัว เดี๋ยวได้ใช้ตอนท้ายบท

## Kruskal

### ไอเดีย

เรียงเส้นจาก **ถูกไปแพง** แล้วไล่ทีละเส้น

* ถ้าสองปลายของเส้นนี้ **ยังไปถึงกันไม่ได้** ด้วยเส้นที่หยิบมาแล้ว: หยิบเส้นนี้
* ถ้า **ไปถึงกันได้อยู่แล้ว**: ข้าม (หยิบแล้วจะเกิดวง)

หยิบครบ $N - 1$ เส้นเมื่อไหร่ก็เสร็จ

ทำไมถูก? ตอนพิจารณาเส้น $(u, v)$ ที่สองปลายยังอยู่คนละกลุ่ม ให้แบ่งฝั่งเป็น "กลุ่มของ $u$" กับ "ที่เหลือทั้งหมด" เส้นที่ถูกกว่านี้ที่เคยดูมาแล้ว ถ้าหยิบไปแล้วก็อยู่ในกลุ่มเดียวกัน ถ้าข้ามไปก็เพราะสองปลายอยู่กลุ่มเดียวกันอยู่แล้ว ไม่มีเส้นที่ถูกกว่าเส้นไหนข้ามฝั่งนี้เลย $(u, v)$ จึงเป็นเส้นข้ามฝั่งที่ถูกที่สุด cut property บอกว่าหยิบได้อย่างปลอดภัย

ส่วนที่ยากคือคำถาม "สองจุดนี้อยู่กลุ่มเดียวกันหรือยัง" ถ้าตอบด้วยการ DFS/BFS บนป่าที่สร้างมาทุกครั้ง จะเป็น $O(N)$ ต่อเส้น รวม $O(NM)$ ช้าเกินไป เราต้องการโครงสร้างข้อมูลที่ตอบได้แทบจะทันที

### DSU (Disjoint Set Union)

DSU (หรือ union-find) ดูแลจุดที่แบ่งเป็นกลุ่ม ๆ ไม่ทับกัน และทำได้สองอย่าง

* `find(x)`: บอกว่า `x` อยู่กลุ่มไหน (คืน "หัวหน้า" ของกลุ่ม) สองจุดอยู่กลุ่มเดียวกันก็ต่อเมื่อ `find` ได้หัวหน้าคนเดียวกัน
* `unite(a, b)`: รวมกลุ่มของ `a` กับกลุ่มของ `b` เป็นกลุ่มเดียว

แต่ละกลุ่มเก็บเป็นต้นไม้ โดยทุกจุดจำแค่ `parent[x]` (ใครอยู่เหนือตัวเอง) หัวหน้าคือจุดที่ `parent[x] == x` การ `find` ก็คือเดินขึ้นไปเรื่อย ๆ จนเจอหัวหน้า ส่วน `unite` ก็แค่เอาหัวหน้ากลุ่มหนึ่งไปเกาะใต้หัวหน้าอีกกลุ่ม

```text
กลุ่ม {1, 2, 3, 4} กับ {5, 6}

      1          5          parent[1] = 1   parent[5] = 5   <- หัวหน้า
     / \         |          parent[2] = 1   parent[6] = 5
    2   3        6          parent[3] = 1
        |                   parent[4] = 3
        4

find(4): 4 -> 3 -> 1   ได้หัวหน้า 1
unite(4, 6): หัวหน้า 1 กับ 5 ต่างกัน ให้ parent[5] = 1 (กลุ่มเล็กไปเกาะกลุ่มใหญ่)
```

ถ้าทำแค่นี้ ต้นไม้อาจยาวเป็นเส้นตรง แล้ว `find` จะช้าเป็น $O(N)$ มีสองท่าที่แก้ได้ และควรใส่ **ทั้งสองท่า** เสมอ

1. **union by size**: เก็บขนาดของแต่ละกลุ่ม ตอนรวมให้หัวหน้า **กลุ่มเล็กไปเกาะกลุ่มใหญ่** จุดหนึ่งจะลึกขึ้นหนึ่งชั้นก็ต่อเมื่อกลุ่มของมันใหญ่ขึ้นอย่างน้อยเท่าตัว จึงลึกไม่เกิน $\log_2 N$ ชั้น
2. **path compression**: ระหว่าง `find(x)` เดินขึ้นไปเจอหัวหน้าแล้ว ให้ทุกจุดที่เดินผ่าน **ชี้ตรงไปหาหัวหน้าเลย** ครั้งหน้าจะได้ไม่ต้องเดินไกลอีก

```text
ก่อน find(4)        หลัง find(4)
      1                  1
      |                 / \
      3                3   4
      |
      4             (4 ชี้ไปหา 1 ตรง ๆ แล้ว)
```

ใช้ทั้งสองท่าพร้อมกัน แต่ละ operation เหลือ $O(\alpha(N))$ โดย $\alpha$ (inverse Ackermann) โตช้ามากจนไม่เกิน $4$ สำหรับ $N$ ทุกขนาดที่เจอจริง คิดว่าเป็น **ค่าคงที่** ไปได้เลย

### Template: Kruskal + DSU พิมพ์ราคารวมและหมายเลขเส้นที่เลือก

กราฟไม่มีทิศ $N$ จุด $M$ เส้น (รับประกันว่าเชื่อมกันหมด) พิมพ์ราคารวมของ MST แล้วตามด้วยหมายเลขเส้น (ตามลำดับใน input) ที่เลือก

```cpp
#include <bits/stdc++.h>
using namespace std;

struct DSU {
  vector<int> parent, sz;
  DSU(int n) : parent(n + 1), sz(n + 1, 1) {
    iota(parent.begin(), parent.end(), 0);       // ตอนแรกทุกจุดเป็นหัวหน้าของตัวเอง
  }
  int find(int x) {
    if (parent[x] == x) return x;
    return parent[x] = find(parent[x]);          // path compression: ชี้ตรงไปหาหัวหน้าเลย
  }
  bool unite(int a, int b) {
    a = find(a);
    b = find(b);
    if (a == b) return false;                    // อยู่กลุ่มเดียวกันแล้ว (ต่อแล้วจะเกิดวง)
    if (sz[a] < sz[b]) swap(a, b);               // union by size: กลุ่มเล็กไปเกาะกลุ่มใหญ่
    parent[b] = a;
    sz[a] += sz[b];
    return true;
  }
};

int main() {
  ios::sync_with_stdio(false);
  cin.tie(nullptr);
  int n, m;
  cin >> n >> m;
  vector<array<int, 4>> edges(m);                // {w, u, v, หมายเลขเส้น}
  for (int i = 0; i < m; i++) {
    cin >> edges[i][1] >> edges[i][2] >> edges[i][0];
    edges[i][3] = i + 1;
  }
  sort(edges.begin(), edges.end());              // เรียงจากถูกไปแพง (เทียบ w ก่อน)

  DSU dsu(n);
  long long total = 0;
  vector<int> chosen;
  for (auto [w, u, v, id] : edges) {
    if (dsu.unite(u, v)) {                       // คนละกลุ่ม: หยิบเส้นนี้
      total += w;
      chosen.push_back(id);
      if ((int)chosen.size() == n - 1) break;    // ครบ N - 1 เส้นแล้ว หยุดได้
    }
  }
  sort(chosen.begin(), chosen.end());
  cout << total << '\n';
  for (int id : chosen) cout << id << ' ';
  cout << '\n';
}
```

สองจุดที่ควรสังเกต: `w` ถูกวางไว้ช่องแรกของ `array` เพื่อให้ `sort` เรียงตามราคาโดยไม่ต้องเขียน comparator และ `unite` คืน `true` เฉพาะตอนที่รวมสองกลุ่มได้จริง เลยใช้เป็นทั้ง "เช็ก" และ "รวม" ในบรรทัดเดียว ส่วน `find` แบบ recursive ปลอดภัยใน C++ เพราะ union by size ทำให้ลึกไม่เกิน $\log_2 N$ ชั้น

## Prim

### ไอเดีย

Prim ปลูกต้นไม้ **จากจุดเดียว** แล้วค่อย ๆ ขยาย ทุกรอบให้หยิบ **เส้นที่ถูกที่สุดที่ต่อจากต้นไม้ออกไปหาจุดที่ยังไม่อยู่ในต้นไม้** ถ้ามองว่า "ต้นไม้ตอนนี้" เป็นฝั่ง A และ "ที่เหลือ" เป็นฝั่ง B นี่คือ cut property ตรง ๆ เลย ทุกเส้นที่หยิบจึงปลอดภัย

หน้าตาเหมือน Dijkstra จากบท Shortest Paths มาก ใช้ min-heap กับ lazy deletion แบบเดียวกัน ต่างกันแค่ **ค่าที่ใส่ใน heap** คือ **ราคาของเส้นเดียว** ไม่ใช่ระยะสะสมจากจุดเริ่ม

### Template: Prim กับ priority_queue

input แบบเดียวกับ Kruskal พิมพ์ราคารวม หรือ `DISCONNECTED` ถ้าต่อไม่ครบ

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
  ios::sync_with_stdio(false);
  cin.tie(nullptr);
  int n, m;
  cin >> n >> m;
  vector<vector<pair<int, int>>> adj(n + 1);     // adj[u] = {(v, w), ...}
  for (int i = 0; i < m; i++) {
    int u, v, w;
    cin >> u >> v >> w;
    adj[u].push_back({v, w});
    adj[v].push_back({u, w});
  }

  vector<char> inTree(n + 1, 0);
  // min-heap ของ (ราคาเส้นที่จะใช้ต่อ, จุด)
  priority_queue<pair<int, int>, vector<pair<int, int>>, greater<>> pq;
  pq.push({0, 1});                               // เริ่มที่จุด 1 ด้วยราคา 0
  long long total = 0;
  int added = 0;
  while (!pq.empty()) {
    auto [w, u] = pq.top();
    pq.pop();
    if (inTree[u]) continue;                     // อยู่ในต้นไม้แล้ว เป็นของเก่า ข้ามไป
    inTree[u] = 1;
    total += w;
    added++;
    for (auto [v, c] : adj[u])
      if (!inTree[v]) pq.push({c, v});           // เส้นที่ข้ามจากต้นไม้ออกไป
  }
  if (added < n) cout << "DISCONNECTED\n";
  else cout << total << '\n';
}
```

ไล่กับกราฟเดิม เริ่มที่จุด `1`

| pop | ทำอะไร | push | ราคารวม |
|---|---|---|---|
| `(0, 1)` | เพิ่มจุด `1` | `(4,2)` `(1,3)` | $0$ |
| `(1, 3)` | เพิ่มจุด `3` | `(2,2)` `(8,4)` `(6,5)` | $1$ |
| `(2, 2)` | เพิ่มจุด `2` | `(5,4)` | $3$ |
| `(4, 2)` | ข้าม (`2` อยู่ในต้นไม้แล้ว) | | $3$ |
| `(5, 4)` | เพิ่มจุด `4` | `(3,5)` | $8$ |
| `(3, 5)` | เพิ่มจุด `5` | | $11$ |

ที่เหลือใน heap คือ `(6,5)` กับ `(8,4)` ถูกข้ามทั้งคู่ ได้ $11$ เท่ากับ Kruskal แม้ลำดับที่หยิบเส้นจะต่างกัน ความซับซ้อน $O(M \log M)$ เท่ากับ Kruskal

### Prim แบบ $O(N^2)$ สำหรับกราฟหนาแน่น

ถ้ากราฟเป็น **กราฟสมบูรณ์** (ทุกคู่มีเส้น) เช่น "จุด $N$ จุดบนระนาบ ราคาเชื่อมคือระยะระหว่างจุด" จะมีเส้นถึง $N(N - 1)/2$ เส้น ถ้า $N = 5{,}000$ ก็ $1.25 \times 10^7$ เส้น Kruskal ต้องสร้างและเรียงทั้งหมด หนักทั้งเวลาและหน่วยความจำ

ทางที่ดีกว่าคือ Prim แบบไม่มี heap: เก็บ `key[v]` = ราคาเส้นที่ถูกที่สุดจากต้นไม้ไป `v` ทุกรอบไล่หา `v` ที่ `key` น้อยสุดด้วยลูปธรรมดา แล้วอัปเดต `key` ของจุดที่เหลือ รอบละ $O(N)$ รวม $O(N^2)$ โดยไม่ต้องเก็บเส้นไว้เลย (คำนวณราคาสด ๆ)

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
  ios::sync_with_stdio(false);
  cin.tie(nullptr);
  int n;
  cin >> n;
  vector<long long> x(n), y(n);
  for (int i = 0; i < n; i++) cin >> x[i] >> y[i];
  auto cost = [&](int a, int b) { return llabs(x[a] - x[b]) + llabs(y[a] - y[b]); };

  const long long INF = LLONG_MAX;
  vector<long long> key(n, INF);                 // key[v] = เส้นที่ถูกที่สุดจากต้นไม้ไป v
  vector<char> inTree(n, 0);
  key[0] = 0;
  long long total = 0;
  for (int step = 0; step < n; step++) {
    int u = -1;
    for (int v = 0; v < n; v++)                  // หาจุดนอกต้นไม้ที่ key น้อยที่สุด: O(N)
      if (!inTree[v] && (u == -1 || key[v] < key[u])) u = v;
    inTree[u] = 1;
    total += key[u];
    for (int v = 0; v < n; v++)                  // อัปเดต key ของทุกจุดที่เหลือ: O(N)
      if (!inTree[v]) key[v] = min(key[v], cost(u, v));
  }
  cout << total << '\n';
}
```

ลองกับจุด `(0,0)`, `(2,2)`, `(3,10)`, `(5,2)` (input คือ `4` แล้วตามด้วยพิกัดทีละบรรทัด) ราคาเป็นระยะแบบ Manhattan $|x_1 - x_2| + |y_1 - y_2|$ ได้ต้นไม้ `(2,2)-(5,2)` ราคา $3$, `(0,0)-(2,2)` ราคา $4$ และ `(2,2)-(3,10)` ราคา $9$ โปรแกรมพิมพ์ `16`

## Kruskal หรือ Prim?

| สถานการณ์ | เลือก | เวลา |
|---|---|---|
| ได้ edge list มา กราฟเบาบาง (ส่วนใหญ่ของโจทย์) | Kruskal + DSU | $O(M \log M)$ |
| ต้องการแค่ "กลุ่มไหนต่อกับกลุ่มไหน" หรือหยุดกลางทาง (ดูทริกด้านล่าง) | Kruskal + DSU | $O(M \log M)$ |
| มี adjacency list อยู่แล้ว อยากเขียนคล้าย Dijkstra | Prim + heap | $O(M \log M)$ |
| กราฟสมบูรณ์ ราคาคำนวณจากสูตร $N$ ไม่เกินหลักพัน | Prim $O(N^2)$ | $O(N^2)$ |

ในการแข่งจริง Kruskal + DSU เขียนสั้นที่สุดและพลาดยากที่สุด ใช้เป็นตัวหลักได้เลย ส่วน DSU เองก็เป็นเครื่องมือที่ใช้ได้อีกเยอะนอกเหนือจาก MST เช่นนับจำนวนกลุ่มขณะที่เส้นค่อย ๆ ถูกเพิ่มเข้ามา

## ทริกที่ใช้บ่อย

### เส้นที่บังคับใช้ หรือจุดที่ "ต่อถึงกันอยู่แล้ว"

บางโจทย์บอกว่ามีถนนบางเส้น **สร้างไว้แล้ว** (ฟรี) หรือบางเมือง **มีโรงไฟฟ้าอยู่แล้ว** และแค่ต้องให้ทุกเมืองต่อถึงโรงไฟฟ้าสักแห่ง ท่าคือ **`unite` ของที่ต่อกันอยู่แล้วก่อนเริ่มลูป** สำหรับโรงไฟฟ้า ให้ `unite` ทุกเมืองที่มีโรงไฟฟ้าเข้าด้วยกัน เหมือนว่าโรงไฟฟ้าทั้งหมดเป็นจุดเดียว (ต่อถึงโรงไหนก็ได้ไฟเหมือนกัน)

```cpp
DSU dsu(n);
for (int i = 1; i < (int)plants.size(); i++)
  dsu.unite(plants[0], plants[i]);               // โรงไฟฟ้าทุกโรงนับเป็นกลุ่มเดียวกันตั้งแต่ต้น
// จากนั้น Kruskal ตามปกติ: เส้นไหนต่อสองกลุ่มที่ต่างกันก็หยิบ
```

### แบ่งเป็น $K$ กลุ่ม

ถ้าโจทย์อยากให้เหลือ **$K$ กลุ่ม** แทนที่จะเชื่อมกันหมด ให้หยุด Kruskal ตอนหยิบได้ $N - K$ เส้น (แต่ละเส้นลดจำนวนกลุ่มลงหนึ่ง) ได้ราคารวมน้อยที่สุดของการแบ่งเป็น $K$ กลุ่ม แถมราคาของเส้นถัดไปที่ Kruskal **จะ** หยิบ คือระยะที่ใกล้ที่สุดระหว่างสองกลุ่มที่ต่างกัน ซึ่งมากที่สุดแล้วเมื่อเทียบกับทุกวิธีแบ่ง $K$ กลุ่ม ทริกนี้ใช้กับโจทย์จัดกลุ่ม (clustering) ได้

### เส้นที่แพงที่สุดบนทาง

เส้นทางระหว่าง $u$ กับ $v$ **บน MST** เป็นเส้นทางที่ทำให้ "เส้นที่แพงที่สุดที่ต้องผ่าน" น้อยที่สุดในบรรดาทุกเส้นทางของกราฟเดิม (เหตุผลมาจาก cycle property) ถ้าโจทย์ถามว่า "รถบรรทุกหนักได้มากสุดเท่าไร" หรือ "ต้องทนความชันมากสุดเท่าไร" ลองคิดถึง MST ก่อน แล้วค่อยตอบหลายคำถามด้วย binary lifting จากบท LCA

:::problem lp_mst02_village_wells

:::hint ใบ้ Village Wells
ถ้ามีแต่ท่อ ข้อนี้ก็คือ MST ธรรมดา ปัญหาคือการขุดบ่อไม่ใช่ "เส้น" ระหว่างสองหมู่บ้าน ลองถามตัวเองว่า ถ้าจะมองการขุดบ่อในหมู่บ้าน $i$ ราคา $c_i$ ให้เป็นเส้นเชื่อมไปยัง **อะไรสักอย่าง** ได้ไหม และสิ่งนั้นเกี่ยวอะไรกับทริกโรงไฟฟ้าข้างบน
:::

## เมื่อราคาซ้ำกัน: MST มีได้หลายต้น

ถ้าทุกเส้นราคาไม่ซ้ำกันเลย MST มีต้นเดียว แต่ถ้ามีราคาเท่ากัน อาจมีหลายต้น เช่นสี่เหลี่ยม `1-2-3-4-1` ที่ทุกเส้นราคา $1$ ทุบเส้นไหนทิ้งหนึ่งเส้นก็ได้ MST ทั้งนั้น (สี่ต้น)

```text
  1 --1-- 2
  |       |
  1       1        MST: ทุบทิ้งเส้นใดก็ได้หนึ่งเส้น
  |       |
  4 --1-- 3
```

สิ่งที่ **เหมือนกันทุกต้น** คือราคารวม และถ้าเอาราคาของเส้นในต้นมาเรียง ก็ได้ลำดับเดียวกันทุกต้น Kruskal เลือกต้นไหนขึ้นกับว่า `sort` วางเส้นราคาเท่ากันไว้ลำดับไหน ดังนั้นถ้าโจทย์ถามเรื่อง "เส้นนี้อยู่ใน MST ไหม" ต้องระวังมาก เพราะต้นที่โปรแกรมเราบังเอิญได้ ไม่ใช่ทุกต้นที่เป็นไปได้

:::problem lp_mst03_candidate_roads

:::hint ใบ้ Candidate Roads (1)
กลับไปดู cycle property: เส้น $(u, v, w)$ จะ **ไม่มีทาง** อยู่ใน MST ใดเลยเมื่อไร? ลองคิดในรูป "$u$ กับ $v$ ไปถึงกันได้ไหม ถ้าใช้แค่เส้นที่ ... กว่า $w$" แล้วเติมคำในช่องว่างให้ถูก (ระหว่าง "ถูกกว่า" กับ "ถูกกว่าหรือเท่ากับ" ต่างกันมาก)
:::

:::hint ใบ้ Candidate Roads (2)
ถ้าตอบคำถามข้อ (1) ด้วย BFS ใหม่ทุกเส้นจะช้าเกินไป แต่ Kruskal ก็เติมเส้นจากถูกไปแพงอยู่แล้ว ตอนที่ดูเส้นราคา $w$ DSU ควรมีเส้นชุดไหนอยู่ข้างในบ้าง? ลองนึกถึงสามเส้นราคาเท่ากันที่เป็นวงสามเหลี่ยม (ตัวอย่างที่ 1 ของโจทย์) แล้วดูว่าถ้า `unite` ไปทีละเส้นพร้อมกับตอบไปด้วย จะตอบผิดตรงไหน
:::

## จุดที่พลาดบ่อย

:::warning DSU ที่ไม่มีทั้งสองท่า
ไม่มี union by size และไม่มี path compression ต้นไม้ของ DSU ยาวเป็นเส้นได้ `find` กลายเป็น $O(N)$ ผ่านตัวอย่างแต่ TLE ตอนส่ง (แถม `find` แบบ recursive อาจลึกจน stack overflow) ใส่ทั้งสองท่าเป็นนิสัย
:::

:::warning รวมที่ปลาย ไม่ใช่ที่หัวหน้า
`parent[v] = u` ผิด ต้องหาหัวหน้าก่อน `a = find(u)`, `b = find(v)` แล้วค่อย `parent[b] = a` ถ้ารวมที่ปลาย กลุ่มเดิมของ `v` จะหลุดออกจากกันแบบเงียบ ๆ
:::

:::warning ลืมเช็กว่ากราฟเชื่อมกัน
ถ้ากราฟไม่เชื่อม Kruskal จะได้ป่า (หลายต้น) ไม่ใช่ต้นไม้ ต้องนับว่าหยิบได้ครบ $N - 1$ เส้นไหม (Prim: นับว่าเพิ่มจุดครบ $N$ จุดไหม) ถ้าไม่เช็ก จะพิมพ์ราคาของป่าออกไปเหมือนเป็นคำตอบ
:::

:::warning Prim ไม่ใช่ Dijkstra
ใน Prim ค่าที่ push คือ **ราคาเส้นเดียว** `c` ไม่ใช่ `dist[u] + c` ถ้าเผลอใส่ระยะสะสมเข้าไป จะได้ shortest-path tree ซึ่งโดยทั่วไป **ไม่ใช่** MST และราคารวมจะแพงกว่า
:::

:::warning ราคารวมล้น int
ราคาเส้นละ $10^6$ คูณ $N - 1$ เส้นระดับ $10^5$ ได้ $10^{11}$ ให้ `total` เป็น `long long` เสมอ
:::

:::note Python
ใน Python อย่าเขียน `find` แบบ recursive (ลิมิตความลึก $1000$ และช้า) ใช้ path halving แบบวนลูปแทน `while parent[x] != x: parent[x] = parent[parent[x]]; x = parent[x]` และเรียงเส้นด้วย `order = sorted(range(m), key=w.__getitem__)` จะเร็วกว่าสร้าง tuple ทีละเส้น
:::

## สรุปสั้น ๆ

* MST คือ $N - 1$ เส้นที่เชื่อมทุกจุดโดยไม่มีวง และราคารวมน้อยที่สุด
* **Cut property**: เส้นข้ามฝั่งที่ถูกที่สุดของการแบ่งฝั่งใด ๆ หยิบได้อย่างปลอดภัย **cycle property**: เส้นที่แพงกว่าทุกเส้นในวงไม่อยู่ใน MST ใดเลย
* **Kruskal**: เรียงเส้นจากถูกไปแพง หยิบเส้นที่สองปลายอยู่คนละกลุ่ม ใช้ **DSU** (union by size + path compression) เช็กและรวมกลุ่ม $O(M \log M)$
* **Prim**: ปลูกจากจุดเดียว หยิบเส้นถูกสุดที่ออกจากต้นไม้ด้วย min-heap $O(M \log M)$ หรือแบบลูปธรรมดา $O(N^2)$ สำหรับกราฟสมบูรณ์
* ทริก: `unite` ของที่ต่อกันอยู่แล้วก่อนเริ่ม, หยุดที่ $N - K$ เส้นเพื่อได้ $K$ กลุ่ม, ทางบน MST ทำให้เส้นที่แพงที่สุดบนทางน้อยที่สุด
* ราคาซ้ำกันทำให้ MST มีหลายต้น แต่ราคารวมเท่ากันเสมอ
* เช็กเสมอว่ากราฟเชื่อมกันครบ และเก็บราคารวมเป็น `long long`
