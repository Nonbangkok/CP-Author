## ถามช่วง แต่ข้อมูลก็เปลี่ยนไปเรื่อย ๆ

สมมติมีอาเรย์ $a_1, a_2, \ldots, a_N$ แล้วมีคำสั่งปนกันมา $Q$ คำสั่ง สองแบบ

* **แก้ค่าจุดเดียว**: ให้ $a_i = x$
* **ถามช่วง**: ผลรวม (หรือค่าน้อยสุด ค่ามากสุด ...) ของ $a_l, \ldots, a_r$

ท่าที่เรารู้จักมีจุดอ่อนคนละด้าน

| ท่า | แก้จุดเดียว | ถามช่วง |
|---|---|---|
| อาเรย์ธรรมดา | $O(1)$ | $O(N)$ ไล่ทั้งช่วง |
| prefix sum | $O(N)$ ต้องสร้างใหม่ | $O(1)$ |

ทั้งสองแบบเจอ $N, Q = 10^5$ ก็กลายเป็น $O(NQ) = 10^{10}$ ทันที บทที่แล้วเราเพิ่งเห็น Fenwick tree ที่ทำได้ทั้งคู่ใน $O(\log N)$ แต่ Fenwick ถนัดแค่ผลรวม (ของที่ "ลบออกได้") ถ้าเปลี่ยนเป็น **ค่าน้อยสุดในช่วง** Fenwick ก็เริ่มลำบาก เพราะ $\min$ ลบออกไม่ได้

**Segment tree** ทำได้ทั้งสองอย่างใน $O(\log N)$ และใช้กับการรวมแบบไหนก็ได้ที่ "เอาสองช่วงที่ติดกันมาต่อกันได้" ตั้งแต่ผลรวม $\min$ $\max$ $\gcd$ ไปจนถึงข้อมูลที่ซับซ้อนกว่านั้นที่เก็บเป็น `struct`

## หน้าตาของต้นไม้

ไอเดียคือแบ่งครึ่งไปเรื่อย ๆ เหมือนบท Divide and Conquer: โหนดบนสุดดูแลทั้งช่วง $[1, N]$ แล้วแบ่งให้ลูกซ้ายดูแลครึ่งซ้าย ลูกขวาดูแลครึ่งขวา ทำซ้ำจนเหลือช่วงยาว $1$ ซึ่งเป็นใบ **ทุกโหนดเก็บคำตอบของช่วงตัวเองไว้** เช่น ผลรวมของช่วงนั้น

ตัวอย่าง `a = [5, 3, 8, 6, 2, 7, 4, 1]` กับผลรวม (ตัวเลขในวงเล็บคือหมายเลขโหนด `v`)

```text
                         [1,8] = 36  (1)
                /                            \
        [1,4] = 22  (2)                  [5,8] = 14  (3)
         /          \                     /          \
  [1,2] = 8 (4)  [3,4] = 14 (5)   [5,6] = 9 (6)   [7,8] = 5 (7)
    /     \        /     \          /     \         /     \
  5(8)   3(9)   8(10)   6(11)    2(12)   7(13)   4(14)   1(15)
```

เก็บต้นไม้ไว้ในอาเรย์ `t` แบบเดียวกับ heap: **ราก = 1, ลูกของ `v` คือ `2v` กับ `2v + 1`** ไม่ต้องมี pointer เลย ส่วนช่วงของแต่ละโหนดไม่ต้องเก็บ เพราะคำนวณเอาตอนเดินลงได้: โหนดที่ดูแล $[t_l, t_r]$ มี $t_m = \lfloor (t_l + t_r) / 2 \rfloor$ ลูกซ้ายได้ $[t_l, t_m]$ ลูกขวาได้ $[t_m + 1, t_r]$

ทำไมต้องจองอาเรย์ขนาด $4N$? ถ้า $N$ เป็นกำลังของสองพอดี ต้นไม้มี $2N - 1$ โหนด แต่ถ้าไม่ใช่ ต้นไม้จะไม่เต็ม หมายเลขโหนดอาจกระโดดไปถึงเกือบ $4N$ จองเผื่อไว้ $4N$ จึงปลอดภัยเสมอ

## สามงานหลัก

* **build**: สร้างลูกทั้งสองก่อน แล้วรวมเป็นค่าของตัวเอง ทุกโหนดทำงาน $O(1)$ รวม $O(N)$
* **update** (แก้ $a_{pos}$): เดินจากรากลงไปหาใบของ $pos$ ทางเดียว แก้ใบ แล้ว **คิดค่าของทุกโหนดบนทางกลับขึ้นมาใหม่** มีแค่ $O(\log N)$ โหนดที่ช่วงของมันมี $pos$ อยู่
* **query** (ถาม $[l, r]$): ที่แต่ละโหนดมีสามกรณี
  1. ช่วงของโหนด **ไม่ทับ** $[l, r]$ เลย: คืนค่ากลาง (identity) เช่น $0$ สำหรับผลรวม
  2. ช่วงของโหนด **อยู่ข้างใน** $[l, r]$ ทั้งก้อน: คืนค่าที่เก็บไว้ได้เลย ไม่ต้องลงไปต่อ
  3. **ทับกันบางส่วน**: ถามลูกทั้งสองแล้วรวมผล

### Template: แก้ค่าจุดเดียว + ผลรวมของช่วง

คำสั่ง `1 i x` คือ $a_i = x$ และ `2 l r` คือถามผลรวมของ $a_l..a_r$ (นับจาก $1$)

```cpp
#include <bits/stdc++.h>
using namespace std;

int n;
vector<long long> a, t;   // a[1..n] คืออาเรย์, t คือต้นไม้ (ขนาด 4n)

// สร้างโหนด v ที่ดูแลช่วง [tl, tr]
void build(int v, int tl, int tr) {
  if (tl == tr) { t[v] = a[tl]; return; }       // ใบ: ช่วงยาว 1
  int tm = (tl + tr) / 2;
  build(2 * v, tl, tm);                          // ลูกซ้าย  [tl, tm]
  build(2 * v + 1, tm + 1, tr);                  // ลูกขวา  [tm+1, tr]
  t[v] = t[2 * v] + t[2 * v + 1];                // merge
}

// a[pos] = x
void update(int v, int tl, int tr, int pos, long long x) {
  if (tl == tr) { t[v] = x; return; }
  int tm = (tl + tr) / 2;
  if (pos <= tm) update(2 * v, tl, tm, pos, x);
  else update(2 * v + 1, tm + 1, tr, pos, x);
  t[v] = t[2 * v] + t[2 * v + 1];                // ลูกเปลี่ยน พ่อต้องคิดใหม่
}

// ผลรวมของ a[l..r]
long long query(int v, int tl, int tr, int l, int r) {
  if (r < tl || tr < l) return 0;                // ไม่ทับกันเลย: คืน identity
  if (l <= tl && tr <= r) return t[v];           // อยู่ข้างในทั้งก้อน: ใช้ค่าที่เก็บไว้
  int tm = (tl + tr) / 2;                        // ทับกันบางส่วน: ถามลูกทั้งสอง
  return query(2 * v, tl, tm, l, r) + query(2 * v + 1, tm + 1, tr, l, r);
}

int main() {
  ios::sync_with_stdio(false);
  cin.tie(nullptr);
  int q;
  cin >> n >> q;
  a.assign(n + 1, 0);
  t.assign(4 * n, 0);
  for (int i = 1; i <= n; i++) cin >> a[i];
  build(1, 1, n);
  while (q--) {
    int type;
    cin >> type;
    if (type == 1) {                 // 1 i x : a[i] = x
      int i; long long x;
      cin >> i >> x;
      update(1, 1, n, i, x);
    } else {                         // 2 l r : ผลรวม a[l..r]
      int l, r;
      cin >> l >> r;
      cout << query(1, 1, n, l, r) << '\n';
    }
  }
}
```

### ลองไล่ด้วยมือ

ใช้ต้นไม้ในรูปข้างบน ถามผลรวมของ $[2, 6]$

| โหนด | ช่วง | กรณี | ได้ |
|---|---|---|---|
| 1 | $[1, 8]$ | ทับบางส่วน ถามลูก | |
| 2 | $[1, 4]$ | ทับบางส่วน ถามลูก | |
| 4 | $[1, 2]$ | ทับบางส่วน ถามลูก | |
| 8 | $[1, 1]$ | ไม่ทับ | $0$ |
| 9 | $[2, 2]$ | อยู่ข้างใน | $3$ |
| 5 | $[3, 4]$ | อยู่ข้างใน | $14$ |
| 3 | $[5, 8]$ | ทับบางส่วน ถามลูก | |
| 6 | $[5, 6]$ | อยู่ข้างใน | $9$ |
| 7 | $[7, 8]$ | ไม่ทับ | $0$ |

รวมได้ $3 + 14 + 9 = 26$ ตรงกับ $3 + 8 + 6 + 2 + 7$ สังเกตว่าโหนด 5 กับ 6 ตอบแทนลูกของมันได้ทั้งก้อน ไม่ต้องลงไปถึงใบ

ทีนี้แก้ $a_3 = 1$: เดินลง $1 \to 2 \to 5 \to 10$ แก้ใบ 10 เป็น $1$ แล้วคิดใหม่ขากลับ โหนด 5 เป็น $1 + 6 = 7$ โหนด 2 เป็น $8 + 7 = 15$ โหนด 1 เป็น $15 + 14 = 29$ โหนดอื่นไม่ต้องแตะเลย ถาม $[2, 6]$ อีกรอบจะได้ $19$

ลองป้อน `8 4`, `5 3 8 6 2 7 4 1`, `2 2 6`, `1 3 1`, `2 2 6`, `2 1 8` ให้ template ดู จะได้ `26`, `19`, `29`

### ทำไมถึงเป็น $O(\log N)$

ต้นไม้ลึก $\lceil \log_2 N \rceil$ ชั้น update เดินชั้นละโหนดเดียว ส่วน query มีข้อสังเกตสำคัญ: **ในแต่ละชั้น มีโหนดที่ "ทับบางส่วน" ได้ไม่เกินสองโหนด** คือโหนดที่คร่อมปลาย $l$ กับโหนดที่คร่อมปลาย $r$ เพราะโหนดที่อยู่ระหว่างสองตัวนั้นอยู่ข้างใน $[l, r]$ ทั้งก้อนและไม่ถูกแตกต่อ แต่ละชั้นจึงถูกเยี่ยมไม่เกินสี่โหนด รวม $O(\log N)$ ต่อคำถาม

ทั้งโปรแกรม: build $O(N)$ บวก $Q$ คำสั่งคำสั่งละ $O(\log N)$ ได้ $O(N + Q \log N)$ ใช้หน่วยความจำ $O(N)$

## เปลี่ยน "ผลรวม" เป็นอย่างอื่น

โครงเดิมใช้ได้กับการรวมทุกแบบที่ **เอาคำตอบของสองช่วงที่ติดกันมาคำนวณคำตอบของช่วงที่ต่อกันได้** เรียกว่าฟังก์ชัน merge สิ่งที่ต้องเปลี่ยนมีแค่สองอย่าง คือบรรทัด merge กับค่าที่คืนตอนไม่ทับ (identity: ค่าที่ merge กับอะไรแล้วได้ตัวนั้นเหมือนเดิม)

| อยากได้ | merge | identity |
|---|---|---|
| ผลรวม | `L + R` | `0` |
| ค่าน้อยสุด | `min(L, R)` | ค่าที่ใหญ่กว่าทุกค่า เช่น `INT_MAX` |
| ค่ามากสุด | `max(L, R)` | ค่าที่เล็กกว่าทุกค่า เช่น `INT_MIN` |
| ห.ร.ม. | `gcd(L, R)` | `0` (เพราะ $\gcd(0, x) = x$) |
| XOR | `L ^ R` | `0` |

merge ต้องมีสมบัติเปลี่ยนกลุ่ม (associative) ไม่อย่างนั้นการแบ่งช่วงต่างแบบกันจะได้ผลไม่เท่ากัน แต่ **ไม่จำเป็นต้องสลับที่ได้** ต้นไม้แบบ recursive รวม "ซ้ายก่อนขวา" เสมออยู่แล้ว ข้อนี้สำคัญมากกับ merge แบบ struct ข้างล่าง

:::problem lp_seg01_cheapest_stall

:::hint ใบ้ Cheapest Stall
เปลี่ยน template แค่สองจุด: merge เป็น `min` และค่าที่คืนตอนไม่ทับต้องเป็นค่าที่ "ไม่มีวันชนะ" ราคาไหนเลย ถ้าเผลอคืน $0$ แบบผลรวม ทุกคำตอบจะกลายเป็น $0$ ทันที
:::

## โหนดแบบ struct

บางคำถามตอบด้วยตัวเลขตัวเดียวต่อช่วงแล้ว merge ไม่ได้ ต้องเก็บข้อมูลหลายอย่างในโหนดเดียว ตัวอย่างคลาสสิก: **ค่ามากสุดในช่วง และมันโผล่กี่ครั้ง**

ถ้ารู้ `(mx, cnt)` ของช่วงซ้ายและช่วงขวา ช่วงที่ต่อกันมีค่ามากสุดเป็นตัวที่มากกว่า ถ้าสองฝั่งเท่ากันก็นับรวมกัน เขียนเป็นโค้ดได้แบบนี้ (ตัวอื่นเหมือน template ทุกอย่าง แค่ `t` เป็น `vector<Node>` และใบเป็น `{a[tl], 1}`)

```cpp
struct Node {
  int mx, cnt;   // ค่ามากสุดของช่วง และมันโผล่กี่ครั้ง
};

Node merge(Node L, Node R) {
  if (L.mx > R.mx) return L;
  if (R.mx > L.mx) return R;
  return {L.mx, L.cnt + R.cnt};      // เท่ากัน: นับรวมทั้งสองฝั่ง
}

const Node NONE = {INT_MIN, 0};       // identity: แพ้ทุกค่าและไม่เพิ่มจำนวน

Node query(int v, int tl, int tr, int l, int r) {
  if (r < tl || tr < l) return NONE;
  if (l <= tl && tr <= r) return t[v];
  int tm = (tl + tr) / 2;
  return merge(query(2 * v, tl, tm, l, r), query(2 * v + 1, tm + 1, tr, l, r));
}
```

เช่น `a = [4, 7, 2, 7, 1, 7]` ถาม $[1, 6]$ ได้ `7 3` ถาม $[1, 3]$ ได้ `7 1` แก้ $a_4 = 3$ แล้วถาม $[1, 6]$ อีกครั้งได้ `7 2`

วิธีคิด merge แบบ struct ที่ใช้ได้เกือบทุกครั้ง: ถามตัวเองว่า **"คำตอบของช่วงที่ต่อกัน อาจมาจากไหนได้บ้าง"** อาจอยู่ในซ้ายล้วน ขวาล้วน หรือ **คร่อมรอยต่อ** ถ้ากรณีคร่อมรอยต่อต้องรู้อะไรเพิ่มจากแต่ละฝั่ง ก็เพิ่ม field นั้นเข้าไปใน struct แล้วถามซ้ำว่า field ใหม่นั้น merge ยังไง จนกว่าทุก field จะ merge ได้จาก field ของลูกเอง

ถ้าหา identity ของ struct ยาก (บาง field ไม่มีค่าที่เป็นกลางจริง ๆ) ก็เลี่ยงได้: ให้ query เดินลงเฉพาะฝั่งที่ทับกับ $[l, r]$ ถ้า $[l, r]$ อยู่ในลูกซ้ายล้วนก็ไปซ้ายอย่างเดียว อยู่ในลูกขวาล้วนก็ไปขวาอย่างเดียว คร่อมสองฝั่งจึงค่อย merge แบบนี้จะไม่มีวันต้อง merge กับช่วงว่างเลย

:::problem lp_seg02_best_streak

:::hint ใบ้ Best Streak
ช่วงที่ดีที่สุดของช่วงที่ต่อกันมีสามแบบ: อยู่ในซ้ายล้วน อยู่ในขวาล้วน หรือคร่อมรอยต่อ แบบคร่อมรอยต่อคือ "ท้ายของฝั่งซ้าย" ต่อกับ "หัวของฝั่งขวา" แล้วจะรู้ได้ยังไงว่าท้ายที่ดีที่สุดของช่วงที่ต่อกันคืออะไร? ลองใช้ผลรวมของทั้งช่วงช่วย ส่วนช่วงต้องไม่ว่าง identity จึงตั้งยาก ใช้ query ที่เดินลงเฉพาะฝั่งที่ทับดีกว่า
:::

## เดินลงต้นไม้เพื่อหาตำแหน่ง

บางคำถามไม่ได้ถามค่า แต่ถาม **ตำแหน่ง** เช่น "ในอาเรย์ $0/1$ เลข $1$ ตัวที่ $k$ อยู่ช่องไหน" ถ้า binary search บนคำตอบแล้วใช้ query เช็ก จะได้ $O(\log^2 N)$ แต่เราทำให้ดีกว่านั้นได้ เพราะต้นไม้มีข้อมูลพร้อมอยู่แล้ว: ที่โหนดหนึ่ง ถ้าลูกซ้ายมีเลข $1$ อย่างน้อย $k$ ตัว ตัวที่ $k$ ก็อยู่ซ้าย ไม่อย่างนั้นก็อยู่ขวา และกลายเป็นตัวที่ $k - t_{2v}$ ของฝั่งขวา เดินลงทางเดียวถึงใบ $O(\log N)$

```cpp
// ใช้กับต้นไม้ผลรวมใน template: ตำแหน่งของเลข 1 ตัวที่ k ทั้งอาเรย์ ไม่มีคืน -1
int kth_one(int v, int tl, int tr, int k) {
  if (t[v] < k) return -1;                 // ทั้งช่วงมีเลข 1 ไม่ถึง k ตัว
  if (tl == tr) return tl;
  int tm = (tl + tr) / 2;
  if (t[2 * v] >= k) return kth_one(2 * v, tl, tm, k);    // ตัวที่ k อยู่ฝั่งซ้าย
  return kth_one(2 * v + 1, tm + 1, tr, k - t[2 * v]);    // ข้ามฝั่งซ้ายไปทั้งก้อน
}
```

กับ `a = [0, 1, 1, 0, 0, 1, 0, 1]` เรียก `kth_one(1, 1, n, k)` สำหรับ $k = 1..5$ ได้ `2 3 6 8 -1`

หลักของการเดินลงคือ **ใช้ค่าที่เก็บในโหนดตัดสินว่าคำตอบอยู่ฝั่งไหน แล้วทิ้งอีกฝั่งไปทั้งก้อน** ข้อมูลในโหนดเปลี่ยนไปตามโจทย์ (ผลรวม, ค่ามากสุด, ...) และถ้าโจทย์จำกัดให้หาแค่ในช่วง $[l, r]$ ก็ต้องเพิ่มเงื่อนไขทิ้งโหนดที่อยู่นอกช่วงด้วย

:::hint ใบ้ Tall Enough
เก็บค่ามากสุดในโหนด ถ้าค่ามากสุดของโหนดหนึ่งยังน้อยกว่า $x$ ทั้งก้อนนั้นไม่มีคำตอบแน่นอน ข้ามไปได้เลย ไม่อย่างนั้นลองลูกซ้ายก่อน (เพราะอยากได้ดัชนีที่น้อยที่สุด) ถ้าซ้ายไม่เจอค่อยไปขวา โหนดที่อยู่นอก $[l, r]$ ก็ทิ้ง ลองคิดดูว่าทำไมการ "ลองซ้ายแล้วไม่เจอ" ถึงไม่ทำให้ช้าลงจนเป็น $O(N)$
:::

## แบบไม่ใช้ recursion (bottom-up)

มีอีกแบบที่สั้นและเร็วกว่ามาก นิยมใช้เมื่อเป็นการแก้จุดเดียว: วางใบของ $a_i$ (นับจาก $0$) ไว้ที่ `t[n + i]` แล้วให้ `t[v] = t[2v] + t[2v+1]` สำหรับ `v` จาก `n - 1` ลงมาถึง `1` ใช้อาเรย์แค่ $2N$

* update: แก้ใบแล้วเดิน `i /= 2` ขึ้นไปคิดใหม่จนถึงราก
* query ช่วงครึ่งเปิด $[l, r)$: ให้ `l` กับ `r` ไต่ขึ้นพร้อมกัน ถ้า `l` เป็นลูกขวา (เลขคี่) แปลว่าพ่อของมันคลุมเกินออกไปทางซ้าย จึงเอา `t[l]` ไว้แล้วขยับ `l` ไปทางขวาหนึ่งช่อง ฝั่ง `r` ก็ทำกลับกัน

```cpp
#include <bits/stdc++.h>
using namespace std;

int n;
vector<long long> t;   // ขนาด 2n: ใบของ a[i] (0-indexed) อยู่ที่ t[n + i]

void build() {
  for (int v = n - 1; v >= 1; v--) t[v] = t[2 * v] + t[2 * v + 1];
}

void update(int i, long long x) {        // a[i] = x
  i += n;
  t[i] = x;
  for (i /= 2; i >= 1; i /= 2) t[i] = t[2 * i] + t[2 * i + 1];
}

long long query(int l, int r) {          // ผลรวมของ a[l..r-1] (ครึ่งเปิด)
  long long res = 0;
  for (l += n, r += n; l < r; l /= 2, r /= 2) {
    if (l & 1) res += t[l++];            // l เป็นลูกขวา: เอามันไว้ แล้วขยับเข้า
    if (r & 1) res += t[--r];            // r เป็นลูกขวา: เอาตัวทางซ้ายของ r
  }
  return res;
}

int main() {
  ios::sync_with_stdio(false);
  cin.tie(nullptr);
  int q;
  cin >> n >> q;
  t.assign(2 * n, 0);
  for (int i = 0; i < n; i++) cin >> t[n + i];
  build();
  while (q--) {
    int type;
    cin >> type;
    if (type == 1) {                     // 1 i x  (i นับจาก 1 เหมือนโจทย์)
      int i; long long x;
      cin >> i >> x;
      update(i - 1, x);
    } else {                             // 2 l r  (นับจาก 1, รวมสองปลาย)
      int l, r;
      cin >> l >> r;
      cout << query(l - 1, r) << '\n';
    }
  }
}
```

ป้อน input ชุดเดียวกับ template แรกจะได้ `26`, `19`, `29` เหมือนกัน

:::note bottom-up กับ merge ที่สลับที่ไม่ได้
เวอร์ชันนี้หยิบโหนดฝั่ง `l` จากซ้ายไปขวา แต่หยิบฝั่ง `r` จาก **ขวามาซ้าย** ถ้า merge สลับที่ได้ (ผลรวม, min, max, gcd) ใส่ลง `res` ตัวเดียวได้เลย แต่ถ้าเป็น struct แบบ Best Streak ต้องแยกเป็น `resl = merge(resl, t[l++])` กับ `resr = merge(t[--r], resr)` แล้วตอบ `merge(resl, resr)` และถ้า $N$ ไม่ใช่กำลังของสอง ให้เติมใบว่างจนเป็นกำลังของสองก่อนจะปลอดภัยที่สุด

ถ้าเขียน Python: ใช้แบบ bottom-up นี้แหละ (ไม่มี recursion, เก็บใน list แบน ๆ) และอ่าน input ทีเดียวด้วย `sys.stdin.buffer.read().split()` จะเร็วกว่าแบบ recursive หลายเท่า
:::

## จุดที่พลาดบ่อย

:::warning จองต้นไม้ไม่พอ
แบบ recursive ต้อง `4 * n` ไม่ใช่ `2 * n` (ถ้า $N$ ไม่ใช่กำลังของสอง หมายเลขโหนดจะเกิน $2N$ ได้) ส่วนแบบ bottom-up ใช้ `2 * n` พอดี อย่าสลับกัน
:::

:::warning identity ผิด
ค่าที่คืนตอน "ไม่ทับ" ต้องเป็นกลางจริง ๆ สำหรับ merge นั้น min ที่คืน $0$ หรือ max ที่คืน $0$ ทั้งที่ค่าติดลบได้ คือบั๊กที่เจอบ่อยที่สุด และระวังคืน `LLONG_MIN` ในงานที่เอาไปบวกต่อ เพราะบวกแล้วล้น (judge ของเราจะหยุดโปรแกรมเป็น Runtime Error ทันทีเมื่อ signed overflow)
:::

:::warning ลืมคิดพ่อใหม่หลัง update
หลังเรียก update ลูกเสร็จต้องมี `t[v] = merge(t[2v], t[2v+1])` เสมอ ไม่อย่างนั้นโหนดข้างบนจะยังเก็บค่าเก่า และคำถามที่ใช้โหนดนั้นทั้งก้อนจะตอบผิดแบบเงียบ ๆ
:::

:::warning ส่ง vector เข้าฟังก์ชันแบบ by value
`void build(vector<long long> t, ...)` จะ copy ทั้งต้นไม้ทุกครั้งที่เรียก ช้ามากและแก้ค่าไม่ติด ให้ใช้ตัวแปร global แบบ template หรือส่งเป็น `vector<long long> &t`
:::

:::warning ดัชนี 0 กับ 1 ปนกัน
template แรกใช้ $[1, N]$ และ `build(1, 1, n)` ถ้าอาเรย์เก็บแบบ $0$-indexed ต้องเรียก `build(1, 0, n - 1)` และแปลง $l, r$ ของโจทย์ให้ตรงกัน เลือกแบบเดียวแล้วใช้ให้ตลอดทั้งโปรแกรม
:::

## สรุปสั้น ๆ

* Segment tree เก็บคำตอบของทุกช่วงที่ได้จากการแบ่งครึ่ง ราก = 1 ลูกของ `v` คือ `2v`, `2v + 1` จองขนาด $4N$
* build $O(N)$, แก้จุดเดียว $O(\log N)$ (แก้ใบแล้วคิดพ่อใหม่ขากลับ), ถามช่วง $O(\log N)$ (แต่ละชั้นแตกต่อไม่เกินสองโหนด)
* เปลี่ยนงานได้ด้วยการเปลี่ยน merge กับ identity: ผลรวม, min, max, gcd, xor
* ข้อมูลที่ซับซ้อนใช้ struct: ถามว่าคำตอบของช่วงที่ต่อกันมาจากซ้าย ขวา หรือคร่อมรอยต่อ แล้วเก็บ field ที่ต้องใช้
* หา "ตำแหน่งแรกที่..." ด้วยการเดินลงต้นไม้ $O(\log N)$ แทน binary search ครอบ query
* แบบ bottom-up สั้นและเร็ว เหมาะกับการแก้จุดเดียว และเหมาะกับ Python
