## ต้นไม้คือกราฟแบบไหน

ในบทกราฟเราเจอกราฟหน้าตาหลากหลาย บทนี้เราสนใจกราฟแบบพิเศษที่โผล่ในโจทย์บ่อยที่สุดแบบหนึ่ง คือ **ต้นไม้ (tree)**: กราฟไม่มีทิศทาง $N$ จุด ที่**เชื่อมถึงกันหมด**และ**ไม่มีวงจร** สามข้อนี้จำไว้ให้ขึ้นใจ เพราะโจทย์มักบอกแค่ข้อเดียวแล้วให้เรารู้เองว่าที่เหลือตามมา

* ต้นไม้ $N$ จุดมีเส้นเชื่อม **$N - 1$ เส้นพอดี** (ถ้าโจทย์บอก "มี $N$ เมือง ถนน $N - 1$ เส้น และไปถึงกันหมด" นั่นคือต้นไม้)
* ระหว่างสองจุดใด ๆ มี **เส้นทางที่ไม่เดินซ้ำเพียงเส้นทางเดียว** ไม่ต้องเลือกว่าจะไปทางไหน ระยะทางจึงไม่ต้องใช้ Dijkstra
* ตัดเส้นเชื่อมเส้นไหนก็ตาม ต้นไม้จะ**ขาดเป็นสองส่วนพอดี**

ข้อสุดท้ายนี่แหละที่ทำให้โจทย์ต้นไม้หลายข้อง่ายกว่าที่เห็น เพราะทุกเส้นเชื่อมแบ่งจุดออกเป็น "ฝั่งนี้" กับ "ฝั่งโน้น" ชัดเจน

## ตั้งราก: parent, children, depth, subtree

ต้นไม้ที่ให้มาเป็นแค่เส้นเชื่อมไม่มีทิศ แต่เกือบทุกเทคนิคเริ่มจากการ**เลือกรากหนึ่งจุด** (ปกติคือจุด $1$) แล้วหิ้วต้นไม้ขึ้นมาจากจุดนั้น ทุกอย่างก็มีลำดับชั้นทันที

```text
              1           depth 0
            /   \
           2     3        depth 1
           |    / \
           7   4   5      depth 2
                   |
                   6      depth 3

parent[3] = 1      children ของ 3 = {4, 5}      leaf = {7, 4, 6}
subtree ของ 3 = {3, 4, 5, 6}  ->  sz[3] = 4
```

* **parent** ของ $v$ คือจุดที่อยู่ถัดขึ้นไปหนึ่งชั้นบนทางไปราก (รากไม่มี parent)
* **children** คือจุดที่มี $v$ เป็น parent ส่วนจุดที่ไม่มีลูกเรียกว่า **leaf**
* **depth** คือจำนวนเส้นเชื่อมจากรากถึง $v$
* **subtree** ของ $v$ คือ $v$ กับทุกจุดที่อยู่ใต้มัน และ **subtree size** `sz[v]` คือจำนวนจุดในนั้น

รับข้อมูลยังไงก็เก็บเป็น adjacency list แบบเดียวกับกราฟทั่วไป (`adj[u].push_back(v)` และ `adj[v].push_back(u)`) ความต่างเดียวคือตอนเดิน เราไม่ต้องมี `visited` เพราะต้นไม้ไม่มีวงจร แค่**ห้ามเดินย้อนกลับไปหา parent** ก็พอ

## DFS แบบ recursion: สั้น แต่ระเบิดได้

ถ้าเขียนแบบที่คุ้นมือที่สุด จะได้ประมาณนี้

```cpp
void dfs(int u, int p) {
  sz[u] = 1;
  for (int v : adj[u])
    if (v != p) {
      depth[v] = depth[u] + 1;
      dfs(v, u);
      sz[u] += sz[v];
    }
}
```

ถูกต้องทุกบรรทัด แต่ถ้าต้นไม้เป็น**เส้นตรงยาว** เช่น $1 - 2 - 3 - \cdots - 200000$ ฟังก์ชันจะเรียกตัวเองซ้อนกันสองแสนชั้น แต่ละชั้นกิน stack ไปก้อนหนึ่ง (ยิ่ง grader ของเรา compile แบบไม่มี `-O2` ก้อนยิ่งใหญ่) stack ปกติมีแค่ราว 8 MB เราลองแล้ว: โค้ดข้างบนบนเส้นตรง $10^5$ จุดก็ **Segmentation fault** แล้ว ได้ Runtime Error ทั้งที่อัลกอริทึมถูก

และโจทย์ต้นไม้ที่ดีจะมีเทสต์เส้นตรงเสมอ เพราะมันคือกรณีที่ลึกที่สุด บทนี้จึงใช้ DFS ที่**จัดการ stack เอง**เป็นหลัก

## Template: ตั้งรากแบบไม่ใช้ recursion

ไอเดียมีสองขั้น

1. ใช้ `vector` เป็น stack: หยิบจุดบนสุดออกมา จดลง `order` แล้วดันลูก (เพื่อนบ้านที่ไม่ใช่ parent) ลงไป พร้อมตั้ง `parent` และ `depth` ให้ลูก
2. จุดหนึ่งจะถูกดันลง stack ก็ต่อเมื่อ parent ของมันถูกหยิบออกไปแล้ว ดังนั้นใน `order` **parent มาก่อนลูกเสมอ** ถ้าเดิน `order` **จากท้ายมาหัว** ลูกทุกตัวจะถูกคิดเสร็จก่อนพ่อ ซึ่งเป็นสิ่งที่ recursion ทำให้เราตอนขากลับพอดี

โปรแกรมข้างล่างรับต้นไม้ $N$ จุด (บรรทัดแรก $N$ ตามด้วยเส้นเชื่อม $N - 1$ บรรทัด) แล้วพิมพ์ parent, depth และ subtree size ของทุกจุด

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
  ios::sync_with_stdio(false);
  cin.tie(nullptr);
  int n;
  cin >> n;
  vector<vector<int>> adj(n + 1);
  for (int i = 0; i < n - 1; i++) {
    int u, v;
    cin >> u >> v;
    adj[u].push_back(v);
    adj[v].push_back(u);
  }

  // 1) ให้ 1 เป็นราก: หา parent, depth และลำดับที่เจอ (order) ด้วย DFS ที่ใช้ stack เอง
  vector<int> parent(n + 1, 0), depth(n + 1, 0), order;
  order.reserve(n);
  vector<int> st = {1};              // parent[1] = 0 แปลว่าไม่มีพ่อ (ไม่มีจุดยอดหมายเลข 0)
  while (!st.empty()) {
    int u = st.back();
    st.pop_back();
    order.push_back(u);
    for (int v : adj[u]) {
      if (v == parent[u]) continue;  // อย่าเดินย้อนกลับไปหาพ่อ
      parent[v] = u;
      depth[v] = depth[u] + 1;
      st.push_back(v);
    }
  }

  // 2) เดิน order จากท้ายมาหัว: ลูกทุกตัวถูกคิดก่อนพ่อเสมอ
  vector<int> sz(n + 1, 1);
  for (int i = n - 1; i >= 1; i--) {
    int v = order[i];
    sz[parent[v]] += sz[v];
  }

  for (int v = 1; v <= n; v++)
    cout << v << ": parent " << parent[v] << ", depth " << depth[v] << ", size " << sz[v] << '\n';
}
```

ลูปขั้นที่ 2 หยุดที่ `i >= 1` เพราะ `order[0]` คือรากซึ่งไม่มีพ่อให้บวกต่อ จะใช้ BFS (`queue`) แทน stack ก็ได้ผลเหมือนกัน เพราะ BFS ก็เจอพ่อก่อนลูกเสมอ

## ไล่มือหนึ่งรอบ

ใช้ต้นไม้ในรูปข้างบน input คือ

```text
7
1 2
1 3
3 4
3 5
5 6
2 7
```

ขั้นที่ 1 (stack เขียนจากล่างขึ้นบน ตัวขวาสุดคือตัวบนสุด)

```text
หยิบ  order ตอนนี้          ดันลง        stack หลังดัน
 1    1                    2, 3         [2, 3]
 3    1 3                  4, 5         [2, 4, 5]
 5    1 3 5                6            [2, 4, 6]
 6    1 3 5 6              -            [2, 4]
 4    1 3 5 6 4            -            [2]
 2    1 3 5 6 4 2          7            [7]
 7    1 3 5 6 4 2 7        -            []
```

ขั้นที่ 2 เดิน `order` จากท้าย: `7` บวกเข้า `sz[2]` ได้ $2$, `2` บวกเข้า `sz[1]` ได้ $3$, `4` บวกเข้า `sz[3]` ได้ $2$, `6` บวกเข้า `sz[5]` ได้ $2$, `5` บวกเข้า `sz[3]` ได้ $4$, `3` บวกเข้า `sz[1]` ได้ $7$ ตรงกับรูปทุกตัว สังเกตว่าตอนที่ `5` บวกเข้าพ่อ มันได้รับค่าจาก `6` มาครบแล้ว นี่คือเหตุผลที่ต้องเดินจากท้าย

ทั้งหมดเป็น $O(N)$: ทุกจุดเข้าและออกจาก stack ครั้งเดียว และทุกเส้นเชื่อมถูกมองสองครั้ง (จากปลายทั้งสองข้าง)

## subtree size ใช้ทำอะไร

ตัดเส้นเชื่อมระหว่าง $v$ กับ parent ของมัน ฝั่งล่างมี `sz[v]` จุด และฝั่งบนมี $N - \text{sz}[v]$ จุด นี่คือสมบัติ "ตัดแล้วขาดเป็นสองส่วน" ในรูปตัวเลข และใช้ได้บ่อยมาก เช่น

* ถามว่าตัดเส้นไหนแล้วสองส่วนมีขนาดใกล้กันที่สุด: ไล่ดู $|N - 2 \cdot \text{sz}[v]|$ ทุก $v$
* **centroid** (จุดที่ตัดทิ้งแล้วไม่มีชิ้นไหนใหญ่เกิน $N/2$) หาได้จาก `sz` ล้วน ๆ
* นับว่า "คู่จุดกี่คู่ที่เส้นทางผ่านเส้นเชื่อมนี้" ก็คือจับคู่จุดฝั่งล่างกับฝั่งบน

## Tree DP: ลูกตอบก่อน แล้วพ่อค่อยรวม

`sz[v]` คือ DP บนต้นไม้ที่ง่ายที่สุด: คำตอบของซับทรี $v$ สร้างจากคำตอบของซับทรีลูก ๆ เทคนิคเดียวกันนี้แก้โจทย์ได้อีกเยอะ ขอแค่ตอบสองคำถาม

1. **state** ของแต่ละจุดคืออะไร (บ่อยครั้งต้องมีมากกว่าหนึ่งค่า เช่น "ถ้า $v$ ถูกเลือก" กับ "ถ้า $v$ ไม่ถูกเลือก")
2. **พ่อรวมค่าจากลูกยังไง**

ตัวอย่างโจทย์ข้างเคียง: หมู่บ้านต้นไม้ $N$ หลัง อยากวาง**ยาม**ไว้ที่บ้านบางหลังให้ถนน**ทุกเส้น**มียามอยู่ที่ปลายอย่างน้อยหนึ่งข้าง ใช้ยามน้อยที่สุดกี่คน (minimum vertex cover)

* `in[v]` = ยามน้อยสุดในซับทรีของ $v$ เมื่อบ้าน $v$ **มี**ยาม: ถนนไปหาลูกปลอดภัยแล้ว ลูกแต่ละคนเลือกแบบที่ถูกกว่า คือ $1 + \sum \min(\text{in}[c], \text{out}[c])$
* `out[v]` = ยามน้อยสุดเมื่อบ้าน $v$ **ไม่มี**ยาม: ถนน $v - c$ ต้องพึ่งยามที่ลูก ลูกทุกคนจึงต้องมี คือ $\sum \text{in}[c]$
* คำตอบคือ $\min(\text{in}[1], \text{out}[1])$

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
  ios::sync_with_stdio(false);
  cin.tie(nullptr);
  int n;
  cin >> n;
  vector<vector<int>> adj(n + 1);
  for (int i = 0; i < n - 1; i++) {
    int u, v;
    cin >> u >> v;
    adj[u].push_back(v);
    adj[v].push_back(u);
  }

  vector<int> parent(n + 1, 0), order;
  vector<int> st = {1};
  while (!st.empty()) {
    int u = st.back();
    st.pop_back();
    order.push_back(u);
    for (int v : adj[u])
      if (v != parent[u]) {
        parent[v] = u;
        st.push_back(v);
      }
  }

  // in[v]  = ยามน้อยสุดในซับทรีของ v เมื่อ v มียาม
  // out[v] = ยามน้อยสุดในซับทรีของ v เมื่อ v ไม่มียาม (ลูกทุกคนจึงต้องมียาม)
  vector<long long> in(n + 1, 1), out(n + 1, 0);
  for (int i = n - 1; i >= 0; i--) {
    int v = order[i];                // ลูกของ v ถูกคิดเสร็จหมดแล้ว
    int p = parent[v];
    if (p != 0) {
      in[p] += min(in[v], out[v]);   // p มียาม: ถนน p-v ปลอดภัยแล้ว v จะมีหรือไม่มีก็ได้
      out[p] += in[v];               // p ไม่มียาม: v ต้องมี
    }
  }
  cout << min(in[1], out[1]) << '\n';
}
```

ลองกับต้นไม้ 7 จุดเดิม: leaf `4`, `6`, `7` มี `in = 1, out = 0` จุด `5` ได้ `in = 1 + min(1, 0) = 1`, `out = in[6] = 1` จุด `3` ได้ `in = 1 + 0 + 1 = 2`, `out = 1 + 1 = 2` จุด `2` ได้ `in = 1`, `out = 1` สุดท้ายราก `in = 1 + 1 + 2 = 4`, `out = 1 + 2 = 3` ตอบ $3$ (วางยามที่ `2`, `3`, `5`) โปรแกรมนี้พิมพ์ `3` จริง

แบบนี้คือการ**ส่งค่าขึ้นไปให้พ่อ**ตอนเดิน `order` จากท้าย ไม่ต้องเก็บรายชื่อลูกแยกเลย

## Diameter: เส้นทางที่ยาวที่สุด

**เส้นผ่านศูนย์กลาง (diameter)** ของต้นไม้คือระยะที่มากที่สุดระหว่างสองจุด วิธีตรง ๆ คือ BFS จากทุกจุดแล้วดูระยะที่ไกลที่สุด ได้ $O(N^2)$ ซึ่งช้าเกินเมื่อ $N$ เป็นแสน แต่ต้นไม้มีท่าลัดที่สวยมาก

1. เริ่มจากจุดไหนก็ได้ (เช่น $1$) หาจุดที่ไกลที่สุด เรียกว่า $a$
2. จาก $a$ หาจุดที่ไกลที่สุด เรียกว่า $b$
3. ระยะจาก $a$ ถึง $b$ คือ diameter

ทำไมถึงถูก (แบบคร่าว ๆ): ให้ $x - y$ เป็น diameter เส้นหนึ่ง จุด $a$ ที่ไกลจาก $1$ ที่สุดต้องเป็นปลายของ diameter สักเส้น เพราะถ้าไม่ใช่ เส้นทางจาก $1$ ไป $a$ จะต้องแตกออกจากเส้น $x - y$ ที่ไหนสักแห่ง แล้วเราเอาครึ่งที่ยาวกว่าของ $x - y$ ไปต่อกับกิ่งที่ไป $a$ ได้เส้นที่ยาวกว่าหรือเท่ากับ diameter เสมอ พอรู้ว่า $a$ เป็นปลายข้างหนึ่งแล้ว จุดที่ไกลจาก $a$ ที่สุดก็คือปลายอีกข้าง

```cpp
#include <bits/stdc++.h>
using namespace std;

int n;
vector<vector<int>> adj;

// BFS จาก s: เติม dist ให้ทุกจุด แล้วคืนจุดที่ไกลจาก s ที่สุด
int farthest(int s, vector<int> &dist) {
  dist.assign(n + 1, -1);
  dist[s] = 0;
  queue<int> q;
  q.push(s);
  int best = s;
  while (!q.empty()) {
    int u = q.front();
    q.pop();
    if (dist[u] > dist[best]) best = u;
    for (int v : adj[u])
      if (dist[v] < 0) {
        dist[v] = dist[u] + 1;
        q.push(v);
      }
  }
  return best;
}

int main() {
  ios::sync_with_stdio(false);
  cin.tie(nullptr);
  cin >> n;
  adj.resize(n + 1);
  for (int i = 0; i < n - 1; i++) {
    int u, v;
    cin >> u >> v;
    adj[u].push_back(v);
    adj[v].push_back(u);
  }
  vector<int> dist;
  int a = farthest(1, dist);   // รอบที่ 1: จากจุดไหนก็ได้ ไปจุดที่ไกลที่สุด
  int b = farthest(a, dist);   // รอบที่ 2: จาก a ไปจุดที่ไกลที่สุด
  cout << "diameter " << dist[b] << " edges, from " << a << " to " << b << '\n';
}
```

กับต้นไม้ 7 จุดเดิม รอบแรกจาก `1` เจอ `6` (ลึก $3$) รอบสองจาก `6` เจอ `7` ผ่าน `6 - 5 - 3 - 1 - 2 - 7` โปรแกรมพิมพ์ `diameter 5 edges, from 6 to 7` ทั้งหมดคือ BFS สองรอบ $O(N)$

ถ้าเส้นเชื่อมมี**ความยาว** วิธีเดิมยังใช้ได้ ขอแค่ทุกความยาว**ไม่ติดลบ** แต่ BFS ธรรมดาที่นับจำนวนเส้นใช้ไม่ได้แล้ว ต้องสะสมความยาวจริง (ในต้นไม้ทำได้ด้วย DFS ธรรมดา เพราะไปแต่ละจุดได้ทางเดียว ไม่ต้องใช้ Dijkstra) อีกวิธีที่ไม่ต้องพึ่งเงื่อนไขนี้คือ tree DP: ที่แต่ละจุดเก็บ "ทางที่ยาวที่สุดที่ลงไปในซับทรี" แล้ว diameter คือจุดที่เอาสองกิ่งที่ยาวที่สุดมาต่อกัน

:::problem lp_tr02_longest_trail

:::hint ใบ้ Longest Trail
ใช้สองรอบได้เลยเพราะความยาวเป็นบวก แต่ "ไกลที่สุด" ต้องวัดเป็น**เมตร** ไม่ใช่จำนวนทางเดิน (ตัวอย่างที่ 2 ตั้งใจดักจุดนี้) ระยะสะสมไปได้ถึง $10^5 \cdot 10^6 = 10^{11}$ ต้องใช้ `long long` และเทสต์มีเส้นตรงยาว $10^5$ จุด อย่าค้นด้วย recursion
:::

## ความซับซ้อน

| งาน | เวลา | หมายเหตุ |
|---|---|---|
| ตั้งราก หา parent, depth, order | $O(N)$ | stack หรือ queue ก็ได้ |
| subtree size, tree DP | $O(N)$ | เดิน order จากท้าย |
| diameter | $O(N)$ | ค้นสองรอบ |
| BFS จากทุกจุด | $O(N^2)$ | ช้าเกินเมื่อ $N \geq 10^4$ ขึ้นไปโดยประมาณ |

หน่วยความจำ $O(N)$ ทั้งหมด adjacency list ของต้นไม้มีแค่ $2(N - 1)$ ช่อง

:::warning จุดที่พลาดบ่อย
* **recursion บนต้นไม้ลึก** เส้นตรง $10^5$ จุดก็ทำ stack ล้นแล้ว ใช้ stack ของเราเองหรือ BFS order เสมอ ถ้าไม่แน่ใจว่าโจทย์ลึกแค่ไหน
* **ลืมเช็ก parent** ในต้นไม้ไม่ต้องมี `visited` ก็จริง แต่ต้องข้ามจุดที่เป็น parent ไม่อย่างนั้นจะวนไปมาไม่จบ
* **คิดว่า $p_i < i$** ถ้าโจทย์ให้ parent มาโดยไม่รับประกันว่าน้อยกว่า การวน $i = N, N - 1, \ldots$ ไม่ใช่ลำดับลูกก่อนพ่อ สร้าง order เองจากราก
* **$N = 1$** ไม่มีบรรทัดเส้นเชื่อมเลย ลูปอ่าน $N - 1$ บรรทัดต้องไม่พัง และคำตอบอย่าง diameter ต้องเป็น $0$
* **ล้น `int`** ผลรวมหรือผลคูณของขนาดซับทรีและความยาวไปถึง $10^{10}$ ขึ้นไปได้ง่าย ใช้ `long long`
* **diameter สองรอบกับความยาวติดลบ** ใช้ไม่ได้ เปลี่ยนไปใช้ tree DP
:::

## สรุปสั้น ๆ

* ต้นไม้ $N$ จุด = เชื่อมถึงกัน + ไม่มีวงจร = $N - 1$ เส้น ระหว่างสองจุดมีเส้นทางเดียว และตัดเส้นไหนก็ขาดเป็นสองส่วน
* เลือกราก แล้วหา `parent`, `depth`, `order` ด้วย stack ของเราเอง (หรือ BFS) ไม่ต้องใช้ `visited` แค่ไม่เดินกลับหา parent
* เดิน `order` จากท้ายมาหัว = ลูกเสร็จก่อนพ่อ ใช้ทำ subtree size และ tree DP ทุกแบบ
* tree DP: เลือก state (บ่อยครั้งสองค่า "เลือก" / "ไม่เลือก") แล้วเขียนว่าพ่อรวมค่าจากลูกยังไง
* diameter: จากจุดไหนก็ได้ไปจุดที่ไกลที่สุด $a$ แล้วจาก $a$ ไปจุดที่ไกลที่สุด ใช้ได้เมื่อความยาวไม่ติดลบ
* เทสต์เส้นตรงกับเทสต์ดาว (star) คือสองกรณีที่ต้องลองในหัวทุกครั้ง: ลึกที่สุดกับกว้างที่สุด
