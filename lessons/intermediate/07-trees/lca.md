## สองจุดมาบรรจบกันที่ไหน

ตั้งรากต้นไม้แล้ว (ทำเป็นแล้วจากบท Tree Basics) ถ้าเอาจุด $u$ กับ $v$ มาไล่ขึ้นไปหาราก ทางของทั้งสองจะมาเจอกันที่จุดหนึ่ง แล้วเดินร่วมกันไปจนถึงราก จุดที่เจอกันครั้งแรกนั้นคือ **lowest common ancestor (LCA)**: บรรพบุรุษร่วมที่อยู่**ลึกที่สุด** (นับว่าแต่ละจุดเป็นบรรพบุรุษของตัวเองด้วย ถ้า $u$ อยู่เหนือ $v$ ก็ได้ $\text{lca}(u, v) = u$)

```text
              1             depth 0
            /   \
           2     3          depth 1
          / \     \
         4   5     6        depth 2
             |      \
             7       8      depth 3
             |
             9              depth 4

lca(9, 4) = 2      lca(9, 8) = 1      lca(5, 9) = 5
```

ทำไมต้องสนใจ เพราะเส้นทางเดียวระหว่าง $u$ กับ $v$ ในต้นไม้คือ "ขึ้นจาก $u$ ไปถึง LCA แล้วลงไปหา $v$" พอรู้ LCA ก็ตอบได้หลายอย่างทันที

* **ระยะทาง** (จำนวนเส้น): $\text{depth}[u] + \text{depth}[v] - 2 \cdot \text{depth}[\text{lca}(u, v)]$
* ถ้าเส้นเชื่อมมี**ความยาว** ให้เก็บ $D[v]$ = ระยะจากรากถึง $v$ แล้ว $d(u, v) = D[u] + D[v] - 2 \cdot D[\text{lca}(u, v)]$ เหมือนกันเป๊ะ
* จุด $c$ **อยู่บนเส้นทาง** $a - b$ ก็ต่อเมื่อ $d(a, c) + d(c, b) = d(a, b)$ (ถ้าเส้นเชื่อมยาวเป็นบวก)

ปัญหาคือโจทย์มักถาม LCA เป็นแสนครั้ง เราต้องตอบแต่ละครั้งให้เร็ว

## วิธีตรง ๆ: ไล่ขึ้นทีละชั้น

ยกจุดที่ลึกกว่าขึ้นจนลึกเท่ากัน แล้วยกทั้งคู่ขึ้นพร้อมกันทีละชั้นจนเจอกัน

```cpp
int lcaNaive(int u, int v) {
  while (depth[u] > depth[v]) u = parent[u];
  while (depth[v] > depth[u]) v = parent[v];
  while (u != v) {
    u = parent[u];
    v = parent[v];
  }
  return u;
}
```

ถูกต้องและสั้น แต่ใช้เวลา $O(\text{depth})$ ต่อคำถาม ถ้าต้นไม้เป็นเส้นตรง $10^5$ จุด และมี $10^5$ คำถาม ก็คือราว $10^{10}$ ก้าว ไม่มีทางทัน ต้องหาวิธีที่ "ก้าวยาว ๆ" ได้

## Binary lifting: เก็บก้าวยาว $2^k$

ไอเดียเดียวกับ binary exponentiation ในบท Math Tools: จำนวนใด ๆ เขียนเป็นผลรวมของกำลังของสองได้ ถ้าเรารู้ว่า**บรรพบุรุษชั้นที่ $2^k$** ของทุกจุดคือใคร การขึ้นไป $d$ ชั้นก็คือกระโดดตามบิตของ $d$ ไม่เกิน $\log_2 d$ ครั้ง

ให้ `up[k][v]` = บรรพบุรุษชั้นที่ $2^k$ ของ $v$ (ถ้าทะลุรากให้ติดอยู่ที่ราก)

* `up[0][v]` = parent ของ $v$ (ของรากให้เป็นรากเอง)
* กระโดด $2^k$ ชั้น = กระโดด $2^{k-1}$ ชั้นสองครั้ง: `up[k][v] = up[k-1][ up[k-1][v] ]`

ตารางทั้งหมดสร้างได้ใน $O(N \log N)$ แล้ว LCA ทำสองขั้น

1. **ทำให้ลึกเท่ากัน**: ให้ $u$ ลึกกว่า $\text{diff} = \text{depth}[u] - \text{depth}[v]$ ชั้น ไล่บิตของ `diff` บิตไหนเป็น 1 ก็กระโดด `u = up[k][u]` ถ้าได้ `u == v` แปลว่า $v$ เป็นบรรพบุรุษของ $u$ ตอบ $v$ เลย
2. **ยกทั้งคู่**: ไล่ $k$ จาก**ใหญ่ไปเล็ก** ถ้า `up[k][u] != up[k][v]` (กระโดดไปแล้วยังไม่เจอกัน) ให้กระโดดทั้งคู่ ถ้าเท่ากันแปลว่ากระโดดไกลไป เลยจุดบรรจบแล้ว อย่ากระโดด จบลูปแล้ว $u$ กับ $v$ จะเป็นลูกของ LCA คนละกิ่งพอดี ตอบ `up[0][u]`

ขั้นที่ 2 คือ binary search แบบหนึ่ง: เรากำลังหา "ชั้นสุดท้ายที่ยังไม่เจอกัน" ซึ่งเป็น `F F F T T T` แบบในบท binary search ถ้ากระโดดแล้วยังไม่เจอ ก็ปลอดภัย ถ้าเจอแล้ว ลองก้าวที่เล็กกว่า

## Template

โปรแกรมข้างล่างรับต้นไม้ $N$ จุด และคำถาม $Q$ ข้อ (บรรทัดแรก $N$ $Q$ ตามด้วยเส้นเชื่อม $N - 1$ บรรทัด แล้วคำถามบรรทัดละ $u$ $v$) แล้วตอบ LCA กับระยะทางเป็นจำนวนเส้น

```cpp
#include <bits/stdc++.h>
using namespace std;

const int LOG = 18;  // 2^18 = 262144 มากกว่าความลึกที่เป็นไปได้ (N <= 2*10^5)
int n;
vector<vector<int>> adj;
vector<int> depth_;
vector<vector<int>> up;  // up[k][v] = บรรพบุรุษชั้นที่ 2^k ของ v (ทะลุรากแล้วติดอยู่ที่ราก)

void build(int root) {
  depth_.assign(n + 1, 0);
  up.assign(LOG, vector<int>(n + 1, root));
  vector<bool> seen(n + 1, false);
  vector<int> order = {root};          // BFS: พ่อถูกเจอก่อนลูกเสมอ
  seen[root] = true;
  for (int i = 0; i < (int)order.size(); i++) {
    int u = order[i];
    for (int v : adj[u])
      if (!seen[v]) {
        seen[v] = true;
        up[0][v] = u;
        depth_[v] = depth_[u] + 1;
        order.push_back(v);
      }
  }
  for (int k = 1; k < LOG; k++)        // กระโดด 2^k = กระโดด 2^(k-1) สองครั้ง
    for (int v = 1; v <= n; v++) up[k][v] = up[k - 1][up[k - 1][v]];
}

int lca(int u, int v) {
  if (depth_[u] < depth_[v]) swap(u, v);   // ให้ u อยู่ลึกกว่า (หรือเท่ากัน)
  int diff = depth_[u] - depth_[v];
  for (int k = 0; k < LOG; k++)            // 1) ยก u ขึ้น diff ชั้น ตามบิตของ diff
    if (diff >> k & 1) u = up[k][u];
  if (u == v) return u;                    // v เป็นบรรพบุรุษของ u อยู่แล้ว
  for (int k = LOG - 1; k >= 0; k--)       // 2) ยกทั้งคู่ จากก้าวใหญ่ไปก้าวเล็ก
    if (up[k][u] != up[k][v]) {            //    ขยับเฉพาะเมื่อยังไม่เจอกัน
      u = up[k][u];
      v = up[k][v];
    }
  return up[0][u];                         // u, v เป็นลูกของ LCA คนละกิ่งพอดี
}

int main() {
  ios::sync_with_stdio(false);
  cin.tie(nullptr);
  int q;
  cin >> n >> q;
  adj.resize(n + 1);
  for (int i = 0; i < n - 1; i++) {
    int u, v;
    cin >> u >> v;
    adj[u].push_back(v);
    adj[v].push_back(u);
  }
  build(1);
  while (q--) {
    int u, v;
    cin >> u >> v;
    int w = lca(u, v);
    cout << "lca " << w << ", distance " << depth_[u] + depth_[v] - 2 * depth_[w] << '\n';
  }
}
```

ใช้ BFS ตั้งรากเพื่อไม่ต้องพึ่ง recursion (เส้นตรงสองแสนจุดก็ไม่พัง) และการตั้ง `up[0][root] = root` ทำให้กระโดดเกินรากแล้วติดอยู่ที่ราก ไม่หลุดไปจุดที่ไม่มีอยู่จริง

## ไล่มือหนึ่งรอบ

ต้นไม้ในรูปด้านบน input คือ

```text
9 3
1 2
1 3
2 4
2 5
3 6
5 7
6 8
7 9
9 4
9 8
5 9
```

ตาราง `up` (แถว $k \geq 3$ เป็น $1$ หมด เพราะต้นไม้ลึกแค่ $4$)

```text
v          1  2  3  4  5  6  7  8  9
depth      0  1  1  2  2  2  3  3  4
up[0]      1  1  1  2  2  3  5  6  7     พ่อ
up[1]      1  1  1  1  1  1  2  3  5     ขึ้น 2 ชั้น = up[0] ของ up[0]
up[2]      1  1  1  1  1  1  1  1  1     ขึ้น 4 ชั้น
```

**lca(9, 4)**: ลึก $4$ กับ $2$, $\text{diff} = 2 = 10_2$ บิตที่ 1 เป็น 1 จึงกระโดด `u = up[1][9] = 5` ตอนนี้ $5 \neq 4$ ไปขั้นที่ 2: `up[2]` และ `up[1]` ของ `5` กับ `4` เป็น `1` ทั้งคู่ (เท่ากัน ไม่กระโดด) `up[0]` เป็น `2` ทั้งคู่ (เท่ากัน ไม่กระโดด) ตอบ `up[0][5] = 2` ระยะทาง $4 + 2 - 2 \cdot 1 = 4$

**lca(9, 8)**: $\text{diff} = 1$ กระโดด `u = up[0][9] = 7` ขั้นที่ 2: $k = 2$ ได้ `1` กับ `1` ไม่กระโดด, $k = 1$ ได้ `up[1][7] = 2` กับ `up[1][8] = 3` ไม่เท่ากัน กระโดดเป็น `u = 2, v = 3`, $k = 0$ ได้ `1` กับ `1` ไม่กระโดด ตอบ `up[0][2] = 1` ระยะทาง $4 + 3 - 0 = 7$ (คือ `9 - 7 - 5 - 2 - 1 - 3 - 6 - 8` จริง)

**lca(5, 9)**: สลับให้ `u = 9` ลึกกว่า $\text{diff} = 2$ กระโดดได้ `u = 5` เท่ากับ `v` พอดี ตอบ `5` ระยะ $2$

โปรแกรมพิมพ์ `lca 2, distance 4` / `lca 1, distance 7` / `lca 5, distance 2` ตรงกับที่ไล่มือ

:::problem lp_lca01_family_tree

:::hint ใบ้ Family Tree
คราวนี้โจทย์ให้พ่อแม่ $p_i$ มาตรง ๆ แทนเส้นเชื่อม `up[0]` จึงได้มาฟรี แต่ depth ยังต้องคำนวณเอง และเพราะ $p_i$ อาจมากกว่า $i$ จะวน $i = 2, 3, \ldots$ แล้วเขียน `depth[i] = depth[p[i]] + 1` ไม่ได้ (พ่ออาจยังไม่มี depth) ให้สร้างรายชื่อลูกแล้ว BFS จากต้นตระกูล อย่าลืมให้ `up[0][1] = 1`
:::

## ต่อยอด: ระยะทางกับคำถามบนเส้นทาง

ถ้าเส้นเชื่อมมีความยาว เพิ่มอาเรย์ `D` (`long long`) ตอน BFS: `D[v] = D[u] + w` แล้วใช้

```cpp
long long dist(int u, int v) { return D[u] + D[v] - 2 * D[lca(u, v)]; }
```

ตาราง `up` ไม่ต้องเปลี่ยนเลย เพราะ LCA ไม่สนใจความยาว สนใจแค่โครงของต้นไม้ ด้วยฟังก์ชันนี้ คำถามอย่าง "จุด $c$ อยู่บนทาง $a - b$ ไหม" "ทางจาก $a$ ไป $b$ ผ่าน LCA ตรงไหน" หรือ "ระยะทางรวมของการเดิน $a \to c \to b$" ก็ตอบได้ด้วย LCA ไม่กี่ครั้งต่อคำถาม

:::problem lp_lca02_detour

:::hint ใบ้ Detour
ถ้ามี `dist(x, y)` ที่เร็ว สูตรในโจทย์ก็คำนวณได้ตรง ๆ ลองถามตัวเองว่ากรณีอย่าง $a = b$ หรือ $c$ อยู่บนเส้นทางต้องแยกคิดไหม (ลองแทนค่าในตัวอย่างดู) ระวังสองเรื่อง: โจทย์ให้แค่เส้นเชื่อม ต้องเลือกรากเองแล้วสร้าง `up`, `depth`, `D` ด้วย BFS และ `D` ไปได้ถึง $5 \cdot 10^{10}$ ต้องเป็น `long long`
:::

## เกริ่น Euler tour: เช็กบรรพบุรุษใน $O(1)$

DFS ที่ใช้ stack ในบท Tree Basics มีสมบัติที่ยังไม่ได้ใช้: ใน `order` **ซับทรีของแต่ละจุดอยู่ติดกันเป็นช่วงเดียว** เริ่มที่ตัวมันเอง (เพราะพอหยิบจุดหนึ่งออกมา ลูกหลานทั้งหมดของมันจะถูกหยิบจนหมดก่อนจะกลับไปหยิบของที่อยู่ใต้มันใน stack) ให้ `tin[v]` = ตำแหน่งของ $v$ ใน `order` แล้วซับทรีของ $v$ คือช่วง `[tin[v], tin[v] + sz[v] - 1]`

```cpp
// ตอนหยิบ u ออกจาก stack:  tin[u] = order.size();  order.push_back(u);
// แล้วคำนวณ sz แบบเดิม
auto isAncestor = [&](int u, int v) {   // u เป็นบรรพบุรุษของ v (นับตัวเองด้วย) ไหม
  return tin[u] <= tin[v] && tin[v] < tin[u] + sz[u];
};
```

กับต้นไม้และ input ในบทนี้ได้ `tin[2] = 4` และ `sz[2] = 5` (คือ `2, 4, 5, 7, 9`) ซับทรีจึงเป็นช่วง $[4, 8]$ ซึ่งมี `tin[9] = 7` อยู่ด้วย จึงรู้ว่า `2` เป็นบรรพบุรุษของ `9` โดยไม่ต้องกระโดดเลย (ระวัง: สมบัตินี้เป็นของ DFS order เท่านั้น BFS order ไม่มี)

การแบนต้นไม้เป็นอาเรย์แบบนี้เรียกว่า **Euler tour** และพาไปสู่อีกหลายท่า เช่น "บวกค่าให้ทั้งซับทรี" กลายเป็น "บวกค่าให้ทั้งช่วงในอาเรย์" และ LCA เองก็หาได้ด้วย Euler tour รุ่นที่จดจุดซ้ำตอนเดินกลับ แล้วถาม "จุดที่ตื้นที่สุดในช่วง" ด้วย sparse table ได้ $O(1)$ ต่อคำถาม ซึ่งจะต่อยอดได้เมื่อเรียน range queries ใน track Advanced

## ความซับซ้อน

| วิธี | เตรียม | ต่อคำถาม | หน่วยความจำ |
|---|---|---|---|
| ไล่ขึ้นทีละชั้น | $O(N)$ | $O(\text{depth})$ ซึ่งเป็น $O(N)$ ในเส้นตรง | $O(N)$ |
| binary lifting | $O(N \log N)$ | $O(\log N)$ | $O(N \log N)$ |

$N = 2 \cdot 10^5$ กับ `LOG = 18` คือตาราง $3.6$ ล้านช่อง `int` ราว $14$ MB สบาย ๆ

:::note ถ้าเขียน Python
binary lifting ใน Python หนักกว่า C++ มาก ท่าที่ช่วย: อ่าน input ทีเดียวด้วย `sys.stdin.buffer.read().split()`, สร้างแถวของตารางด้วย list comprehension `nxt = [prev[x] for x in prev]`, ขั้นที่ 1 วนเฉพาะบิตของ `diff` (`while diff: ... diff >>= 1`), ขั้นที่ 2 เริ่ม $k$ จาก `depth[v].bit_length() - 1` แทน `LOG - 1` เพราะก้าวที่ยาวกว่าความลึกไม่มีประโยชน์ และรวมคำตอบไว้พิมพ์ทีเดียวด้วย `"\n".join(...)`
:::

:::warning จุดที่พลาดบ่อย
* **`LOG` เล็กไป** ต้องได้ $2^{\text{LOG}} > $ ความลึกที่มากที่สุด ($N - 1$ ในเส้นตรง) ไม่อย่างนั้นขั้นที่ 1 ยกไม่ถึง
* **ลืมให้ parent ของรากเป็นรากเอง** ถ้า `up[0][root] = 0` แล้วจุด $0$ ไม่ได้ตั้งค่าไว้ การกระโดดเกินรากจะพาไปจุดมั่ว ๆ
* **ขั้นที่ 2 วน $k$ จากเล็กไปใหญ่** ผิดทันที ต้องจากใหญ่ไปเล็ก (ขั้นที่ 1 วนทางไหนก็ได้ เพราะแค่บวกก้าวตามบิต)
* **ลืมเช็ก `u == v` หลังขั้นที่ 1** กรณีที่จุดหนึ่งเป็นบรรพบุรุษของอีกจุด ขั้นที่ 2 จะไม่กระโดดเลยแล้วตอบ `up[0][u]` ซึ่งสูงไปหนึ่งชั้น
* **สร้างตารางผิดลำดับ** ต้องเติม `up[k - 1]` ให้ครบทุกจุดก่อนเริ่ม `up[k]` (ลูปนอกคือ $k$ ลูปในคือ $v$)
* **ระยะทางแบบมีความยาว** ใช้ `long long` ทั้ง `D` และผลลัพธ์
:::

## สรุปสั้น ๆ

* LCA = จุดที่ทางขึ้นรากของ $u$ กับ $v$ มาเจอกันครั้งแรก เส้นทาง $u - v$ คือขึ้นไปถึง LCA แล้วลง
* ระยะทาง $= \text{depth}[u] + \text{depth}[v] - 2 \cdot \text{depth}[\text{lca}]$ (มีความยาวก็ใช้ $D$ แทน depth) และ $c$ อยู่บนทาง $a - b$ เมื่อ $d(a, c) + d(c, b) = d(a, b)$
* ไล่ขึ้นทีละชั้นได้ $O(\text{depth})$ ต่อคำถาม ช้าในต้นไม้ที่เป็นเส้นยาว
* binary lifting: `up[k][v] = up[k-1][up[k-1][v]]` แล้ว (1) ยกตัวที่ลึกกว่าตามบิตของ `diff` (2) ยกทั้งคู่จาก $k$ ใหญ่ไปเล็กเมื่อยังไม่เจอกัน ตอบ `up[0][u]`
* เตรียม $O(N \log N)$ ถาม $O(\log N)$ ตั้งรากด้วย BFS และให้ parent ของรากเป็นตัวเอง
* DFS order ทำให้ซับทรีเป็นช่วงติดกัน: เช็กบรรพบุรุษได้ $O(1)$ และเป็นประตูสู่ Euler tour
