## กราฟอยู่รอบตัวเรา

เพื่อนในเฟซบุ๊ก, ถนนระหว่างเมือง, เที่ยวบิน, ลิงก์ระหว่างเว็บ ทั้งหมดนี้หน้าตาเหมือนกันคือ มี "สิ่งของ" กับ "ความเชื่อมโยงระหว่างสิ่งของ" เราเรียกโครงสร้างแบบนี้ว่า **กราฟ (graph)**

* **จุดยอด (vertex)** คือสิ่งของ เช่น คนหรือเมือง โจทย์มักใส่หมายเลข $1$ ถึง $N$
* **เส้นเชื่อม (edge)** คือความเชื่อมโยงระหว่างจุดยอดสองจุด โจทย์มักให้มา $M$ เส้น

เส้นเชื่อมมีสองแบบหลัก ๆ

* **ไม่มีทิศทาง (undirected)** เช่นความเป็นเพื่อน: ถ้า A เป็นเพื่อน B แล้ว B ก็เป็นเพื่อน A
* **มีทิศทาง (directed)** เช่นถนนเดินรถทางเดียว: ไป $a \to b$ ได้ ไม่ได้แปลว่าไป $b \to a$ ได้

```text
ไม่มีทิศทาง (N = 7, M = 6)              มีทิศทาง

  1 --- 2          6 --- 7              1 ---> 2
  |     |                               ^      |
  3 --- 4 --- 5                         |      v
                                        4 <--- 3
```

กราฟฝั่งซ้ายนี้จะใช้เป็นตัวอย่างตลอดบท สังเกตว่ามันแยกเป็นสองก้อน: $\{1, 2, 3, 4, 5\}$ กับ $\{6, 7\}$ ก้อนแบบนี้เรียกว่า **connected component** ถ้าเส้นเชื่อมมีน้ำหนัก (เช่นระยะทางถนน) ก็เรียกว่ากราฟถ่วงน้ำหนัก ซึ่งจะอยู่ในบท Shortest Paths บทนี้สนใจแค่ว่า "เชื่อมกันหรือไม่"

## เก็บกราฟในคอมพิวเตอร์

โจทย์ส่วนใหญ่ให้กราฟมาเป็น **edge list** คือบรรทัดแรกบอก $N$ กับ $M$ แล้วตามด้วย $M$ บรรทัด บรรทัดละคู่ $u\ v$ เราต้องแปลงมันเป็นโครงสร้างที่ถามได้เร็วว่า "จุดนี้ติดกับใครบ้าง" มีสองแบบให้เลือก

**Adjacency matrix** ตาราง `adj[u][v] = 1` ถ้ามีเส้น $u$–$v$ ถามว่ามีเส้นไหมได้ใน $O(1)$ แต่กินที่ $N^2$ ช่องเสมอ และการไล่เพื่อนบ้านของ $u$ ต้องวนครบ $N$ ช่อง

**Adjacency list** ให้แต่ละจุดเก็บรายชื่อเพื่อนบ้านของตัวเองใน `vector` กินที่แค่ $N + 2M$ ไล่เพื่อนบ้านได้เร็วเท่าจำนวนเพื่อนบ้านจริง ๆ

```text
adj[1] = {2, 3}       adj[4] = {2, 3, 5}       adj[7] = {6}
adj[2] = {1, 4}       adj[5] = {4}
adj[3] = {1, 4}       adj[6] = {7}
```

| | adjacency matrix | adjacency list |
|---|---|---|
| หน่วยความจำ | $N^2$ | $N + 2M$ |
| $N = 10^5$, $M = 2 \cdot 10^5$ | $10^{10}$ ช่อง (ประมาณ 10 GB แม้ใช้ `bool`) | ประมาณ $5 \cdot 10^5$ ตัวเลข (ไม่ถึง 4 MB) |
| ไล่เพื่อนบ้านของทุกจุด | $O(N^2)$ | $O(N + M)$ |
| เหมาะกับ | $N$ เล็ก (ไม่เกินราว ๆ $2{,}000$) หรือต้องถาม "มีเส้นนี้ไหม" บ่อย ๆ | เกือบทุกโจทย์ |

ในการแข่งขันใช้ adjacency list เป็นค่าเริ่มต้นได้เลย การอ่านกราฟจะหน้าตาแบบนี้ทุกครั้ง

```cpp
int n, m;
cin >> n >> m;
vector<vector<int>> adj(n + 1);    // n + 1 เพราะจุดยอดเริ่มที่ 1
for (int i = 0; i < m; i++) {
  int u, v;
  cin >> u >> v;
  adj[u].push_back(v);
  adj[v].push_back(u);             // ไม่มีทิศทาง: ใส่ทั้งสองฝั่ง (มีทิศทางให้ลบบรรทัดนี้)
}
```

## DFS: เดินลึกไปก่อน

**Depth-First Search** คือการเดินสำรวจแบบ "เจอทางไหนลุยไปทางนั้นจนสุด แล้วค่อยถอยกลับมาลองทางอื่น" เหมือนเดินในเขาวงกตแล้วเอามือแตะกำแพงไว้ สิ่งเดียวที่ต้องจำคือ `seen[v]` ว่าจุดไหนไปมาแล้ว จะได้ไม่วนไม่รู้จบ

เขียนแบบ recursive ได้สั้นมาก และเป็นท่าเดียวกับ backtracking ในบท Recursion

### Template: นับจำนวนจุดที่ไปถึงได้จากจุด $s$ (recursive)

```cpp
#include <bits/stdc++.h>
using namespace std;

vector<vector<int>> adj;
vector<char> seen;

int dfs(int u) {           // คืนจำนวนจุดที่เพิ่งได้ไปเยือนจาก u
  seen[u] = 1;
  int count = 1;
  for (int v : adj[u])
    if (!seen[v]) count += dfs(v);
  return count;
}

int main() {
  ios::sync_with_stdio(false);
  cin.tie(nullptr);
  int n, m, s;
  cin >> n >> m >> s;
  adj.assign(n + 1, {});
  seen.assign(n + 1, 0);
  for (int i = 0; i < m; i++) {
    int u, v;
    cin >> u >> v;
    adj[u].push_back(v);
    adj[v].push_back(u);
  }
  cout << dfs(s) << '\n';
}
```

กับกราฟตัวอย่างและ $s = 1$ (input `7 6 1` แล้วตามด้วยเส้น `1 2`, `1 3`, `2 4`, `3 4`, `4 5`, `6 7`) จะพิมพ์ `5`

### ระวังความลึกของ recursion

ทุกครั้งที่ `dfs` เรียกตัวเอง ระบบต้องจองที่บน **stack** เพิ่ม ถ้ากราฟเป็นเส้นตรงยาว $10^6$ จุด recursion ก็ลึก $10^6$ ชั้น ซึ่งเกิน stack (ปกติประมาณ 8 MB) แล้วโปรแกรมพังเป็น Runtime Error ทั้งที่อัลกอริทึมถูก ลองรัน template ข้างบนด้วย stack 8 MB ดู: เส้นตรง $10^5$ จุดยังรอด แต่ $10^6$ จุดได้ Segmentation fault ทันที ถ้า $N$ ใหญ่ระดับหลักแสนขึ้นไปและกราฟอาจเป็นเส้นยาว (หรือเป็นตาราง ซึ่งจะเจอในบทถัดไป) ให้เปลี่ยนมาใช้ **stack ที่เราถือเอง**

### Template: แบบ iterative ด้วย stack ของเราเอง

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
  ios::sync_with_stdio(false);
  cin.tie(nullptr);
  int n, m, s;
  cin >> n >> m >> s;
  vector<vector<int>> adj(n + 1);
  for (int i = 0; i < m; i++) {
    int u, v;
    cin >> u >> v;
    adj[u].push_back(v);
    adj[v].push_back(u);
  }
  vector<char> seen(n + 1, 0);
  vector<int> st = {s};      // stack ของเราเอง อยู่บน heap ไม่มีปัญหาเรื่องความลึก
  seen[s] = 1;               // mark ตอนใส่ลง stack แต่ละจุดจะถูกใส่แค่ครั้งเดียว
  int count = 0;
  while (!st.empty()) {
    int u = st.back();
    st.pop_back();
    count++;
    for (int v : adj[u]) {
      if (!seen[v]) {
        seen[v] = 1;
        st.push_back(v);
      }
    }
  }
  cout << count << '\n';
}
```

ลำดับที่แบบนี้เดินไม่ตรงกับ recursive เป๊ะ ๆ แต่ **ชุดของจุดที่ไปถึงเหมือนกันทุกประการ** ซึ่งเป็นทั้งหมดที่ต้องการเวลานับ component หรือเช็กว่าไปถึงกันไหม

## Connected components

อยากรู้ว่ากราฟแยกเป็นกี่ก้อน ก็วนทุกจุด ถ้าเจอจุดที่ยังไม่เคยไป แปลว่าเจอก้อนใหม่ ให้ DFS จากจุดนั้นหนึ่งรอบ ซึ่งจะ mark ทั้งก้อนเป็น "ไปแล้ว"

```cpp
int components = 0;
for (int s = 1; s <= n; s++) {
  if (seen[s]) continue;
  components++;
  // DFS จาก s แบบในเทมเพลตข้างบน: ทั้งก้อนของ s จะถูก mark
}
```

ดูเหมือนลูปซ้อน แต่ทุกจุดถูก mark แค่ครั้งเดียว และทุกเส้นเชื่อมถูกมองแค่สองครั้ง (จากปลายทั้งสองข้าง) รวมทั้งหมดจึงเป็น $O(N + M)$

:::problem lp_gph01_friend_groups

:::hint ใบ้ Friend Groups
ใช้ลูป component ข้างบนได้เลย แต่ละรอบ DFS ให้นับด้วยว่าก้อนนั้นมีกี่จุด (ตัวแปร `count` ใน template) แล้วจดตัวที่มากที่สุด อย่าลืมคนที่ไม่มีเพื่อนเลย เขาก็เป็นก้อนขนาด $1$ ด้วย และ $N$ ถึง $10^5$ กราฟอาจเป็นเส้นยาว ใช้แบบ iterative จะสบายใจกว่า
:::

## กราฟนี้มีวงไหม

ในกราฟไม่มีทิศทาง ระหว่างเดิน ถ้าเราเจอเพื่อนบ้าน $v$ ที่ **ไปมาแล้ว** และ $v$ **ไม่ใช่จุดที่พาเรามา** (parent) แปลว่ามีอีกทางหนึ่งที่มาถึง $v$ ได้ นั่นคือเจอวงแล้ว

```text
     1          เดินจาก 1: 1 -> 2 -> 3 แล้ว 3 มองเห็น 1
    / \         1 ไปมาแล้ว และ 1 ไม่ใช่ parent ของ 3 (parent คือ 2)
   2 - 3        จึงมีวง 1 - 2 - 3 - 1
```

ต้องเช็ก parent ด้วยเพราะเส้น $u$–$v$ ถูกเก็บไว้ทั้งใน `adj[u]` และ `adj[v]` ถ้าไม่เช็ก เส้นที่เพิ่งเดินมาจะถูกนับเป็นวงเสมอ ดัดแปลงจาก template แบบ iterative ได้แบบนี้ (อ่านกราฟเหมือนเดิม)

```cpp
vector<int> parent(n + 1, -1);   // -1 = ยังไม่เคยไป, 0 = จุดเริ่มของก้อน
bool cycle = false;
for (int s = 1; s <= n && !cycle; s++) {
  if (parent[s] != -1) continue;
  parent[s] = 0;
  vector<int> st = {s};
  while (!st.empty() && !cycle) {
    int u = st.back();
    st.pop_back();
    for (int v : adj[u]) {
      if (parent[v] == -1) {
        parent[v] = u;
        st.push_back(v);
      } else if (v != parent[u]) {
        cycle = true;            // v ไปมาแล้ว และไม่ใช่ทางที่พา u มา
        break;
      }
    }
  }
}
```

กับกราฟตัวอย่างได้ `cycle = true` จากวง $1$–$2$–$4$–$3$–$1$ ถ้าลบเส้น $3$–$4$ ออกจะได้ `false`

:::note ทางลัดด้วยการนับ
ก้อนที่มี $k$ จุดและไม่มีวงคือต้นไม้ ซึ่งมีเส้นเชื่อม $k - 1$ เส้นพอดี ดังนั้นถ้าให้ $c$ เป็นจำนวน component กราฟ (ที่ไม่มีเส้นซ้ำ) จะไม่มีวงเลยก็ต่อเมื่อ $M = N - c$ นับ component ได้ก็เช็กวงได้ทันที
:::

## BFS: เดินเป็นชั้น ๆ และหาทางที่สั้นที่สุด

**Breadth-First Search** เดินต่างจาก DFS: แทนที่จะลุยลึก มันกระจายออกเป็น **ชั้น ๆ** เหมือนคลื่นน้ำเวลาโยนหินลงสระ ชั้นที่ $0$ คือจุดเริ่ม ชั้นที่ $1$ คือเพื่อนบ้านของจุดเริ่ม ชั้นที่ $2$ คือเพื่อนบ้านของชั้น $1$ ที่ยังไม่เคยเจอ ไปเรื่อย ๆ

เครื่องมือคือ **queue** (เข้าก่อนออกก่อน) ทำให้ทุกจุดของชั้น $d$ ถูกหยิบออกมาก่อนทุกจุดของชั้น $d + 1$ เสมอ ผลคือ **ครั้งแรกที่ BFS เจอจุด $v$ ก็คือผ่านทางที่ใช้จำนวนเส้นน้อยที่สุดแล้ว** เพราะถ้ามีทางที่สั้นกว่า $v$ ก็ต้องอยู่ชั้นที่ตื้นกว่าและถูกเจอไปก่อนหน้านี้แล้ว

นี่คือเหตุผลที่ BFS เป็นอัลกอริทึมหา **shortest path ในกราฟที่ไม่มีน้ำหนัก** (ทุกเส้นยาวเท่ากัน) ส่วน DFS ให้คำตอบนี้ไม่ได้

### Template: ระยะทาง (จำนวนเส้น) จาก $s$ ไปทุกจุด

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
  ios::sync_with_stdio(false);
  cin.tie(nullptr);
  int n, m, s;
  cin >> n >> m >> s;
  vector<vector<int>> adj(n + 1);
  for (int i = 0; i < m; i++) {
    int u, v;
    cin >> u >> v;
    adj[u].push_back(v);
    adj[v].push_back(u);
  }
  vector<int> dist(n + 1, -1);     // -1 = ยังไปไม่ถึง (ใช้แทน seen ได้ด้วย)
  queue<int> q;
  dist[s] = 0;
  q.push(s);
  while (!q.empty()) {
    int u = q.front();
    q.pop();
    for (int v : adj[u]) {
      if (dist[v] == -1) {         // เจอครั้งแรก = ทางที่สั้นที่สุด
        dist[v] = dist[u] + 1;
        q.push(v);
      }
    }
  }
  for (int v = 1; v <= n; v++) cout << dist[v] << " \n"[v == n];
}
```

### ลองไล่ด้วยมือ

กราฟตัวอย่าง เริ่มที่ $s = 1$

| หยิบ `u` | `dist[u]` | เพื่อนบ้านที่เพิ่งเจอ (ได้ `dist`) | queue หลังจบรอบ |
|---|---|---|---|
| | | เริ่ม: `dist[1] = 0` | `1` |
| 1 | 0 | 2 (1), 3 (1) | `2 3` |
| 2 | 1 | 4 (2) | `3 4` |
| 3 | 1 | ไม่มี (1 กับ 4 เจอแล้ว) | `4` |
| 4 | 2 | 5 (3) | `5` |
| 5 | 3 | ไม่มี | ว่าง |

ผลคือ `0 1 1 2 3 -1 -1` จุด $6$ กับ $7$ อยู่คนละก้อนจึงเป็น $-1$ สังเกตแถวของจุด $3$: มันเห็นจุด $4$ แต่ $4$ ถูกเจอแล้วจากจุด $2$ ด้วยระยะ $2$ เท่ากัน ไม่ต้องทำอะไรเพิ่ม

:::problem lp_gph02_one_way_flights

:::hint ใบ้ One-Way Flights
เที่ยวบินมีทิศทาง ใส่แค่ `adj[a].push_back(b)` ฝั่งเดียว แล้วถามตัวเองว่า: คำถามทุกข้อเริ่มจากเมือง $1$ เหมือนกันหมด จำเป็นต้อง BFS ใหม่ทุกคำถามจริงหรือ? BFS รอบเดียวให้ `dist` ของ **ทุกเมือง** อยู่แล้ว
:::

## พรีวิว: แบ่งเป็นสองฝั่งได้ไหม (bipartite)

กราฟ **bipartite** คือกราฟที่ระบายสีจุดยอดด้วยสองสีได้ โดยทุกเส้นเชื่อมจุดต่างสีกันเสมอ เช่น แบ่งคนเป็นสองทีมโดยไม่มีคู่ที่มีปัญหากันอยู่ทีมเดียวกัน

ใช้ BFS (หรือ DFS) ระบายสีได้ตรง ๆ: จุดเริ่มเป็นสี $0$ เพื่อนบ้านต้องเป็นสีตรงข้าม ถ้าเจอเพื่อนบ้านที่ระบายไปแล้วและ **สีเดียวกัน** ก็แบ่งไม่ได้ ทำแบบนี้กับทุก component เพราะแต่ละก้อนระบายแยกกันได้อิสระ

```text
วงสี่จุด: ได้                  สามเหลี่ยม: ไม่ได้
  1(0) - 2(1)                    1(0) - 2(1)
   |      |                         \   /
  4(1) - 3(0)                       3(?)   ติดกับทั้งสี 0 และสี 1
```

ความจริงที่น่าจำ: กราฟเป็น bipartite **ก็ต่อเมื่อไม่มีวงที่ยาวเป็นจำนวนคี่** วงคู่ระบายสลับกันได้พอดี แต่วงคี่จะวนกลับมาชนสีตัวเองเสมอ

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
  ios::sync_with_stdio(false);
  cin.tie(nullptr);
  int n, m;
  cin >> n >> m;
  vector<vector<int>> adj(n + 1);
  for (int i = 0; i < m; i++) {
    int u, v;
    cin >> u >> v;
    adj[u].push_back(v);
    adj[v].push_back(u);
  }
  vector<int> color(n + 1, -1);
  bool ok = true;
  for (int s = 1; s <= n && ok; s++) {
    if (color[s] != -1) continue;    // ก้อนใหม่ เริ่มระบายที่ s
    color[s] = 0;
    queue<int> q;
    q.push(s);
    while (!q.empty() && ok) {
      int u = q.front();
      q.pop();
      for (int v : adj[u]) {
        if (color[v] == -1) {
          color[v] = 1 - color[u];   // สีตรงข้าม
          q.push(v);
        } else if (color[v] == color[u]) {
          ok = false;                // สองฝั่งของเส้นสีเดียวกัน
        }
      }
    }
  }
  cout << (ok ? "YES" : "NO") << '\n';
}
```

input `4 4` / `1 2` / `2 3` / `3 4` / `4 1` พิมพ์ `YES` และ `3 3` / `1 2` / `2 3` / `3 1` พิมพ์ `NO`

:::problem lp_gph03_rival_teams

:::hint ใบ้ Rival Teams
ถ้าคู่อริ $k$ คู่แรกแบ่งทีมไม่ได้แล้ว เพิ่มคู่อริเข้าไปอีกจะกลับมาแบ่งได้ไหม? ไม่มีทาง เพราะวงคี่ที่มีอยู่ไม่หายไปไหน คำถาม "$k$ คู่แรกยังแบ่งได้ไหม" จึงเป็น `T T T F F F` ซึ่งเป็นรูปแบบเดียวกับบท Binary Search on the Answer เป๊ะ ใช้โค้ดระบายสีข้างบนเป็นฟังก์ชันตรวจ (สร้างกราฟจากเส้น $k$ เส้นแรก) แล้ว binary search หา `F` ตัวแรก อย่าลืมเช็กก่อนว่าครบ $M$ คู่แล้วยังเป็น `T` หรือเปล่า
:::

## ความซับซ้อน

ทั้ง DFS และ BFS บน adjacency list หยิบแต่ละจุดออกมาแค่ครั้งเดียว และไล่เพื่อนบ้านของมันครั้งเดียว รวมเป็น $O(N + M)$ ทั้งการนับ component, หาวง, ระบายสองสี และหาระยะทางจากจุดเริ่มหนึ่งจุด ถ้าเก็บเป็น adjacency matrix การไล่เพื่อนบ้านทุกจุดกลายเป็น $O(N^2)$ ทันที

สิ่งที่ทำให้ช้าบ่อยที่สุดไม่ใช่ตัว BFS แต่คือ **การเรียกมันซ้ำ ๆ** โดยไม่จำเป็น เช่น BFS ใหม่ทุกคำถาม หรือตรวจทั้งกราฟใหม่ทุกครั้งที่เพิ่มเส้น ถ้า $Q$ หรือ $M$ ใหญ่ $O(Q(N + M))$ ไม่มีทางทัน

## จุดที่พลาดบ่อย

:::warning ขนาดของ vector
จุดยอดเริ่มที่ $1$ ให้จอง `adj(n + 1)` และ `dist(n + 1)` ถ้าจองแค่ `n` การเข้าถึง `adj[n]` จะเขียนทับหน่วยความจำนอกขอบ ซึ่งบางทีก็ไม่พังให้เห็นทันที แต่ผลลัพธ์เพี้ยน
:::

:::warning ลืมใส่ทิศกลับ หรือใส่เกิน
กราฟไม่มีทิศทางต้อง `push_back` ทั้ง `adj[u]` และ `adj[v]` ส่วนกราฟมีทิศทางใส่แค่ `adj[a]` อ่านโจทย์ให้ดีว่าเส้นเชื่อมเดินได้ทางเดียวหรือสองทาง
:::

:::warning mark ตอนใส่ ไม่ใช่ตอนหยิบ
ใน BFS ให้ตั้ง `dist[v]` (หรือ `seen[v]`) **ตอนใส่ลง queue** ถ้าไป mark ตอนหยิบออก จุดเดียวกันจะถูกใส่ซ้ำได้หลายรอบจากเพื่อนบ้านหลายตัว queue บวม เวลาพุ่ง และถ้าเขียนไม่ระวังระยะที่ได้ก็ผิดด้วย
:::

:::warning recursion ลึกเกินไป
DFS แบบ recursive บนกราฟเส้นตรงที่ยาวหลักแสนถึงหลักล้านจุดอาจทำ stack ล้นจนได้ Runtime Error ถ้าไม่แน่ใจให้ใช้แบบ iterative ไปเลย
:::

:::warning ไปไม่ถึงต้องตอบอะไร
ตั้ง `dist` เริ่มต้นเป็น $-1$ (หรือค่าที่โจทย์กำหนด) ไม่ใช่ $0$ ไม่อย่างนั้นจุดที่ไปไม่ถึงจะดูเหมือนอยู่ห่าง $0$ ก้าว
:::

## สรุปสั้น ๆ

* กราฟ = จุดยอด $N$ จุด + เส้นเชื่อม $M$ เส้น แบบมีทิศทางหรือไม่มีทิศทาง
* เก็บเป็น adjacency list (`vector<vector<int>> adj(n + 1)`) กินที่ $O(N + M)$ matrix ใช้ได้เฉพาะเมื่อ $N$ เล็ก
* DFS เดินลึกก่อน ใช้หาว่าไปถึงไหนบ้าง นับ component และหาวง ถ้ากราฟอาจลึกมากให้ใช้ stack ของตัวเอง
* BFS เดินเป็นชั้นด้วย queue ครั้งแรกที่เจอจุดไหนคือระยะที่สั้นที่สุด (กราฟไม่มีน้ำหนัก)
* Bipartite = ระบายสองสีได้ = ไม่มีวงคี่ เช็กด้วย BFS ระบายสีทีละก้อน
* ทุกอย่างเป็น $O(N + M)$ ต่อการเดินหนึ่งรอบ อย่าเดินซ้ำโดยไม่จำเป็น
