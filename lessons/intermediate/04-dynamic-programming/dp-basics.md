## ปัญหาย่อยที่ซ้ำกัน

ลองเขียน Fibonacci แบบตรงตามนิยาม $F(n) = F(n - 1) + F(n - 2)$ ด้วย recursion จากบท Thinking Recursively ดู

```cpp
long long fib(int n) {
  if (n <= 1) return n;
  return fib(n - 1) + fib(n - 2);
}
```

ถูกต้องทุกอย่าง แต่ `fib(50)` รอเป็นนาที ลองวาดต้นไม้การเรียกของ `fib(5)` ดู

```text
                       fib(5)
                /                 \
           fib(4)                 fib(3)      <- fib(3) โผล่สองรอบ
          /      \               /      \
      fib(3)    fib(2)       fib(2)    fib(1)  <- fib(2) โผล่สามรอบ
      /    \     /   \       /   \
  fib(2) fib(1) fib(1) fib(0) fib(1) fib(0)
  /   \
fib(1) fib(0)
```

ปัญหาย่อยตัวเดิมถูกคิดใหม่ซ้ำแล้วซ้ำอีก จำนวนการเรียกโตแบบ exponential (ประมาณ $1.6^n$) ทั้งที่จริง ๆ มีปัญหาย่อยที่ต่างกันแค่ $n + 1$ ตัว คือ `fib(0)` ถึง `fib(n)` เท่านั้น

นี่คือหัวใจของ **Dynamic Programming (DP)**: ถ้าปัญหาแตกเป็นปัญหาย่อยที่ **ซ้ำกัน** (overlapping subproblems) และคำตอบของปัญหาใหญ่สร้างได้จากคำตอบของปัญหาย่อย ก็ **คิดแต่ละปัญหาย่อยแค่ครั้งเดียวแล้วจดไว้** พอต้องใช้อีกก็หยิบจากที่จดมาใช้เลย

## สองวิธีจด: memoisation กับ tabulation

**Memoisation (top-down)** เขียน recursion เหมือนเดิมทุกอย่าง แค่เพิ่มสมุดจด ก่อนคำนวณให้ดูก่อนว่าเคยคิดไว้หรือยัง

```cpp
#include <bits/stdc++.h>
using namespace std;

vector<long long> memo;   // -1 = ยังไม่เคยคิด

long long fib(int n) {
  if (n <= 1) return n;
  if (memo[n] != -1) return memo[n];          // เคยคิดแล้ว หยิบมาใช้เลย
  return memo[n] = fib(n - 1) + fib(n - 2);   // คิดครั้งแรก แล้วจดไว้
}

int main() {
  int n;
  cin >> n;               // n <= 90 (fib(92) ยังพอดี long long)
  memo.assign(n + 1, -1);
  cout << fib(n) << '\n';
}
```

**Tabulation (bottom-up)** ไม่ใช้ recursion เลย แต่เติมตารางจากปัญหาย่อยที่เล็กที่สุดขึ้นไป เพราะรู้ว่า `dp[i]` ใช้แค่ `dp[i - 1]` กับ `dp[i - 2]` ซึ่งเติมไว้ก่อนแล้ว

```cpp
vector<long long> dp(max(n + 1, 2));
dp[0] = 0;
dp[1] = 1;                                   // base case
for (int i = 2; i <= n; i++) dp[i] = dp[i - 1] + dp[i - 2];
```

ทั้งสองแบบเป็น $O(n)$ เท่ากัน เลือกยังไงดี?

| | Memoisation | Tabulation |
|---|---|---|
| เขียน | แปลงจาก recursion ตรง ๆ คิดง่าย | ต้องคิดลำดับการเติมตารางเอง |
| คิดเฉพาะ state ที่ใช้จริง | ใช่ | ไม่ เติมทั้งตาราง |
| ความลึกของ recursion | ลึกได้ถึงจำนวน state อาจ stack overflow | ไม่มีปัญหา |
| ความเร็วจริง | ช้ากว่านิดหน่อย (ค่าเรียกฟังก์ชัน) | เร็ว ลดหน่วยความจำได้ง่าย |

ในการแข่งขัน ส่วนใหญ่เขียนแบบ tabulation แต่ตอนคิดโจทย์ใหม่ ๆ การนึกเป็น recursion ก่อนแล้วค่อยแปลงมักง่ายกว่า

## สี่คำถามก่อนเขียน DP ทุกข้อ

1. **State คืออะไร** `dp[i]` แปลว่าอะไร **เป็นประโยคภาษาคน** เช่น "จำนวนวิธีขึ้นบันไดให้ถึงขั้นที่ $i$" ถ้าเขียนประโยคนี้ไม่ได้ อย่าเพิ่งเขียนโค้ด
2. **Transition คืออะไร** `dp[i]` สร้างจาก state ไหนบ้าง วิธีคิดที่ได้ผลบ่อยคือถามว่า "**ก้าวสุดท้าย**ที่มาถึง state นี้ เป็นได้กี่แบบ" แล้วแยกกรณีตามนั้น
3. **Base case คืออะไร** state เล็กสุดที่ตอบได้ทันทีโดยไม่ต้องอาศัยใคร
4. **ลำดับการคำนวณ** ต้องเติม state ที่ `dp[i]` ใช้ ก่อน `dp[i]` เสมอ ใน 1D มักคือ $i$ จากน้อยไปมาก

แล้วอย่าลืมข้อห้า: **คำตอบอยู่ที่ state ไหน** บางทีเป็น `dp[n]` บางทีเป็นค่ามากสุดของทั้งตาราง

## ตัวอย่าง: ขึ้นบันไดทีละ 1, 2 หรือ 3 ขั้น

บันได $n$ ขั้น ก้าวหนึ่งขึ้นได้ $1$, $2$ หรือ $3$ ขั้น มีกี่วิธีที่จะไปถึงขั้นที่ $n$ (ตอบ mod $10^9 + 7$)

1. State: `ways[i]` = จำนวนวิธีไปถึงขั้นที่ $i$ พอดี
2. Transition: ก้าวสุดท้ายมาจากขั้น $i - 1$, $i - 2$ หรือ $i - 3$ สามกรณีนี้ไม่ทับกัน จึงบวกกันได้เลย: `ways[i] = ways[i-1] + ways[i-2] + ways[i-3]`
3. Base case: `ways[0] = 1` (ยืนอยู่ที่พื้นแล้ว มีหนึ่งวิธีคือไม่ก้าวเลย) และขั้นติดลบไม่มีวิธี
4. ลำดับ: $i = 1, 2, \ldots, n$

```cpp
#include <bits/stdc++.h>
using namespace std;

const long long MOD = 1'000'000'007;

int main() {
  int n;
  cin >> n;
  vector<long long> ways(n + 1, 0);
  ways[0] = 1;                                  // base case
  for (int i = 1; i <= n; i++)
    for (int step = 1; step <= 3; step++)
      if (i - step >= 0) ways[i] = (ways[i] + ways[i - step]) % MOD;
  cout << ways[n] << '\n';
}
```

ไล่มือกับ $n = 5$

| $i$ | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| `ways[i]` | 1 | 1 | 2 | 4 | 7 | 13 |

เช่น `ways[4] = ways[3] + ways[2] + ways[1] = 4 + 2 + 1 = 7` ได้ $13$ วิธีสำหรับ $n = 5$

:::note ทำไม ways[0] = 1
ถ้าตั้ง `ways[0] = 0` ทุกช่องจะเป็น $0$ หมด ลองคิดว่า `ways[1]` ควรเป็น $1$ (ก้าวเดียวขั้นเดียว) ซึ่งมาจาก `ways[0]` ดังนั้น "ยืนที่พื้นโดยยังไม่ก้าว" ต้องนับเป็นหนึ่งวิธี base case ที่ดีคือค่าที่ทำให้สูตร transition ให้คำตอบถูกตั้งแต่ช่องแรก ๆ
:::

## ค่าน้อยที่สุดแทนจำนวนวิธี

โครงเดิมใช้กับ "ค่าใช้จ่ายน้อยที่สุด" ได้ด้วย แค่เปลี่ยน **บวก** เป็น **min** ตัวอย่างข้างเคียง: หิน $n$ ก้อนเรียงเป็นแถว เหยียบก้อนที่ $i$ ต้องจ่าย $c_i$ เริ่มที่ก้อน $0$ (จ่ายด้วย) ก้าวไปข้างหน้าทีละ $1$ หรือ $2$ ก้อน ต้องจบที่ก้อน $n - 1$ จ่ายน้อยที่สุดเท่าไร

* State: `dp[i]` = ค่าใช้จ่ายน้อยที่สุดที่จะไปยืนบนก้อนที่ $i$ (รวมค่าเหยียบก้อน $i$)
* Transition: ก้าวสุดท้ายมาจาก $i - 1$ หรือ $i - 2$ ให้เลือกทางที่ถูกกว่า: `dp[i] = c[i] + min(dp[i-1], dp[i-2])`
* Base case: `dp[0] = c[0]`, `dp[1] = c[0] + c[1]`

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
  int n;
  cin >> n;
  vector<long long> c(n);
  for (auto &x : c) cin >> x;
  vector<long long> dp(n);
  dp[0] = c[0];
  if (n > 1) dp[1] = c[0] + c[1];
  for (int i = 2; i < n; i++) dp[i] = c[i] + min(dp[i - 1], dp[i - 2]);
  cout << dp[n - 1] << '\n';
}
```

ไล่มือกับ $c = [1, 100, 1, 1, 100, 1]$

| $i$ | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| $c_i$ | 1 | 100 | 1 | 1 | 100 | 1 |
| `dp[i]` | 1 | 101 | 2 | 3 | 103 | 4 |

ตอบ $4$ จากเส้นทาง $0 \to 2 \to 3 \to 5$

:::hint ใบ้ Frog Jumps
State เหมือนตัวอย่างข้างบนเลย `dp[i]` = เหนื่อยน้อยที่สุดที่จะไปยืนบนก้อน $i$ ต่างกันแค่ก้าวสุดท้ายมาได้จาก $K$ ก้อนก่อนหน้า และค่าใช้จ่ายขึ้นกับทั้งก้อนต้นทางและปลายทาง ใช้ลูปซ้อนสองชั้นรวม $O(NK)$ อย่าลืม `long long` และกรณี $N = 1$
:::

## Longest Increasing Subsequence

คราวนี้คำตอบไม่ได้อยู่ที่ช่องสุดท้าย ให้อาเรย์ $a$ ยาว $n$ หา **subsequence** (เลือกบางตัว ลำดับเดิม ไม่ต้องติดกัน) ที่ **เพิ่มขึ้นอย่างเคร่งครัด** และยาวที่สุด

* State: `dp[i]` = ความยาว LIS ที่ **จบที่ตัว $i$ พอดี** (ต้องเลือก $a_i$ เป็นตัวสุดท้าย)
* Transition: ตัวก่อนหน้า $a_i$ ใน subsequence คือ $a_j$ บางตัวที่ $j < i$ และ $a_j < a_i$: `dp[i] = 1 + max(dp[j])` หรือ $1$ ถ้าไม่มี $j$ แบบนั้นเลย
* คำตอบ: **ค่ามากสุดของทุก `dp[i]`** เพราะ LIS จบที่ตัวไหนก็ได้

ทำไมต้อง "จบที่ตัว $i$ พอดี"? เพราะ transition ต้องรู้ว่าตัวสุดท้ายคือใคร จึงจะเช็ก $a_j < a_i$ ได้ ถ้านิยามแค่ "LIS ในช่วง $a_0..a_i$" จะต่อตัวถัดไปไม่ได้ เพราะไม่รู้ว่ามันจบด้วยค่าเท่าไร นี่คือบทเรียนสำคัญ: **state ต้องจำข้อมูลเท่าที่ transition ต้องใช้**

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
  int n;
  cin >> n;
  vector<int> a(n);
  for (int &x : a) cin >> x;
  vector<int> dp(n, 1);              // อย่างน้อยก็มี a[i] ตัวเดียว
  for (int i = 0; i < n; i++)
    for (int j = 0; j < i; j++)
      if (a[j] < a[i]) dp[i] = max(dp[i], dp[j] + 1);
  cout << *max_element(dp.begin(), dp.end()) << '\n';
}
```

ไล่มือกับ $a = [3, 1, 4, 1, 5, 9, 2, 6]$

| $i$ | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| $a_i$ | 3 | 1 | 4 | 1 | 5 | 9 | 2 | 6 |
| `dp[i]` | 1 | 1 | 2 | 1 | 3 | 4 | 2 | 4 |

ตอบ $4$ เช่น $3, 4, 5, 9$ หรือ $1, 4, 5, 6$ ช่องสุดท้าย `dp[7]` บังเอิญเป็น $4$ แต่ `dp[6]` เป็นแค่ $2$ ถ้าตอบ `dp[n-1]` ตรง ๆ จะผิดกับหลายอาเรย์

ความซับซ้อน $O(n^2)$ ใช้ได้ถึง $n$ ประมาณ $10^4$ ถ้า $n$ ถึง $10^5$ มีวิธี $O(n \log n)$ ที่เก็บ "ค่าท้ายที่เล็กที่สุดของ LIS แต่ละความยาว" ไว้ในอาเรย์ที่เรียงอยู่เสมอ แล้วใช้ `lower_bound` จากบท Binary Search on an Array หาตำแหน่งที่จะแทน ใครสนใจลองค้นคำว่า patience sorting ดู

## Coin change: นับวิธีกับเหรียญน้อยสุด ไม่เหมือนกัน!

มีเหรียญ $m$ ชนิด (แต่ละชนิดใช้กี่เหรียญก็ได้) อยากจ่ายเงิน $X$ บาทพอดี คำถามที่หน้าตาคล้ายกันมากมีอย่างน้อยสามแบบ และคำตอบต่างกันหมด

1. **จำนวนวิธีแบบไม่สนลำดับ** ($1 + 3$ กับ $3 + 1$ นับเป็นวิธีเดียว)
2. **จำนวนวิธีแบบสนลำดับ** (นับแยกกัน เหมือนขึ้นบันไดทีละ "มูลค่าเหรียญ" ขั้น)
3. **จำนวนเหรียญน้อยที่สุด**

แบบที่ 2 กับ 3 ใช้ state `f[s]` = คำตอบสำหรับเงิน $s$ บาท แล้วถาม "เหรียญสุดท้ายคืออะไร" ส่วนแบบที่ 1 ต้องกันไม่ให้ลำดับต่างกันถูกนับซ้ำ ทริกคือ **ใส่ลูปเหรียญไว้ข้างนอก** ทำให้ทุกวิธีถูกสร้างตามลำดับชนิดเหรียญเสมอ (ใช้เหรียญชนิดแรกให้หมดก่อน แล้วค่อยชนิดที่สอง ...) แต่ละชุดเหรียญจึงถูกนับแค่ครั้งเดียว

```cpp
#include <bits/stdc++.h>
using namespace std;

const long long MOD = 1'000'000'007;
const int INF = 1e9;

int main() {
  int m, x;
  cin >> m >> x;
  vector<int> coin(m);
  for (int &c : coin) cin >> c;

  // 1. ไม่สนลำดับ: ลูปเหรียญอยู่ข้างนอก
  vector<long long> combos(x + 1, 0);
  combos[0] = 1;
  for (int c : coin)
    for (int s = c; s <= x; s++) combos[s] = (combos[s] + combos[s - c]) % MOD;

  // 2. สนลำดับ: ลูปเงินอยู่ข้างนอก (เหรียญสุดท้ายเป็นอะไรก็ได้)
  vector<long long> orders(x + 1, 0);
  orders[0] = 1;
  for (int s = 1; s <= x; s++)
    for (int c : coin)
      if (s - c >= 0) orders[s] = (orders[s] + orders[s - c]) % MOD;

  // 3. เหรียญน้อยสุด: บวกเปลี่ยนเป็น min, ค่าเริ่มต้นเป็น INF (จ่ายไม่ได้)
  vector<int> fewest(x + 1, INF);
  fewest[0] = 0;
  for (int s = 1; s <= x; s++)
    for (int c : coin)
      if (s - c >= 0 && fewest[s - c] != INF) fewest[s] = min(fewest[s], fewest[s - c] + 1);

  cout << combos[x] << ' ' << orders[x] << ' ';
  cout << (fewest[x] == INF ? -1 : fewest[x]) << '\n';
}
```

ลองกับเหรียญ $\{1, 3, 4\}$ และ $X = 6$ โปรแกรมพิมพ์ `4 9 2`

* ไม่สนลำดับ $4$ วิธี: $1{+}1{+}1{+}1{+}1{+}1$, $1{+}1{+}1{+}3$, $1{+}1{+}4$, $3{+}3$
* สนลำดับ $9$ วิธี: เช่น $1{+}1{+}4$, $1{+}4{+}1$ และ $4{+}1{+}1$ นับเป็นสามวิธี
* เหรียญน้อยสุด $2$ เหรียญ ($3 + 3$) ทั้งที่ greedy "หยิบเหรียญใหญ่สุดก่อน" จะได้ $4 + 1 + 1$ สามเหรียญ

ทั้งสามแบบเป็น $O(mX)$ จุดที่ต้องจำคือ **สลับลูปนิดเดียว ความหมายเปลี่ยนเลย** ก่อนเขียนให้ถามตัวเองเสมอว่าโจทย์นับลำดับต่างกันเป็นคนละวิธีหรือเปล่า

:::problem lp_dp02_secret_code

:::hint ใบ้ Secret Code
นี่คือ "ขึ้นบันได" ที่ลำดับสำคัญ ให้ `dp[i]` = จำนวนวิธีแบ่ง $i$ ตัวแรกของสตริง แล้วถามว่า **ชิ้นสุดท้าย** ยาวเท่าไร เพราะ $M \leq 999$ ชิ้นยาวได้แค่ $1$ ถึง $3$ ตัว ต่างจากบันไดตรงที่ "ก้าว" แต่ละแบบใช้ได้หรือไม่ได้ขึ้นกับตัวเลขตรงนั้น (ขึ้นต้นด้วย $0$ ไหม, ค่าเกิน $M$ ไหม) ลองไล่ตัวอย่างที่ 1 แล้วจะเห็นตารางเดียวกับบันได 1, 2, 3 ขั้นข้างบน
:::

## เมื่อ state ต้องจำมากกว่าตำแหน่ง

บางโจทย์แค่ `dp[i]` ไม่พอ เพราะ transition ต้องรู้ข้อมูลเพิ่ม เหมือน LIS ที่ต้องรู้ว่าจบที่ตัวไหน ตัวอย่างข้างเคียง: มีงาน $n$ วัน วันที่ $i$ ถ้าทำงานได้เงิน $a_i$ แต่ **ห้ามทำงานสามวันติดกัน** ได้เงินมากสุดเท่าไร

ถ้ารู้แค่ "เงินมากสุดของ $i$ วันแรก" จะไม่รู้ว่าวันที่ $i + 1$ ทำงานได้หรือเปล่า จึงเพิ่มมิติ: `dp[i][k]` = เงินมากสุดของวันที่ $0..i$ โดยที่ **ท้ายสุดทำงานติดกันมาแล้ว $k$ วัน** ($k = 0, 1, 2$)

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
  int n;
  cin >> n;
  vector<long long> a(n);
  for (auto &x : a) cin >> x;
  const long long NEG = LLONG_MIN / 4;          // state ที่เป็นไปไม่ได้
  array<long long, 3> dp = {0, NEG, NEG};       // ก่อนวันแรก: ยังไม่ได้ทำงานเลย
  for (int i = 0; i < n; i++) {
    array<long long, 3> nd;
    nd[0] = max({dp[0], dp[1], dp[2]});         // วันนี้พัก
    nd[1] = dp[0] + a[i];                       // ทำงานวันแรกของช่วง
    nd[2] = dp[1] + a[i];                       // ทำงานวันที่สองติดกัน
    dp = nd;
  }
  cout << max({dp[0], dp[1], dp[2]}) << '\n';
}
```

ไล่มือกับ $a = [5, 5, 5, 1, 5, 5]$ (เขียน `-` แทน state ที่เป็นไปไม่ได้)

| วัน $i$ | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| $a_i$ | 5 | 5 | 5 | 1 | 5 | 5 |
| `dp[i][0]` (พัก) | 0 | 5 | 10 | 10 | 11 | 16 |
| `dp[i][1]` | 5 | 5 | 10 | 11 | 15 | 16 |
| `dp[i][2]` | - | 10 | 10 | 11 | 16 | 20 |

ตอบ $\max(16, 16, 20) = 20$ เช่นทำวัน $0, 1, 4, 5$ แล้วพักวัน $2$ กับ $3$ อ่านตารางทีละช่องได้เลย เช่น `dp[4][2] = dp[3][1] + 5 = 11 + 5 = 16` แปลว่า "ทำวัน $3$ กับ $4$ ติดกัน (วัน $2$ จึงต้องพัก) ได้มากสุด $16$"

สังเกตอีกอย่าง: `dp[i]` ใช้แค่ `dp[i - 1]` จึงเก็บแค่แถวเดียวพอ ท่า "เก็บแค่แถวก่อนหน้า" นี้ลดหน่วยความจำจาก $O(n)$ เหลือ $O(1)$ ได้บ่อยมาก

:::problem lp_dp03_lakeside_stalls

:::hint ใบ้ Lakeside Stalls (ข้อแรก)
เริ่มจากเวอร์ชันง่ายก่อน: ถ้าจุดเรียงเป็น **เส้นตรง** (จุด $1$ กับ $N$ ไม่ติดกัน) ใช้ state สองแบบ "เปิดร้านที่จุดนี้" กับ "ไม่เปิด" แบบเดียวกับตัวอย่างข้างบน ซึ่งง่ายกว่าเพราะห้ามแค่สองจุดติดกัน
:::

:::hint ใบ้ Lakeside Stalls (ข้อสอง)
วงกลมต่างจากเส้นตรงตรงคู่ $(N, 1)$ คู่เดียว และในคำตอบใด ๆ จุด $1$ กับจุด $N$ **อย่างน้อยหนึ่งจุดต้องว่าง** ลองแยกเป็นสองกรณีตามนี้ แต่ละกรณีกลายเป็นเส้นตรงหรือเปล่า?
:::

## ความซับซ้อนของ DP

นับง่าย ๆ ว่า **จำนวน state × งานต่อ state**

| ตัวอย่าง | state | งานต่อ state | รวม |
|---|---|---|---|
| ขึ้นบันได 1, 2, 3 | $n$ | $3$ | $O(n)$ |
| Frog กระโดดได้ $K$ | $N$ | $K$ | $O(NK)$ |
| LIS | $n$ | $n$ | $O(n^2)$ |
| Coin change | $X$ | $m$ | $O(mX)$ |
| ห้ามทำงานสามวันติด | $3n$ | $O(1)$ | $O(n)$ |

ส่วนหน่วยความจำคือจำนวน state ที่ต้องเก็บพร้อมกัน ซึ่งมักลดได้ถ้า transition ใช้แค่ไม่กี่แถวก่อนหน้า

## จุดที่พลาดบ่อย

:::warning base case ผิด ทั้งตารางผิดตาม
ค่าในตารางทุกช่องมาจาก base case ถ้า `ways[0]` ผิด ทุกช่องผิดหมด เวลาไม่แน่ใจ ให้ไล่ $n$ เล็ก ๆ ($0, 1, 2$) ด้วยมือเทียบกับโปรแกรมก่อนเสมอ
:::

:::warning mod ทุกครั้งที่บวก
นับวิธีต้อง `% MOD` ทุกครั้งที่บวก ไม่ใช่แค่ตอนพิมพ์ ถ้าบวกเลขที่ใกล้ $10^9$ สามตัวโดยไม่ mod แล้วเก็บใน `int` จะล้นทันที (grader ของเราจับ signed overflow เป็น Runtime Error) ใช้ `long long` แล้ว mod หลังบวกแต่ละครั้งจะปลอดภัย
:::

:::warning INF + ค่าใช้จ่าย ล้นได้
state ที่ "เป็นไปไม่ได้" มักตั้งเป็น INF แล้ว `INF + c` อาจล้น ให้เช็กก่อนบวก (แบบ `fewest[s - c] != INF` ในโค้ด coin change) หรือเลือก INF ที่บวกกันแล้วยังไม่ล้น เช่น `LLONG_MAX / 4`
:::

:::warning memoisation ที่ลึกเกินไป
recursion ที่มี state $10^6$ ตัวเรียงต่อกัน จะลึกถึง $10^6$ ชั้น ซึ่งอาจ stack overflow ได้ ถ้า state เรียงกันเป็นเส้นตรงแบบนี้ เขียนเป็น tabulation ดีกว่า และใน Python ห้าม recursion ลึกเด็ดขาด (ค่าเริ่มต้นจำกัดที่ $1{,}000$ ชั้น)
:::

:::warning คำตอบอยู่ที่ไหน
`dp[n]`, `dp[n - 1]` หรือค่ามากสุดของทั้งตาราง? ตอบให้ตรงกับนิยามของ state เช่น LIS ต้องเอาค่ามากสุด ส่วนโจทย์ที่มี $n$ ตัวแต่ใช้ดัชนี $0$ ถึง $n - 1$ คำตอบมักอยู่ที่ `dp[n - 1]` ไม่ใช่ `dp[n]`
:::

## สรุปสั้น ๆ

* DP = ปัญหาย่อยซ้ำกัน → คิดแต่ละอันครั้งเดียวแล้วจดไว้ จาก exponential เหลือ "จำนวน state × งานต่อ state"
* Memoisation คือ recursion + สมุดจด, tabulation คือเติมตารางจากเล็กไปใหญ่
* ก่อนเขียนตอบให้ได้: state แปลว่าอะไร (เป็นประโยค), transition มาจากไหน (ถาม "ก้าวสุดท้าย"), base case, ลำดับการคำนวณ และคำตอบอยู่ที่ไหน
* นับวิธีใช้บวก (mod ทุกครั้ง), หาค่าดีสุดใช้ min/max
* Coin change: ลูปเหรียญข้างนอก = ไม่สนลำดับ, ลูปเงินข้างนอก = สนลำดับ, เหรียญน้อยสุด = min
* state ต้องจำข้อมูลที่ transition ต้องใช้ ถ้าไม่พอก็เพิ่มมิติ (LIS จบที่ $i$, ทำงานติดกันมากี่วัน)
