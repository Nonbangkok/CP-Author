## ปริศนาที่ไม่มีอาเรย์ให้ไล่

โจทย์บางข้อไม่ได้ให้อาเรย์หรือกราฟมาตรง ๆ แต่ให้ "ปริศนา" มาหนึ่งอัน: กระดานที่ต้องวางหมาก, เหยือกน้ำที่ต้องตวงให้ได้ปริมาณพอดี, ตารางตัวเลขที่ต้องหมุนจนเรียง ถ้าดูดี ๆ ทุกข้อมีโครงเดียวกัน

* **state** (สถานะ) คือ "ภาพถ่าย" ของปริศนา ณ ขณะหนึ่ง ที่บอกทุกอย่างที่ต้องรู้เพื่อเล่นต่อ
* **move** (การเดิน) คือกฎที่เปลี่ยน state หนึ่งไปเป็นอีก state หนึ่ง
* มี **state เริ่มต้น** และ **state เป้าหมาย** (หรือเงื่อนไขว่าแบบไหนถือว่าจบ)

ถ้าวาด state เป็นจุด และวาดลูกศรตาม move ก็จะได้ **กราฟ** ที่ไม่มีใครเขียนให้เราเห็นทั้งก้อน เรียกว่า **state space** เราสร้างเพื่อนบ้านของ state ไหนก็ได้ด้วยกฎของโจทย์เอง

```text
เหยือก 3 ลิตร กับ 5 ลิตร state = (น้ำในเหยือก 3, น้ำในเหยือก 5)

            เติม 3          เท 3 -> 5
   (0,0) ----------> (3,0) ----------> (0,3) ----> ...
     |
     | เติม 5
     v
   (0,5) ----------> (3,2) ----------> (0,2) ----> ...
          เท 5 -> 3          เททิ้ง 3
```

บทนี้มีเครื่องมือสองชิ้นสำหรับเดินใน state space ซึ่งตอบคำถามคนละแบบ

| คำถาม | เครื่องมือ |
|---|---|
| "มีกี่วิธี / มีวิธีไหนไหมที่ผ่านทุกเงื่อนไข" | backtracking + pruning (DFS) |
| "ต้องเดินน้อยที่สุดกี่ก้าว" | BFS บน state |

## Backtracking + pruning: ตัดกิ่งตายให้เร็วที่สุด

ในบท Recursion เราไล่ทุก subset และทุก permutation ด้วยการ "เลือก แล้วเรียกตัวเองต่อ แล้ว undo" มาแล้ว ปัญหาคือจำนวนทางเลือกโตแบบ exponential ถ้าไล่ให้ครบก่อนแล้วค่อยตรวจตอนจบ $N = 12$ ก็อาจเป็นหลักร้อยล้านแบบ

ทริกคือ **ตรวจเงื่อนไขตั้งแต่ตอนวางแต่ละชิ้น** ถ้าวางไปครึ่งทางแล้วผิดกติกาแล้ว ไม่ว่าจะวางที่เหลือยังไงก็ผิดอยู่ดี ให้ตัดทิ้ง (prune) ทั้งกิ่งทันที

```text
generate-then-check:                    prune:
  วาง 1 -> วาง 2 -> ... -> วางครบ -> ตรวจ     วาง 1 -> ตรวจ -> วาง 2 -> ตรวจ x  (ตัดทิ้ง)
  ทุกใบของต้นไม้ถูกสร้างจริง                   ต้นไม้ที่เหลือจริงเล็กกว่ามาก
```

ตัวอย่างที่ใช้อธิบาย: **วงแหวนจำนวนเฉพาะ** วางเลข $1, 2, \ldots, N$ เป็นวงกลม ให้ผลบวกของทุกคู่ที่อยู่ติดกัน (รวมคู่สุดท้ายที่วนกลับมาหาตัวแรก) เป็นจำนวนเฉพาะ นับว่ามีกี่วง โดยหมุนวงให้เลข $1$ อยู่ตำแหน่งแรกเสมอ (วงที่หมุนแล้วเหมือนกันนับครั้งเดียว)

ถ้าไล่ทุก permutation ของเลข $2$ ถึง $N$ แล้วค่อยตรวจ จะเป็น $(N-1)!$ แบบ แต่สังเกตว่าแค่วางเลขตัวที่สองผิด (เช่น $1$ ติดกับ $3$ รวมเป็น $4$) ทุก permutation ที่ขึ้นต้นแบบนั้นก็ตายหมดแล้ว

### Template: backtracking ที่ตรวจตอนวาง

```cpp
#include <bits/stdc++.h>
using namespace std;

int n;
int ring[20];
bool used[20];
long long ways = 0;

bool isPrime(int x) {
  if (x < 2) return false;
  for (int d = 2; d * d <= x; d++)
    if (x % d == 0) return false;
  return true;
}

void place(int pos) {                 // ring[0..pos-1] ถูกวางแล้ว และทุกคู่ติดกันผ่านเงื่อนไข
  if (pos == n) {
    if (isPrime(ring[n - 1] + ring[0])) ways++;   // คู่สุดท้ายที่วนกลับมาหาตัวแรก
    return;
  }
  for (int v = 2; v <= n; v++) {
    if (used[v]) continue;
    if (!isPrime(ring[pos - 1] + v)) continue;    // pruning: ตัดทิ้งตั้งแต่ตอนวาง
    used[v] = true;
    ring[pos] = v;
    place(pos + 1);
    used[v] = false;                              // undo ก่อนลองค่าถัดไป
  }
}

int main() {
  cin >> n;
  ring[0] = 1;            // หมุนวงให้เลข 1 อยู่ตำแหน่งแรกเสมอ จะได้ไม่นับวงเดิมซ้ำ
  used[1] = true;
  place(1);
  cout << ways << '\n';
}
```

โครงที่ต้องจำมีสามท่อน: **เช็กเงื่อนไขก่อนวาง**, วางแล้ว **mark** ว่าใช้แล้ว, เรียกตัวเองต่อแล้ว **undo** ทุกอย่างที่ mark ไว้ ส่วน `used[]` คือ "ข้อมูลของ state ตอนนี้" ที่ทำให้เช็กได้ใน $O(1)$ แทนที่จะไล่ดูทั้งวงใหม่

│   ├─ 3 (2+3=5)
│   │   └─ 4 (3+4=7)
│   │       └─ 5? 4+5=9 x   6? 4+6=10 x         ตันกลางทาง
│   └─ 5 (2+5=7)
│       └─ 6 (5+6=11)
│           └─ 3? 6+3=9 x   ...                  ตันอีก
├─ 4 (1+4=5)
│   └─ 3 (4+3=7)
│       └─ 2 (3+2=5)
│           └─ 5 (2+5=7)
│               └─ 6 (5+6=11), ปิดวง 6+1=7 ✓   วงที่ 1: 1 4 3 2 5 6
└─ 6 (1+6=7)
    └─ 5 (6+5=11)

ได้ $2$ วง สังเกตว่า $1$ ติดกับ $3$ หรือ $5$ ไม่ได้เลย (รวมเป็น $4$ และ $6$) กิ่งพวกนั้นจึงไม่ถูกสร้างตั้งแต่ชั้นแรก จาก $5! = 120$ permutation โปรแกรมเดินไปจริงแค่สิบกว่าโหนด พอ $N = 16$ ก็ยังตอบ $81024$ ได้ในเสี้ยววินาที ทั้งที่ $15!$ มีถึงราว $1.3$ ล้านล้านแบบ

### ความซับซ้อน

กรณีแย่สุดยังเป็น exponential เสมอ pruning ไม่ได้เปลี่ยนสัญกรณ์ Big-O แต่ลดจำนวนโหนดที่เดินจริงลงหลายเท่าตัว (บางครั้งเป็นพันเท่า) วิธีประเมินที่ใช้ได้จริงคือ **ลองรันกรณีที่ใหญ่ที่สุดดู** หรือนับจำนวนครั้งที่ `place` ถูกเรียก

### ตัวอย่างคลาสสิก: N-Queens

วางควีน $N$ ตัวบนกระดาน $N \times N$ ไม่ให้กินกัน คือตัวอย่างประจำของท่านี้ ให้วาง **ทีละแถว** (แถวละหนึ่งตัวแน่ ๆ) แล้วสิ่งที่ต้องเช็กตอนวางแถว $r$ หลัก $c$ คือ หลัก $c$ และแนวทแยงทั้งสองแนวที่ผ่าน $(r, c)$ ยังว่างไหม

```text
ทแยงลง   (\) : ทุกช่องบนเส้นเดียวกันมี r - c เท่ากัน
ทแยงขึ้น (/) : ทุกช่องบนเส้นเดียวกันมี r + c เท่ากัน

      c=0 c=1 c=2 c=3
r=0    .   .   .   .        ช่อง (1,2): r-c = -1, r+c = 3
r=1    .   .   Q   .        ช่องที่มี r-c = -1 คือ (0,1) (2,3)
r=2    .   .   .   .        ช่องที่มี r+c = 3 คือ (0,3) (2,1) (3,0)
r=3    .   .   .   .
```

:::hint ใบ้ Queens on a Broken Floor
เก็บ `bool` สามชุด: หลักที่ใช้แล้ว, ทแยงที่ใช้ $r + c$ เป็นดัชนี และทแยงที่ใช้ $r - c$ (ซึ่งติดลบได้ จึงบวก $N - 1$ ก่อนใช้เป็นดัชนี) เช็กทั้งสามบวกกับ "ช่องนี้แตกไหม" **ก่อน** วาง แล้วอย่าลืม undo ทั้งสามชุด ถ้าแถวไหนไม่มีช่องให้วางเลย กิ่งนั้นก็ตายเองโดยไม่ต้องทำอะไรเพิ่ม

## BFS บน state: ก้าวน้อยที่สุด

ถ้าคำถามคือ "ต้องเดินน้อยที่สุดกี่ครั้ง" DFS/backtracking ไม่ใช่เครื่องมือที่ถูก เพราะ DFS จะดำดิ่งไปทางเดียวจนสุดก่อน ทางแรกที่เจอไม่จำเป็นต้องสั้นที่สุด และ state เดิมอาจถูกเดินซ้ำแบบไม่รู้จบ

**BFS** (breadth-first search) ไล่เป็นชั้น ๆ: ชั้น $0$ คือ state เริ่มต้น, ชั้น $1$ คือทุก state ที่ไปถึงได้ในหนึ่งก้าว, ชั้น $2$ คือที่ไปได้ในสองก้าวแต่ยังไม่เคยเห็น, ... ใช้คิว (queue) ที่หยิบตัวที่เข้าก่อนออกก่อน state ที่ถูกหยิบออกมาจึงเรียงตามระยะจากน้อยไปมากเสมอ **ครั้งแรกที่เจอเป้าหมาย คือจำนวนก้าวที่น้อยที่สุด** (ใช้ได้เมื่อทุก move มีราคาเท่ากัน คือ 1 ก้าว)

ของที่ต้องมีเสมอคือ `dist` หรือ visited: state ไหนเคยเข้าคิวแล้วห้ามเข้าซ้ำ ไม่อย่างนั้นคิวจะบวมแบบ exponential เหมือน DFS ที่ไม่มี visited

### Template: เหยือกน้ำสองใบ

มีเหยือกจุ $A$ ลิตรกับ $B$ ลิตร เริ่มจากว่างทั้งคู่ ทำได้หกอย่าง: เติมใบใดใบหนึ่งให้เต็ม, เทใบใดใบหนึ่งทิ้งหมด, เทจากใบหนึ่งไปอีกใบจนใบต้นทางหมดหรือใบปลายทางเต็ม ต้องทำน้อยที่สุดกี่ครั้งถึงจะมีเหยือกใบใดใบหนึ่งมีน้ำ $D$ ลิตรพอดี (ถ้าทำไม่ได้ตอบ $-1$)

state คือคู่ $(a, b)$ มีทั้งหมด $(A+1)(B+1)$ แบบ เราแปลงเป็นเลขเดียว `a * (B + 1) + b` แล้วใช้เป็นดัชนีของ `vector` ตรง ๆ

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
  int A, B, D;
  cin >> A >> B >> D;
  // state (a, b) -> id = a * (B + 1) + b   ใช้เป็นดัชนีของอาเรย์ได้เลย
  auto id = [&](int a, int b) { return a * (B + 1) + b; };
  vector<int> dist((A + 1) * (B + 1), -1);
  queue<pair<int, int>> q;
  dist[id(0, 0)] = 0;
  q.push({0, 0});
  while (!q.empty()) {
    auto [a, b] = q.front();
    q.pop();
    if (a == D || b == D) {             // BFS หยิบ state ตามระยะจากน้อยไปมาก เจอครั้งแรก = น้อยสุด
      cout << dist[id(a, b)] << '\n';
      return 0;
    }
    int pourAB = min(a, B - b);         // เทจาก A ไป B ได้เท่าไร
    int pourBA = min(b, A - a);
    pair<int, int> nexts[6] = {
        {A, b}, {a, B},                 // เติมให้เต็ม
        {0, b}, {a, 0},                 // เททิ้งหมด
        {a - pourAB, b + pourAB},       // เท A -> B
        {a + pourBA, b - pourBA},       // เท B -> A
    };
    for (auto [na, nb] : nexts) {
      if (dist[id(na, nb)] != -1) continue;   // เคยเห็นแล้ว ไม่ต้องเข้าคิวซ้ำ
      dist[id(na, nb)] = dist[id(a, b)] + 1;  // จดตอน push ไม่ใช่ตอน pop
      q.push({na, nb});
    }
  }
  cout << -1 << '\n';                    // ไล่ครบทุก state แล้วยังไม่เจอ
}
```

### ลองไล่ด้วยมือ ($A = 3$, $B = 5$, $D = 4$)

| ชั้น (`dist`) | state ที่เพิ่งเจอในชั้นนี้ |
|---|---|
| 0 | $(0,0)$ |
| 1 | $(3,0)$, $(0,5)$ |
| 2 | $(3,5)$, $(0,3)$, $(3,2)$ |
| 3 | $(3,3)$, $(0,2)$ |
| 4 | $(1,5)$, $(2,0)$ |
| 5 | $(1,0)$, $(2,5)$ |
| 6 | $(0,1)$, $(3,4)$ |

ชั้น $6$ มี $(3, 4)$ ซึ่งเหยือก $5$ ลิตรมีน้ำ $4$ ลิตร โปรแกรมตอบ $6$ ไล่ย้อนได้ว่า $(0,0) \to (0,5) \to (3,2) \to (0,2) \to (2,0) \to (2,5) \to (3,4)$ คือเติม 5, เท 5 ไป 3, ทิ้ง 3, เท 5 ไป 3, เติม 5, เท 5 ไป 3 สังเกตว่า $(3,5)$ โผล่ในชั้น $2$ ได้จากหลายทาง แต่เข้าคิวแค่ครั้งเดียวเพราะ `dist` กันไว้

### ความซับซ้อน

ทุก state เข้าคิวไม่เกินหนึ่งครั้ง และแต่ละครั้งสร้างเพื่อนบ้าน $k$ ตัว (ในที่นี้ $k = 6$) งานรวมคือ $O(S \cdot k)$ เมื่อ $S$ คือจำนวน state ทั้งหมด หน่วยความจำ $O(S)$ สำหรับ `dist` กับคิว ดังนั้นคำถามแรกที่ต้องถามเสมอคือ **"มี state ทั้งหมดกี่แบบ"** ถ้าเป็นหลักล้านถึงสิบล้าน BFS สบาย ถ้าเป็นหลักพันล้าน ต้องหาวิธีอื่น

## เข้ารหัส state (state encoding)

BFS ต้องถามว่า "state นี้เคยเห็นหรือยัง" ได้เร็ว จึงต้องเปลี่ยน state ให้เป็นอะไรสักอย่างที่ใช้เป็น key ได้

* **ตัวเลขเล็ก ๆ ไม่กี่ตัว** เช่น $(a, b)$ หรือ $(r, c)$ บนตาราง: แปลงเป็น `a * (B + 1) + b` แบบ template แล้วใช้ `vector` ธรรมดา เร็วที่สุด
* **ชุดของ bit** เช่น ไฟเปิด/ปิด $N \leq 20$ ดวง: ใช้ bitmask เป็นดัชนีของอาเรย์ขนาด $2^N$ ได้เลย (บท Bitmasks)
* **การเรียงของของ $9$ ชิ้น** เช่น ตาราง $3 \times 3$: จะใช้ `string` ยาว $9$ หรืออ่านเป็นเลข $9$ หลัก `123456789` เก็บใน `int` แล้วใส่ `map` / `unordered_map` ก็ได้ ถ้าอยากใช้อาเรย์ธรรมดา ให้แปลงเป็น "ลำดับที่ของ permutation" (Lehmer code) ซึ่งอยู่ในช่วง $0$ ถึง $9! - 1 = 362879$

```text
Lehmer code ของ g[0..8]: สำหรับแต่ละตำแหน่ง i นับว่าทางขวามีกี่ตัวที่น้อยกว่า g[i]
แล้วคูณด้วย (8 - i)!   เช่น 213456789 -> 1 * 8! = 40320
```

ไม่ว่าจะเลือกแบบไหน ขอแค่ **state ต่างกันต้องได้ key ต่างกัน** และ state เดียวกันต้องได้ key เดียวกันเสมอ

## BFS ครั้งเดียว ตอบได้หลายคำถาม

ถ้าโจทย์ถามหลายรอบว่า "จาก state $s_1, s_2, \ldots, s_Q$ ไปถึงเป้าหมายเดียวกันใช้กี่ก้าว" การ BFS ใหม่ทุกคำถามเสียเวลา $O(Q \cdot S)$ ทางที่ดีกว่าคือ **BFS ครั้งเดียวจากเป้าหมาย** แล้วตอบทุกคำถามด้วยการเปิด `dist` ดู

แต่ระวังทิศทาง: BFS จากเป้าหมายต้องเดินด้วย **move ย้อนกลับ** ถ้า move เดิมพา $u \to v$ ตอนเดินจากเป้าหมายต้องถามว่า "state ไหนที่เดินมาถึงฉันได้" ถ้าเดินบนตารางสี่ทิศ move ย้อนกลับได้ในก้าวเดียวเสมอ สองทิศจึงเหมือนกัน แต่ถ้า move ย้อนไม่ได้ (เช่น เททิ้งแล้วเอาน้ำกลับคืนไม่ได้, หมุนได้ทิศเดียว, ปุ่ม ×2 ที่ไม่มีปุ่มหาร) ระยะไปกับระยะกลับไม่เท่ากัน

:::problem lp_ss03_spin_tiles

:::hint ใบ้ Spin the Tiles
มีตารางทั้งหมด $9! = 362880$ แบบ BFS ทั้งก้อนครั้งเดียวทันสบาย แต่ $Q$ ครั้งไม่ทัน คิดว่า BFS ควรเริ่มจากตารางไหน แล้วตอนเดินจากตารางนั้น ป้ายในบล็อกต้องเลื่อนไปทางไหน ลองตรวจกับตัวอย่างที่ 1: ตารางที่ห่างเป้าหมาย "หมุนตามเข็มหนึ่งครั้ง" ต้องตอบ $3$ ไม่ใช่ $1$
:::

## Meet in the middle (ตัวอย่างเรียกน้ำย่อย)

บางที state space ใหญ่เกินจะไล่ทั้งก้อน แต่ถ้า **ไล่สองครึ่งแยกกันแล้วจับคู่** จะเหลือนิดเดียว เช่น เลือกของจาก $N = 40$ ชิ้นให้น้ำหนักรวมมากที่สุดแต่ไม่เกิน $C$: ไล่ทุก subset ตรง ๆ คือ $2^{40} \approx 10^{12}$ แต่ถ้าแบ่งของเป็นสองกอง กองละ $20$ ชิ้น ไล่ผลรวมของแต่ละกอง ($2^{20} \approx 10^6$ แบบต่อกอง) แล้วสำหรับผลรวม $s$ ของกองซ้าย ใช้ binary search หาผลรวมกองขวาที่มากที่สุดที่ไม่เกิน $C - s$

```cpp
#include <bits/stdc++.h>
using namespace std;

// ทุกผลรวมของ subset ของ v
vector<long long> allSums(const vector<long long> &v) {
  vector<long long> sums = {0};
  for (long long x : v) {
    int size = sums.size();
    for (int i = 0; i < size; i++) sums.push_back(sums[i] + x);
  }
  return sums;
}

int main() {
  int n;
  long long cap;
  cin >> n >> cap;
  vector<long long> w(n);
  for (auto &x : w) cin >> x;
  vector<long long> left(w.begin(), w.begin() + n / 2), right(w.begin() + n / 2, w.end());
  vector<long long> L = allSums(left), R = allSums(right);   // 2^(n/2) ตัวต่อฝั่ง
  sort(R.begin(), R.end());
  long long best = 0;
  for (long long s : L) {
    if (s > cap) continue;
    // ฝั่งขวาที่มากที่สุดที่ยังไม่เกิน cap - s
    auto it = upper_bound(R.begin(), R.end(), cap - s);
    best = max(best, s + *prev(it));   // R มี 0 เสมอ จึงมีตัวที่ใช้ได้อย่างน้อยหนึ่งตัว
  }
  cout << best << '\n';
}
```

ลองกับ `6 10` และน้ำหนัก `37 1 9 23 15 4`: กองซ้าย $\{37, 1, 9\}$ มีผลรวม $10$ (จาก $1 + 9$) ซึ่งเต็ม $C$ พอดี โปรแกรมตอบ $10$ งานรวมคือ $O(2^{N/2} \cdot N)$ แทน $O(2^N)$

ไอเดียเดียวกันใช้กับ BFS ได้ด้วย เรียกว่า **bidirectional BFS**: BFS จากต้นทางและจากปลายทางพร้อมกันอย่างละครึ่งทาง ถ้าแต่ละ state มีเพื่อนบ้าน $4$ ตัวและคำตอบคือ $14$ ก้าว BFS ทางเดียวอาจแตะ state ราว $4^{14} \approx 2.7 \times 10^8$ แบบ แต่สองฝั่งฝั่งละ $7$ ก้าวแตะแค่ราว $2 \times 4^7 \approx 3.3 \times 10^4$ แบบ เทคนิคนี้จะกลับมาอีกในแทร็ก Advanced

## จุดที่พลาดบ่อย

:::warning จด visited ตอน push ไม่ใช่ตอน pop
ถ้าไปจด `dist` ตอนหยิบออกจากคิว state เดียวกันจะถูก push ซ้ำได้หลายรอบก่อนถูกหยิบ คิวบวม และถ้าเขียน `dist` ทับตอนหลังอาจได้ระยะที่ผิด จดทันทีที่ push แบบใน template
:::

:::warning เช็กขอบก่อนใช้เป็นดัชนี
เพื่อนบ้านที่หลุดช่วง ($x - 1 = 0$, $2x > L$, ออกนอกตาราง) ต้องทิ้ง **ก่อน** ไปอ่าน `dist[...]` ไม่อย่างนั้นจะอ่านอาเรย์เกินขอบ ซึ่งบางทีไม่ crash แต่ได้คำตอบเพี้ยนแบบเงียบ ๆ
:::

:::warning DFS ไม่ได้ให้ทางที่สั้นที่สุด
ทางแรกที่ DFS เจอคือทางที่ "บังเอิญลองก่อน" ถ้าโจทย์ถามจำนวนก้าวน้อยที่สุดและทุกก้าวราคาเท่ากัน ให้ใช้ BFS
:::

:::warning ลืม undo ใน backtracking
ทุกอย่างที่ mark ก่อนเรียกตัวเอง (หลัก, ทแยง, `used[]`) ต้องถูกปลดกลับหลังเรียกเสร็จ ลืมตัวเดียว กิ่งถัดไปจะเห็นกระดานที่ผิด
:::

:::warning ทิศของ move ตอน BFS จากเป้าหมาย
ถ้า move ย้อนกลับไม่ได้ในก้าวเดียว การ BFS จากเป้าหมายด้วย move เดิมจะได้ "ระยะจากเป้าหมายไปหา state" ไม่ใช่ "ระยะจาก state มาหาเป้าหมาย" ต้องใช้ move ย้อนกลับ
:::

## สรุปสั้น ๆ

* ปริศนา = state + move กลายเป็นกราฟที่สร้างเพื่อนบ้านเอาเองระหว่างทาง
* นับวิธี/หาว่ามีวิธีไหม: backtracking ที่เช็กเงื่อนไขตอนวาง (pruning) แล้ว undo
* ก้าวน้อยที่สุดเมื่อทุกก้าวราคาเท่ากัน: BFS + `dist`, จด visited ตอน push
* ก่อนเขียนให้นับจำนวน state ทั้งหมด และเลือกการเข้ารหัส (ดัชนีตรง ๆ, bitmask, string, Lehmer code)
* หลายคำถามไปเป้าหมายเดียว: BFS ครั้งเดียวจากเป้าหมายด้วย move ย้อนกลับ
* state space ใหญ่เกิน: meet in the middle / bidirectional BFS ไล่สองครึ่งแล้วจับคู่
