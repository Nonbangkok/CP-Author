## แบ่ง แก้ รวม

**Divide and conquer (แบ่งแยกแล้วเอาชนะ)** คือการแก้โจทย์ใหญ่ด้วยสามขั้น

1. **Divide (แบ่ง)** ตัดโจทย์เป็นโจทย์ย่อยแบบเดียวกันที่เล็กลง ส่วนใหญ่คือผ่าครึ่ง
2. **Conquer (แก้)** แก้โจทย์ย่อยแต่ละอันด้วยการเรียกตัวเองซ้ำ (recursion) จนเล็กพอจะตอบได้ทันที (base case)
3. **Combine (รวม)** เอาคำตอบของโจทย์ย่อยมาประกอบเป็นคำตอบของโจทย์ใหญ่

เราเคยเจอมันมาแล้วโดยไม่รู้ตัว: binary search แบ่งครึ่งแล้วทิ้งไปครึ่งหนึ่ง (แก้แค่ครึ่งเดียว ไม่ต้องรวม) และ binary exponentiation คำนวณ $a^n$ จาก $a^{n/2}$ ในบทนี้จะดูกรณีที่ต้องแก้ **ทั้งสองครึ่ง** แล้วเอามารวมกัน ซึ่งเป็นจุดที่เทคนิคนี้เก่งที่สุด และส่วนที่ต้องคิดจริง ๆ มักอยู่ที่ขั้น **combine**

## Merge sort

ตัวอย่างคลาสสิกที่สุดคือ merge sort: อยากเรียงอาเรย์ ก็ผ่าครึ่ง เรียงครึ่งซ้าย เรียงครึ่งขวา แล้ว **รวม** สองครึ่งที่เรียงแล้วเข้าด้วยกัน

```text
              [5 2 4 6 1 3]                    แบ่งลงไปจนเหลือตัวเดียว
            /               \
       [5 2 4]             [6 1 3]
       /     \             /     \
     [5]   [2 4]         [6]   [1 3]
           /   \               /   \
         [2]   [4]           [1]   [3]

     [5]   [2 4]         [6]   [1 3]           แล้ว merge กลับขึ้นมา
       [2 4 5]             [1 3 6]
              [1 2 3 4 5 6]
```

การรวมสองครึ่งที่ **เรียงแล้ว** ทำได้ใน $O(n)$: มีตัวชี้ `i` ที่หัวของครึ่งซ้าย `j` ที่หัวของครึ่งขวา หยิบตัวที่น้อยกว่าออกไปใส่ผลลัพธ์ทีละตัว เหมือนสองคิวที่ต่อแถวเรียงความสูงมาแล้ว แค่ดูหัวแถวสองคนก็รู้ว่าใครเตี้ยกว่า

| ซ้าย (เหลือ) | ขวา (เหลือ) | หยิบ | ผลลัพธ์ |
|---|---|---|---|
| `2 4 5` | `1 3 6` | `1` จากขวา | `1` |
| `2 4 5` | `3 6` | `2` จากซ้าย | `1 2` |
| `4 5` | `3 6` | `3` จากขวา | `1 2 3` |
| `4 5` | `6` | `4` จากซ้าย | `1 2 3 4` |
| `5` | `6` | `5` จากซ้าย | `1 2 3 4 5` |
| | `6` | `6` ที่เหลือ | `1 2 3 4 5 6` |

### Template: merge sort

```cpp
#include <bits/stdc++.h>
using namespace std;

vector<int> a, buf;

// เรียง a[l, r) (ครึ่งเปิด: รวม l ไม่รวม r)
void mergeSort(int l, int r) {
  if (r - l <= 1) return;                 // base case: ตัวเดียวหรือว่าง เรียงอยู่แล้ว
  int m = (l + r) / 2;
  mergeSort(l, m);                        // divide + conquer: ครึ่งซ้าย
  mergeSort(m, r);                        //                   ครึ่งขวา
  int i = l, j = m, k = l;                // combine: รวมสองครึ่งที่เรียงแล้ว
  while (i < m && j < r) {
    if (a[i] <= a[j]) buf[k++] = a[i++];  // เท่ากันหยิบซ้ายก่อน (stable)
    else buf[k++] = a[j++];
  }
  while (i < m) buf[k++] = a[i++];
  while (j < r) buf[k++] = a[j++];
  for (int t = l; t < r; t++) a[t] = buf[t];
}

int main() {
  ios::sync_with_stdio(false);
  cin.tie(nullptr);
  int n;
  cin >> n;
  a.resize(n);
  buf.resize(n);                          // จองที่ไว้ครั้งเดียว ใช้ร่วมกันทุกระดับ
  for (int &v : a) cin >> v;
  mergeSort(0, n);
  for (int v : a) cout << v << ' ';
  cout << '\n';
}
```

ใส่ `6` กับ `5 2 4 6 1 3` จะได้ `1 2 3 4 5 6` ในการแข่งจริงเรียงอาเรย์ด้วย `sort` ก็พอ ที่เราเขียน merge sort เองเพราะ **ขั้น merge คือจุดที่เราแอบนับอะไรบางอย่างได้** เดี๋ยวจะเห็น

## Recursion tree: ทำไมได้ $O(n \log n)$

ให้ $T(n)$ คือเวลาที่ merge sort ใช้กับอาเรย์ยาว $n$ มันเรียกตัวเองสองครั้งกับขนาด $n/2$ แล้ว merge อีก $O(n)$

$$T(n) = 2T(n/2) + O(n)$$

วาดการเรียกทั้งหมดเป็นต้นไม้ แล้วรวมงานทีละชั้น

```text
level 0               n                    work n
level 1          n/2     n/2               work n
level 2       n/4  n/4  n/4  n/4           work n
  ...               ...                     ...
level log n   1 1 1 1 ... 1 1 (n pieces)   work n
```

ทุกชั้นทำงานรวม $n$ เท่ากัน (ก้อนเล็กลงครึ่งหนึ่ง แต่จำนวนก้อนเพิ่มเป็นสองเท่า) และผ่าครึ่งได้ $\log_2 n$ ครั้งก็เหลือก้อนละตัว รวมเป็น $n \cdot \log_2 n$ คือ $O(n \log n)$ สำหรับ $n = 10^5$ ประมาณ $1.7 \times 10^6$ เทียบกับ $O(n^2)$ ที่ $10^{10}$

หลักคิดแบบ master theorem ฉบับจำง่าย: **ดูว่างานต่อชั้นเป็นยังไง** ถ้าเท่ากันทุกชั้นก็คูณ $\log n$ ถ้าลดลงเรื่อย ๆ ชั้นบนสุดชนะ ถ้าเพิ่มขึ้นเรื่อย ๆ ชั้นล่างสุดชนะ

| recurrence | ตัวอย่าง | ผลลัพธ์ |
|---|---|---|
| $T(n) = T(n/2) + O(1)$ | binary search | $O(\log n)$ |
| $T(n) = 2T(n/2) + O(1)$ | หาค่ามากสุดแบบแบ่งครึ่ง | $O(n)$ |
| $T(n) = 2T(n/2) + O(n)$ | merge sort | $O(n \log n)$ |
| $T(n) = 2T(n/2) + O(n \log n)$ | ขั้น combine ต้อง `sort` | $O(n \log^2 n)$ |
| $T(n) = T(n-1) + O(n)$ | แบ่งเบี้ยว ข้างหนึ่งเหลือตัวเดียว | $O(n^2)$ |

แถวสุดท้ายสำคัญ: การแบ่งต้อง **สมดุล** ถ้าแบ่งแล้วข้างหนึ่งเล็กนิดเดียว ต้นไม้จะลึก $n$ ชั้นแทน $\log n$ ชั้น ความเร็วหายหมด

## นับคู่ที่คร่อมสองครึ่ง: inversions

**Inversion** คือคู่ $(i, j)$ ที่ $i < j$ แต่ $a_i > a_j$ หรือ "คู่ที่อยู่ผิดลำดับ" นับตรง ๆ ก็ลูปซ้อน $O(n^2)$ แต่ divide and conquer ทำได้ดีกว่า ลองแบ่งคู่ทั้งหมดเป็นสามแบบ

* ทั้งคู่อยู่ในครึ่งซ้าย: ให้ recursion นับ
* ทั้งคู่อยู่ในครึ่งขวา: ให้ recursion นับ
* **คร่อม**: $i$ อยู่ซ้าย $j$ อยู่ขวา ต้องนับเองในขั้น combine

จุดเด็ดคือ สำหรับคู่คร่อม เงื่อนไข $i < j$ เป็นจริงอัตโนมัติ (ทุกตัวในซ้ายอยู่ก่อนทุกตัวในขวา) สิ่งเดียวที่ต้องสนคือ **ค่า** ดังนั้นต่อให้ recursion เรียงแต่ละครึ่งไปแล้ว จำนวนคู่คร่อมก็ไม่เปลี่ยน และพอเรียงแล้วก็นับง่ายมาก

```text
left (sorted):  2 4 5        right (sorted):  1 3 6
                ^ i                          ^ j

merge หยิบ 1 จากขวา: ตอนนี้ซ้ายยังเหลือ 2 4 5 ทุกตัวมากกว่า 1
และทุกตัวอยู่ก่อน 1 ในอาเรย์เดิม -> คู่คร่อมเพิ่ม 3 คู่
```

ทุกครั้งที่ merge หยิบตัวจาก **ขวา** ทุกตัวที่ยังค้างอยู่ฝั่งซ้ายคือคู่ inversion กับมันทั้งหมด งานเพิ่มแค่ $O(1)$ ต่อการหยิบ ทั้งอัลกอริทึมจึงยังเป็น $O(n \log n)$

:::problem lp_dc01_taller_in_front

:::hint ใบ้ Taller in Front
ใช้ template merge sort ได้เลย แค่ให้ฟังก์ชันคืนจำนวนคู่ด้วย (ของซ้าย + ของขวา + ที่นับตอน merge) ตอนหยิบจากขวา ฝั่งซ้ายเหลือกี่ตัว? นับจาก `i` กับ `m` ได้ทันที คนสูงเท่ากันไม่นับ ลองคิดว่าตอน `a[i] == a[j]` ควรหยิบฝั่งไหนก่อน และคำตอบอาจถึง $n(n-1)/2$ ต้องใช้ `long long`
:::

### เมื่อเงื่อนไขไม่ตรงกับลำดับของ merge

ถ้าเงื่อนไขของคู่ไม่ใช่ "มากกว่า" ตรง ๆ เช่น $a_i > 2 \cdot a_j$ จะนับตอน merge แบบเดิมไม่ได้ เพราะลำดับที่ merge หยิบ (ตามค่า $a$) ไม่ตรงกับเงื่อนไข แต่หลักเดิมยังใช้ได้: **สองครึ่งเรียงแล้ว** และ **คู่คร่อมสนแค่ค่า** ดังนั้นแยกเป็นอีกรอบหนึ่งก่อน merge ได้ ลองถามตัวเองว่า ถ้าไล่ฝั่งขวาจากน้อยไปมาก ขอบเขตของตัวฝั่งซ้ายที่ "ผ่านเงื่อนไข" ขยับไปทางเดียวไหม? ถ้าใช่ ก็คือ two pointers ที่เราคุ้นเคย รวม $O(n)$ ต่อชั้น

:::problem lp_dc02_twice_as_big

:::hint ใบ้ Twice as Big
ก่อน merge ให้นับคู่คร่อมด้วยตัวชี้สองตัว: เมื่อ $a_j$ (ฝั่งขวา) เพิ่มขึ้น $2 \cdot a_j$ ก็เพิ่มขึ้น ตัวแรกของฝั่งซ้ายที่มากกว่า $2 \cdot a_j$ จึงขยับไปทางขวาอย่างเดียว ค่าติดลบไม่ได้ทำให้เหตุผลนี้เสีย แต่ $2 \cdot a_j$ ใหญ่ถึง $2 \times 10^9$ ต้องคำนวณเป็น `long long` แล้วค่อย merge ตามปกติ (จะใช้ `std::merge` ก็ได้)
:::

## Maximum subarray แบบแบ่งครึ่ง

โจทย์: หา **ผลรวมที่มากที่สุดของช่วงที่ติดกัน** (ไม่ว่าง) ในอาเรย์ที่มีค่าติดลบได้ ช่วงที่ดีที่สุดอยู่ได้สามแบบเหมือนเดิม: ทั้งก้อนอยู่ซ้าย ทั้งก้อนอยู่ขวา หรือ **คร่อมกลาง** สองแบบแรก recursion จัดการ ส่วนแบบคร่อมต้องมีทั้ง `a[m-1]` และ `a[m]` จึงเป็น "suffix ของครึ่งซ้าย" ต่อกับ "prefix ของครึ่งขวา" และสองส่วนนี้เลือกแยกกันได้ ให้เอา suffix ที่ผลรวมมากที่สุด บวก prefix ที่ผลรวมมากที่สุด

```text
          left half           |          right half
   -2     1    -3     4       |    -1     2     1    -5
             <-------- suffix | prefix -------->
          (from m-1 leftward) | (from m rightward)
```

### Template: maximum subarray (divide and conquer)

```cpp
#include <bits/stdc++.h>
using namespace std;

vector<long long> a;

// ผลรวมมากที่สุดของ subarray (ไม่ว่าง) ที่อยู่ใน a[l, r)
long long best(int l, int r) {
  if (r - l == 1) return a[l];
  int m = (l + r) / 2;
  long long answer = max(best(l, m), best(m, r));   // อยู่ในครึ่งเดียวทั้งก้อน

  // คร่อมกลาง = suffix ของครึ่งซ้าย (ต้องมี a[m-1]) + prefix ของครึ่งขวา (ต้องมี a[m])
  long long sum = 0, leftBest = LLONG_MIN;
  for (int i = m - 1; i >= l; i--) {
    sum += a[i];
    leftBest = max(leftBest, sum);
  }
  sum = 0;
  long long rightBest = LLONG_MIN;
  for (int j = m; j < r; j++) {
    sum += a[j];
    rightBest = max(rightBest, sum);
  }
  return max(answer, leftBest + rightBest);
}

int main() {
  ios::sync_with_stdio(false);
  cin.tie(nullptr);
  int n;
  cin >> n;
  a.resize(n);
  for (auto &v : a) cin >> v;
  cout << best(0, n) << '\n';
}
```

### ลองไล่ด้วยมือ

input `8` กับ `-2 1 -3 4 -1 2 1 -5` ชั้นบนสุด $m = 4$ ครึ่งซ้าย `-2 1 -3 4` ครึ่งขวา `-1 2 1 -5`

* recursion ฝั่งซ้ายตอบ $4$ (ตัว `4` ตัวเดียว) ฝั่งขวาตอบ $3$ (`2 1`)
* suffix ของซ้าย ไล่จาก `4` ไปทางซ้าย: ผลรวม $4, 1, 2, 0$ มากสุด $4$
* prefix ของขวา ไล่จาก `-1` ไปทางขวา: ผลรวม $-1, 1, 2, -3$ มากสุด $2$
* คร่อมกลางได้ $4 + 2 = 6$ คือช่วง `4 -1 2 1`

คำตอบ $\max(4, 3, 6) = 6$ ขั้น combine ใช้ $O(n)$ จึงได้ $T(n) = 2T(n/2) + O(n) = O(n \log n)$

:::note แล้ว Kadane ล่ะ?
โจทย์นี้มีวิธี $O(n)$ ชื่อ **Kadane's algorithm**: เดินจากซ้ายไปขวา เก็บ "ช่วงที่ดีที่สุดที่จบตรงนี้" ถ้าช่วงเดิมติดลบก็ทิ้งแล้วเริ่มใหม่

```cpp
long long bestSum = LLONG_MIN, cur = 0;
for (long long v : a) {
  cur = max(v, cur + v);      // ต่อช่วงเดิม หรือเริ่มใหม่ที่ v
  bestSum = max(bestSum, cur);
}
```

ถ้าเจอโจทย์นี้ตรง ๆ ใช้ Kadane ไปเลย ที่เราฝึกแบบแบ่งครึ่งเพราะท่า "จัดการช่วงที่คร่อมกลาง" ใช้ได้กับโจทย์ที่ไม่มี Kadane ให้ใช้ด้วย
:::

ข้อถัดไปเป็นแบบนั้น ค่าของช่วงคือผลรวม **ลบด้วยค่ามากที่สุดในช่วง** ซึ่งทำให้ "ต่อช่วงเดิมหรือเริ่มใหม่" ตัดสินใจไม่ได้อีกแล้ว เพราะค่ามากสุดของช่วงอาจเปลี่ยนตามสิ่งที่จะต่อเข้ามาในอนาคต แต่ช่วงที่คร่อมกลางยังเป็น suffix ซ้ายบวก prefix ขวาเหมือนเดิม

:::problem lp_dc03_minus_the_max

:::hint ใบ้ Minus the Maximum
ช่วงคร่อมกลาง = suffix ซ้ายยาว $p$ (ผลรวม $S_L$ ค่ามากสุด $M_L$) ต่อกับ prefix ขวายาว $q$ (ผลรวม $S_R$ ค่ามากสุด $M_R$) ได้ค่า $S_L + S_R - \max(M_L, M_R)$ ปัญหาอยู่ที่ $\max$ ลองแยกกรณีว่าค่ามากสุดอยู่ฝั่งไหน ถ้าไล่ $p$ จากสั้นไปยาว $M_L$ เพิ่มขึ้นเรื่อย ๆ แล้วเซตของ $q$ ที่ $M_R \leq M_L$ หน้าตาเป็นยังไง? (คำใบ้: $M_R$ ก็เพิ่มตาม $q$) ถ้าเตรียม prefix max กับ suffix max ของบางค่าไว้ก่อน แต่ละ $p$ จะตอบได้ใน $O(1)$ อย่าลืมว่าช่วงที่มีตัวเดียวได้ $0$
:::

## ชิมลาง: closest pair of points

อีกโจทย์คลาสสิกของเทคนิคนี้: มีจุด $n$ จุดบนระนาบ หาคู่ที่ **ใกล้กันที่สุด** ลองทุกคู่คือ $O(n^2)$ แบบแบ่งครึ่งทำอย่างนี้

1. เรียงจุดตามแกน $x$ แล้วลากเส้นตั้งแบ่งจุดเป็นซ้ายกับขวาอย่างละครึ่ง
2. หาคู่ที่ใกล้สุดในแต่ละฝั่งด้วย recursion ได้ระยะ $d$ = ค่าที่น้อยกว่าของสองฝั่ง
3. คู่คร่อมที่จะชนะ $d$ ได้ ต้องอยู่ห่างเส้นแบ่งไม่เกิน $d$ ทั้งคู่ คือในแถบกว้าง $2d$

```text
              |<- d ->|<- d ->|
     .        |    .  |       |     .
          .   |       |  .    |
              |  .    |     . |        .
              |       |       |
    left        strip | strip       right
                      ^
                  split line
```

ในแถบนั้น ถ้าเรียงจุดตามแกน $y$ แต่ละจุดต้องเทียบกับจุดถัดไปแค่ไม่กี่จุด (พิสูจน์ได้ว่าไม่เกิน $7$ จุด เพราะในกล่อง $d \times 2d$ จะอัดจุดที่ห่างกันอย่างน้อย $d$ ได้ไม่มาก) ขั้น combine จึงเป็น $O(n)$ และทั้งหมดเป็น $O(n \log n)$ บทนี้ยังไม่เขียนโค้ด แค่อยากให้เห็นว่าโครง "สองฝั่ง + คร่อมกลาง" ไปได้ไกลแค่ไหน

## จุดที่พลาดบ่อย

:::warning base case กับการแบ่ง
ใช้ช่วงครึ่งเปิด `[l, r)` กับ `m = (l + r) / 2` แล้วหยุดเมื่อ `r - l <= 1` ถ้าลืม base case หรือแบ่งช่วงยาว $1$ ต่อ จะได้ช่วง `[l, l)` กับ `[l, l + 1)` วนไม่รู้จบจน stack ล้น ลองไล่ด้วยมือกับ $n = 1$ และ $n = 2$ ทุกครั้ง
:::

:::warning จองหน่วยความจำในทุกการเรียก
ถ้าในแต่ละการเรียกสร้าง `vector` ขนาด $n$ (ทั้งอาเรย์) ใหม่ งานรวมจะกลายเป็น $O(n^2)$ ทันที ให้จอง buffer ไว้ครั้งเดียวแบบ template หรืออย่างน้อยให้ขนาดเท่ากับ `r - l` ของช่วงนั้น
:::

:::warning ค่าเท่ากันตอน merge
ตอนนับ inversion ถ้า `a[i] == a[j]` แล้วไปหยิบฝั่งขวาก่อน จะนับคู่ที่เท่ากันเป็น inversion ด้วย ให้หยิบซ้ายก่อนเมื่อเท่ากัน (`<=`) ตาม template
:::

:::warning จำนวนคู่ล้น int
จำนวนคู่ได้ถึง $n(n-1)/2$ ซึ่งที่ $n = 10^5$ ก็เกือบ $5 \times 10^9$ แล้ว ตัวนับต้องเป็น `long long` รวมถึงค่าที่ฟังก์ชัน recursion คืนด้วย
:::

:::note ความลึกของ recursion ไม่น่าห่วง
ต่างจาก recursion ที่ลดทีละหนึ่ง ($n$ ชั้น) การแบ่งครึ่งลึกแค่ประมาณ $\log_2 n$ ชั้น $n = 10^6$ ก็แค่ $20$ ชั้น ไม่มีทาง stack ล้น (ถ้าแบ่งถูก)
:::

## สรุปสั้น ๆ

* Divide and conquer: แบ่งเป็นโจทย์ย่อยแบบเดียวกัน แก้ด้วย recursion แล้ว combine ส่วนที่ต้องคิดคือ combine
* Merge sort: ผ่าครึ่ง เรียงสองฝั่ง merge ด้วยสองตัวชี้ใน $O(n)$
* $T(n) = 2T(n/2) + O(n)$ ให้ $O(n \log n)$ เพราะงานต่อชั้นเท่ากันและมี $\log n$ ชั้น ต้องแบ่งให้สมดุล
* นับคู่: แยกเป็นในซ้าย ในขวา และคร่อม คู่คร่อมสนแค่ค่า จึงนับบนสองครึ่งที่เรียงแล้วได้ (ระหว่าง merge หรือ two pointers ก่อน merge)
* ช่วงคร่อมกลาง = suffix ของซ้าย + prefix ของขวา ใช้ได้ทั้ง maximum subarray และโจทย์ที่ Kadane ใช้ไม่ได้
* Closest pair ก็เป็นโครงเดียวกัน: สองฝั่ง แล้วตรวจแค่แถบแคบ ๆ ตรงกลาง
