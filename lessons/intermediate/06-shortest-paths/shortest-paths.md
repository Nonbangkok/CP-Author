## เมื่อถนนแต่ละเส้นยาวไม่เท่ากัน

บทกราฟที่แล้วเราใช้ BFS หาระยะทางที่สั้นที่สุด ซึ่งได้ผลเพราะทุกเส้นเชื่อม (edge) "ยาวเท่ากัน" คือนับเป็น $1$ ก้าว แต่โจทย์จริงมักให้ **กราฟมีน้ำหนัก** (weighted graph): ถนนแต่ละเส้นมีเวลา ค่าผ่านทาง หรือระยะทาง $w$ ของตัวเอง แล้วถามหาเส้นทางที่ **ผลรวมน้ำหนัก** น้อยที่สุด

ลองดูกราฟเล็ก ๆ นี้

```text
        4
   1 -------> 2
   |          ^
 1 |          | 2
   v          |
   3 ---------+
```

BFS จะบอกว่าไป `2` ใช้ $1$ ก้าว (เส้นตรง ยาว $4$) แต่ทางอ้อม `1 -> 3 -> 2` ใช้สองก้าว ยาวแค่ $1 + 2 = 3$ จำนวนก้าวน้อยไม่ได้แปลว่าระยะทางสั้น BFS จึงใช้ไม่ได้ตรง ๆ อีกต่อไป

บทนี้มีเครื่องมือหลักสามตัว เลือกใช้ตามหน้าตาของกราฟ

1. **Dijkstra** จากจุดเริ่มจุดเดียว น้ำหนักห้ามติดลบ เร็วที่สุด ใช้บ่อยที่สุด
2. **Bellman–Ford** จากจุดเริ่มจุดเดียว น้ำหนักติดลบได้ และจับ **วงจรลบ** ได้
3. **Floyd–Warshall** ระยะทางของ **ทุกคู่** จุด เหมาะกับกราฟที่มีไม่กี่ร้อยจุด

แถมท้ายด้วย **0-1 BFS** สำหรับกราฟที่น้ำหนักมีแค่ $0$ กับ $1$ และเทคนิค **กราฟของสถานะ** ที่ทำให้โจทย์แปลก ๆ กลายเป็น Dijkstra ธรรมดา

## Dijkstra

### ไอเดีย

เก็บ `dist[v]` = ระยะที่ดีที่สุด **เท่าที่รู้ตอนนี้** จากจุดเริ่มไป `v` ตอนแรก `dist[start] = 0` ที่เหลือเป็น $\infty$ แล้วทำซ้ำ

1. หยิบจุด `u` ที่ `dist[u]` **น้อยที่สุด** ในบรรดาจุดที่ยังไม่ได้หยิบ
2. ตอนนี้ `dist[u]` คือคำตอบจริงแล้ว ล็อกได้เลย
3. ลอง **relax** ทุกเส้น `u -> v` น้ำหนัก `w`: ถ้า `dist[u] + w < dist[v]` ก็อัปเดต `dist[v]`

ทำไมขั้นที่ 2 ถึงถูก? สมมติมีทางอื่นไป `u` ที่สั้นกว่า ทางนั้นต้องผ่านจุดที่ยังไม่ล็อกก่อนถึง `u` ให้ `x` เป็นจุดแรกแบบนั้น จุดก่อนหน้า `x` ล็อกแล้วและ relax มาแล้ว ระยะถึง `x` ตามทางนั้นจึงไม่น้อยกว่า `dist[x]` ซึ่งก็ไม่น้อยกว่า `dist[u]` (เพราะเราเลือก `u` ที่น้อยสุด) และเดินต่อจาก `x` ไป `u` ก็มีแต่ **บวกเพิ่ม** เพราะน้ำหนักไม่ติดลบ ทางนั้นจึงสั้นกว่าไม่ได้ เหตุผลนี้พังทันทีถ้ามีน้ำหนักติดลบ จำไว้ให้ดี

ขั้นที่ 1 ถ้าไล่หาด้วยลูปจะเป็น $O(N)$ ต่อครั้ง รวม $O(N^2)$ ใช้ `priority_queue` (min-heap จากบท STL) แทนจะเหลือ $O(\log)$ ต่อครั้ง

### Lazy deletion

`priority_queue` ลดค่าของสมาชิกที่อยู่ข้างในไม่ได้ เวลา `dist[v]` ดีขึ้นเราจึง **push คู่ใหม่ซ้ำเข้าไปเลย** คู่เก่าที่ระยะแย่กว่ายังค้างอยู่ใน heap พอวันหนึ่งมันถูก pop ออกมา เราดูว่า `d > dist[u]` ไหม ถ้าใช่แปลว่าเป็นของหมดอายุ ข้ามไปเฉย ๆ

```text
heap: (4, 2) (3, 2)      <- จุด 2 ถูก push สองรอบ
pop (3, 2)  -> ใช้งาน
pop (4, 2)  -> 4 > dist[2] = 3  ข้าม (continue)
```

ถ้าลืมบรรทัดนี้ คำตอบยังถูก แต่จุดเดียวกันจะถูกขยายหลายรอบ ซึ่งในกราฟที่ออกแบบมาแกล้งจะช้าลงมาก

### Template: เส้นทางที่สั้นที่สุดจาก $1$ ไป $N$ พร้อมพิมพ์เส้นทาง

กราฟทางเดียว $N$ จุด $M$ เส้น พิมพ์ระยะทาง และจุดที่ผ่านตามลำดับ (หรือ $-1$ ถ้าไปไม่ถึง) เก็บ `parent[v]` = จุดก่อนหน้า `v` บนเส้นทางที่ดีที่สุด แล้วเดินย้อนจาก $N$

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
  ios::sync_with_stdio(false);
  cin.tie(nullptr);
  int n, m;
  cin >> n >> m;
  vector<vector<pair<int, int>>> adj(n + 1);   // adj[u] = {(v, w), ...}
  for (int i = 0; i < m; i++) {
    int u, v, w;
    cin >> u >> v >> w;
    adj[u].push_back({v, w});                  // ทางเดียว (ถ้าสองทางให้เพิ่ม adj[v] ด้วย)
  }

  const long long INF = LLONG_MAX;
  vector<long long> dist(n + 1, INF);
  vector<int> parent(n + 1, 0);
  // min-heap ของ (ระยะ, จุด): ตัวที่ระยะน้อยสุดอยู่บนสุด
  priority_queue<pair<long long, int>, vector<pair<long long, int>>, greater<>> pq;
  dist[1] = 0;
  pq.push({0, 1});
  while (!pq.empty()) {
    auto [d, u] = pq.top();
    pq.pop();
    if (d > dist[u]) continue;                 // ของเก่าที่หมดอายุแล้ว ข้ามไป
    for (auto [v, w] : adj[u]) {
      if (dist[u] + w < dist[v]) {             // relax
        dist[v] = dist[u] + w;
        parent[v] = u;
        pq.push({dist[v], v});
      }
    }
  }

  if (dist[n] == INF) {
    cout << -1 << '\n';
    return 0;
  }
  vector<int> path;
  for (int v = n; v != 0; v = parent[v]) path.push_back(v);
  reverse(path.begin(), path.end());
  cout << dist[n] << '\n';
  for (int v : path) cout << v << ' ';
  cout << '\n';
}
```

สังเกตว่า `dist` เป็น `long long`: น้ำหนัก $10^6$ บนเส้นทางยาว $10^5$ เส้นรวมได้ $10^{11}$ เกิน `int` ไปไกล

### ลองไล่ด้วยมือ

กราฟจากรูปข้างบน เพิ่มอีกสามเส้น ($N = 5$, $M = 6$)

```text
5 6
1 2 4
1 3 1
3 2 2
2 4 1
3 4 5
4 5 3
```

| pop | ใช้หรือข้าม | relax | heap หลังจบรอบ |
|---|---|---|---|
| `(0, 1)` | ใช้ | `dist[2] = 4`, `dist[3] = 1` | `(1,3) (4,2)` |
| `(1, 3)` | ใช้ | `dist[2] = 1 + 2 = 3`, `dist[4] = 6` | `(3,2) (4,2) (6,4)` |
| `(3, 2)` | ใช้ | `dist[4] = 3 + 1 = 4` | `(4,2) (4,4) (6,4)` |
| `(4, 2)` | ข้าม ($4 > 3$) | | `(4,4) (6,4)` |
| `(4, 4)` | ใช้ | `dist[5] = 7` | `(6,4) (7,5)` |
| `(6, 4)` | ข้าม ($6 > 4$) | | `(7,5)` |
| `(7, 5)` | ใช้ | ไม่มีเส้นออก | ว่าง |

โปรแกรมพิมพ์ `7` แล้วตามด้วย `1 3 2 4 5` มีสองแถวที่ "ข้าม" นั่นคือ lazy deletion ทำงานอยู่

### ความซับซ้อน

แต่ละเส้นทำให้ push ได้ไม่เกินหนึ่งครั้ง heap จึงมีของไม่เกิน $M + 1$ ชิ้น แต่ละ push/pop เป็น $O(\log M)$ รวม $O((N + M) \log M)$ ซึ่ง $N, M$ ระดับ $10^5$ ถึง $10^6$ ก็ยังสบาย

## Bellman–Ford: เมื่อมีน้ำหนักติดลบ

ถ้ามีเส้นที่น้ำหนักติดลบ เหตุผลของ Dijkstra ใช้ไม่ได้แล้ว ดูตัวอย่างนี้

```text
1 --2--> 2
1 --5--> 3
3 --(-4)--> 2
```

Dijkstra หยิบจุด `2` (ระยะ $2$) ก่อนแล้วคิดว่าล็อกได้ แต่จริง ๆ `1 -> 3 -> 2` ยาว $5 - 4 = 1$ ถ้าใช้ท่า "ล็อกแล้วไม่แตะอีก" จะตอบผิด ส่วนแบบ lazy อาจบังเอิญถูกในกราฟเล็ก ๆ แต่ในกราฟที่ออกแบบมาแกล้งจะช้าแบบ exponential เลย **น้ำหนักติดลบเมื่อไหร่ ลืม Dijkstra ไปก่อน**

**Bellman–Ford** ง่ายกว่ามาก: relax **ทุกเส้น** วนไปเรื่อย ๆ หลังรอบที่ $i$ ทุกเส้นทางที่ใช้ไม่เกิน $i$ เส้นจะถูกต้องแล้ว เส้นทางที่สั้นที่สุดที่ไม่วนซ้ำใช้ไม่เกิน $N - 1$ เส้น ดังนั้น $N - 1$ รอบพอเสมอ

แล้วถ้ามี **วงจรลบ** (วงที่ผลรวมติดลบ) ล่ะ? เดินวนไปเรื่อย ๆ ระยะจะลดลงไม่มีที่สิ้นสุด "ทางที่สั้นที่สุด" จึงไม่มีอยู่จริง และจับได้ง่ายมาก: **ทำรอบที่ $N$ เพิ่ม ถ้ายังมีอะไรลดได้อีก แปลว่ามีวงจรลบ** ที่ไปถึงได้จากจุดเริ่ม

### Template: ระยะจากจุด $1$ หรือบอกว่ามีวงจรลบ

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
  ios::sync_with_stdio(false);
  cin.tie(nullptr);
  int n, m;
  cin >> n >> m;
  vector<array<long long, 3>> edges(m);        // {u, v, w}
  for (auto &e : edges) cin >> e[0] >> e[1] >> e[2];

  const long long INF = LLONG_MAX;
  vector<long long> dist(n + 1, INF);
  dist[1] = 0;
  bool changed = false;
  for (int round = 1; round <= n; round++) {   // N - 1 รอบพอ รอบที่ N เอาไว้จับวงจรลบ
    changed = false;
    for (auto [u, v, w] : edges) {
      if (dist[u] != INF && dist[u] + w < dist[v]) {   // ยังไปไม่ถึง u ก็อย่าเพิ่งใช้
        dist[v] = dist[u] + w;
        changed = true;
      }
    }
    if (!changed) break;                       // ไม่มีอะไรเปลี่ยนแล้ว เสร็จก่อนเวลา
  }

  if (changed) {                               // รอบที่ N ยังลดได้อีก
    cout << "NEGATIVE CYCLE\n";
    return 0;
  }
  for (int v = 1; v <= n; v++) {
    if (dist[v] == INF) cout << "INF ";
    else cout << dist[v] << ' ';
  }
  cout << '\n';
}
```

ลองกับ

```text
4 4
1 2 4
2 3 -2
3 4 3
4 2 -2
```

วง `2 -> 3 -> 4 -> 2` มีผลรวม $-2 + 3 - 2 = -1$ ติดลบ โปรแกรมพิมพ์ `NEGATIVE CYCLE` แต่ถ้าเปลี่ยนเส้นสุดท้ายเป็น `4 2 -1` วงจะรวมได้ $0$ ไม่ติดลบ คำตอบคือ `0 4 2 5`

เงื่อนไข `dist[u] != INF` สำคัญ: ถ้าไม่มี `INF + (ค่าติดลบ)` จะดูเหมือน "ไปถึงได้" ทั้งที่ไปไม่ถึง (และ `LLONG_MAX + w` ที่ $w > 0$ ก็ล้นด้วย)

ความซับซ้อน $O(NM)$ ช้ากว่า Dijkstra มาก ใช้เมื่อจำเป็นต้องรองรับน้ำหนักติดลบหรือต้องจับวงจรลบเท่านั้น

## Floyd–Warshall: ระยะทางทุกคู่

บางโจทย์ถามระยะระหว่าง **หลายคู่** มาก ๆ เช่นมีคำถาม $10^5$ ข้อ ถ้าคิดใหม่ทุกข้อจะไม่ทัน ถ้ากราฟมีจุดน้อย (ประมาณ $N \leq 400$) ให้คำนวณ **ทุกคู่ไว้ก่อน** ทีเดียว แล้วตอบแต่ละคำถามใน $O(1)$

ไอเดียเป็น DP: ให้ `d[i][j]` คือระยะที่สั้นที่สุดจาก `i` ไป `j` ที่ **ใช้จุดกลางทางได้แค่จุด $1..k$** ตอนเริ่ม ($k = 0$) ใช้ได้แค่เส้นตรง พอยอมให้ใช้จุด $k$ เพิ่ม ทางที่ดีที่สุดมีสองแบบ: ไม่ผ่าน $k$ (ค่าเดิม) หรือผ่าน $k$ (ไป `i -> k` แล้ว `k -> j`)

```text
          d[i][k]        d[k][j]
     i  ----------->  k  ----------->  j
     i  ---------------------------->  j
                    d[i][j]

d[i][j] = min(d[i][j], d[i][k] + d[k][j])
```

### Template: เลือกเมืองสร้างโรงพยาบาล

ถนนสองทาง $N$ เมือง อยากสร้างโรงพยาบาลในเมืองที่ทำให้ **เมืองที่ไกลที่สุด** ใกล้ที่สุด (สมมติว่ากราฟเชื่อมกันหมด) พิมพ์หมายเลขเมืองกับระยะนั้น

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
  ios::sync_with_stdio(false);
  cin.tie(nullptr);
  int n, m;
  cin >> n >> m;
  const long long INF = LLONG_MAX / 4;          // บวกกันสองตัวก็ยังไม่ล้น
  vector<vector<long long>> d(n + 1, vector<long long>(n + 1, INF));
  for (int i = 1; i <= n; i++) d[i][i] = 0;
  for (int i = 0; i < m; i++) {
    int u, v;
    long long w;
    cin >> u >> v >> w;
    d[u][v] = min(d[u][v], w);                  // ถนนซ้ำ เก็บเส้นที่สั้นกว่า
    d[v][u] = min(d[v][u], w);                  // ถนนสองทาง
  }

  for (int k = 1; k <= n; k++)                  // k ต้องอยู่นอกสุด!
    for (int i = 1; i <= n; i++)
      for (int j = 1; j <= n; j++)
        d[i][j] = min(d[i][j], d[i][k] + d[k][j]);

  int best = 0;
  long long bestFar = INF;
  for (int i = 1; i <= n; i++) {
    long long far = 0;                          // เมืองที่ไกลที่สุดจาก i
    for (int j = 1; j <= n; j++) far = max(far, d[i][j]);
    if (far < bestFar) {
      bestFar = far;
      best = i;
    }
  }
  cout << best << ' ' << bestFar << '\n';
}
```

### ลองไล่ด้วยมือ

```text
4 4
1 2 3
2 3 4
3 4 2
1 4 10
```

| หลัง $k$ | สิ่งที่เปลี่ยน |
|---|---|
| เริ่ม | มีแค่เส้นตรง: `d[1][2] = 3`, `d[2][3] = 4`, `d[3][4] = 2`, `d[1][4] = 10` |
| $k = 1$ | `d[2][4] = 3 + 10 = 13` |
| $k = 2$ | `d[1][3] = 3 + 4 = 7` |
| $k = 3$ | `d[1][4] = 7 + 2 = 9` (ดีกว่า $10$), `d[2][4] = 4 + 2 = 6` (ดีกว่า $13$) |
| $k = 4$ | ไม่มีอะไรดีขึ้น |

(ตารางเขียนแค่ครึ่งเดียว ถนนสองทาง `d[j][i]` เปลี่ยนตามกัน) เมืองที่ไกลที่สุดจากเมือง $1, 2, 3, 4$ อยู่ห่าง $9, 6, 7, 9$ โปรแกรมจึงพิมพ์ `2 6`

### ทำไม $k$ ต้องอยู่นอกสุด

ตอนคำนวณรอบของ $k$ เราใช้ `d[i][k]` กับ `d[k][j]` ที่ต้อง "เสร็จแล้วสำหรับจุดกลาง $1..k-1$" ถ้าเอา $k$ ไว้ในสุด `d[i][j]` จะถูกคิดจบภายในรอบ `(i, j)` เดียวตั้งแต่ตอนที่ค่าอื่นยังไม่พร้อม แล้วไม่มีใครกลับมาแก้อีก ได้คำตอบผิดแบบเงียบ ๆ (ตัวอย่างเล็กมักผ่าน ส่งจริงแล้วพัง) จำง่าย ๆ: **k-i-j**

ความซับซ้อน $O(N^3)$ หน่วยความจำ $O(N^2)$: $N = 400$ คือ $6.4 \times 10^7$ ยังไหว แต่ $N = 2{,}000$ ไม่ไหวแล้ว ข้อดีแถม: Floyd–Warshall รับน้ำหนักติดลบได้ (ถ้าไม่มีวงจรลบ) และถ้ามีวงจรลบ จะเห็น `d[i][i] < 0` หลังจบ

ดูข้อจำกัดก่อน: $N$ เล็ก แต่คำถามเยอะ และมีน้ำหนักติดลบ ลองคิดว่าทำ Bellman–Ford ใหม่ทุกคำถามต้องใช้งานกี่ครั้ง แล้วเทียบกับ $N^3$ ระวังให้ดีกับ template ข้างบน: มันใช้ `INF = LLONG_MAX / 4` แล้ว `min` ตรง ๆ ซึ่งปลอดภัยเพราะน้ำหนักไม่ติดลบ แต่ข้อนี้ `INF + (ค่าติดลบ)` จะน้อยกว่า `INF` นิดหน่อย แล้วถูกพิมพ์ออกมาเป็นตัวเลขแทนที่จะเป็น `NO` ข้ามคู่ที่ `d[i][k]` หรือ `d[k][j]` ยังเป็น `INF` ไปเลย
:::

## แถม: 0-1 BFS

ถ้าน้ำหนักมีแค่ $0$ กับ $1$ ไม่ต้องใช้ heap ก็ได้ ใช้ `deque` แทน: เส้นน้ำหนัก $0$ ไม่ทำให้ไกลขึ้น จุดใหม่จึง **push_front** (ทำต่อทันที) ส่วนเส้นน้ำหนัก $1$ ให้ **push_back** เหมือน BFS ธรรมดา deque จะเรียงตามระยะเองโดยไม่ต้อง sort งานรวม $O(N + M)$

ตัวอย่างคลาสสิก: ตาราง `#` คือกำแพง เดินในช่องว่างฟรี แต่เดินเข้าช่องกำแพงต้องทุบ $1$ ครั้ง อยากไปจากมุมซ้ายบนถึงมุมขวาล่างโดยทุบน้อยที่สุด

### Template: ทุบกำแพงน้อยที่สุด

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
  ios::sync_with_stdio(false);
  cin.tie(nullptr);
  int r, c;
  cin >> r >> c;
  vector<string> g(r);
  for (auto &row : g) cin >> row;

  const int INF = INT_MAX;
  vector<vector<int>> dist(r, vector<int>(c, INF));
  deque<pair<int, int>> dq;
  dist[0][0] = (g[0][0] == '#');
  dq.push_back({0, 0});
  int dr[] = {1, -1, 0, 0}, dc[] = {0, 0, 1, -1};
  while (!dq.empty()) {
    auto [x, y] = dq.front();
    dq.pop_front();
    for (int k = 0; k < 4; k++) {
      int nx = x + dr[k], ny = y + dc[k];
      if (nx < 0 || nx >= r || ny < 0 || ny >= c) continue;
      int w = (g[nx][ny] == '#');               // เดินเข้าช่องกำแพง = ทุบ 1 ครั้ง
      if (dist[x][y] + w < dist[nx][ny]) {
        dist[nx][ny] = dist[x][y] + w;
        if (w == 0) dq.push_front({nx, ny});    // น้ำหนัก 0 ไปหน้าแถว
        else dq.push_back({nx, ny});            // น้ำหนัก 1 ไปท้ายแถว
      }
    }
  }
  cout << dist[r - 1][c - 1] << '\n';
}
```

```text
4 5
..#..
###.#
..#..
.#...
```

ทางซ้ายมือต้องทุบสองครั้ง แต่ถ้าทุบกำแพงช่องแถว $1$ คอลัมน์ $3$ (นับจาก $1$) จะเดินลงช่องว่างคอลัมน์ $4$ ไปจนถึงมุมขวาล่างได้ โปรแกรมพิมพ์ `1`

## กราฟของสถานะ

โจทย์เส้นทางหลายข้อดูไม่เหมือน shortest path ตรง ๆ เพราะมี "เงื่อนไขพิเศษ" ติดมาด้วย เช่น ต้องแวะร้านก่อน, มีคูปองลดราคา, ต้องเดินจำนวนก้าวเป็นเลขคู่ ท่าที่ใช้คือ **ขยายจุดของกราฟ**: ให้จุดใหม่เป็นคู่ (ที่อยู่, ข้อมูลที่ต้องจำ) แล้ววาดเส้นเชื่อมระหว่างสถานะ จากนั้นก็ Dijkstra บนกราฟใหม่ได้เลย

ตัวอย่าง: เดินทางจากเมือง $1$ ไปเมือง $N$ แต่ **ต้องแวะเมืองที่มีร้านของฝากอย่างน้อยหนึ่งเมือง** สถานะคือ (เมือง, `b`) โดย `b = 1` ถ้าผ่านร้านมาแล้ว กราฟใหม่มีสองชั้น

```text
ชั้น b = 0 :  (1,0) --- (2,0) --- (3,0) ...
                           \
                            \  เดินเข้าเมืองที่มีร้าน: ข้ามขึ้นชั้นบน
                             v
ชั้น b = 1 :  (1,1) --- (2,1) --- (3,1) ...
```

คำตอบคือ `dist[(N, 1)]` ไม่ใช่ `dist[(N, 0)]`

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
  ios::sync_with_stdio(false);
  cin.tie(nullptr);
  int n, m, s;
  cin >> n >> m >> s;
  vector<int> shop(n + 1, 0);
  for (int i = 0; i < s; i++) {
    int x;
    cin >> x;
    shop[x] = 1;
  }
  vector<vector<pair<int, int>>> adj(n + 1);
  for (int i = 0; i < m; i++) {
    int u, v, w;
    cin >> u >> v >> w;
    adj[u].push_back({v, w});
    adj[v].push_back({u, w});
  }

  // สถานะ (เมือง, b): b = 1 ถ้าผ่านร้านมาแล้ว
  const long long INF = LLONG_MAX;
  vector<array<long long, 2>> dist(n + 1, {INF, INF});
  using State = tuple<long long, int, int>;     // (ระยะ, เมือง, b)
  priority_queue<State, vector<State>, greater<>> pq;
  dist[1][shop[1]] = 0;
  pq.push({0, 1, shop[1]});
  while (!pq.empty()) {
    auto [d, u, b] = pq.top();
    pq.pop();
    if (d > dist[u][b]) continue;
    for (auto [v, w] : adj[u]) {
      int nb = b | shop[v];                     // เข้าเมืองที่มีร้าน b กลายเป็น 1
      if (d + w < dist[v][nb]) {
        dist[v][nb] = d + w;
        pq.push({dist[v][nb], v, nb});
      }
    }
  }
  cout << (dist[n][1] == INF ? -1 : dist[n][1]) << '\n';
}
```

ลองกับ $N = 5$ มีร้านที่เมือง $4$ และถนน `1-2 (2)`, `2-5 (2)`, `1-3 (3)`, `3-4 (1)`, `4-5 (4)` ทางที่สั้นที่สุดคือ `1 -> 2 -> 5` ยาว $4$ แต่ไม่ผ่านร้าน คำตอบจริงคือ `1 -> 3 -> 4 -> 5` ยาว $8$ (input คือ `5 5 1` / `4` / ตามด้วยถนนห้าเส้น)

จำนวนจุดของกราฟใหม่คือ $N$ คูณจำนวนค่าที่เป็นไปได้ของข้อมูลที่จำ (ตัวอย่างนี้ $2N$) ถ้าข้อมูลที่จำมีไม่กี่ค่า ก็ยังเร็วเหมือน Dijkstra ปกติ

## เลือกอัลกอริทึมจากข้อจำกัด

| สถานการณ์ | ใช้อะไร | เวลา |
|---|---|---|
| ทุกเส้นยาวเท่ากัน | BFS | $O(N + M)$ |
| น้ำหนักมีแค่ $0$ กับ $1$ | 0-1 BFS | $O(N + M)$ |
| จุดเริ่มเดียว น้ำหนัก $\geq 0$ | Dijkstra | $O((N + M) \log M)$ |
| จุดเริ่มเดียว มีน้ำหนักติดลบ หรือต้องจับวงจรลบ | Bellman–Ford | $O(NM)$ |
| ทุกคู่ และ $N$ ไม่เกินประมาณ $400$ | Floyd–Warshall | $O(N^3)$ |
| ทุกคู่ แต่ $N$ ใหญ่ น้ำหนัก $\geq 0$ | Dijkstra จากทุกจุด | $O(N (N + M) \log M)$ |

## จุดที่พลาดบ่อย

:::warning ใช้ int เก็บระยะ
ผลรวมน้ำหนักบนเส้นทางยาว ๆ เกิน $2^{31}$ ได้ง่ายมาก ให้ `dist` เป็น `long long` ตั้งแต่แรก แล้วเลือก `INF` ให้ดี: ถ้าจะบวก `INF` กับอะไรก่อนเช็ก ใช้ `LLONG_MAX / 4` ไม่ใช่ `LLONG_MAX`
:::

:::warning priority_queue เป็น max-heap
`priority_queue<pair<long long, int>>` เฉย ๆ จะ pop ตัวที่ **มาก** ที่สุดก่อน Dijkstra ต้องการตัวน้อยที่สุด จึงต้องใส่ `greater<>` (หรือ push ระยะเป็นค่าติดลบ) ถ้าลืม คำตอบอาจยังถูกแต่ช้ามหาศาล เพราะทุกจุดถูกขยายซ้ำไปมา
:::

:::warning ลืมบรรทัด continue
`if (d > dist[u]) continue;` คือหัวใจของ lazy deletion ขาดไปแล้วโค้ดจะขยายจุดเดิมจากค่าเก่าซ้ำ ๆ ผ่านตัวอย่างแต่ TLE ตอนส่ง
:::

:::warning Dijkstra กับน้ำหนักติดลบ
ห้ามใช้เด็ดขาด แม้จะมีเส้นติดลบแค่เส้นเดียว ใช้ Bellman–Ford หรือ Floyd–Warshall แทน
:::

:::warning ลำดับลูปของ Floyd–Warshall
`k` นอกสุดเสมอ แล้วค่อย `i`, `j` อย่าลืมตั้ง `d[i][i] = 0` และเก็บเส้นที่สั้นที่สุดเมื่อมีถนนซ้ำระหว่างคู่เดียวกัน
:::

:::warning ถนนสองทาง
ถ้าโจทย์บอกว่าถนนไปกลับได้ ต้องใส่ทั้ง `adj[u]` และ `adj[v]` ลืมฝั่งเดียวแล้วจะไปไม่ถึงบางเมืองแบบงง ๆ
:::

:::note Python
ใน Python ใช้ `heapq` กับ tuple `(ระยะ, จุด)` ได้เลย (`heapq` เป็น min-heap อยู่แล้ว) และใช้เช็ก `if d > dist[u]: continue` แบบเดียวกัน อ่าน input ทีเดียวด้วย `sys.stdin.buffer.read().split()` จะเร็วกว่าอ่านทีละบรรทัดมาก
:::

## สรุปสั้น ๆ

* กราฟมีน้ำหนัก BFS ใช้ไม่ได้ เพราะก้าวน้อยไม่ได้แปลว่าระยะสั้น
* **Dijkstra**: หยิบจุดที่ใกล้ที่สุดจาก min-heap, relax เส้นออก, ข้ามของหมดอายุด้วย `if (d > dist[u]) continue;` ใช้ได้เฉพาะน้ำหนักไม่ติดลบ $O((N + M) \log M)$
* **Bellman–Ford**: relax ทุกเส้น $N - 1$ รอบ ถ้ารอบที่ $N$ ยังลดได้ แปลว่ามีวงจรลบ $O(NM)$
* **Floyd–Warshall**: ทุกคู่ใน $O(N^3)$ ลูป **k-i-j** ใช้กับ $N$ ไม่กี่ร้อย
* **0-1 BFS**: น้ำหนัก $0$ ไปหน้า deque น้ำหนัก $1$ ไปท้าย
* **กราฟของสถานะ**: จุด = (ที่อยู่, สิ่งที่ต้องจำ) แล้ว Dijkstra บนกราฟใหม่
* ระยะเป็น `long long` เสมอ และระวัง `INF` บวกกับอะไรแล้วล้นหรือกลายเป็นค่าที่ดูเหมือนไปถึงได้
