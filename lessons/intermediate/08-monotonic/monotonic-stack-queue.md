## ตัวถัดไปที่มากกว่า

เริ่มจากคำถามง่าย ๆ: มีอาเรย์ $a_0, a_1, \ldots, a_{N-1}$ สำหรับทุกตำแหน่ง $i$ อยากรู้ว่า **ตัวแรกทางขวาที่มากกว่า $a_i$** คือค่าอะไร (ถ้าไม่มีตอบ $-1$) เรียกกันว่า **next greater element**

ท่าตรง ๆ คือจากทุก $i$ เดินไปทางขวาจนเจอตัวที่มากกว่า ถ้าอาเรย์เรียงจากมากไปน้อย ทุกตัวต้องเดินไปจนสุดอาเรย์ งานรวมเป็น $O(N^2)$ ซึ่ง $N = 10^5$ ก็ไม่ทันแล้ว

บทนี้จะพาไปรู้จักเครื่องมือสองชิ้นที่หน้าตาคล้ายกัน คือ **monotonic stack** กับ **monotonic queue** (deque) ทั้งคู่ใช้ไอเดียเดียวกัน: **ทิ้งตัวที่ไม่มีวันเป็นคำตอบได้อีกแล้วออกไปเลย** ของที่เหลือในโครงสร้างจึงเรียงกันเป็นทางเดียว (monotonic) เสมอ

## Monotonic stack

ลองนึกภาพคนยืนต่อแถวกันจากซ้ายไปขวา ทุกคนอยากรู้ว่า "คนแรกทางขวาที่ตัวสูงกว่าเราคือใคร" เราเดินจากซ้ายไปขวาทีละคน แล้วถือ **stack ของคนที่ยังรอคำตอบอยู่**

พอคนใหม่ $a_i$ เดินมา ให้มองไปที่ยอด stack:

* ถ้าคนบนยอดเตี้ยกว่า $a_i$ แปลว่า $a_i$ คือ "คนแรกทางขวาที่สูงกว่า" ของเขาพอดี (คนที่อยู่ระหว่างนั้นไม่มีใครสูงกว่าเขา ไม่อย่างนั้นเขาคงได้คำตอบและออกไปแล้ว) ให้จดคำตอบแล้ว `pop` ออก ทำซ้ำไปเรื่อย ๆ
* พอยอด stack ไม่เตี้ยกว่า $a_i$ แล้ว ก็หยุด แล้ว `push` $a_i$ ลงไปรอคำตอบของตัวเอง

ผลคือค่าใน stack จากล่างขึ้นบน **ไม่เพิ่มขึ้นเลย** (มากไปน้อยหรือเท่ากัน) เพราะทุกครั้งที่ใส่ตัวใหม่ เราได้ไล่ตัวที่เล็กกว่ามันออกไปหมดแล้ว

```text
a = 4 2 1 3 ...            3 arrives

before   [ 4 2 1 ]         (bottom -> top)
           1 < 3   pop     answer of 1 is 3
           2 < 3   pop     answer of 2 is 3
           4 < 3 ? no      stop
after    [ 4 3 ]
```

### Template: next greater element

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
  ios::sync_with_stdio(false);
  cin.tie(nullptr);
  int n;
  cin >> n;
  vector<int> a(n);
  for (int &x : a) cin >> x;

  vector<int> nge(n, -1);  // ค่าของตัวแรกทางขวาที่มากกว่า, -1 = ไม่มี
  vector<int> st;          // เก็บ "ดัชนี" ของตัวที่ยังรอคำตอบ
  for (int i = 0; i < n; i++) {
    while (!st.empty() && a[st.back()] < a[i]) {
      nge[st.back()] = a[i];  // a[i] คือคำตอบของตัวบนยอด
      st.pop_back();
    }
    st.push_back(i);
  }
  // ตัวที่ยังค้างใน stack ไม่มีใครทางขวามากกว่า: คำตอบคือ -1 ตามค่าเริ่มต้น
  for (int i = 0; i < n; i++) cout << nge[i] << (i + 1 < n ? ' ' : '\n');
}
```

สังเกตว่า stack เก็บ **ดัชนี** ไม่ใช่ค่า เพราะตอนจดคำตอบเราต้องรู้ว่าจะเขียนลงช่องไหน และถ้าโจทย์ถามระยะห่าง ก็คิดจากดัชนีได้เลย

### ลองไล่ด้วยมือ

`a = [4, 2, 1, 3, 5, 3]`

| `i` | `a[i]` | pop (และคำตอบที่ได้) | stack หลัง push (ค่า) |
|---|---|---|---|
| 0 | 4 | | `[4]` |
| 1 | 2 | | `[4, 2]` |
| 2 | 1 | | `[4, 2, 1]` |
| 3 | 3 | `1 -> 3`, `2 -> 3` | `[4, 3]` |
| 4 | 5 | `3 -> 5`, `4 -> 5` | `[5]` |
| 5 | 3 | | `[5, 3]` |

จบลูป `5` กับ `3` ตัวสุดท้ายยังค้างอยู่ จึงได้ $-1$ โปรแกรมพิมพ์ `5 3 3 5 -1 -1`

### ทำไมถึงเป็น $O(N)$

หน้าตาเป็นลูปซ้อน แต่ให้นับจากมุมของแต่ละดัชนี: ทุกดัชนีถูก `push` **ครั้งเดียว** และถูก `pop` **ได้ไม่เกินครั้งเดียว** (ออกไปแล้วไม่เคยกลับมา) จำนวนรอบของ `while` รวมกันทั้งโปรแกรมจึงไม่เกิน $N$ งานรวมเป็น $O(N)$ เหตุผลเดียวกับที่ `l` ในบท Sliding Window ไม่เคยถอยหลัง

:::problem lp_mono01_warmer_days

:::hint ใบ้ Warmer Days
โจทย์ถาม "รออีกกี่วัน" ไม่ใช่ "ร้อนกี่องศา" ตอน `pop` เรามีทั้งดัชนีของคนที่รอ (`st.back()`) และดัชนีของวันที่มาตอบ (`i`) อยู่ในมือแล้ว ส่วนวันที่อุณหภูมิเท่ากันต้อง **ไม่** นับว่าร้อนกว่า ลองดูว่าเงื่อนไขใน `while` ควรเป็น `<` หรือ `<=`
:::

## สี่แบบที่หน้าตาเหมือนกัน

เปลี่ยนแค่สองอย่าง ก็ได้คำถามครบสี่แบบ

| อยากได้ | เดินทาง | `pop` ตัวบนยอดเมื่อ | คำตอบอ่านจาก |
|---|---|---|---|
| ตัวถัดไปที่มากกว่า | ซ้าย → ขวา | `a[top] < a[i]` | ตอน `pop` (คำตอบของ `top` คือ `i`) |
| ตัวถัดไปที่น้อยกว่า | ซ้าย → ขวา | `a[top] > a[i]` | ตอน `pop` |
| ตัวก่อนหน้าที่มากกว่า | ซ้าย → ขวา | `a[top] <= a[i]` | ยอด stack หลัง `pop` เสร็จ (คำตอบของ `i`) |
| ตัวก่อนหน้าที่น้อยกว่า | ซ้าย → ขวา | `a[top] >= a[i]` | ยอด stack หลัง `pop` เสร็จ |

แบบ "ก่อนหน้า" เป็นอีกมุมของเรื่องเดียวกัน: หลังไล่ตัวที่ใช้ไม่ได้ออกหมดแล้ว ตัวที่เหลือบนยอดคือตัวที่ใกล้ที่สุดทางซ้ายที่ผ่านเงื่อนไข ถ้าเดินจาก **ขวาไปซ้าย** แทน แบบ "ก่อนหน้า" ก็กลายเป็น "ถัดไป" ทันที

### Template: ตัวที่เล็กกว่าที่ใกล้ที่สุดทั้งสองข้าง

โค้ดนี้หา `L[i]` = ดัชนีของตัวแรกทางซ้ายที่ **น้อยกว่า** `a[i]` (ไม่มีให้เป็น $-1$) และ `R[i]` = ดัชนีของตัวแรกทางขวาที่น้อยกว่า `a[i]` (ไม่มีให้เป็น $N$)

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
  ios::sync_with_stdio(false);
  cin.tie(nullptr);
  int n;
  cin >> n;
  vector<long long> a(n);
  for (auto &x : a) cin >> x;

  vector<int> L(n), R(n), st;
  for (int i = 0; i < n; i++) {            // ซ้าย -> ขวา: ตัวก่อนหน้าที่น้อยกว่า
    while (!st.empty() && a[st.back()] >= a[i]) st.pop_back();
    L[i] = st.empty() ? -1 : st.back();
    st.push_back(i);
  }
  st.clear();
  for (int i = n - 1; i >= 0; i--) {       // ขวา -> ซ้าย: ตัวถัดไปที่น้อยกว่า
    while (!st.empty() && a[st.back()] >= a[i]) st.pop_back();
    R[i] = st.empty() ? n : st.back();
    st.push_back(i);
  }
  for (int i = 0; i < n; i++) cout << L[i] << (i + 1 < n ? ' ' : '\n');
  for (int i = 0; i < n; i++) cout << R[i] << (i + 1 < n ? ' ' : '\n');
}
```

ค่า $-1$ กับ $N$ ไม่ได้เลือกมาลอย ๆ มันคือ "กำแพง" ที่อยู่นอกอาเรย์พอดี ทำให้ช่วงระหว่าง `L[i]` กับ `R[i]` (ไม่รวมปลาย) ยาว `R[i] - L[i] - 1` เสมอ ไม่ต้องแยกกรณี

## สี่เหลี่ยมที่ใหญ่ที่สุดในฮิสโตแกรม

นี่คืองานคลาสสิกของ monotonic stack: มีแท่งกว้าง $1$ หน่วยวางเรียงกัน แท่งที่ $i$ สูง $h_i$ หาสี่เหลี่ยมผืนผ้าที่ใหญ่ที่สุดที่อยู่ในรูปนี้ทั้งผืน

```text
h = 2 1 5 6 2 3

            #
          # #
          # #                สี่เหลี่ยมที่ดีที่สุด: สูง 5
          # #   #            คร่อมแท่งที่ 2 กับ 3
      #   # # # #            พื้นที่ 5 x 2 = 10
      # # # # # #
      0 1 2 3 4 5
```

ไอเดียหลัก: สี่เหลี่ยมที่ดีที่สุดสูงเท่ากับ **แท่งที่เตี้ยที่สุดที่มันคร่อมอยู่** เสมอ (ถ้าเตี้ยกว่านั้นก็ยืดขึ้นได้อีก) ดังนั้นให้ลอง **ทุกแท่ง $i$ เป็นแท่งที่เตี้ยที่สุด** แล้วยืดสี่เหลี่ยมสูง $h_i$ ออกไปทั้งซ้ายและขวาให้กว้างที่สุด มันจะยืดได้จนชนแท่งที่ **เตี้ยกว่า** $h_i$ ซึ่งก็คือ `L[i]` กับ `R[i]` จาก template ข้างบนพอดี

$$\text{area}_i = h_i \times (R_i - L_i - 1)$$

| `i` | $h_i$ | `L[i]` | `R[i]` | กว้าง | พื้นที่ |
|---|---|---|---|---|---|
| 0 | 2 | $-1$ | 1 | 1 | 2 |
| 1 | 1 | $-1$ | 6 | 6 | 6 |
| 2 | 5 | 1 | 4 | 2 | **10** |
| 3 | 6 | 2 | 4 | 1 | 6 |
| 4 | 2 | 1 | 6 | 4 | 8 |
| 5 | 3 | 4 | 6 | 1 | 3 |

คำตอบคือ $10$ ทั้งหมดใช้ stack สองรอบ $O(N)$ แทนการลองทุกคู่ซ้ายขวา $O(N^2)$ (ถ้ามีแท่งสูงเท่ากันหลายแท่ง ทุกแท่งจะได้ช่วงเต็มเท่ากัน ซึ่งไม่ทำให้ค่ามากสุดผิด)

ถ้าใช้ stack แค่รอบเดียวก็ได้: ตอนที่แท่ง `top` ถูก `pop` เพราะเจอแท่งที่เตี้ยกว่า แปลว่าเรารู้ `R[top]` (คือ `i`) และ `L[top]` (คือตัวที่อยู่ใต้มันใน stack) พร้อมกันแล้ว คิดพื้นที่ได้เลย

:::problem lp_mono02_billboard

:::hint ใบ้ Billboard
ตึกไม่ได้กว้าง $1$ เท่ากันหมดแล้ว แต่เหตุผลเรื่อง "ป้ายสูงเท่าตึกที่เตี้ยที่สุดที่คร่อม" ยังจริงเหมือนเดิม ความกว้างของช่วงตึก `L[i] + 1` ถึง `R[i] - 1` หาได้ใน $O(1)$ ถ้าเตรียม prefix sum ของความกว้างไว้ก่อน และพื้นที่ใหญ่ได้ถึงราว $10^{18}$ ต้องเป็น `long long` ทั้งตอนคูณด้วย
:::

## Monotonic queue: ค่ามากสุดในหน้าต่าง

ในบท Sliding Window เราเลื่อนหน้าต่างแล้วอัปเดต **ผลรวม** หรือ **จำนวนนับ** ซึ่งเอาตัวที่ออกไปลบทิ้งได้ง่าย แต่ถ้าอยากได้ **ค่ามากสุด** ในทุกหน้าต่างยาว $K$ ล่ะ ตัวที่ออกอาจเป็นตัวมากสุดพอดี แล้วเราก็ไม่รู้ว่าตัวรองลงมาคือใคร คิดใหม่ทุกหน้าต่างก็ $O(NK)$

ทริกคือสังเกตว่า ถ้ามี `j < i` และ `a[j] <= a[i]` แล้ว **`a[j]` ไม่มีวันเป็นค่ามากสุดของหน้าต่างไหนอีกเลย** เพราะทุกหน้าต่างที่มี `j` และยังไม่หมดอายุในอนาคต จะมี `i` อยู่ด้วยเสมอ (`i` มาทีหลังและออกทีหลัง) ซ้ำยังมากกว่าหรือเท่ากันอีก

ดังนั้นเก็บ **deque ของดัชนี** ที่ค่า **ลดลงอย่างเคร่งครัด** จากหน้าไปหลัง

1. ตัวใหม่ `i` เข้าทาง **หลัง**: ไล่ `pop_back` ทุกตัวที่ค่า `<= a[i]` ออกก่อน (มันหมดหวังแล้ว) แล้วค่อย `push_back(i)`
2. ตัวที่ **หน้า** หมดอายุเมื่อดัชนีของมันหลุดหน้าต่าง: `pop_front`
3. ค่ามากสุดของหน้าต่างคือ `a[dq.front()]` เสมอ

```text
front [ 9  7  4 ] back      6 arrives
              4 <= 6        pop_back
           7 <= 6 ? no      stop
front [ 9  7  6 ] back      max = 9 (if 9 is still inside the window)
```

### Template: ค่ามากสุดของทุกหน้าต่างยาว $K$

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
  ios::sync_with_stdio(false);
  cin.tie(nullptr);
  int n, k;
  cin >> n >> k;
  vector<int> a(n);
  for (int &x : a) cin >> x;

  deque<int> dq;  // ดัชนี, ค่า a[] ลดลงอย่างเคร่งครัดจากหน้าไปหลัง
  for (int i = 0; i < n; i++) {
    while (!dq.empty() && a[dq.back()] <= a[i]) dq.pop_back();  // หมดหวังแล้ว
    dq.push_back(i);
    if (dq.front() <= i - k) dq.pop_front();  // หลุดหน้าต่าง [i-k+1, i]
    if (i >= k - 1) cout << a[dq.front()] << (i + 1 < n ? ' ' : '\n');
  }
}
```

ถ้าอยากได้ **ค่าน้อยสุด** แค่กลับเครื่องหมายในข้อ 1 เป็น `a[dq.back()] >= a[i]`

### ลองไล่ด้วยมือ

`a = [5, 3, 4, 1, 2, 6]`, $K = 3$

| `i` | `a[i]` | `pop_back` | `pop_front` | deque (ค่า) | หน้าต่าง | max |
|---|---|---|---|---|---|---|
| 0 | 5 | | | `[5]` | | |
| 1 | 3 | | | `[5, 3]` | | |
| 2 | 4 | 3 | | `[5, 4]` | `[5, 3, 4]` | 5 |
| 3 | 1 | | 5 (ดัชนี 0) | `[4, 1]` | `[3, 4, 1]` | 4 |
| 4 | 2 | 1 | | `[4, 2]` | `[4, 1, 2]` | 4 |
| 5 | 6 | 2, 4 | | `[6]` | `[1, 2, 6]` | 6 |

โปรแกรมพิมพ์ `5 4 4 6` ทุกดัชนีเข้า deque ครั้งเดียวและออกได้ครั้งเดียว (ไม่ทางหน้าก็ทางหลัง) รวมจึงเป็น $O(N)$ เหมือน stack

ในหน้าต่างขนาดคงที่ แต่ละรอบมีดัชนีหลุดหน้าต่างได้แค่ตัวเดียวคือ `i - k` จึงใช้ `if` ได้ แต่ถ้าเอาไปต่อกับ **หน้าต่างยืดหดได้** ที่ `l` อาจขยับหลายช่องในรอบเดียว ต้องเช็กให้ดีว่าหน้า deque ยังอยู่ในหน้าต่างหรือเปล่า

:::problem lp_mono03_stable_stretch

:::hint ใบ้ Stable Stretch
ถ้าช่วงหนึ่งนิ่ง ช่วงที่อยู่ข้างในมันก็นิ่งด้วย นี่คือเงื่อนไขทางเดียวแบบที่หน้าต่างยืดหดได้ในบท Sliding Window ต้องการ สิ่งที่ขาดคือการรู้ค่ามากสุด **และ** ค่าน้อยสุดของหน้าต่าง `[l, r]` ตลอดเวลา ลองถือ deque สองอันพร้อมกัน แล้วคิดว่าตอน `l` ขยับ ต้องเอาอะไรออกจากหน้า deque บ้าง ส่วนเรื่องช่วงที่เริ่มซ้ายสุด ให้ดูว่าควรอัปเดตคำตอบเมื่อยาว "มากกว่า" หรือ "มากกว่าหรือเท่ากับ"
:::

:::

:::warning `<` กับ `<=` ตอนค่าเท่ากัน
"มากกว่า" กับ "มากกว่าหรือเท่ากับ" ให้คำตอบต่างกันเมื่อมีค่าซ้ำ ก่อนเขียน `while` ให้ถามตัวเองว่า ตัวที่ค่าเท่ากันควรถูก `pop` หรือควรค้างไว้ แล้วลองไล่กับอาเรย์ที่ทุกตัวเท่ากัน เช่น `[7, 7, 7]` ดูว่าได้คำตอบตามที่โจทย์ต้องการไหม
:::

:::warning เช็กว่าว่างก่อนแตะยอด
`st.back()` หรือ `dq.front()` ตอนโครงสร้างว่างเป็น undefined behavior โปรแกรมอาจไม่ crash แต่ให้คำตอบมั่ว ให้เขียน `!st.empty() &&` นำหน้าในเงื่อนไขของ `while` เสมอ
:::

:::warning ตัวที่ค้างอยู่ตอนจบ
หลังลูปจบ ตัวที่ยังอยู่ใน stack คือตัวที่ "ไม่มีคำตอบ" ต้องมีค่าเริ่มต้นที่ถูกต้องรอไว้ (เช่น $-1$, $0$ หรือ $N$ ตามโจทย์) หรือใส่ตัวกั้น (sentinel) ท้ายอาเรย์เพื่อไล่มันออกให้หมด
:::

:::warning พื้นที่ล้น int
ความสูง $10^9$ คูณความกว้าง $10^5$ ก็เกิน `int` แล้ว ให้คูณเป็น `long long` ตั้งแต่ตัวตั้ง ไม่ใช่แปลงหลังคูณเสร็จ
:::

## สรุปสั้น ๆ

* Monotonic stack/queue ทิ้งตัวที่ไม่มีวันเป็นคำตอบอีกแล้ว ของที่เหลือจึงเรียงทางเดียวเสมอ
* Next greater element: เดินซ้ายไปขวา `pop` ตัวที่เล็กกว่าตัวใหม่ แล้วจดว่าตัวใหม่คือคำตอบของมัน
* "ก่อนหน้า" อ่านจากยอด stack หลัง `pop` เสร็จ "ถัดไป" อ่านตอน `pop` หรือเดินกลับทาง
* ฮิสโตแกรม: ลองทุกแท่งเป็นแท่งที่เตี้ยที่สุด ยืดไปจนชนแท่งที่เตี้ยกว่าทั้งสองข้าง
* Sliding window maximum: deque ของดัชนี ค่าลดลงจากหน้าไปหลัง `pop_back` ตัวที่หมดหวัง `pop_front` ตัวที่หลุดหน้าต่าง
* ทุกดัชนีเข้าและออกอย่างละไม่เกินครั้งเดียว จึงเป็น $O(N)$ ทั้งที่หน้าตาเป็นลูปซ้อน
